# V4-04.08 Hardware Isolation and Fault Containment

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04 The Nervous System|V4-04 The Nervous System]]

^sec-nervous-hardware-isolation

A large current transient during a neural accelerator burst can pull down a shared power rail and brown out or reset the permission processor without warning, while memory bus contention on a shared interconnect can delay safety checks past the hard real-time execution tick. Even when safety enforcement executes on a dedicated processor, physical coupling to the proposal engine can silently undermine software isolation. Containing faults across the two paths therefore requires isolating or bounding shared physical resources across four domains: execution hardware, reference oscillators, power distribution rails, and memory hierarchies.[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.15 Footnotes#^fn14|¹⁴]] Where any of those resources remain shared, the architecture must demonstrate that cross-domain interference and declared common-cause faults cannot prevent the permission path from meeting its execution deadline or initiating its qualified fallback.

The running machine’s two-processor architecture addresses each of these four fault paths with an explicit hardware design choice. The permission path executes from private memory over a dedicated board-level link, clocks from an independent oscillator, and draws power from the isolated rail specified in **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/02 The Physical Body/V4-02.09 Which Physical Budget Binds First#^sec-body-permission-rail-isolation|Cross-budget coupling and permission rail isolation]]** rather than from the primary 47.7 V drive bus feeding the application processor. Diode-isolated storage capacitors hold up this safety rail for 2 s. If a transient load fault pulls the drive bus down to the host converter’s undervoltage lockout threshold at 33 V, the safety microcontroller stays powered long enough to capture the undervoltage interrupt, log the event, and command a graceful fallback while the primary host resets. This holds only if the required detector, actuator power, and braking path survive the fault.

Keeping the logic powered does not guarantee motor torque or braking capability. Bringing a moving machine to a controlled stop requires sufficient DC bus energy, healthy inverter stages, and adequate obstacle clearance. If electrical drive power collapses entirely, the system must execute a qualified unpowered fallback whose mechanical brake engagement delay and subsequent stopping motion fit within the pre-allocated physical envelope. These isolation guarantees are design assertions that must be empirically verified on physical hardware. Every shared dependency must be carried forward into the formal verification handoff record.

Substrate isolation ensures that the permission path stays alive when the host crashes, but the enforcer’s downstream action depends entirely on how the proposer failed: through unresponsiveness or through corruption. Unresponsiveness occurs when an inference pipeline deadlocks, thread scheduling misses a deadline, or kernel memory fragmentation stalls process execution, yielding no new trajectory packets. A complete host crash trips the hardware heartbeat timer. Conversely, the host operating system might remain healthy while the user-space neural policy pipeline hangs; in that scenario, the proposer stops emitting admissible action chunks, allowing the active chunk’s lease or evidence deadline to lapse. These complementary deadlines form the supervisory timing hierarchy established in [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.05 Chunk Lease Sizing from the Stopping Budget#^sec-nervous-supervisory-timers|section 4.4.1]].

Corruption occurs when the proposer continues running and satisfies its heartbeat deadline, but outputs invalid or hazardous setpoints. Examples include kinematically unreachable joint configurations, step discontinuities in velocity requests, or floating-point NaNs and infinities caused by out-of-distribution visual tokens or matrix overflow. The enforcer handles these two failure profiles through orthogonal mechanisms: unresponsiveness triggers trajectory revocation as soon as the chunk lease or the heartbeat timer expires, whereas corruption prompts an immediate invariant rejection at the boundary filter upon the arrival of the malformed packet. A live heartbeat therefore never extends motion authority; only an admitted chunk renews it, and authority ends when the chunk lease runs out. Whether the chunk policy can renew quickly enough to keep the machine moving, and why the slower intent model supplies goals rather than holding chunk leases itself, is the coupled budget of [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.10 The Handoffs Matrix#^sec-nervous-coupled-budget|section 4.9.1]].

When active motion authority lapses without an admissible continuation, the permission path must execute an explicit degradation strategy rather than cutting motor bus power unconditionally. As detailed in **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/02 The Physical Body/V4-02.07 Electrical Power Integrity#^sec-body-unpowered-states|Unpowered states and unmanaged fallback dynamics]]**, de-energizing an inverter drops the actuators into uncontrolled freewheeling or dynamic short-circuit braking, neither of which produces an orderly, predictable stop. Instead, the safety path evaluates the plant’s instantaneous kinematic state and selects the safest feasible deceleration profile. An optional brief continuation along the last validated trajectory is permissible only while its state estimates, sensor evidence validity, chunk lease window, and obstacle clearance margins all remain valid.

Once that lease expires, any separately authorized fallback delay ${T_{\text{hold}}}$ is absorbed into the total reaction latency ${\tau_{\text{delay}}}$. It must fit, together with the evidence age, within the 176.3 ms left under the pre-brake ceiling once the lease path and brake onset are charged at the drive limit (notebook [4.1](https://mlsysbook.ai/vol4/04_nervous/04_nervous.html#nbk-nervous-watchdog-stopping-lease)). If measured latency bounds exceed this headroom, the enforcer must initiate deceleration sooner. Controlled braking uses the available actuator torque characterized in **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/02 The Physical Body/V4-02.05 Actuator Transmission Limits#^sec-body-actuator-limits|Actuator Transmission Limits]]** to arrest motion within the remaining clearance. On gravity-loaded manipulators, motion arrest must be backed by engaging rated mechanical holding brakes once the joints reach standstill, preventing gravitational backdriving when drive power is subsequently removed.

After the physical plant comes to a complete halt, the architecture executes a **recovery handshake** before restoring autonomous proposal authority. The safety microcontroller asserts a persistent `FAULT_HELD` latch in its exported status register and publishes the plant’s confirmed physical rest pose $({\mathbf{q}_{\text{rest}}}, {\dot{\mathbf{q}}} = {\mathbf{0}})$. In turn, the application processor must discard all pending action chunks, invalidate internal state tied to the interrupted motion, capture fresh sensor observations tagged with synchronized hardware timestamps, and formulate a newly aligned trajectory proposal.

This recovery sequence must also purge any proposal-side state that assumes the robot executed its planned trajectory to completion. For autoregressive policies and VLA models, this requires flushing token buffers and the key-value (KV) attention cache; retaining pre-fault keys and values would bias future action generation toward a physical trajectory that was interrupted. However, clearing software caches does not by itself establish physical continuity. Before deasserting the `FAULT_HELD` latch and restoring proposal authority, the safety microcontroller inspects the opening waypoint ${\mathbf{a}_0}$ of the incoming proposal, verifying that it aligns with the robot’s measured physical rest pose within a strict spatial bound ($||{\mathbf{a}_0} - {\mathbf{q}_{\text{rest}}}|| \le {\epsilon_{\text{sync}}}$).

Architectural independence cannot simply be read off a schematic or block diagram; it must be empirically validated against identified common-cause faults on the physical board. Similarly, the chunk lease that constrains a malfunctioning proposer derives directly from physical dynamics, sized from the stopping margin that remains after detection delays and actuator responses. Together, these defenses bound a proposer that crashes, stalls, or publishes corrupted actions. The separation leaves one question open, whether a neural policy engineered to execute deterministically at the enforcer’s own update rate still requires an external runtime monitor.
