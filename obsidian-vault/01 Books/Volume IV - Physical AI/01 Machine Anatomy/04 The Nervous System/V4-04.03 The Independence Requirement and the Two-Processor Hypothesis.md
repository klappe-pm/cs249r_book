# V4-04.03 The Independence Requirement and the Two-Processor Hypothesis

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04 The Nervous System|V4-04 The Nervous System]]

^sec-nervous-silicon-partitioning

When an inference model suffers a transient stall or drops a frame, the robot can safely reject the stale proposal and fall back to local control. When a permission check stalls, however, the delay burns directly through the machine’s stopping budget, regardless of whether the processor eventually catches up. The two workloads therefore optimize for different guarantees. A neural chunk policy needs high compute throughput and memory bandwidth to stream motion proposals at its target renewal rate, whereas the permission path needs a strict, provable upper bound on the time required to validate and dispatch each step.

Standard operating-system schedulers decide which ready task executes next, but software priority alone cannot guarantee deterministic timing. Raising a control task’s priority reduces processor contention, yet it cannot prevent microarchitectural delays. A sudden page fault suspends execution while the virtual memory subsystem resolves the missing page. Lock contention on shared kernel primitives leaves a real-time thread waiting behind uncritical background tasks. Memory requests stall at the arbiter while DMA transfers from a GPU or neural accelerator saturate the system interconnect. Long inference latency tails[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.15 Footnotes#^fn2|²]] therefore threaten closed-loop stability even when average proposal latency remains well within nominal bounds.

Bounding the permission tick against those microarchitectural stalls requires separating the parts of its cycle using the standard terms of real-time scheduling ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.14 Source References#^ref-buttazzo2011hard|Buttazzo 2011]]; [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.14 Source References#^ref-kopetz2011real|Kopetz 2011]]). The permission tick runs as a periodic task ${i}$ released once every **period** ${T}_i$, set here to 1 ms. Each release is a single job that must finish before its relative **deadline** ${D}_i$, measured from the release instant and set here to 400 μs. The deadline is shorter than the period so that each admitted setpoint is ready within the cycle that computed it rather than one tick later, a delay whose cost [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.04 Multi-Rate Cadences#^sec-nervous-time-constants-phase-lag|section 4.3.1]] prices. It also leaves the rest of the period free for lower-priority work. A deadline is *hard* when a single miss can cause a physical hazard, as on the permission tick, where one late check adds one more millisecond of unchecked motion. The total wall-clock time from task release to job completion is its **response time** ${R}_i$. The part of that response time spent running the task’s own instructions is bounded above by its **worst-case execution time (WCET)**[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.15 Footnotes#^fn3|³]] ${C}_i$.

**Definition 4.1: Worst-case execution time**

***Worst-case execution time*** is the longest time a task can take to run to completion on a given processor, over every admissible input and every state its caches, pipeline, and buses can be in, with no other task competing for the processor.

1.  **Significance**: It is the ${C}_i$ term of every response bound in this chapter, and every margin above it is sized on it. The permission tick declares 250 μs against an unloaded run of 135 μs. The 115 μs between them is a claim that analysis must justify before the 400 μs deadline, and the stopping budget behind it, can rely on the number.
2.  **Distinction**: Unlike a mean or a high percentile such as $\text{p99}$, which describe the executions a test happened to reach, the WCET covers every admissible path and processor state. A declared WCET is a third quantity, a number the design commits to, which evidence must show is no smaller than the true one.
3.  **Common pitfall**: Recording the largest measured execution time as the WCET. A measured maximum can refute a declared bound but never establish it, because a test campaign reaches only some of the processor states in which the code can run ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.14 Source References#^ref-wilhelm2008worst|Wilhelm et al. 2008]]).

The rest of the response time is spent waiting rather than running. **Blocking** ${B}_i$ is the time a task spends waiting for a lower-priority task to release a shared hardware or software resource, whereas **interference** ${I}_i$ is the time taken by higher-priority tasks, kernel interrupts, and exception handlers that preempt the job. Because blocking and interference vary from one release to the next, the exact timing of recurring events shifts from cycle to cycle, a variation called **jitter**. Task releases, sensor samples, and job completions each have their own jitter, so a tick released on schedule can still miss its completion deadline if its internal wait times fluctuate. Later, [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.06 Real-Time Command Transport and Bus Determinism#^sec-nervous-rta-variance|section 4.5.1]] combines ${C}_i$, ${B}_i$, and ${I}_i$ into a provable bound on ${R}_i$.

Placed on one axis, the terms separate an illustrative unloaded observation from the bound the schedule assumes ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.03 The Independence Requirement and the Two-Processor Hypothesis#^fig-04-permission-tick|figure 1]]). The unloaded run of 135 μs is an illustrative observation, not a reported measurement. The 115 μs above it, up to the declared 250 μs, is a claim that WCET analysis must certify. The slack from there to the 400 μs deadline is all the room left for blocking and interference. Underneath, the base covers 1.5 mm during every tick at its 1.5 m/s drive limit, so each of these microsecond terms is ultimately paid in millimeters.

Blocking introduces an architectural vulnerability that priority schemes alone cannot resolve. In **priority inversion**, a high-priority task waits for a shared resource held by a low-priority task, while medium-priority tasks that need no shared resource preempt the lock holder and so starve the high-priority task for as long as they run. Only a real-time locking protocol, such as priority inheritance or priority ceiling emulation, can bound that wait. The recurring resets of the 1997 Mars Pathfinder spacecraft are the canonical case of an inversion left unbounded; war story [4.1](https://mlsysbook.ai/vol4/04_nervous/04_nervous.html#ws-nervous-1997-mars-pathfinder-priority-inversion) in [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.06 Real-Time Command Transport and Bus Determinism#^sec-nervous-rta-variance|section 4.5.1]] traces it once the response-time bound it violated is in hand.

POSIX real-time extensions (such as `SCHED_FIFO` priority scheduling and memory locking via `mlockall()`), real-time Linux kernels (`PREEMPT_RT`), and dual-kernel architectures (such as Xenomai) target specific software sources of delay. Locking physical memory via `mlockall()` eliminates demand paging inside the timed control loop. Assigning processor affinity confines threads to specific CPU cores to avoid migration latency and cache thrashing. Priority inheritance elevates a low-priority lock holder’s priority whenever a high-priority task requests its mutex. These operating-system mechanisms, however, guarantee determinism only when supported by proper configuration, bounded system calls, and verified timing evidence.

↪ The scheduling, interrupt, and memory mechanisms whose formal contribution enters a response bound are developed in **[[05 Reference/Volume IV - Physical AI/V4 Systems and Hardware#^sec-appendix-systems-timers|Real-Time Timers, Watchdogs, and Schedulability]]**.

Shared hardware introduces delays that operating-system software priorities cannot control. A control task cannot read an optical encoder buffer while a high-bandwidth peripheral monopolizes a shared PCI Express (PCIe) link or system memory bus. Any physical infrastructure that two processing domains share, whether system memory, power regulation, a thermal path, or a reference oscillator, can delay or silence the permission path without a single software fault. Cataloging those physical couplings and gathering the evidence required to verify their isolation belongs to placement (**[[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.03 Two Paths and the Resources They Share#^sec-placement-two-paths-one-die|Two Paths and the Resources They Share]]**). The requirement that analysis tests can be stated now. Under any workload the proposer can generate, the permission path must meet its response bound and keep its authority to refuse an unsafe motion. This chapter calls that requirement independence.

The running machine meets the independence requirement by putting the two paths on two processors, a hypothesis it must still test ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.03 The Independence Requirement and the Two-Processor Hypothesis#^fig-04-two-processor-implementation|figure 2]]). An application processor runs perception, the 2 Hz intent model, and the 20 Hz chunk policy. A separate safety microcontroller unit (MCU) runs the permission path and alone drives the motors. Between them runs a board link, a serial peripheral interface (SPI) or Controller Area Network with Flexible Data-rate (CAN FD) bus carrying framed packets with cyclic redundancy checks (CRCs) and sequence numbers. The link is treated as a *black channel*, one the endpoints do not trust, so each frame carries its own integrity and timing checks ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.05 Chunk Lease Sizing from the Stopping Budget#^sec-nervous-supervisory-timers|section 4.4.1]]). The two paths share no processor cores, caches, or memory buses, and the learned proposers on the host have no memory-mapped input/output (MMIO) access to the drive registers. Candidate chunks cross the link into the MCU’s own SRAM through a double buffer. A receive DMA transfer fills a private receive buffer. The receive interrupt copies each checked frame into a single mailbox slot guarded by a sequence lock, or *seqlock*, whose protocol [[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.04 Multi-Rate Cadences#^sec-nervous-mailbox-exchanges|section 4.3.2]] develops. A 1 kHz permission tick reads that slot, checks each proposal’s freshness, lease, and kinematic limits against measured encoder feedback, and is the only code that can send an admitted setpoint to the drives. The host is an unprivileged client; the microcontroller, with a short and cycle-counted loop, is the part whose worst-case execution time can be bounded.

Physical separation onto separate chips represents one realization. A single system-on-chip can also host both paths, provided that on-chip interconnects, cache partitioning, and memory controllers demonstrate equivalent response bounds and fault containment under stress. Choosing between discrete silicon and partitioned on-chip cores is the central placement trade-off, and until loaded experiments settle it, physical separation remains a foundational design hypothesis. Scheduling both paths on shared processor cores introduces the problem of *mixed-criticality scheduling*, in which each task carries execution-time bounds of graduated assurance levels. The operating system guarantees each deadline only under the bound its own criticality demands, which allows the proposer to overrun while the permission path executes deterministically ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.14 Source References#^ref-vestal2007preemptive|Vestal 2007]]). Sharing memory on a single die also demands explicit memory-bandwidth regulation to prevent tensor accelerators from starving real-time safety routines.

Designating an embedded controller as a *safety microcontroller* claims far more than physical separation on a circuit board. It denotes a device developed, qualified, and assessed under the IEC 61508 functional-safety standard, accompanied by a safety manual specifying its certified integrity level and the operational conditions that support depends on ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.14 Source References#^ref-iec61508-2-2010|International Electrotechnical Commission 2010b]]). At the silicon level, a safety MCU integrates specialized hardware redundancy to detect internal faults autonomously. Dual processor cores execute in lockstep while a comparator flags divergent execution. Error-correcting codes (ECC) protect internal SRAM and flash memories against single-event upsets. A hardware memory protection unit (MPU) confines each task to its assigned memory range. Analog monitors continuously watch the clock and supply voltages. Built-in self-tests run at power-up and periodically during operation to verify internal logic. An external watchdog timer, clocked by its own oscillator and serviced within a strict time window or through challenge-response messages, monitors the core. Because the watchdog relies on an independent clock source, a physical fault that stops the microcontroller’s oscillator cannot stall the watchdog, allowing it to detect that silent processor failure and command a qualified out-of-band response. Successful physical containment still depends on the response path, its surviving power, and the actuator premises.

Two different protections meet at this microcontroller, and keeping them apart explains the standards that follow. The chunk lease protects the stopping budget against a proposer that stalls or misbehaves. The rated claim that the machine will not strike a person rests elsewhere, on the independent protective path of **[[01 Books/Volume IV - Physical AI/00 Introduction/01 The Causal Boundary/V4-01.05 Defining the Causal Boundary#^sec-boundary-kinematic-roofline|Delay consumes stopping clearance]]** (a certified safety scanner wired to the drives, with its own sensing, timing, and power) and on the drives’ certified stop functions. Hardware diagnostic features alone do not confer a safety rating on the robot. Under functional safety standards, integrity belongs to a specific safety function, such as revoking actuator authority when a lease expires, rather than to an individual chip. The industrial standard IEC 61508 classifies safety functions by Safety Integrity Level (SIL 1 through SIL 4), where each numerical increment demands approximately an order-of-magnitude reduction in the allowable rate of dangerous failure ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.14 Source References#^ref-iec61508|International Electrotechnical Commission 2010a]]). The machinery standard ISO 13849-1 grades safety functions by Performance Level (PL a through PL e) ([[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.14 Source References#^ref-iso13849part1|International Organization for Standardization 2023]]). A Performance Level combines four architectural factors. The structural Category ranges from single-channel architectures using well-tried components (Categories B and 1), through single channels with periodic diagnostic testing (Category 2), to dual-channel redundant designs in which no single hardware fault defeats safety enforcement (Categories 3 and 4). Component reliability is quantified as the mean time to dangerous failure. Diagnostic coverage defines the fraction of dangerous failures detected by internal testing. Physical defenses guard against common-cause failure, where a shared disturbance disables redundant channels simultaneously. The safety microcontroller contributes certified failure rates and diagnostic coverage to this calculation, while the target Performance Level is dictated by the severity and exposure of the physical hazard the safety function must mitigate.

↪ The Performance Level each certified stop and speed function of the running machine must reach is developed in **[[01 Books/Volume IV - Physical AI/03 Running the Machine/12 Safety Enforcement/V4-12.10 The Fallback Ladder#^sec-enforcement-certified-functions|Certified safety functions beneath the permission path]]**.

The physical architecture of the robot makes a deliberate engineering trade-off that functional safety certification must evaluate. Its permission path executes real-time performance tasks, validating trajectory proposals and interpolating admitted waypoints into drive setpoints, alongside the safety function intended for qualification: revoking actuator authority and commanding a safe stop when a chunk lease expires or the host heartbeat falls silent. The algorithmic admission checks themselves carry no formal safety rating, which is why the protective claim stays with the scanner and the drive stop circuits (**[[01 Books/Volume IV - Physical AI/03 Running the Machine/12 Safety Enforcement/V4-12.10 The Fallback Ladder#^sec-enforcement-certified-functions|Certified safety functions beneath the permission path]]**). Standard functional-safety practice keeps complex control algorithms out of the certified safety channel, relying instead on an independent monitoring channel to satisfy Category 3 and Category 4 redundancy requirements. Modern motor drives supply part of that second channel through integrated hardware safety functions such as Safe Stop 1 (SS1), which brakes the motor under drive control and then removes torque.

↪ How Safe Stop 1 and the other drive safety functions realize the industrial stop categories is developed in **[[01 Books/Volume IV - Physical AI/03 Running the Machine/12 Safety Enforcement/V4-12.10 The Fallback Ladder#^sec-enforcement-stop-categories|Industrial stop categories and the safe torque off trap]]**.

Any hardware split must keep the permission path the sole writer of the actuators and bound its check time across all expected hardware and software faults. Putting the two paths on separate chips is the cleanest way to start, though empirical timing evidence under load must still confirm that isolation. Separate processors, however, run on asynchronous clocks at very different rates, so the link between them must pass trajectory updates continuously without ever forcing the fast permission reader to wait on the slower host writer.
