*Why can a robot recognize what to do yet still be too late to act?*

Learned models are what let a physical machine handle objects and scenes that no engineer enumerated, and they are also the largest and least predictable computation the machine carries. A model that recognizes the right object still has to move its weights through an onboard processor that sensing and control also depend on, and a larger model that recognizes more takes longer to answer. While it computes, the world keeps moving, so a correct answer can arrive after the conditions that justified it have changed. Predicting a sequence of future motions keeps the actuators supplied between model updates, but it cannot make those motions respond to observations the model has not yet received, and a proposal that arrives on time can still be wrong in ways the model’s own confidence does not reveal. An engineer who treats the learned model as a function that returns actions cannot size the processor, set the rates at which proposals are renewed, or say how long the machine may keep moving on an answer that has gone stale. Because motion beyond the causal boundary cannot be recalled, every learned proposal must remain a request that an independent permission path can refuse in time.

**Learning Objectives**

- Compare classical analytical pipelines and learned representations on coverage, sensory robustness, and formal verifiability
- Calculate the memory wall bound on a model’s fresh-evaluation rate (${f} \le {\text{BW}_{\text{mem}}} / {M_{\text{weights}}}$) under the embodied batch size 1 constraint, and explain why weight-only quantization shortens the bandwidth-bound decode but not the compute-bound prefill
- Estimate key-value cache expansion from multi-camera tokenization, hidden dimensions, and retained history windows
- Explain how action chunking (${H}$) amortizes off-chip weight transfers without improving closed-loop reaction latency, and why that gap requires a second, smaller proposer
- Compare autoregressive, one-pass, and iterative action decoders by the sequential evaluations and off-chip transfers one chunk costs
- Apply replanning period, inference latency, and target drift to size an action chunk for a dynamic target
- Evaluate the interface between a slow and a fast proposer by what the permission path can check against its own evidence
- Diagnose cognitive failure modes: semantic hallucinations, uncalibrated softmax overconfidence, perceptual chattering, and expired intent leases
- Identify the trajectory, timestamps, and validity information a proposer must hand to independent real-time verification
