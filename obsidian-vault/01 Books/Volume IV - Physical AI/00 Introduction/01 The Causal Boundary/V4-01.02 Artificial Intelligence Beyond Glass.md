# V4-01.02 Artificial Intelligence Beyond Glass

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/00 Introduction/01 The Causal Boundary/V4-01 The Causal Boundary|V4-01 The Causal Boundary]]

^sec-boundary-beyond-glass

When an image classifier mislabels a warehouse photograph on a server, a downstream filter can discard the label before any machine moves; when a mobile robot’s policy misjudges aisle clearance and drives its wheel motors, the chassis is already accelerating toward the rack. Across offline advisory prediction, digital agency, and physical embodiment, computation acquires different consequences as its outputs enter an action loop, and physical AI diverges from the other two in how agency, time, and recovery behave ([[01 Books/Volume IV - Physical AI/00 Introduction/01 The Causal Boundary/V4-01.02 Artificial Intelligence Beyond Glass#^tbl-01-paradigms|table 1]]).

In the offline or advisory case, a model delivers predictions against a static dataset before any downstream action closes a feedback loop. Whether classifying an image, predicting customer churn, estimating a bounding box, or ranking search results, the model operates in open loop. Its input distribution is exogenous, because the predictions it emits do not alter the process that generates later test examples. Because those requests arrive independently, throughput-oriented serving can batch many inputs together (${B} \gg 1$) across pipeline stages, performing many arithmetic operations for every byte of weights fetched from memory (its arithmetic intensity). The advisory model exercises no agency of its own. Before a person or downstream service acts on the output, an incorrect label or irrelevant search result can be ignored, filtered, or recalculated without having done physical work.

The emergence of agentic machine learning marked an architectural transition from passive, single-shot prediction to active, sequential decision-making. Endowed with reasoning loops and test-time deliberation, an agentic model formulates multi-step plans, maintains internal state across execution traces, and autonomously invokes external tools. These tools execute database queries, call web APIs, run generated code in execution environments, and coordinate software subagents. In this regime, the execution loop is closed. An action taken at step ${t}$ alters the state of the software environment, so subsequent observations ${o}_{t+1}$ depend directly on prior decisions ${a}_t$. The system possesses genuine agency.

Within a controlled software environment, this agency can operate inside a protective envelope, “behind the glass.” Such environments can grant agentic systems three structural privileges, though external services and consequential tool calls may fall outside that envelope:

- **Elastic virtual time**: A controlled software environment can wait while the model computes. Whether an agent requires $200\text{ ms}$ or $30\text{ s}$ of test-time compute to plan its next tool call, the environment can hold its simulated state until the action is emitted. External services continue evolving on their own clocks.
- **Transactional rollback and sandboxing**: Tool execution can occur within isolated containers, virtual machines, or transactional databases. When an action produces an error inside this envelope, software exceptions catch the fault, database transactions roll back, or the container restarts from a clean snapshot. These mechanisms cannot undo consequences already delivered outside it.
- **Discrete symbolic interfaces**: Actions are structured strings, JSON schemas, or API payloads whose syntax and validity can be verified by deterministic compilers and linters before execution.

Physical artificial intelligence represents the arrival of agency in the physical world. A physical AI system does not invoke a software API inside a virtual sandbox; its outputs cross the **causal boundary** into physical actuators. A learned model’s output becomes a setpoint (the target value a low-level controller drives toward), the setpoint becomes electrical current in a motor phase winding (one of the stationary copper coils whose current turns the motor), and the current becomes electromagnetic torque. The torque accelerates physical mass through gearboxes, linkages, and contact surfaces sharing space with people and objects. That physical embodiment strips away every digital privilege:

- **Continuous time**: Physical time advances under Newtonian mechanics regardless of processor state. The **physical plant**, the apparatus being controlled such as a robot’s wheeled base or arm, does not pause while a neural network deliberates. In a moving robot, computational latency is not a software delay. A machine moving at speed ${v}$ that takes a time ${\tau_{\text{delay}}}$ to begin braking covers ${v}\,{\tau_{\text{delay}}}$ toward an obstacle under unguided momentum. Delay is physical distance.
- **Mechanical and thermodynamic irreversibility**: Physical state transitions admit no software rollback. Once software commands current through an inverter (the power electronics that switch a DC supply into the motor’s phase currents), electromagnetic force accelerates mass, dissipating irreversible Joule heat (${P_{\text{phase}}} = {I_{\text{phase}}}^2 {R_{\text{phase}}}$ in each phase winding) and altering mechanical contact states. Kinetic energy (${E_k} = \frac{1}{2}{m} {v}^2$) cannot be garbage-collected, and a mechanical impact cannot be undone by restoring a checkpoint. A command that has moved a machine can be answered only by another physical action, which itself consumes time, clearance, and energy.
- **Single-batch, hard real-time execution**: On the running machine, each new action proposal depends on observations shaped by prior motion, so the live loop does not accumulate independent observations into a throughput batch (${B}=1$). Control loops must also meet hard real-time deadlines across several coupled timescales: motor current loops at tens of kilohertz, loops near a kilohertz that check motion and regulate contact force, learned policies renewing at tens of hertz, and slower models interpreting the scene a few times per second. [[01 Books/Volume IV - Physical AI/00 Introduction/01 The Causal Boundary/V4-01.08 The Machine in Five Levels#^sec-boundary-machine-model|Section 1.7]] gives the running machine’s rates. A missed deadline does not degrade user experience; it can destabilize the physical plant.

Losing these privileges forces an architectural response. Deep neural networks are statistical function approximators, vulnerable to distribution shift, sensor noise, and hallucination, so they cannot be granted unmediated authority over physical actuators. Physical AI therefore separates proposal from permission. High-capacity learned models act only as *proposers* in an unprivileged tier (the Brain). An independent, deterministic *permission path* (in the Nervous System) checks each proposal against the machine’s physical limits and *admits* (accepts for execution) only the proposals that pass. It also keeps an executable fallback ready on isolated real-time hardware. The permission path does all of this before any action crosses the causal boundary into the plant (the Body).

|:--------------------------------|:------------------------------|:--------------------------------------------|:----------------------------------------------|:------------------------------------------------|:---------------------------------------------------|:----------------------------------------------------|
| **Offline/advisory prediction** | Cloud servers / accelerators  | Advisory prediction (label, score, token)   | Open-loop (static dataset, exogenous data)    | Batchable in the selected serving case          | Discard or recompute before downstream action      | Advisory; downstream software or human decides      |
| **Agentic ML**                  | Digital software environments | Tool execution (API payload, code snippet)  | Closed-loop in software (actions alter state) | Elastic virtual time in controlled environments | Software exception, container restart, DB rollback | Sandboxed permission; API scopes and virtual gates  |
| **Physical AI**                 | Embodied physical plant       | Physical force and motion (current, torque) | Closed-loop in physics (actions alter world)  | Inexorable continuous time; delay is distance   | Irreversible work; energy dissipation; damage      | Proposal vs. permission; deterministic runtime veto |

Table 1: **Three deployment regimes of machine learning systems**: The selected arrangements progress from offline advisory prediction to digital agency to physical embodiment. The unit of engineering shifts from advisory prediction to digital tool execution, and finally to irreversible physical action across the causal boundary.

^tbl-01-paradigms

Physical AI did not arrive solely through the scaling of language models. It represents the convergence of two long-standing engineering traditions: robotics and control, which learned to act reliably on a physical world that pushes back, and machine learning, which learned to extract representations from data at scale. Over eighty years, the learned model has moved step by step from the periphery of the machine toward its actuators, and each step shifted what the surrounding systems architecture had to guarantee. That history explains what physical AI inherits from classical control and digital learning, and why its central systems challenge is new.
