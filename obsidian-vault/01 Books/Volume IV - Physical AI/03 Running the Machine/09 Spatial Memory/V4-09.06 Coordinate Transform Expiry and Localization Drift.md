# V4-09.06 Coordinate Transform Expiry and Localization Drift

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09 Spatial Memory|V4-09 Spatial Memory]]

^sec-memory-reference-frames

A coordinate frame binds a spatial representation to a physical body, but on an active robot that frame is continuously moving. Embodied architectures relate sensors, chassis links, and end-effectors through a transform tree, in which every frame has exactly one parent. A static drawing of this graph, however, conceals how rapidly its edges go stale. In the arm chain of [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.06 Coordinate Transform Expiry and Localization Drift#^fig-09-robot-transform-tree|figure 3]], each edge stores a rigid-body pose parameterized by joint angles ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-lynch2017modern|Lynch and Park 2017]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-craig2005introduction|Craig 2005]]), describing the machine only at the instant its physical geometry was transduced. When an onboard computer chains transforms sampled at different timestamps, whether through neural inference latency, bus transport delays, asynchronous sensor clocks, or dropped packets, the resulting mathematical product yields a hybrid pose that the physical machine never occupied.

↪ Rigid-body transforms, their composition along a kinematic chain, and their rotation parameterizations are developed in **[[05 Reference/Volume IV - Physical AI/V4 Machine Learning Background#^sec-appendix-ml-spatial|Spatial Representations and Scene Parameterization]]**.

Transform state also spans multiple machine words: three floating-point numbers for translation and four for rotation as a unit quaternion. A high-rate control reader racing an asynchronous perception writer can therefore tear a read, observing an old rotation paired with a new translation. The lock-free sequence lock (seqlock) mailbox established in **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.04 Multi-Rate Cadences#^sec-nervous-mailbox-exchanges|Lock-free and wait-free mailbox exchanges]]** resolves this concurrency race without blocking hard real-time control threads. Each reader makes a single bounded attempt per tick and never blocks. If the sequence count reveals a torn read, the thread discards the sample and lets the last validated transform age in place.

^fig-09-robot-transform-tree

On the arm itself ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.06 Coordinate Transform Expiry and Localization Drift#^fig-09-robot-transform-tree|figure 3]], panel a), an effective lever arm ${r_{\text{arm}}}$ separates the rotating wrist (joint 7) from the tool center point (`tool0`), so an angular lag ${\Delta}{\theta_{\text{joint}}} = {\omega}\,{\Delta} {t}$ sweeps the end-effector through an unmodeled arc ${e_{\text{tool}}} \approx {r_{\text{arm}}}\,{\Delta}{\theta_{\text{joint}}}$. The links (`link1` through `link7`) are connected by revolute joints whose optical encoders sample joint angles ${q}_i({t})$ continuously, so the arm’s own edges can be updated frequently; the edge that ages is the wrist camera’s estimate of the target.

Panel (b) shows the corresponding coordinate transform tree, maintained in robot middleware such as the Robot Operating System (ROS) library `tf2` ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-foote2013tf|Foote 2013]]). Each directed edge represents a $4 \times 4$ homogeneous transformation matrix ${\mathbf{T}_{AB}}$ mapping points from child frame ${B}$ into parent frame ${A}$. Because the arm’s joint state arrives at its 1 kHz joint-control rate over a deterministic fieldbus while the wrist camera publishes detected object poses (`target_object`) at only 60 Hz over an asynchronous transport, the transform tree inevitably buffers edges with disparate timestamps. Properly designed transform libraries refuse to mix these epochs. A `tf2` lookup for a transform chain at query time ${t}$ evaluates every edge at that exact timestamp ${t}$, interpolating each edge between its buffered samples. If ${t}$ lies beyond the newest sample of any edge, the lookup raises an extrapolation error. Similarly, requesting the “latest” transform returns the chain at the newest timestamp common across all constituent edges, preserving a single consistent epoch ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-foote2013tf|Foote 2013]]).

Unphysical hybrid poses arise when application code bypasses these library guarantees. If a node caches an edge, pairs a target pose from an asynchronous detection message with a live lookup of the arm at the current instant, or republishes an old edge under a refreshed timestamp, it multiplies the current forward kinematics ${\mathbf{T}_{\text{base} \leftarrow \text{wrist}}}({t})$ by a stale vision edge ${\mathbf{T}_{\text{wrist} \leftarrow \text{object}}}({t} - {\Delta} {t})$. This composition represents the **chimeric kinematic product anti-pattern**: an unphysical geometric artifact that corresponds to no configuration the physical robot ever occupied.

Enforcing a common timestamp leaves the application with an operational decision whenever a query timestamp lies ahead of the newest buffered sample. A lookup can fail immediately, or a noncritical consumer can block until new samples arrive subject to a timeout. In safety-critical execution paths, such as permission enforcement, lookups must remain strictly nonblocking and fail closed upon rejection. If an application instead attempts to predict a future transform, it must propagate a validated uncertainty bound; naive dead-reckoning extrapolation during an unannounced sensor stall rapidly accumulates lever-arm error ${e_{\text{rot}}} \approx {r_{\text{arm}}}\,{\omega}\,{\Delta} {t}$.

Transform expiration becomes spatial displacement at the plant interface. At the cage door the vision edge is the wrist camera’s estimate of the latch-release slot (the `target_object` of [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.06 Coordinate Transform Expiry and Localization Drift#^fig-09-robot-transform-tree|figure 3]]), which the controller composes with the arm chain to place the finger relative to the slot. Composing that stale camera-to-slot edge with the current arm pose adds lateral drift ${e_{\text{trans}}} = {v_{\text{drift}}}\,{\Delta} {t}$, from motion of the base and door that no sensor reported during the interval, to the initial error ${e_0}$. It also adds a wrist lever-arm sweep ${e_{\text{rot}}} \approx {r_{\text{arm}}}\,{\omega}\,{\Delta} {t}$. The sum can carry the tool error ${e_{\text{tool}}}$ outside the slot tolerance ${r_{\text{tol}}}$ ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.06 Coordinate Transform Expiry and Localization Drift#^fig-frame-staleness-error|figure 4]]). Applying the age-as-displacement principle to manipulator kinematics shows that uncompensated latency translates directly into geometric positioning error through the lever arm of downstream links.

↪ The lever-arm kinematics behind this error propagation, built from the vector cross product, are developed in **[[05 Reference/Volume IV - Physical AI/V4 Control and Dynamics#^sec-appendix-control-spatial|Spatial coordinate frames and lever-arm kinematics]]**.

The vulnerability of high-precision manipulation to transform staleness becomes clear when positioning an end-effector at a latch-release slot while the slot remains in direct view of the wrist camera. The wrist camera captures a new frame every 16.7 ms, renewing the observed slot pose and updating the camera-to-slot transform that guides fine alignment. To clear the opening, the fingertip must remain within a tight mechanical tolerance ${r_{\text{tol}}} =$ 1 mm. To isolate the geometric penalty of a single missed frame, assume the camera observation is available at its capture epoch with zero ingestion delay, after which the transform edge ages by exactly one frame interval ${\Delta} {t} =$ 16.7 ms. On a production machine, pipeline ingestion latency makes the edge older still; control loops must always charge the full capture-to-use latency, including neural inference, message serialization, and transport. Starting from an initial calibration error ${e_0} =$ 0.1 mm, lateral motion drifts by at most ${e_{\text{trans}}} = {v_{\text{drift}}}\,{\Delta} {t} =$ 0.20 mm under an unobserved lateral velocity bound of ${v_{\text{drift}}} =$ 12 mm/s.

The kinematic lever arm magnifies this displacement substantially. With the fingertip positioned at a distance ${r_{\text{arm}}} =$ 0.15 m beyond the wrist joint, an alignment rotation at angular rate ${\omega} =$ 0.30 rad/s sweeps the tip through an arc of ${e_{\text{rot}}} \approx {r_{\text{arm}}}\,{\omega}\,{\Delta} {t} =$ 0.75 mm. The optical encoders register the wrist rotation correctly; the error comes from what the rotation is applied to. The cached camera-to-slot transform states where the slot sat relative to the camera at the previous frame, and the camera rides on the wrist. Application code that chains that cached transform with the current wrist pose therefore swings the computed slot along with the wrist, while the real slot, fixed in the door, stays where it was. The result is a hybrid pose that the arm never occupied. Correcting this error requires either querying the kinematic chain at the exact capture epoch of the camera frame or expiring the stale transform outright. Unchecked, the stale transform displaces the estimated finger position by ${e_{\text{tool}}} \approx {e_0} + {e_{\text{trans}}} + {e_{\text{rot}}} =$ 1.05 mm, which exceeds the mechanical tolerance by 5 percent. The lever arm contributes over three times as much error as translational drift alone. Because the matrix multiplications complete without raising a runtime exception, the control loop blindly aligns the tool to an invalid target, driving the finger into the surrounding strike plate.

^fig-frame-staleness-error

The red error vector in [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.06 Coordinate Transform Expiry and Localization Drift#^fig-frame-staleness-error|figure 4]] pierces the tolerance boundary even though every underlying matrix multiplication remains numerically valid. Because the dominant error originates in the kinematic lever arm rather than translational drift, a faster or more precise clock does not help; the stale chain is wrong at any timestamp resolution. Only composing every edge at the same epoch, or expiring the stale edge, removes the error, so systems software must enforce one or the other.

**Systems Perspective 9.1: The lever arm of staleness**

*A transform’s admissible age is set at the point it serves, not at the joint it measures. The tool point drifts at roughly ${v_{\text{drift}}} + {r_{\text{arm}}}{\omega}$, so the longer the lever arm, the sooner an edge expires, and an edge still fresh enough to locate the wrist can be too old to locate the tool center point.*

### Localization Drift and Map Frames That Jump

^sec-memory-localization-slam

Unlike a manipulator arm bolted to a chassis with optical encoders on every joint, a wheeled mobile base has no mechanical anchor to the floor. Dead-reckoning odometry drifts past the stopping budget’s localization bound within a single aisle, while map-based loop closures snap the pose back into alignment by jumping remembered obstacles across the map frame. Every map-anchored spatial belief in this chapter, and every allocation in the safety stopping budget, relies on that localization bound ${\delta_{\text{loc}}}$, the guarantee that the robot estimates its position in the map within a bounded uncertainty radius. Maintaining that bound requires combining two distinct state estimators with complementary failure modes, and spatial memory must account for how each estimator alters stored observations.

Odometry integrates high-rate incremental motion from wheel encoders, inertial measurement units (IMUs), or scan-to-scan lidar odometry. Odometric integration produces smooth, high-frequency pose updates with low latency, but because it measures only relative displacements, incremental integration errors accumulate without bound. Absolute position along the trajectory represents an unobservable subspace ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.09 Observability Ceilings and Estimation Limits#^sec-memory-state-estimation-bounds|section 9.8]]). Conversely, **map-based localization** matches real-time range scans against an authoritative pre-built map, bounding absolute drift at the expense of discrete, lower-frequency corrections. When an operating environment lacks a prior map, **simultaneous localization and mapping (SLAM)**[[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.16 Footnotes#^fn5|⁵]] estimates the robot trajectory while constructing the map concurrently. Modern SLAM architectures formulate this estimation over a pose graph, a factor graph whose vertices represent historic robot poses and whose edges encode odometric and scan-matching constraints ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-thrun2005probabilistic|Thrun et al. 2005]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-cadena2016past|Cadena et al. 2016]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-dellaert2017factor|Dellaert and Kaess 2017]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-hess2016real|Hess et al. 2016]]). When the robot revisits a previously mapped area, a **loop closure** introduces a cross-trajectory factor. Re-optimizing the nonlinear graph distributes the accumulated drift across historic poses, retroactively adjusting the estimated trajectory. While the underlying fusion filters follow the Bayesian prediction-correction mechanics detailed in [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.03 Estimating State from Dated Measurements#^sec-perception-state-estimation|section 9.2]] and [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.03 Estimating State from Dated Measurements#^sec-perception-discrete-state-estimation|section 9.2.3]], spatial memory systems must manage the distinct ways these estimators distort the age and coordinates of stored evidence.

How fast odometry spends that bound can be measured. The standard protocol for quantifying systematic odometry drift is Borenstein and Feng’s University of Michigan Benchmark (UMBmark) ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-borenstein1996measurement|Borenstein and Feng 1996]]). A differential-drive robot traverses a 4 m square path covering 16 m of total travel, executing five runs clockwise and five runs counterclockwise. By comparing the odometric return pose against ground-truth external measurements, the benchmark calculates the average return error across both directions. Traversal in opposite directions isolates the two primary sources of systematic error, unequal wheel diameters and wheelbase uncertainty, which would otherwise partially mask one another on unidirectional trajectories.

On their experimental base, uncalibrated runs produced an average systematic return error of 317 mm. Calibrating the wheelbase and wheel-diameter ratio reduced this error to 21 mm, achieving a 15.1× precision gain. Normalized by path length, the systematic drift rate drops from 2.0 percent to 0.13 percent of distance traveled. At the uncalibrated rate, a mobile base exhausts an illustrative 50 mm localization bound after traversing only 2.5 m, equivalent to 1.9 s of operation at an aisle cruising speed of 1.3 m/s. Traversing a single 30 m aisle accumulates 594.4 mm of position drift, exceeding the bound by a factor of 11.9×. Even with careful calibration, pure odometry exhausts the 50 mm bound after 38.1 m (29.3 s), accumulating 39.4 mm across one aisle. Plotted against distance driven ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.06 Coordinate Transform Expiry and Localization Drift#^fig-09-odometry-drift|figure 5]]), even the calibrated line crosses the bound only just past one 30 m aisle, which makes ${\delta_{\text{loc}}}$ a constraint on how often external map corrections arrive rather than an intrinsic property of the mobile base.

Three physical realities prevent this illustrative calibrated extrapolation from establishing an operational design margin. First, the laboratory benchmark operated at 0.2 m/s along straight segments to minimize wheel slip, stopping to pivot at each corner; production warehouse bases travel 6.5× faster under varying operational payloads. Second, kinematic calibration eliminates only deterministic systematic errors. Non-systematic stochastic errors (floor irregularities and micro-slip) produced a run-to-run standard deviation of approximately 25 mm, eclipsing the residual calibrated systematic error of 21 mm. Third, a constant per-meter error rate is merely a first-order linearization. An uncorrected heading error ${\delta}{\theta_{\text{head}}}$ produces lateral position displacement ${\delta}{\theta_{\text{head}}}\,{d}$ over a straight traverse of distance ${d}$. Because wheel-diameter mismatch causes heading error to accumulate linearly with distance (${\delta}{\theta_{\text{head}}} \approx {\kappa} {d}$ for a constant heading curvature ${\kappa}$), the resulting lateral error grows quadratically, about $\tfrac{1}{2}{\kappa} {d}^2$, quadrupling each time the straight run doubles. Under this illustrative drift model, reserving localization margin requires external corrections at intervals shorter than the calculated crossing distance; the deployed interval must come from the machine’s qualified drift envelope. In deployed systems, the site parameter ${\delta_{\text{loc}}}$ must be established empirically, by driving the robot past surveyed fiducials at nominal velocity and maximum payload across actual facility flooring, reporting drift rates at a defined operating percentile.

^fig-09-kitti-drift

The best of the 127 ranked methods drifts 0.53 percent of distance, and the median stereo and lidar methods drift 1.23 and 0.68 percent. At those rates the 50 mm bound lasts about 9 m for the best method, 7 m for the median lidar method, and 4 m for the median stereo method, all shorter than one 30 m aisle. These total-error rates sit above the calibrated laboratory figure of 0.13 percent, because they include the slip, vibration, and scene-dependent errors that UMBmark’s calibration deliberately excludes. Read together, the two benchmarks bracket the problem rather than resolve it: the optimistic systematic rate stretches the bound just past one aisle, and the measured total rates of the best published methods spend it within a third of one. Every odometry source on the base is a bridge between external corrections, and the bound remains a requirement on how often those corrections arrive.

Loop closure introduces a consistency challenge that timestamp-based age tracking alone cannot resolve. An occupancy cell anchored in the global map frame retains its original capture epoch (the photons reflected from that obstacle are no newer), yet its spatial coordinates shift whenever the SLAM backend re-optimizes the underlying pose graph. Although the sensor evidence has not been refreshed, its spatial position changes discontinuously. Any local memory snapshot constructed prior to the loop closure now misplaces the obstacle by the magnitude of the graph correction, even while every timestamp within the snapshot passes validation. Robust spatial memory architectures must therefore tag spatial beliefs with the generation or revision identifier of the pose graph alongside individual cell epochs. When a loop closure shifts supporting trajectory poses, the system must either re-anchor dependent snapshots or invalidate them immediately.

The REP 105 frame convention met in **[[01 Books/Volume IV - Physical AI/03 Running the Machine/08 Sensor Perception/V4-08.04 Dating and Placing the Measurement#^tbl-08-rep105-tree|REP 105 frame roles for a mobile robot]]** already separates the two estimators ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-meeussen2010rep105|Meeussen 2010]]). Poses in `odom` are continuous but drift without bound. Poses in `map` stay globally bounded but jump whenever a scan-matching correction or loop closure resolves accumulated drift, and the localizer absorbs each correction by adjusting only the `map`-to-`odom` edge. What memory must decide is which frame its safety snapshot lives in. The permission controller builds its local collision-checking snapshots in the continuous `odom` frame, so a correction never moves an obstacle inside a snapshot that is in use. Over a snapshot’s short lifespan (typically hundreds of milliseconds to several seconds), the drift that calibrated odometry accumulates is small and is charged against ${\delta_{\text{loc}}}$ in proportion to distance traversed; uncalibrated odometry, which spends the whole bound within 2.5 m, cannot rely on this. Anchoring safety snapshots in the `map` frame instead would make obstacle bounding hulls teleport discontinuously upon every map correction. Global mission planners, long-term semantic maps, and snapshot construction routines operate in `map`. When a major map correction occurs, the host invalidates and rebuilds the local snapshot rather than forcing real-time controllers to absorb discontinuous jumps. The `map`-to-`odom` edge remains subject to the same temporal expiration rules as any kinematic transform.

A stale transform displaces both the tool estimate and any observations mapped through it. The surrounding world ages too, but it has no joint encoders to report its motion. Memory must therefore record which surfaces and empty regions the sensors actually verified, as well as the frames in which those observations hold.
