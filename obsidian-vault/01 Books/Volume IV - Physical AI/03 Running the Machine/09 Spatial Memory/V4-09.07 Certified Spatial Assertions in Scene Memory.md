# V4-09.07 Certified Spatial Assertions in Scene Memory

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09 Spatial Memory|V4-09 Spatial Memory]]

^sec-memory-scene-attention-buffers

When a mobile manipulator sweeps its range sensors down an aisle, spatial memory must partition the physical volume by what the sensors established: space observed to be occupied, space observed to be empty, and unobserved space. Only observed empty space can support a physical clearance claim, and only while that evidence remains temporally valid; once it lapses, the space becomes a fourth category, expired, which [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^sec-memory-volumetric-metric-maps|section 9.6.1]] adds to the cell states. If a map representation merges unobserved space with free space, the permission path cannot detect occlusions, defeating evidence-freshness checks regardless of timestamp accuracy.

Distinct downstream consumers place competing demands on this spatial memory architecture. A learned manipulation policy requires object identities and local geometry to plan collision-free grasps or navigation trajectories. In contrast, the hard-real-time permission path requires bounded geometric queries whose supporting evidence can be verified before an execution deadline expires. To satisfy these disparate consumers, spatial memory organizes into a functional hierarchy. Metric maps compute geometric clearances and volumetric occupancy. 3D scene graphs structure those measurements into topological places and semantically labeled objects. Episodic memory retains interaction histories needed to interpret operational context. While higher layers draw upon metric observations for geometric grounding, semantic labels and remembered events never possess the authority to certify physical clearance on their own.

### Volumetric Metric Maps and Distance Fields

^sec-memory-volumetric-metric-maps

At the metric layer, a clearance query along a warehouse aisle demands a single, safety-critical quantity: the minimum distance from the robot’s body hull (the simple solid that encloses the machine’s body for collision checking) to the nearest region that is occupied, unobserved, or backed by expired evidence. In contrast, a neural or graphics rendering query estimates what a camera would observe from a specific vantage point. If the safety microcontroller had to scan thousands of occupancy voxels or chase pointer-linked octree nodes to find the nearest obstacle for each of the robot’s body spheres, the clearance check would overrun its microsecond budget inside the permission tick. A spatial representation qualifies for the hard-real-time permission path only if it evaluates conservative physical clearance within the strict execution deadline of a permission tick, operating entirely within the memory footprint supported by the safety microcontroller. The design therefore allocates the query workload first, counts what each candidate representation must read from memory to answer it, and only then sizes the storage.

#### The Clearance Query Inside the Permission Tick

^the-clearance-query-inside-the-permission-tick

The worked design allocates spatial collision checking within the machine’s 1 kHz permission loop (${T_{\text{tick}}} =$ 1,000 μs). The required query returns conservative clearance at each body collision hull, where a hull is one of a set of spheres, the evaluation spheres, whose union covers the machine’s body. Where the selected check also needs a clearance gradient, that work belongs in the same measured query. For an illustrative 20 to 50 evaluation spheres, the total work is:

$$
{T_{\text{query\_total}}} = \sum_{k=1}^{{N_{\text{hulls}}}} {t_{\text{query}}}({\mathbf{p}}_k) \le {T_{\text{reflex\_budget}}} \tag{7}
$$

 To bound the total collision workload in [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^eq-mem-query-latency-budget|equation 7]], the worked ${N_{\text{hulls}}} =$ 50 case reserves ${T_{\text{reflex\_budget}}} =$ 100 μs for local collision checking (the subscript names the reflexive, every-tick check, as opposed to planning). That allocation is part of the permission tick schedule of **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04 The Nervous System#^sec-nervous|The Nervous System]]** (**[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.03 The Independence Requirement and the Two-Processor Hypothesis#^fig-04-permission-tick|figure]]**), not an addition to it. The job declares a 250 μs WCET against a 400 μs deadline, and collision checking takes 40 percent of that WCET, leaving the rest for the other admission checks. Measured against the whole period instead, collision checking leaves 90 percent of the tick for everything else. This is an allocation to be tested on the deployed controller; full-map updates and trajectory optimization run outside this tick. Dividing the allocation among the hulls gives

$$
{t_{\text{query}}} \le \frac{{T_{\text{reflex\_budget}}}}{{N_{\text{hulls}}}},
$$

 which for the worked case is 100 μs over 50 hulls, or 2 μs per query.

^eq-mem-query-latency-budget

A latency allocation becomes a concrete architectural constraint only when translated into hardware resources: memory bus transactions and cache reads. The permission controller streams its local SRAM at 3.2 GB/s, so the 2 μs allocation covers at most 800 reads of an 8-byte cell per hull query, before any arithmetic, cache effect, or contention; qualification on the deployed controller must still measure the real bound. Against that ceiling, the candidate representations differ less in execution speed than in the physical question a single read answers ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^tbl-09-representation-queries|table 1]]). An **occupancy grid**[[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.16 Footnotes#^fn6|⁶]] stores, per cell, whether that cell is occupied ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-elfes1989using|Elfes 1989]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-moravec1985high|Moravec and Elfes 1985]]). Certifying that a sphere hull of radius 0.25 m keeps its protective clearance means reading every cell within 0.35 m of its center, $\frac{4}{3}\pi\left(({r_{\text{hull}}}+{\delta_{\text{margin}}})/{r}\right)^3$ cells at pitch ${r}$. A hierarchical **octree** such as OctoMap ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-hornung2013octomap|Hornung et al. 2013]]) answers the same point query after descending the tree, one dependent read per level, so near surfaces, where pruning cannot merge cells, the scan costs its cell count times the tree depth. A **truncated signed distance field (TSDF)** stores a projective distance to an observed surface along the sensor ray, clamped at a truncation distance of a few voxels ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-curless1996volumetric|Curless and Levoy 1996]]). This ray-based construction does not give the nearest-obstacle distance in all directions, even within the truncation band; hull clearance requires a separately validated occupancy or Euclidean-distance conversion. A **Euclidean signed distance field (ESDF)** stores the straight-line distance to the nearest obstacle ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-oleynikova2017voxblox|Oleynikova et al. 2017]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-millane2024nvblox|Millane et al. 2024]]), so one interpolated geometric lookup, 8 corner reads together with the snapshot validity checks developed below, supplies conservative clearance for an entire sphere. The hull passes when the distance at its center exceeds ${r_{\text{hull}}} + {\delta_{\text{margin}}}$ plus the geometric error. Rendering representations answer the second question. A 3D Gaussian splatting (3DGS) scene fits anisotropic Gaussians to a photometric loss ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-kerbl20233d|Kerbl et al. 2023]]), and a neural radiance field integrates learned density along camera rays. Neither stores a conservative distance, and collision checking on splats requires an added assumption that the fitted ellipsoids enclose the physical surface ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-chen2025splatnav|Chen et al. 2025]]).

↪ The parameterization of a 3D Gaussian splatting scene is developed in **[[05 Reference/Volume IV - Physical AI/V4 Machine Learning Background#^sec-appendix-ml-3dgs|3D Gaussian splatting parameters]]**.

Counted against the 800-read budget ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^fig-09-memory-3d-representation-pareto|figure 7]]), the representation families separate cleanly. A dense occupancy scan exceeds the budget at 2 cm and 5 cm and fits only at 10 cm, where spatial quantization error alone, up to half the voxel diagonal or 87 mm, consumes most of the protective clearance. A worst-case octree scan exceeds the budget at every pitch, because each cell lookup first descends a chain of dependent tree pointers. An ESDF needs exactly 8 geometric reads for one trilinear interpolation regardless of pitch, plus fixed snapshot-header validity checks. Both the metadata checks and the geometric lookup must fit inside the query allocation. The fixed geometric cost favors an ESDF for real-time safety snapshots, while memory capacity constrains the voxel pitch.

A dense ESDF snapshot of the stopping corridor, spanning the aisle width, the clear distance, and an illustrative 2 m manipulator reach height (2.86 m³ in all), requires a voxel payload of 183 kB at 5 cm resolution, below the microcontroller’s 1.05 MB SRAM capacity. The complete static allocation must also include the snapshot header and certificate, active buffers, controller binary, and validation workspace. At 2 cm pitch, the voxel payload alone swells to 2.86 MB, exhausting available SRAM. Adopting the 5 cm pitch introduces up to 43 mm of spatial quantization error into each lookup, an uncertainty that the collision filter must explicitly subtract from the reported clearance. A projective TSDF also cannot substitute for a Euclidean distance field simply because its point lookup is computationally inexpensive; a projective distance along a sensor ray fails to bound the distance to off-axis obstacles.

The host computer maintains the global reconstruction and extracts a bounded local snapshot enclosing the proposed robot trajectory and its emergency stopping corridor. The permission microcontroller admits a new snapshot only after validating its cryptographic provenance, spatial bounding box, per-voxel evidence timestamps, and geometric consistency against a qualified schema. Generating, transferring, and validating these snapshots introduces latency and bus traffic that must be scheduled and qualified independently from the inner-loop collision query. If the host pipeline stalls or drops frames, the active snapshot in microcontroller SRAM continues to age monotonically. The robot may sustain autonomous motion only as long as every cell the snapshot relies on remains within its invalidation horizon and the snapshot’s geometric coverage encloses the vehicle’s stopping envelope.

Eight recent corner samples do not establish that the whole region behind a distance claim remains free. Although a trilinear lookup reads only eight local corner voxels around the hull center, the Euclidean distance value stored inside each corner vouches for the absence of obstacles across a surrounding sphere of voxels that the microcontroller never inspects at runtime, and if any distant voxel within that radius carries older evidence or borders an occlusion frontier from which an unseen hazard can advance, the local distance value becomes optimistic before the corner cell’s own timestamp expires. The qualified construction path therefore selects an absolute support deadline for the snapshot, fixing its frame and pose-graph revision, spatial coverage, clock mapping, and physical growth and entry-speed assumptions. Before building the frozen ESDF, it treats unknown and occupied regions as obstacles and removes from the observed free set every region whose evidence cannot support that set through the selected deadline. This conservative erosion reserves the entire declared interval, including the assumed entry and disturbance envelope. Independent validation must establish that the resulting field lower-bounds clearance throughout that interval; neither a producer’s declaration nor its digest establishes the claim.

The local consumer checks the fixed header against its own upper-bounded clock, the declared frame revision, coverage, and validity conditions before reading the eight geometric corners. It refuses dependent proposals at the support deadline without a host callback or a map scan; a changed frame or physical assumption invalidates the certificate earlier. Header loads and checks belong inside the same per-query allocation, and motion admission must reserve a feasible response before expiry. The later per-hull erosion calculation can impose a shorter horizon. Because the frozen field already includes the declared interval’s erosion, the consumer must not subtract that identical erosion a second time; hull motion and its stopping continuation still require complete swept coverage and qualified aggregate work.

#### Volumetric Memory Footprint Scaling

^volumetric-memory-footprint-scaling

The local snapshot decision leaves the host compute platform with capacity and update constraints. Keeping the chosen snapshot supplied requires sufficient memory capacity for the underlying map and sufficient memory bandwidth to integrate range observations before their physical evidence expires.

For the illustrative host-map sizing calculation, consider an operational workspace of physical volume ${V_{\text{ws}}} = {L_x} {L_y} {L_z}$. Discretizing this domain into cubic voxels of uniform pitch ${r}$ requires memory proportional to workspace volume and to the inverse cube of voxel width:

$$
{M_{\text{dense}}} = \left(\frac{{V_{\text{ws}}}}{{r}^3}\right) {s_{\text{voxel}}} \tag{8}
$$

 where ${s_{\text{voxel}}}$ represents the storage footprint per voxel, here 8 bytes: 4 for a 32-bit distance, 2 for the observation weight, and 2 for the evidence epoch.

^eq-mem-footprint-dense

Obstacles occupy physical 2D surfaces embedded in 3D space rather than solid volumes, and a TSDF[[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.16 Footnotes#^fn7|⁷]] requires stored values only near those surfaces. Truncating the distance field to a band $[-{\mu_{\text{tsdf}}}, +{\mu_{\text{tsdf}}}]$ around observed surfaces restricts storage to a shell ${V_{\text{band}}} \approx 2{\mu_{\text{tsdf}}} \cdot {A_{\text{surface}}}$, where ${A_{\text{surface}}}$ is the total obstacle surface area. Partitioning space into blocks of ${n_{\text{blk}}}^3$ voxels with block pitch ${L_{\text{blk}}} = {n_{\text{blk}}} \cdot {r}$, and allocating a block only when it holds data, the sparse hashed footprint obeys:

$$
{M_{\text{hashed}}} = {N_{\text{blocks}}} \left( {n_{\text{blk}}}^3 {s_{\text{voxel}}} + {s_{\text{meta}}} \right) + {N_{\text{buckets}}} {s_{\text{entry}}} \tag{9}
$$

 where ${N_{\text{blocks}}} \approx \lceil 2{\mu_{\text{tsdf}}} {A_{\text{surface}}} / ({n_{\text{blk}}} {r})^3 \rceil$, ${s_{\text{meta}}}$ is the block metadata (coordinates, allocation flags), and ${s_{\text{entry}}}$ is the hash-table entry size.

^eq-mem-footprint-hashed

Sparse volumetric storage requires an indexing mechanism that resolves 3D coordinates without the sequential pointer traversals of an octree. **Voxel block hashing** discretizes continuous world coordinates ${\mathbf{p}} = [{x}, {y}, {z}]^\top \in \mathbb{R}^3$ into an integer block coordinate vector ${\mathbf{b}} = [{b_x}, {b_y}, {b_z}]^\top \in \mathbb{Z}^3$:

$$
{\mathbf{b}}({\mathbf{p}}) = \left\lfloor \frac{{\mathbf{p}}}{{n_{\text{blk}}} \cdot {r}} \right\rfloor \tag{10}
$$

 A spatial hash function then maps the block index ${\mathbf{b}}$ from [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^eq-mem-block-index|equation 10]] to a specific hash table bucket index ${h}({\mathbf{b}}) \in \{0, \dots, {N_{\text{buckets}}}-1\}$. The scheme comes from real-time surface reconstruction ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-niessner2013real|Nießner et al. 2013]]), built on the spatial hashing of Teschner et al. ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-teschner2003optimized|2003]]), and underlies the Voxblox and nvblox mapping frameworks ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-oleynikova2017voxblox|Oleynikova et al. 2017]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-millane2024nvblox|Millane et al. 2024]]). In an architecture packing $8^3 = 512$ voxels per block with an 8-byte payload per voxel, each allocated block forms a contiguous 4,096 byte memory buffer. A single hash resolution loads an entire local 3D neighborhood into the processor cache. While average-case access time is $\mathcal{O}(1)$, worst-case retrieval latency depends on hash bucket collisions, probe sequence lengths, cache misses, and lock contention during concurrent sensor updates. Because hard-real-time safety guarantees require deterministic execution bounds rather than average-case performance, the local permission snapshot avoids pointer chasing and hashing overhead altogether by organizing its bounded stopping corridor as a dense, pre-allocated array in microcontroller SRAM. Notebook [9.1](https://mlsysbook.ai/vol4/09_memory/09_memory.html#nbk-memory-empty-air-tax) applies both footprint equations to one warehouse workcell.

^eq-mem-block-index

**Napkin Math 9.1: The empty-air tax**

**Problem**: A host map must cover a warehouse workcell of 10 m by 10 m by 3 m at the resolution manipulation needs, with an evidence epoch in every stored voxel so that each region’s claim can expire. How much memory does a dense grid take, how much does a hashed band around the obstacle surfaces take, and what fraction of the dense grid describes empty air?

**Variables**:

- Workcell volume ${V_{\text{ws}}} =$ 300 m³ (illustrative) at pitch ${r} =$ 1 cm (chosen), with ${s_{\text{voxel}}} =$ 8 B per voxel (illustrative).
- Obstacle surface ${A_{\text{surface}}} =$ 120 m² (illustrative) and band half-width ${\mu_{\text{tsdf}}} =$ 4 cm (chosen).
- Block edge ${n_{\text{blk}}} = 8$ voxels, the nvblox layout (datasheet).

**Math**: The dense grid, by [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^eq-mem-footprint-dense|equation 8]]:

$$
M_{\text{dense}} = \frac{300\ \text{m}^3}{(0.01\ \text{m})^3} \times 8\ \text{B} = 3 \times 10^{8} \times 8\ \text{B} = 2.4\ \text{GB}
$$

 The band and its voxel payload, by [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^eq-mem-footprint-hashed|equation 9]] without metadata or hash entries:

$$
V_{\text{band}} = 2 \times 0.04\ \text{m} \times 120\ \text{m}^2 = 9.6\ \text{m}^3
$$

$$
N_{\text{blocks}} = \frac{9.6\ \text{m}^3}{(8 \times 0.01\ \text{m})^3} = \text{18,750}, \qquad \text{18,750} \times 8^3 \times 8\ \text{B} = 76.8\ \text{MB}
$$

**Result**: The dense grid needs 2.4 GB for 3 × 10⁸ voxels. The band is 3.2 percent of the workcell, so 96.8 percent of the dense grid describes space with no surface in it, and the hashed payload of 76.8 MB in 18,750 blocks is about 31 times smaller.

**Systems insight**: Obstacles are surfaces, not volumes, so a dense grid allocates the vast majority of its capacity to empty air. In an embedded robot computer, that multi-gigabyte memory footprint directly contends with memory pools required by vision foundation backbones and real-time motion controllers. The hashed calculation represents a theoretical lower bound: block metadata headers, hash table bucket arrays, and boundary fragmentation in partially occupied blocks increase this overhead in practice. This memory reduction applies strictly to the truncated surface representation. It also alters temporal bookkeeping: because the sparse map allocates memory only near detected surfaces, unallocated open space carries no explicit evidence timestamp. Unallocated space cannot vouch for its own clearance until the system explicitly logs a free-space ray-clearing observation.

This narrow-band scaling applies strictly to a TSDF, not to the full Euclidean distance field required by the permission snapshot. An ESDF stores metric clearance throughout the entire navigable volume where queries might occur. Its memory footprint therefore scales with the observed volume ${V_{\text{obs}}}/{r}^3$ rather than surface area ${A_{\text{surface}}}$. For a mobile warehouse manipulator, this observed volume corresponds to the spatial corridor reachable by the chassis and arm during stopping maneuvers, which dictates the snapshot dimensions evaluated above. Memory allocation semantics also dictate safety interpretation. In systems that perform volumetric free-space carving along sensor rays, unallocated blocks reliably represent unobserved, unknown space. In systems that allocate only narrow surface bands, however, an unallocated block could represent either confirmed open space or unobserved space hidden behind an occlusion. A safety-critical spatial memory system cannot conflate allocation status with occupancy state. Alongside observed occupied space, it must explicitly represent the three states that allocation cannot tell apart: observed free space backed by a valid evidence timestamp, unobserved space, and expired space where past observations have exceeded their maximum validity horizon. Every cell therefore carries one of four states, occupied, free, unknown, or expired.

#### Ray-Marching Update Traffic and Negative Evidence

^ray-marching-update-traffic-and-negative-evidence

When depth cameras stream range frames at framerate ${f_{\text{cam}}}$ with ${N_{\text{rays}}} = {W} \times {H}$ pixels per frame, updating the volumetric map requires ray marching from the sensor origin to each observed surface point ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-curless1996volumetric|Curless and Levoy 1996]]). Each ray traverses a line-of-sight distance ${d_{\text{ray}}}$ at voxel stepping pitch ${r}$, requiring ${N_{\text{steps}}} = {d_{\text{ray}}} / {r}$ discrete cell evaluations. The raw DRAM update bandwidth consumed by naive ray marching is:

$$
\text{BW}_{\text{DRAM}} = {f_{\text{cam}}} \cdot {N_{\text{rays}}} \cdot \left(\frac{{d_{\text{ray}}}}{{r}}\right) \cdot {s_{\text{rw}}} \tag{11}
$$

 where ${s_{\text{rw}}}$ is the read-modify-write memory traffic per traversed voxel (8 to 16 bytes for reading the current occupancy or distance, updating running weights, and writing back).

^eq-mem-dram-bandwidth

For an illustrative VGA depth stream of 307,200 rays at 30 Hz, marched over 2 m at a 2 cm pitch (100 steps per ray) with 8 bytes per step, [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^eq-mem-dram-bandwidth|equation 11]] gives 7.37 GB/s, 3.6 percent of the peak 204 GB/s of the host system-on-chip (SoC). This share of peak understates the actual performance impact, because these volumetric map updates share the memory interconnect with vision foundation models and motion controllers, and their throughput penalty stems from non-sequential access locality and memory bus contention rather than aggregate bandwidth alone. This update bandwidth represents a substantial baseline load that system architects must incorporate into hardware contention profiling, as memory bus saturation and cache thrashing degrade perception pipelines long before theoretical DRAM bandwidth is exhausted. Block hashing reduces this traffic by keeping active blocks in on-chip memory, and projective TSDF updates project voxels inside the viewing frustum onto the depth image instead of marching every ray. These methods reduce repeated memory traffic, but the reduction depends on scene coverage and update strategy. Sparse allocation still grows as the machine explores new regions; a bounded host store needs an explicit retention policy.

What a map can certify comes from how a range return updates it. Traversing the ray[[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.16 Footnotes#^fn8|⁸]] from the sensor to the return ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-amanatides1987fast|Amanatides and Woo 1987]]), the map records **negative evidence** along the traversed ray and positive evidence at its return. Treating an entire crossed voxel as free requires qualified beam coverage, resolution, and geometric error allowances. The ray alone does not observe every point in that voxel.[[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.16 Footnotes#^fn9|⁹]] A valid empty ray can retire a phantom obstacle, but it says nothing about the volume behind a return, the hatched cells in [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^fig-09-ray-update-epochs|figure 8]] that keep their earlier epoch. A new scan down the aisle therefore cannot renew cells hidden behind the rack. Sparse allocation saves capacity without eliminating ray traversal, and any resulting processing delay adds to evidence age.

Cells behind the return and every cell off the ray keep whatever epoch their own last evidence gave them, here ${t}_0$, so the map’s publication time dates none of them.

^fig-09-ray-update-epochs

Because a return renews only the cells it touched, a map’s global publication timestamp cannot certify the freshness of individual voxels. The manifest in [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^tbl-09-schema-volumetric-belief|table 2]] therefore carries cell evidence epochs alongside occupancy. For the worked local snapshot, construction and independent validation establish support for every admitted distance claim through the fixed support deadline. The local hull query checks that certificate’s header and validity conditions within its allocated time, rather than scanning the supporting cells each tick. A freshly copied distance value without valid support cannot establish clearance. The manifest travels with the bounded snapshot as well as the host map; the isolated controller does not traverse the full host store.

Synthesizing these elements yields the primary metric the reactive permission path requires, the **free-space depth** ${d_{\text{free}}}$. To construct this bound, the qualified snapshot path generates and independently validates an ESDF wherein occupied, unobserved, expired, and insufficiently supported regions are obstacles throughout the declared support interval. Evaluating this field at the center of a spherical body hull and subtracting the hull radius yields ${d_{\text{free}}}$: the Euclidean distance from the hull surface to the nearest physical coordinate that lacks certified, fresh evidence of being empty. Under the validated coverage and entry-envelope assumptions, any dynamic hazard (a pedestrian stepping around a corner, a falling carton) remains within the regions treated as unobserved or uncertified, so ${d_{\text{free}}}$ conservatively bounds the spatial margin available for vehicle motion within that interval. When evaluating a candidate trajectory segment down an aisle, the collision filter subtracts the composite geometric error (encompassing sensor calibration noise, localization covariance, and spatial voxel quantization) as well as the protective safety clearance ${\delta_{\text{margin}}}$ from ${d_{\text{free}}}$. The test is applied not at the hull’s present pose alone but along every pose the admitted motion and its stopping trajectory will sweep, so the stopping distance of the stopping budget enters through the length of that swept path. The motion is permitted if and only if the remaining margin is strictly positive at every pose along it. If the robot approaches an occluded cross aisle, ${d_{\text{free}}}$ contracts rapidly regardless of how quickly the microcontroller evaluates the memory lookup; computational throughput cannot compensate for physical occlusion. How rapidly this usable clearance margin decays under persistent occlusion is analyzed in [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.08 Forward State Propagation and Occlusion Decay#^sec-memory-belief-through-occlusion|section 9.7]].

#### Forgetting, Decay, and Change

^forgetting-decay-and-change

A dynamic physical environment requires spatial memory to evict stale data systematically. In a logistics facility, pallets move, access doors swing open, and workers cross aisles that range finders observed to be vacant moments earlier. An embodied system that preserves observations indefinitely accumulates both phantom obstacles (retaining records of objects that have moved away) and phantom free space (assuming unobserved regions remain empty after hazards enter). Active negative evidence clears phantom obstacles whenever fresh sensor rays traverse previously occupied cells. However, detecting hazards that enter unobserved voids presents a different challenge, because no sensor returns exist to contradict the stale assumption of clearance.

Practical mapping systems handle unobserved space through varying assumptions ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^tbl-09-map-maintenance|table 3]]). OctoMap clamps cell log-odds between fixed saturation limits, ensuring that a voxel reinforced by hundreds of historical returns can still be cleared rapidly by a small batch of contradicting observations ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-hornung2013octomap|Hornung et al. 2013]]). Clamping accelerates adaptation upon re-observation, but it cannot alter belief in unvisited cells. Independent Markov chain occupancy grids assign each cell an explicit two-state transition model with online-learned transition rates, allowing an unobserved voxel’s occupancy belief to relax gradually toward its historical steady-state prior ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-saarinen2012independent|Saarinen et al. 2012]]). Modern GPU-accelerated mapping pipelines adapt these concepts to real-time volumetric streams. For example, the nvblox library periodically decays the occupancy probability of out-of-view voxels toward 0.5 (the uninformative state), discarding the assumption that the unobserved world is strictly static ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-millane2024nvblox|Millane et al. 2024]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-nvidia2026nvbloxdocs|NVIDIA 2026]]). Dynablox identifies transient dynamic objects by maintaining an incremental model of high-confidence free space and flagging unexpected point returns that penetrate that volume ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-schmid2023dynablox|Schmid et al. 2023]]). Similarly, Khronos separates spatial dynamics across temporal scales, employing a fast tracking loop for short-term movements inside an active window alongside an asynchronous factor-graph optimizer for persistent architectural shifts ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-schmid2024khronos|Schmid et al. 2024]]).

These approaches rely on statistical rate models. They parameterize the expected rate of environmental change based on past traffic patterns or heuristic tuning. While average-case models are well suited for high-level motion planning and route optimization, the permission path requires hard worst-case bounds. The deterministic expiration mechanism formulated in this chapter establishes that worst-case counterpart. Specifically, an observed free cell reverts to the unknown state no later than the minimum time required for an unobserved object, moving at the facility’s maximum physical velocity bound, to traverse the distance from the nearest occlusion boundary into that cell. A heuristic decay model satisfies safety requirements only if its decay schedule transitions cells to unknown at or before this physical traversal deadline. Otherwise, statistical decay remains an optimization heuristic for path planners rather than a certifiable safety assertion for motion gating.

| Mechanism                           | What happens to a cell nobody observes                               | Representative system (as of 2026) | What it cannot certify                            |
|:------------------------------------|:---------------------------------------------------------------------|:-----------------------------------|:--------------------------------------------------|
| Clamped log-odds                    | Nothing; clamping only speeds change when the cell is seen again     | OctoMap                            | Any change in cells no ray reaches                |
| Per-cell transition model           | Occupancy relaxes toward a learned long-run value                    | Independent Markov chain grids     | A worst case; learned rates describe past traffic |
| Decay toward unknown                | Occupancy relaxes toward 0.5 at a fixed rate once out of view        | nvblox                             | Safety, unless the rate is set from a speed bound |

| Spatio-temporal SLAM                | Unchanged until revisited; change is detected on reobservation       | Khronos                            | The interval between visits                       |
| Deterministic expiry (this chapter) | Free becomes unknown at the erosion deadline set by the speed bound  | Worked design                      | Nothing past the deadline, by construction        |

Together, these volumetric grid and distance-field rules bound where the machine may move, but they stop at geometry. While a volumetric distance field certifies where free space ends, it treats every occupied cell as an anonymous obstacle and cannot tell the task planner which surface is the tote handle or the cage door.

### 3D Dynamic Scene Graphs

^sec-memory-hierarchical-scene-graphs

Supplying that identity is the job of semantic scene memory, which sits above the raw metric layer and inherits its physical constraints. Learned neural models infer what an object is, whereas the underlying metric mapping pipeline anchors where that object sits in physical space. Open-vocabulary scene memory bridges these domains using **3D vision foundation models**. A self-supervised visual backbone such as DINOv2 ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-oquab2023dinov2|Oquab et al. 2023]]) extracts dense patch feature representations. A promptable segmentation model such as the Segment Anything Model (SAM) ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-kirillov2023segment|Kirillov et al. 2023]]) generates class-agnostic instance masks. Systems such as ConceptGraphs ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-kuwajerwala2024conceptgraphs|Gu et al. 2024]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-jatavallabhula2023conceptfusion|Jatavallabhula et al. 2023]]) and Hydra ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-hughes2022hydra|Hughes et al. 2022]]) lift those 2D masks and semantic features through calibrated depth, extrinsics, and visual odometry into an **object-centric 3D scene graph**. In this structured representation, each node represents an entity parameterized by a 3D centroid, a spatial covariance matrix, and a text-aligned multimodal embedding vector.

Drawn for the warehouse ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^fig-09-dynamic-scene-graph|figure 9]]), such a graph stacks five layers: a metric mesh, the objects and agents segmented from it (mugs, totes, the cage door, a walking person), topological places linked through free space, rooms such as aisles and dock bays, and the building itself. Edges between layers run both ways, compressing metric surfaces into symbols on the way up and grounding task tokens in metric coordinates on the way down.

Constructing and maintaining this semantic hierarchy consumes substantial compute and latency budgets. An illustrative vision foundation encoder requiring 3 TFLOP per frame at the navigation camera’s full 60 Hz capture rate demands 180 TFLOP/s of sustained tensor throughput, even before accounting for image preprocessing, memory bandwidth, or post-processing clustering. By comparison, an edge application processor such as the NVIDIA Jetson AGX Orin achieves a manufacturer-specified peak of 43 dense FP16 TFLOP/s (as documented in its [technical brief](https://www.nvidia.com/content/dam/en-zz/Solutions/gtcf21/jetson-orin/nvidia-jetson-agx-orin-technical-brief.pdf)). This is a theoretical arithmetic ceiling that sustained neural workloads rarely approach, because memory bandwidth caps any kernel whose arithmetic per byte falls short of the processor’s ratio of peak compute to peak bandwidth ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-williams2009roofline|Williams et al. 2009]]).

Because the illustrative foundation backbone exceeds this processor’s peak throughput at full camera rate, the worked architecture implements a **multi-rate hierarchy**. In this decoupled design, lightweight metric processing pipelines running on the application processor consume raw frames delivered via direct memory access (DMA) to extract geometric obstacle points, update occupancy voxels, and track camera poses at the camera’s full 60 Hz rate. Meanwhile, compute-intensive vision foundation backbones run asynchronously on selected keyframes at a reduced rate of 1 to 5 Hz, associating semantic embeddings and updating topological nodes. This multi-rate separation remains safe only because the high-frequency metric loop and the independent permission filter maintain certified physical stopping envelopes during the intervals between semantic updates.

↩︎ Each rate tier meets its own deadline across a nonblocking boundary, the decoupling established in **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.04 Multi-Rate Cadences#^sec-nervous-cadences|Multi-Rate Cadences]]**.

The vertical edges spanning the hierarchy in [[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.07 Certified Spatial Assertions in Scene Memory#^fig-09-dynamic-scene-graph|figure 9]] enable dual-path reasoning. An agentic planner can query spatial relationships among objects and topological rooms without traversing millions of raw mesh vertices, while downstream manipulation requests (such as grasping a bin handle) resolve downward into precise Cartesian frames and localized geometry. From a systems memory perspective, each node encapsulates state elements that age at radically different physical rates:

1.  *Geometric pose*: The spatial coordinates of an entity age according to the physical velocity bound of its category. A permanently anchored storage rack does not drift, whereas an unobserved cart or tote may displace at human walking speeds.
2.  *Existence confidence*: The probability that an object remains present decays independently of its pose estimate. An unobserved tote may be removed entirely by a human worker; a narrow spatial covariance on an unobserved object provides false confidence if the entity itself is no longer present ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.12 Fallacies and Pitfalls#^sec-memory-fallacies-pitfalls|section 9.11]]).
3.  *Semantic classification*: Node category labels originate from learned visual embeddings. While semantic labels do not suffer physical drift over time, their validity is bounded by model calibration and out-of-distribution uncertainty, remaining uncorrected until the object is re-observed.

Contemporary frameworks update graph structures primarily upon re-observation: Hydra optimizes scene graph node poses when pose-graph loop closures update the underlying trajectory ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-hughes2022hydra|Hughes et al. 2022]]), and Khronos registers object additions or removals when the robot revisits previously mapped areas ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-schmid2024khronos|Schmid et al. 2024]]). Neither system explicitly tracks the temporal decay of unobserved entities using physical kinematic bounds. Tracking and enforcing these physical validity limits remains the responsibility of the belief record, and high-level symbolic abstractions can never refresh the evidence timestamps of the underlying metric cells. Beyond knowing where objects sit in the scene graph, a manipulation policy also needs to remember which physical actions it has already completed upon them.

### Episodic Memory and Interaction History

^sec-memory-episodic

When a transformer policy’s sliding context window evicts older tokens as new camera frames stream in, the model can forget that it already unlatched the cage door or experienced a torque stall a hundred cycles ago. Metric representations and 3D scene graphs capture *where* surfaces, free space, and objects exist in the physical environment; **episodic memory** records *what happened*: the sequence of discrete contact transitions, grasping events, torque stalls, and human interventions that define a task execution history. By indexing physical events by their monotonic acquisition timestamps, episodic memory enables task planners to verify preconditions, for example confirming whether a mechanical latch was successfully unlatched or a transport tote was deposited into a fixture.

Learned policies frequently use attention mechanisms over past interaction tokens to infer task progress. However, maintaining unconstrained sequence histories is computationally intractable. A **streaming window** bounds transformer attention buffers by evicting historical tokens based on recency or attention sink criteria ([[01 Books/Volume IV - Physical AI/03 Running the Machine/09 Spatial Memory/V4-09.15 Source References#^ref-xiao2024streamingllm|Xiao et al. 2024]]). Such eviction policies operate independently of physical causality; an observation confirming that a container latch was secured a hundred navigation cycles ago is precisely the type of token dropped by a sliding context window. Consequently, the durable metric record and structured episodic state anchors must persist outside the transformer’s transient attention buffer whenever their physical consequences continue to constrain manipulation. Retrieval augmentation supplies the policy with task context and relevant geometry, while the underlying belief record carries the evidence epochs and error bounds that the permission path independently checks before admitting execution.

For reactive motion permission, any spatial assertion lacking an explicit evidence timestamp is treated as unverified, and any state estimate whose spatial uncertainty bound exceeds certified safety tolerances must be rejected before trajectory commands reach the hardware controller. Nevertheless, an embodied system cannot trigger emergency braking on every dropped sensor packet. Sustaining safe, fluid motion across transient sensor dropouts requires state estimators that propagate spatial belief forward in time under a declared error-growth law, with a deadline that governs execution until fresh observations either corroborate or correct the state.
