# V4-13.04 Contention for Shared Resources

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13 Workload Placement|V4-13 Workload Placement]]

^sec-placement-resource-contention

Had the mobile manipulator placed its permission path on the application SoC, camera DMA, neural weight fetches, telemetry writes, cache writebacks, and enforcement reads would compete for memory service. Their simultaneous bursts determine the queue seen by the enforcer. On the selected machine, those host-side bursts delay the observation and chunk rather than the permission tick. The permission path encounters their effects as evidence age, refusing stale evidence and entering fallback if no admitted chunk renews the lease.

↩︎ How host-side memory contention, including camera DMA, ages observations is established in **[[01 Books/Volume IV - Physical AI/03 Running the Machine/08 Sensor Perception/V4-08.06 Ingestion Overhead and Memory Bus Contention#^sec-perception-cost-ingestion|Ingestion Overhead and Memory Bus Contention]]**.

### DRAM Bank Conflicts, AXI4 Burst Slicing, and Arbiter Starvation

^dram-bank-conflicts-axi4-burst-slicing-and-arbiter-starvation

A small urgent read can wait behind a large transfer even when the memory bus is mostly idle over a longer interval. The deadline depends on the traffic already ahead of that read and on whether the controller lets it pass. This queueing delay, which arises when memory and DMA transactions share an interconnect and controller, is the mechanism inside the UMA crossbar trap, and its bound depends on transaction size, queue policy, and bank timing.

Each claimant’s average demand follows from its transfer size and event rate. On a shared multi-channel LPDDR5 interface, camera DMA streams, weight fetches at the policy rate, the enforcer’s reads, drive writes, cache writebacks, and logging together occupy a modest fraction of theoretical peak bandwidth on average. An engineer who inspects only that average concludes that most of the memory bus remains free. Memory crossbar arbiters and DRAM schedulers do not schedule average rates. They arbitrate discrete, bursty transactions, and two workloads with identical average throughput interfere with radically different latency profiles if one streams in small, sporadic packets while the other arrives in long, saturating blocks. The weight transfers that set the memory wall ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-wulf1995|Wulf and McKee 1995]]) of **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/03 The Cognitive Brain/V4-03.05 The Cost of a Fresh Evaluation#^sec-brain-memory-wall|The memory wall]]** are the long blocks here, and on a shared controller the proposer’s throughput limit becomes the permission path’s queue.

How long a safety read waits depends on transaction arbitration and DRAM scheduling. An accelerator moving weights in large 256 KB tiles generates discrete memory transactions across the internal system interconnect. The example assumes an arbiter that completes each granted burst before serving a different requester.[[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.14 Footnotes#^fn8|⁸]] Although bus protocols provide quality-of-service (QoS) priority signals (`ARQOS`), commodity memory controllers frequently treat these tags as advisory unless strict hardware priority bypass with bounded preemption latency is explicitly certified in register configurations. Whether an in-flight transfer can delay the urgent read, and whether queued tensor transactions can pass it, depends on the selected interconnect and arbiter. AXI burst limits alone do not establish a service-time or starvation bound.

Every memory request passes through four stages: the requester issues it, the interconnect arbiter grants it a slot, the memory controller queues it, and the target bank serves it. Each DRAM bank holds one open row in its **row buffer**. An LPDDR5 channel has 16 banks, divided into 4 bank groups at the higher data rates, or 8 larger banks, each formed by merging two, in an alternative mode ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-steiner2022lpddr5|Steiner et al. 2022]]). A read to the open row (a *row hit*) needs only a column access. A read to a different row of the same bank (a *row conflict*) must first close the open row with a precharge (${t_{\text{RP}}}$) and then open the new one with an activation (${t_{\text{RCD}}}$). The memory standard sets a minimum time in nanoseconds for each step, 18 ns for both, and the controller can only wait whole cycles of its command clock. At the 6,400 MT/s data rate of the machine’s application SoC, that clock ticks every 1.25 ns, each step rounds up to 15 cycles, or 18.75 ns, and a conflict adds 37.5 ns ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-luo2024ramulator|Luo et al. 2024]]). Bank-group spacing, refresh, and bus turnaround add further terms, which **[[05 Reference/Volume IV - Physical AI/V4 Systems and Hardware#^sec-appendix-systems-dram|DRAM Contention and Interconnect Arbitration]]** treats.

The controller also decides the order of service. Controllers that use **first-ready, first-come-first-served (FR-FCFS)** scheduling serve ready row hits before older requests that need a new row, which maximizes throughput ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-rixner2000memory|Rixner et al. 2000]]). A streaming accelerator supplies an unbroken run of row hits across its weight matrices, so an FR-FCFS scheduler can keep passing the safety core’s sporadic read until an internal starvation counter expires. Under a FIFO queue that lets no later arrival pass the safety read, the idealized wait is

$$
{t_{\text{queue}}} = \sum_{k \in {\mathcal{Q}}} \frac{{{D_{\text{vol}}}}_{k}}{\text{BW}_{\text{peak}}} + {N_{\text{conflict}}} ({t_{\text{RP}}} + {t_{\text{RCD}}}) \tag{1}
$$

 where ${\mathcal{Q}}$ holds the transactions ahead of the read, ${{D_{\text{vol}}}}_{k}$ is each one’s byte count, ${N_{\text{conflict}}}$ counts changes to a different row within an already active bank, and $\text{BW}_{\text{peak}}$ is an optimistic service rate. The application SoC achieves that aggregate peak bandwidth across parallel 16-bit LPDDR5 channels, each containing its own sixteen internal banks, so dividing a backlog by $\text{BW}_{\text{peak}}$ holds only when physical address bits interleave transactions evenly across all channels rather than funneling them into a single channel queue. Arbitration overhead and refresh add to the result. Exceeding the sensing allowance first violates the allocation to that subtask; it does not by itself imply that the whole tick misses its deadline. The worked comparison below keeps the sense allocation, declared execution bound, and physical deadline separate.

^eq-placement-dram-queuing

**Napkin Math 13.1: The backlog budget**

**Problem**: Suppose the same permission tick, with the same sub-costs and the same blocking and interference budget, ran on a core of the application SoC and read its sensor snapshot from the SoC’s shared DRAM. How much queued traffic could precede that read before the tick exceeds its sense allowance, its declared worst-case execution time, and its deadline?

**Variables**:

- Sense allowance 40 μs and 95 μs of constraint evaluation and drive-frame write (Illustrative sub-costs), declared worst-case execution time ${T_{\text{wcet}}} =$ 250 μs and deadline ${T_{\text{deadline,enf}}} =$ 400 μs (Chosen), with 90 μs of blocking and interference charged as in **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.06 Real-Time Command Transport and Bus Determinism#^eq-nervous-response-budget|equation 4.3]]** (Illustrative).
- Peak DRAM bandwidth $\text{BW}_{\text{peak}} =$ 204 GB/s (Datasheet), served at that aggregate rate because the controller interleaves addresses across all channels (Illustrative premise).
- One backlog ahead of the read: a weight tile (64 transactions), a camera transfer, and a telemetry record, 88 transactions and 360,448 bytes, with 3 same-bank row conflicts (Illustrative), each costing ${t_{\text{RP}}} + {t_{\text{RCD}}} =$ 37.5 ns (Datasheet). The snapshot itself is 4,096 bytes (Illustrative).

**Math**: By [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.04 Contention for Shared Resources#^eq-placement-dram-queuing|equation 1]], one backlog waits 360,448 B $/$ 204 GB/s $+$ 3 $\times$ 37.5 ns $=$ 1.879 ${\text{µ}}\text{s}$, and the snapshot then reads in 0.020 ${\text{µ}}\text{s}$. The number of backlogs ${n}$ that fit a read ceiling ${R}$ is $\lfloor ({R} - {t_{\text{own}}})/{t_{\text{queue}}} \rfloor$. The sense allowance gives $\lfloor ($ 40 $-$ 0.020 $)/$ 1.879 $\rfloor =$ 21. The declared bound leaves 155 μs for the read after the 95 μs of later work, so it is crossed beyond 82 backlogs. The deadline, less blocking and interference, leaves 310 μs for the tick and 215 μs for the read, and it is crossed beyond 114. With validated priority bypass, only the one in-flight transaction waits ahead, and the read takes 0.04 ${\text{µ}}\text{s}$.

**Result**: Between 82 and 114 backlogs, the tick still meets its deadline but exceeds ${T_{\text{wcet}}}$. Within this stipulated FIFO model, the fixed isolated sub-costs remain unchanged, so the excess comes from shared-memory queueing. It refutes the placement’s timing premise even though this tick was on time. A measured overrun would instead require distinguishing an underestimated baseline from interference, as [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.08 Empirical Verification of Silicon Isolation#^sec-placement-testing-separation|section 13.7]] explains.

**Systems insight**: The read’s bound belongs to the memory controller, not to the workload. The bound exists only if the controller limits how much traffic it admits ahead of a safety read or lets that read bypass the queue. An FR-FCFS controller serving a streaming accelerator provides neither unless its configuration is qualified to do so. At the SoC’s full bandwidth, though, plain queueing is a weak threat, since the allowance absorbs 21 backlogs. The interleaving premise carries much of that result. If the backlog and the snapshot shared one of the interface’s 16 channels, each backlog would take 28.4 ${\text{µ}}\text{s}$, the allowance would absorb 1, and more than 5 would cross the declared bound. The address mapping therefore belongs in the placement evidence. The mechanisms that actually threaten the declared bound are the ones this FIFO model omits, which [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.04 Contention for Shared Resources#^sec-placement-interference-mechanisms|section 13.3.2]] prices next.

Drawn to scale on one 1 ms period, the thresholds show how far the declared bound sits from the deadline and the period ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.04 Contention for Shared Resources#^fig-13-loaded-tick|figure 2]]). The unloaded tick ends at 135 μs. The next three rows carry the largest backlog counts that keep each bound: 21 for the 40 μs sense allowance, 82 for the declared 250 μs, and 114 for the 400 μs deadline once 90 μs is reserved for blocking and interference. The bottom row confines the traffic to one memory channel, where 5 backlogs already reach the declared bound.

### Which Interference Mechanism Threatens the Declared Bound

^sec-placement-interference-mechanisms

The notebook’s arithmetic makes the shared die look safe, and that impression is the danger. The permission tick can absorb a stretch of its unloaded 135 μs cycle by a factor of 1.85 before it crosses the declared worst-case execution time. The allowed stretch is 2.30 before the tick crosses the deadline, once blocking and interference take their 90 μs. Bandwidth queueing at the SoC’s full rate does not come close. Two other mechanisms do, and both live in the shared cache rather than in DRAM.

A non-blocking cache tracks each outstanding miss in a *miss status holding register* (MSHR) and parks each dirty line it evicts in a *writeback buffer* until DRAM accepts it. Both structures are small and shared by every core behind the cache. When a streaming co-runner keeps them full, each miss of the victim core waits until an entry drains, so the victim’s delay grows with its own miss count times the aggressor’s drain time, not with the bytes it reads. Partitioning cache capacity does not help, because the partition divides the lines and leaves the MSHRs and the writeback buffer shared. Measured on commercial embedded multicores, MSHR contention raised a task’s worst-case execution time by up to 21× with the cache partitioned ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-valsan2016taming|Valsan et al. 2016]]). A deliberate attack on the writeback buffer slowed a victim on a dedicated core by more than 300×, partitioned or not ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-bechtel2019denial|Bechtel and Yun 2019]]). DRAM adds its own multiplier on top. An analytical bound for commercial controllers shows that each of the victim’s requests can wait behind every request that other cores may place ahead of it in the same bank. That number is set by queue depth and the reordering window rather than by average bandwidth ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-kim2014bounding|Kim et al. 2014]]).

These slowdowns were measured on other platforms, on victims whose time was mostly memory stall, so they cannot be charged to the enforcer directly. Using them as assumed multipliers on its memory-stall share provides a sensitivity calculation, not a prediction of target behavior. If a fraction ${f}$ of the unloaded tick waits on shared-cache misses and interference slows that fraction by a factor ${r_{\text{slow}}}$ while the rest runs unchanged, the tick takes ${t_{\text{unloaded}}}[(1-{f}) + {f} {r_{\text{slow}}}] = {t_{\text{unloaded}}}[1 + {f}({r_{\text{slow}}}-1)]$. Setting that no larger than ${T_{\text{wcet}}}$ and solving for ${f}$ shows that the loaded tick stays within the declared bound only while

$$
{f} \le \frac{{T_{\text{wcet}}}/{t_{\text{unloaded}}} - 1}{{r_{\text{slow}}} - 1}. \tag{2}
$$

 At the MSHR-class 21×, the declared bound falls once more than 4.3 percent of the tick is miss stall, and the deadline once more than 6.5 percent is. At the writeback-buffer attack’s 300×, the threshold is 0.28 percent. A target profile must establish whether the constraint evaluation exceeds those fractions; touching tables in shared memory alone does not establish its stall share. The mechanism that threatens the declared bound is therefore miss handling in the shared cache, amplified by bank queueing. The only placements that remove it are those whose tick runs from private memory, candidates (c) and (d) of [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.03 Two Paths and the Resources They Share#^tbl-13-placement-candidates|table 1]]. On (a) and (b), the measured stall share on the target and a regulation mechanism that bounds ${r_{\text{slow}}}$ ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.07 Silicon Isolation Decisions#^sec-placement-isolation-decisions|section 13.6]]) are what a qualification must supply.

### Power-Rail Interference

^power-rail-interference

When a neural accelerator steps its current draw in nanoseconds on a core supply rail shared with a permission core, the voltage droops across the package inductance and resistance before board regulators can respond. The droop stretches logic gate delays or triggers adaptive clock stretching inside the permission tick. The rail at issue here is not the drive bus or the microcontroller’s isolated rail; it is the on-die core supply that a shared-die placement, candidate (a) or (b), would share with the accelerator inside one package. A sudden accelerator current step lowers the voltage available to every core on that supply, and the first-order package model is

$$
{\Delta V_{\text{droop}}} = {L_{\text{pkg}}} \frac{d{I}}{d{t}} + {\Delta} {I} \cdot {R_{\text{pkg}}} \tag{3}
$$

 The placement decision depends on whether regulation, decoupling, and stored energy keep the permission path inside its characterized operating range. The package hierarchy and transistor-level delay model are developed in **[[05 Reference/Volume IV - Physical AI/V4 Systems and Hardware#^sec-appendix-systems-droop|Inductive Voltage Droop and Gate Delay Stretch]]**; here the model identifies the disturbance a shared core rail would carry into the permission tick. The chosen placement keeps its core supply out of that package, and its isolated rail must instead survive board-level events (drive-bus sag, a contactor trip, converter dropout), the disturbances of stress regime 1 and the transient generators of [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.08 Empirical Verification of Silicon Isolation#^sec-placement-testing-separation|section 13.7]].

^eq-placement-droop

For the illustrative package parameters, a 6 A step with a 2 ns rise through 30 pH gives 90 mV of inductive droop. The same step through 8 m${\Omega}$ gives 48 mV of resistive droop, 138 mV in all from a 0.850 V nominal rail. This pure ${L_{\text{pkg}}}\,d{I}/d{t}$ term ignores on-die decoupling capacitance, and does not resolve the actual transient. Power-integrity engineers instead design the delivery network to a target impedance[[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.14 Footnotes#^fn9|⁹]] across frequency, and the first droop is set by package inductance resonating with on-die capacitance. The alpha-power model[[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.14 Footnotes#^fn10|¹⁰]] ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-sakurai1990alpha|Sakurai and Newton 1990]]) relates the resulting voltage to gate delay:

$$
\frac{{t_{\text{prop}}}({V_{\text{droop}}})}{{t_{\text{prop}}}({V_{\text{nom}}})} = \frac{{V_{\text{droop}}}}{{V_{\text{nom}}}} \left( \frac{{V_{\text{nom}}} - {V_{\text{th}}}}{{V_{\text{droop}}} - {V_{\text{th}}}} \right)^{\alpha}
$$

 Here ${V_{\text{th}}}$ is the modeled threshold voltage, stipulated as 0.420 V, and ${\alpha}$ is the technology-dependent exponent, stipulated as 1.3. With those inputs, the modeled delay increases by 39 percent. This is a sensitivity calculation, not a measured reset threshold or a universal delay increase for every gate, and ignoring decoupling does not establish a guaranteed upper bound on a resonant transient. The stretch lasts nanoseconds, so it does not lengthen the tick by that percentage. It threatens the setup-time margin of the paths switching during the droop, and it grows without bound as the drooped voltage approaches ${V_{\text{th}}}$. Many current processors detect the droop and stretch the clock until the rail recovers ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-grenat2014adaptive|Grenat et al. 2014]]), which turns a timing violation into lost cycles that the tick must absorb. Device characterization must establish whether the actual critical paths still meet setup time, how many cycles adaptive clocking removes, and whether undervoltage protection trips.

**Checkpoint 13.1: Which shared resource breaks the bound**

Queueing, miss handling, and rail droop all delay the permission tick through hardware the two paths share. Before moving to heat, confirm that the distinctions among these physical mechanisms are clear:

**Resource inventory**: Can you list, for candidates (b) and (c) of [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.03 Two Paths and the Resources They Share#^tbl-13-placement-candidates|table 1]], which shared rows could delay the tick and which could disable it?

**Averages versus order**: Can you explain why a memory controller at low average utilization can still hold a safety read behind a long backlog, and what a controller must provide for the read to have a bound?

**Miss-stall estimate**: If interference slowed the tick’s memory stalls by 10× instead of the measured 21×, what share of the 135 μs unloaded tick could be miss stall before the loaded tick crossed the declared 250 μs?

**Droop timescale**: Can you explain why a droop that stretches gate delay by tens of percent for nanoseconds does not stretch the tick by the same percentage, and what it threatens instead?

A separate permission rail removes the modeled shared core-supply path, but the common battery, wiring, converter behavior, and return paths remain qualification obligations. Rail probes and independent timing instruments must observe them under simultaneous motor and proposal load. Droop and queueing both end within microseconds of the burst that causes them. The heat that the same accelerator dissipates does not, and it couples the paths on a timescale a million times longer.
