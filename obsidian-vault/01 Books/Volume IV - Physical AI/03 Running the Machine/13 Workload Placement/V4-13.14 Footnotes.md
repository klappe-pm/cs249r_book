# V4-13.14 Footnotes

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13 Workload Placement|V4-13 Workload Placement]]

^footnotes

<sup>1</sup> **Dual-Core Lockstep**: Dual-core lockstep runs identical instruction streams across two physical cores, typically offset by several cycles so that a single transient fault cannot corrupt both pipelines in the same way, while a hardware comparator flags any divergence. While lockstep execution catches internal CPU faults, it cannot catch bad envelopes computed from corrupted sensor inputs or common-mode voltage sags on shared power rails. Lockstep is therefore one piece of the safety microcontroller’s watchdog design rather than a complete integrity defense.

^fn1

<sup>2</sup> **PREEMPT_RT**: The Linux real-time patch set makes most kernel code preemptible and runs interrupt handlers as schedulable threads, and it was merged into the mainline kernel in Linux 6.12 in 2024 after about two decades out of tree ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-kernelnewbies2024linux612|KernelNewbies 2024]]). It shortens the scheduler’s latency tail but cannot bound delays that drivers, firmware, or shared memory add, so a PREEMPT_RT host needs a measured bound before it may carry any part of the permission tick.

^fn2

<sup>3</sup> **MPU and IOMMU**: A memory protection unit (MPU) checks each CPU access against a few fixed address regions without translating addresses, so its cost is constant and analyzable. An input-output memory management unit (IOMMU) applies the same check to direct memory access (DMA) from accelerators and camera interfaces. Both govern *where* a memory transaction may access without arbitrating *when* the interconnect serves it; they enforce spatial partitioning while delegating deadline guarantees to hardware bus arbiters.

^fn3

<sup>4</sup> **Multicore Interference Certification (FAA AC 20-193)**: Avionics met this problem first. The 2016 CAST-32A position paper named shared caches, interconnects, and memory controllers as interference channels, and FAA Advisory Circular AC 20-193, issued in 2024 and aligned with EASA’s AMC 20-193, replaced it with formal acceptance criteria ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-faa2024ac20193|Federal Aviation Administration 2024]]). Its lesson for this machine is that a timing bound measured on one core is void on a multicore until every shared row of [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.03 Two Paths and the Resources They Share#^tbl-13-placement-candidates|table 1]] has been analyzed or mitigated.

^fn4

<sup>5</sup> **TLB Shootdown**: When an operating system modifies page tables, it broadcasts inter-processor interrupts (IPIs) to invalidate stale Translation Lookaside Buffer entries across all active cores. Receiving cores must pause thread execution and flush affected entries, adding unbudgeted multi-microsecond stalls. On shared silicon, these synchronization pauses break the cycle determinism needed by inner motor loops.

^fn5

<sup>6</sup> **DMA Cache Coherence**: Direct memory access transfers bypass CPU caches, requiring explicit cache-line invalidation or writeback to keep peripherals and cores consistent. Without hardware snoop filtering or explicit barriers, processors read stale sensor frames or overwrite pending actuator commands. These cache maintenance steps inject variable delay into high-rate control loops unless static, uncached SRAM regions are dedicated to peripheral transfers.

^fn6

<sup>7</sup> **CAN Arbitration**: Controller Area Network protocols resolve bus contention at the physical layer using wired-AND dominant (‘0’) and recessive (‘1’) signaling. If a defective transceiver continuously drives a dominant state (a “babbling idiot” fault), it monopolizes the shared wire and blocks all other traffic. Hardware bus guardians and dominant-timeout clamp circuits time each transmission and physically disconnect jabbering nodes to keep the bus available for remaining safety nodes.

^fn7

<sup>8</sup> **AXI4 (Advanced eXtensible Interface 4)**: Arm’s AMBA on-chip bus protocol permits incrementing bursts of up to 256 beats and forbids any burst from crossing a 4,096-byte address boundary. At a 16-byte beat, one full burst is exactly one such page, which is why the notebook below splits a weight tile into one transaction per page. An urgent read that waits for the granted burst to finish, as this example assumes, is a property of the chosen arbiter, not an AXI guarantee.

^fn8

<sup>9</sup> **Target Impedance**: Power-integrity engineers hold the delivery network’s impedance, seen from the die, below the allowed ripple divided by the largest current step, at every frequency the load can excite ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-smith1999power|Smith et al. 1999]]). A flat impedance bounds the droop from a current step of any shape, which a single ${L_{\text{pkg}}}\,d{I}/d{t}$ term cannot. That documented bound is what a shared-die placement would owe the permission core’s rail, and what the discrete placement owes only its own isolated rail.

^fn9

<sup>10</sup> **Alpha-Power Law**: The model was proposed in 1990 ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-sakurai1990alpha|Sakurai and Newton 1990]]) because short-channel transistors no longer followed the long-channel square law: carrier velocity saturates, and drain current grows as $({V}-{V_{\text{th}}})^{\alpha}$ with ${\alpha}$ falling from 2 toward 1. Delay therefore depends on the headroom between supply and threshold, not on the supply alone. A low-voltage core chosen for efficiency has the least headroom, so it is also the most droop-sensitive home for the permission path.

^fn10

<sup>11</sup> **Thermal RC Analogy**: Heat flow is mathematically equivalent to electric current, temperature difference to voltage, thermal resistance (K/W) to electrical resistance, and heat capacity (J/K) to capacitance. Under a single dominant heat path, the silicon junction behaves as a first-order RC circuit with ${\tau_{\text{th}}} = {R_{\text{th,JA}}} {C_{\text{th}}}$. The parameters in this scenario imply a lumped thermal capacitance of 4 J/K, representing the stored thermal energy the package must shed through ${R_{\text{th,JA}}}$ before the governor can restore the clock. Much like an electrical RC low-pass filter smooths voltage spikes, this physical thermal mass integrates fast fluctuations in proposal compute power into a slow, sustained temperature rise that directly governs the permission core’s clock.

^fn11

<sup>12</sup> **Time Partitioning (TDMA)**: Time-division multiple access gives each requester a fixed recurring slot, so its worst wait is one schedule cycle whatever the others demand. Integrated modular avionics made the same idea the basis of processor sharing: the ARINC 653 interface schedules partitions in fixed windows of a repeating major frame, and the assurance argument for such partitioning treats spatial and temporal separation as distinct obligations ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-rushby1999partitioning|Rushby 1999]]). The price is capacity reserved even when its owner is idle, the cost this paragraph charges to the proposer.

^fn12

<sup>13</sup> **Microarchitectural Timing Anomalies**: A local speedup, such as an unexpected cache hit, can reorder subsequent pipeline or interconnect resource contention and paradoxically lengthen total execution time ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-lundqvist1999timing|Lundqvist and Stenström 1999]]). Although first identified in dynamically scheduled out-of-order processors, timing anomalies also appear in pipelined in-order cores coupled to shared buses or caches ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-wilhelm2008worst|Wilhelm et al. 2008]]). Consequently, composing local worst-case assumptions at each pipeline stage does not guarantee the global worst-case execution time, and empirical observation on an in-order core cannot substitute for formal timing analysis.

^fn13

<sup>14</sup> **Transistor Aging (BTI and HCI)**: Bias temperature instability (BTI) and hot-carrier injection (HCI) gradually increase transistor threshold voltages over operational lifetimes. This shift degrades switching speeds across logic gates, an impairment exacerbated during transient voltage droops. Because engineers cannot measure multi-year degradation on fresh silicon, production designs incorporate explicit end-of-life timing guardbands. A physical stress campaign on new development boards cannot certify silicon against aging; the placement qualification record must formally log aging as an analytically budgeted, rather than empirically measured, condition.

^fn14
