# V4-13.02 The Silicon Substrate

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13 Workload Placement|V4-13 Workload Placement]]

^sec-placement-silicon-substrate

When the warehouse mobile manipulator’s permission check finishes late, its motor drives keep executing the last admitted command, and the loaded base covers distance that the stopping budget of **[[01 Books/Volume IV - Physical AI/03 Running the Machine/12 Safety Enforcement/V4-12 Safety Enforcement#^sec-enforcement|Safety Enforcement]]** never reserved. The control barrier filter, the stopping reservation, and the fallback ladder developed there hold only while the permission path completes its check inside its hard real-time deadline on every cycle. The enforcement record declares a worst-case execution time inside that deadline, a bound on the check running alone, and whether the bound survives while the learned proposers run beside it is a question about the silicon underneath. Workload placement decides which silicon executes each computation, and with that choice, which memories, interconnects, clocks, power supplies, and thermal paths each task shares with the others. In conventional computing, placement is an optimization over throughput, latency, or energy. On a machine whose refusals must arrive on time, it becomes a safety problem.

Modern silicon integration works directly against the separation the permission path needs. A contemporary heterogeneous system-on-chip (SoC) integrates general-purpose application cores, neural accelerators, real-time microcontrollers, and specialized safety islands onto a single monolithic die. On that die, these subsystems share memory controllers, dynamic random-access memory (DRAM) channels, system-level caches, on-chip network interconnects, voltage regulators, clock governors, and the physical package that carries away heat. While silicon integration lowers unit cost, board area, and inter-processor communication latency, it quietly couples through shared hardware the very execution paths that the software architecture keeps apart. The question placement must answer is whether the deterministic permission path can keep its deadline and its authority to refuse unsafe motion while the proposal path runs at full load on shared hardware. Answering it requires a bound on hardware interference for every shared physical resource, derived from worst-case timing analysis and validated under loaded stress tests.

On the warehouse mobile manipulator, the software architecture draws the proposal boundary between the Brain and the Nervous System as a clean logical boundary. Part I adopted a working hypothesis about where that line falls in hardware. That hypothesis places the permission path on a discrete safety microcontroller physically separate from the application SoC. The machine’s two physical jobs show what that separation must guard against. For the mobile base, whose mass-dominated mobility spends stopping clearance, an interconnect stall during visual feature extraction on the proposal engine could delay the permission path’s refusal while the loaded base approaches a rack end. Every tick of delay beyond the single cycle accounted for in the stopping budget is travel distance the machine never reserved. For the arm, whose contact-dominated manipulation spends force margin, a burst of neural accelerator traffic that evicts the permission path’s lookup tables from a shared cache could delay contact force validation while the gripper presses against a spring-latched cage door. The monolithic SoC is therefore an architecture the machine must be able to reject on evidence, and the discrete microcontroller is a design claim that must survive a loaded test rather than be assumed.

↩︎ The independence requirement on the permission path, and the two-processor split as a hypothesis that loaded tests must support, are established in **[[01 Books/Volume IV - Physical AI/01 Machine Anatomy/04 The Nervous System/V4-04.03 The Independence Requirement and the Two-Processor Hypothesis#^sec-nervous-silicon-partitioning|The Independence Requirement and the Two-Processor Hypothesis]]**.

Assigning the permission filter to a dedicated processor core does not create an isolated failure domain. A core running in isolation may still stall on memory arbitration, slow down under dynamic clock throttling, or suffer transient voltage drops when adjacent accelerators become active. Memory protection units and operating system process boundaries enforce spatial partitioning by preventing unauthorized reads and writes across address spaces. However, memory protection hardware governs access permissions rather than access timing. The underlying interconnect crossbar, memory controllers, and DRAM banks determine when memory transactions actually complete. Establishing a sound safety case requires both spatial partitioning to prevent memory corruption and temporal partitioning to guarantee bounded service times for shared hardware resources ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-kopetz2011real|Kopetz 2011]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-rushby1999partitioning|Rushby 1999]]).

**Definition 13.1: Operational independence**

***Operational independence*** is the property that no activity, fault, or overload in the proposal domain can push the permission path’s execution past its deadline or disable its authority to refuse, through any resource the two paths share.

1.  **Significance**: It is the premise under which the stopping budget charges exactly one permission tick of detection delay. Every tick that proposal-side load adds beyond that one is travel at speed ${v}$ that the irreversibility test ${d_{\text{stop}}} \le {D_{\text{clear}}}$ never reserved, and a stall of unbounded length leaves the test with no bound at all.
2.  **Distinction**: Unlike spatial isolation, which private address spaces and separate cores supply, operational independence also covers time, supply, clock, reset, and heat. It is the placement-level form of what functional-safety standards call freedom from interference, the absence of cascading failures from one element into another of higher integrity ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-iso26262|International Organization for Standardization 2018]]).
3.  **Common pitfall**: Arguing independence from the separation alone. A separate core, or even a separate chip, is the hypothesis the Nervous System adopted, not its proof; independence is argued one shared resource at a time, and a loaded test on the real silicon can refute the claim for any one of them.

Every placement claim must therefore name the physical and architectural resources that could delay or disable enforcement, alongside the mechanisms that bound their mutual interference. A shared die and a discrete safety microcontroller are competing hypotheses about those hardware dependencies, not interchangeable processor choices. Testing either hypothesis starts with what each path computes and the deadline it must meet.
