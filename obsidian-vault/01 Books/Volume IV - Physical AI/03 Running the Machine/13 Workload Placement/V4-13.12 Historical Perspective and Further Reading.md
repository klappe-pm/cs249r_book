# V4-13.12 Historical Perspective and Further Reading

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13 Workload Placement|V4-13 Workload Placement]]

^sec-placement-history

Avionics met the placement problem first. Once integrated modular avionics put functions of different criticality on one processor, the certifying question became whether a fault or overrun in one function could reach another. In Rushby ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-rushby1999partitioning|1999]]), the answer separates into two obligations: spatial partitioning, which protects memory and devices, and temporal partitioning, which protects the time each function is promised. The ARINC 653 interface turned the temporal half into fixed windows of a repeating frame, and Kopetz ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-kopetz2011real|2011]]) built whole architectures on a global time base so that timing could be designed rather than discovered. Automotive practice later wrote the same concern into ISO 26262 as freedom from interference and dependent-failure analysis ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-iso26262|International Organization for Standardization 2018]]).

The bound itself had to be computed before it could be defended. Puschner and Koza ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-puschner1989calculating|1989]]) showed how to derive a maximum execution time from program structure. Abstract interpretation ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-cousot1977abstract|Cousot and Cousot 1977]]) gave analyzers a sound way to model caches and pipelines, and implicit path enumeration ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-li1995performance|Li and Malik 1995]]) turned the longest feasible path into an integer linear program. Wilhelm et al. ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-wilhelm2008worst|2008]]) surveys the tools that combined them, while Lundqvist and Stenström ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-lundqvist1999timing|1999]]) showed that local worst cases need not compose into a global one. Vestal ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-vestal2007preemptive|2007]]) then gave each task a budget per assurance level, the idea that lets a proposer overrun while an enforcer may not ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-burns2017survey|Burns and Davis 2017]]).

Multicore processors undid the single-core premise. Cores that share caches and memory controllers turn the memory wall ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-wulf1995|Wulf and McKee 1995]]) from a throughput limit into a deadline problem. The software answers followed in quick succession: phased execution that confines memory access to a separate phase ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-pellizzoni2011predictable|Pellizzoni et al. 2011]]), per-core bandwidth regulation ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-yun2013memguard|Yun et al. 2013]]), and bank-aware allocation ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-yun2014palloc|Yun et al. 2014]]). Measurements then showed that partitioning capacity leaves the miss-handling structures shared ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-valsan2016taming|Valsan et al. 2016]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-bechtel2019denial|Bechtel and Yun 2019]]), and certification caught up with AC 20-193 ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-faa2024ac20193|Federal Aviation Administration 2024]]). What this chapter adds is the physical side of the argument. The enforcer’s bound is charged against a stopping distance, heat and supply couple the paths on timescales no scheduler sees, and the evidence travels to release in a placement record.

For further reading, six works trace the ideas this chapter composes.

- Rushby ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-rushby1999partitioning|1999]]) states the requirements for partitioning processors shared by functions of different criticality and separates the spatial and temporal obligations that the dependent-failure inventory of [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.03 Two Paths and the Resources They Share#^tbl-13-placement-candidates|table 1]] checks row by row.
- Kopetz ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-kopetz2011real|2011]]) develops real-time system design from a global time base, the discipline behind fixed ticks, deadlines, and time-triggered exchange.
- Wilhelm et al. ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-wilhelm2008worst|2008]]) surveys static, measurement-based, and hybrid methods for worst-case execution time and the premises each rests on, the comparison behind [[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.08 Empirical Verification of Silicon Isolation#^sec-placement-testing-separation|section 13.7]].
- Burns and Davis ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-burns2017survey|2017]]) reviews mixed-criticality scheduling from its origin to multicore platforms, the theory behind letting the proposer lose renewal while the permission tick survives.
- Yun et al. ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-yun2013memguard|2013]]) introduces per-core memory-bandwidth regulation, the mechanism that turns an unbounded interference multiplier on a shared die into a bounded one.
- Federal Aviation Administration ([[01 Books/Volume IV - Physical AI/03 Running the Machine/13 Workload Placement/V4-13.13 Source References#^ref-faa2024ac20193|2024]]) is the current certification guidance for multicore processors, and it shows what a regulator requires before a shared-die timing bound can be believed.

**What’s Next: From compute placement to intervention**

When the slowest response delay belongs to a human operator, the stopping budget faces an interval that no silicon placement can bound. Every delay examined in this chapter belonged to the machine (a queued read, a stretched gate, a throttled clock), and each can be bounded or refuted by an empirical test on the chassis. **[[01 Books/Volume IV - Physical AI/04 Governing the Machine/14 Supervisory Intervention/V4-14 Supervisory Intervention#^sec-intervention|Supervisory Intervention]]** opens Part IV by addressing delays that originate outside the machine. A remote assistant taking over the mobile manipulator in an aisle introduces human reaction time over a network link that the onboard permission path cannot control, spending clearance from the exact same stopping budget. The authority to propose motion must then pass safely between the learned policy and the human operator while the permission path continues to validate every commanded actuation. That handover must never induce the hazardous motion it was intended to prevent, and every control tick must immutably record which entity held proposal authority.
