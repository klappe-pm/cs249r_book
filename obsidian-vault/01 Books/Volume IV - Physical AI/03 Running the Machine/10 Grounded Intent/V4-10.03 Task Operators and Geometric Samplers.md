# V4-10.03 Task Operators and Geometric Samplers

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10 Grounded Intent|V4-10 Grounded Intent]]

^sec-intent-task-motion

A symbolic task planner can emit the discrete action `Grasp(Mug, Handle)` and mark the mug as held in its internal state even when no collision-free inverse kinematics solution reaches the handle, a bin wall blocks the approach, or the mug has not been separated from adjacent items on the belt. The high-level action `Grasp(Mug, Handle)` inherits from classical planning traditions, where actions are formalized as **operators** defined by preconditions, an add list, and a delete list. The formalism traces back to the STRIPS[[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.14 Footnotes#^fn5|⁵]] framework ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.13 Source References#^ref-fikes1971strips|Fikes and Nilsson 1971]]) and was standardized by the Planning Domain Definition Language (PDDL) ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.13 Source References#^ref-mcdermott1998pddl|McDermott et al. 1998]]). A discrete world state ${s}$ consists of a set of grounded predicates. An operator ${o}$ is applicable in state ${s}$ if its preconditions hold, $\text{pre}({o}) \subseteq {s}$, producing the successor state

$$
{s'} = \left({s} \setminus \text{del}({o})\right) \cup \text{add}({o}) \tag{2}
$$

 A symbolic planner searches sequences of operators, advancing states by the delete-then-add update of [[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.03 Task Operators and Geometric Samplers#^eq-intent-strips-successor|equation 2]] until reaching a state satisfying the target goal predicates. For the warehouse pick, an operator `pick(mug, handle, conveyor)` requires preconditions `Reachable(handle)`, `Clear(approach)`, `Singulated(window)`, and `HandEmpty`, where a singulated window holds exactly one separated candidate object. Upon execution, it adds `Holding(mug)` and deletes `HandEmpty`.

^eq-intent-strips-successor

Abstract symbols disguise the primary computational challenge: verifying whether a predicate like `Reachable(handle)` holds requires finding a continuous end-effector pose, a valid inverse kinematics solution, and a collision-free joint trajectory. A symbolic planner cannot evaluate these continuous constraints natively. **Integrated task and motion planning** (TAMP) resolves this disconnect by coupling discrete symbolic search with **geometric samplers**, computational routines that sample continuous configuration spaces (proposing candidate grasps, inverse kinematics configurations, and transit paths) to certify symbolic preconditions ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.13 Source References#^ref-kaelbling2011hierarchical|Kaelbling and Lozano-Pérez 2011]]; [[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.13 Source References#^ref-garrett2021integrated|Garrett et al. 2021]]). For instance, PDDLStream treats each geometric sampler as a generator stream whose continuous outputs certify symbolic facts. The task planner can then make optimistic symbolic progress, backtracking or branching when a sampler fails to find a valid configuration ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.13 Source References#^ref-garrett2020pddlstream|Garrett et al. 2020]]). A sampler failure means that the search has not found a collision-free grasp for the given base pose; unless the sampler certifies infeasibility, it does not prove that none exists. The symbolic planner can spend more search effort, reposition the mobile base, or select an alternate interaction sequence.

Large language models (LLMs) increasingly generate the symbolic layer. Systems such as LLM+P prompt an LLM to translate natural-language task specifications into formal PDDL domain and problem instances, subsequently delegating resolution to a classical symbolic planner ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.13 Source References#^ref-liu2023llmp|B. Liu et al. 2023]]). While this decouples linguistic parsing from plan generation, neither the language model nor the symbolic planner verifies geometric feasibility or sensorimotor validity against real-world scene observations. Bridging this gap requires mapping each symbolic precondition to a verifiable motion predicate or geometric certificate evaluated against live physical measurements, as summarized in [[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.03 Task Operators and Geometric Samplers#^tbl-10-operator-predicates|table 1]].

| Operator fact           | Motion predicate or certificate                                                         | Check that discharges it                                                                                      | Where it is checked                                                                                            |
|:------------------------|:----------------------------------------------------------------------------------------|:--------------------------------------------------------------------------------------------------------------|:---------------------------------------------------------------------------------------------------------------|
| `Reachable(handle)`     | ${\mathbf{T}_{\text{grasp}}} \in {\mathcal{W}}$ with an IK solution inside joint limits | Static workspace check and transit lower bound                                                                | Admission ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.07 Admissible Goal Sets#^sec-intent-admissible-goal-sets\|section 10.6]]) |
| `Clear(approach)`       | ${P_{\text{clear}}}$ along the approach corridor                                        | Occupancy and forward occupancy screen, then swept-volume check                                               | Admission, then planner                                                                                        |
| `Singulated(window)`    | One candidate cluster in the pick window                                                | Independent count from fresh depth evidence                                                                   | Station rule ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.08 Intent Grounding Failure Modes and Their Checks#^sec-intent-failure-modes\|section 10.7]])     |
| `At(gripper, pregrasp)` | ${P_{\text{approach}}}$ within ${r_{\text{tol}}}$ and ${\theta_{\text{tol}}}$           | Goal-set membership ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.02 Grounded Affordances#^eq-intent-goal-set-se3\|equation 1]]) | Planner, then permission path                                                                                  |
| `Holding(mug)` (effect) | ${P_{\text{contact}}}$: ${f_{\min}} \le {f_n} \le {f_{\max}}$                           | Per-contact normal squeeze after closure; required for retention                                              | Runtime check                                                                                                  |

Table 1: **From task operator to motion predicate**: Each fact the symbolic `pick` operator requires or predicts for the mug maps directly to a predicate over measured physical quantities and to an explicit verification check in the execution pipeline.

^tbl-10-operator-predicates

In this execution architecture, the predicted effect `Holding(mug)` remains a conditional hypothesis until the declared terminal pose, contact, and retention checks pass following finger closure. The guarded contact predicate ${P_{\text{contact}}}$ supplies the normal squeeze check under the task profile; it cannot alone confirm that the intended mug is held. A symbolic task plan operates as an intent proposal in the same manner as a neural VLA target. It asserts the preconditions and effects it intends to achieve, while the deterministic permission path verifies whether calibrated physical evidence supports execution.

Grounding an open-ended directive therefore yields a structured, time-stamped **intent proposal**. The immediate systems design challenge is converting an identified image region into a calibrated metric target without corrupting its semantic identity, understating its measurement uncertainty, or obscuring its evidence epoch. Once packaged with these invariants, the proposal enters the independent permission path to verify physical admissibility, effort bounds, and expiration limits before execution begins.
