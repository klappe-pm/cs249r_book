# V4-10.08 Intent Grounding Failure Modes and Their Checks

[[Home|Home]] · [[01 Books/Volume IV - Physical AI/Volume 4 Overview|Volume Overview]] · [[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10 Grounded Intent|V4-10 Grounded Intent]]

^sec-intent-failure-modes

Whether an error arises from physical drift or from task misunderstanding, a vision-language model or multimodal transformer emits the same ${SE(3)}$ target pose for a physical manipulator. A specular reflection in empty air, a stale coordinate from a moving belt, or a bolted fixture mistaken for a handle all arrive across the proposal boundary as the same clean seven-number pose:

1.  **Phantom target (hallucination):** Attention concentrates on a specular glare, a shadow, or a transparent surface, and the pipeline predicts an object where none exists. Missing or corrupted depth returns then place the target in empty space or inside a transparent barrier, and an admitted proposal sends the arm into air or into glass.
2.  **Stale target (pipeline latency or temporal drift):** The physical workpiece shifts on a conveyor, vibrates on a feeder tray, or is displaced by a human coworker while the multi-stage perception pipeline buffers, batches, and decodes frames. The machine’s intent model takes 336 ms per inference, longer than the 60 ms untracked horizon before any tail latency is added. A chunked action stream can keep the arm moving throughout, but on the target the model last saw. The resulting proposal arrives downstream with mathematically valid coordinates that describe where the object *used to be* rather than where it *is*, consuming physical clearance before motion begins.
3.  **Semantic ambiguity (bimodal posterior or argmax failure):** Two visually identical candidate objects (e.g., two red mugs) reside within the pick zone, and both score high because the detector scores each box independently. The calibrated prediction set holds both ($|{\mathcal{C}}| = 2$). Keeping only the top box or averaging the candidates’ centroids commands an arbitrary choice or drives the end effector toward the empty midpoint between the objects, risking a dual-object collision.
4.  **Misclassified affordance:** A bolted fixture is taken for a movable handle, or a thin-walled container for a robust one, and the requested grip force destroys it. The approach can be collision-free while the contact wrench is wrong.
5.  **Dynamic unreachability (kinematic transit shortfall):** A requested terminal move is geometrically within the static workspace manifold ${\mathcal{W}}$, but the transit time demanded by actuator velocity and acceleration limits exceeds the remaining sensor evidence window (${t_{\text{transit}}} > {t_{\text{intent\_exp}}} - {t_{\text{now,mono}}}$). The terminal request must be rejected or replaced with guarded stages supported by fresh observations; extending its old evidence deadline cannot make it feasible.

All five failures arrive across the proposal boundary in the same format: a candidate position ${\mathbf{p}} \in \mathbb{R}^3$ and orientation ${\mathbf{R}} \in {SO(3)}$. While a pose in empty air leads to a futile reach and a pose inside a fixture leads to contact unless path and permission checks intervene, the wrong-object case can satisfy every geometric and kinematic check while targeting the wrong item. Because the independent permission path checks only what it can measure (freshness, coverage, geometry, current state, and actuator limits), it makes no claim to verify the task’s meaning. **The Safety MCU enforces physical feasibility, not semantic truth. A goal can be collision-free, kinematically smooth, and torque-limited, yet wrong for the task.** Semantic verification therefore belongs to upstream task monitoring and operator oversight, and the same boundary holds under adversarial attack, where an injected instruction or a printed patch in the camera view still yields a well-formed pose.

↪ What the permission path can and cannot catch when the proposer itself is attacked is developed in **[[01 Books/Volume IV - Physical AI/04 Governing the Machine/15 Adversarial Verification/V4-15.07 Deriving the Fault List#^sec-verification-transduction-attacks|Physical sensor spoofing and proposer injection]]**.

A fresh depth observation can reject a proposed grasp when required object evidence is absent inside a covered, visible region, whereas missing returns in an occluded or unobserved region leave that space unknown. On this station, the singulation rule goes further by requiring independently qualified depth evidence of a single candidate in the pick window, even when the grounding model reports high confidence. Because the Safety MCU holds no scene representation with which to count objects, this check runs in a separate station component before any proposal is forwarded. The component routes any window with multiple candidates to a coworker for manual selection (a scoped station policy; another qualified operating mode could select a uniquely identified mug among several objects). Counting itself depends on validated sensor coverage and segmentation, so it shares a failure mode with phantom targets. Touching items can merge into a single cluster, and transparent objects such as the glass jar return little or no depth ([[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.13 Source References#^ref-sajjan2020cleargrasp|Sajjan et al. 2020]]). The counter’s qualified domain must therefore exclude those cases or route them to a manual pick. Even when the count finds a single cluster, it still cannot verify that the lone object is a mug, and while the producer’s calibrated ambiguity filter may refuse earlier, it cannot replace the station’s independent check.

[[01 Books/Volume IV - Physical AI/03 Running the Machine/10 Grounded Intent/V4-10.08 Intent Grounding Failure Modes and Their Checks#^tbl-10-grounding-failure-modes|Table 5]] groups these failures by the check that can expose them. Dynamic transit insufficiency can be rejected before motion, whereas a misclassified affordance may first become observable through contact residuals. The table separates admission checks from responses after motion or contact has begun. At the cage-door latch of notebook [10.1](https://mlsysbook.ai/vol4/10_intent/10_intent.html#nbk-intent-lease-duration-collision-exposure-tradeoff-across), the 2 ms contact-loop response already leaves 39 N at brake-command onset, and the peak comes later. Precontact speed and force limits, actuator response, compliance, and available clearance therefore determine whether the full contact trace stays within the validated contact limits.

| Failure mode                                                             | Evidence or check                                                                                                                               | Admission or response                                                                                          | Physical limit to verify                                                                                                                |
|:-------------------------------------------------------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------|:---------------------------------------------------------------------------------------------------------------|:----------------------------------------------------------------------------------------------------------------------------------------|
| **Phantom target:** image artifact in empty space                        | Fresh depth evidence and target-region occupancy, with coverage and occlusion checked                                                           | Reject the proposal when the required object evidence is absent; request another view if the region is unknown | Rejection precedes motion only if the proposal has not already been admitted. Missing returns alone do not prove empty space.           |
| **Stale target:** workpiece moved after capture                          | Converted capture time, bounded clock error, local tracking, and target-error envelope                                                          | Revoke dependent tracking when the evidence limit fails; select the validated fallback                         | Total detection, communication, actuation, and braking delay must fit the measured clearance.                                           |
| **Station singulation failure:** multiple candidates in the pick window  | Independent count of candidates in the pick window from fresh depth evidence; calibrated prediction-set size as an earlier producer-side signal | Refuse admission and route the item to the coworker for a manual pick                                          | A single wrong object passes the count, and a confident model can return a singleton set; independent physical checks remain necessary. |
| **Misclassified affordance:** bolted fixture selected as graspable       | Contact-force and motion residuals after contact; precontact task/geometry checks where possible                                                | Limit precontact speed and force, then invoke the validated contact response on a threshold crossing           | A reactive trip does not cap the first impact peak; test the full force trace, response delay, and stopping energy.                     |
| **Dynamic unreachability:** target cannot be reached in its valid window | Speed-ceiling transit lower bound followed by a complete path and stopping check                                                                | Reject terminal completion on that record; consider separately admitted guarded segments                       | Passing the lower bound proves neither collision-free motion nor a feasible stop.                                                       |

Table 5: **Grounding failure modes and their evidence limits**: Each check addresses a different failure class. The table separates proposal rejection from a response to an already moving plant.

^tbl-10-grounding-failure-modes

Every row of the table therefore requires the proposal to carry its spatial bounds, the provenance of its evidence, and its expiry in a form the permission path can check without the model. A rejected proposal returns a diagnostic reason to the learned layer without revoking an earlier active record, which remains usable while its own state, evidence, lease, and fallback hold. An admitted proposal stays subject to independent permission checks as the plant moves, and the record the permission path grants from it is the intent lease.
