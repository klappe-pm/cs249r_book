# V1-01.11 Book Organization

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/00 Introduction/01 Introduction/V1-01 Introduction|V1-01 Introduction]]

^sec-introduction-book-organization-0b64

Production ML work divides into responsibilities that engineering teams own: data engineering, training systems, deployment infrastructure, operations and monitoring, and ethics and governance ([[01 Books/Volume I - Foundations/00 Introduction/01 Introduction/V1-01.15 Source References#^ref-paleyes2022|Paleyes et al. 2022]]). Those boundaries leak. Upstream data pipelines limit what training can reach, training choices fix the memory and latency footprint at serving time, and governance constrains every stage, so the book does not follow an organization chart. Its four parts follow the order in which constraints must be understood. The organizing principle is *context before theory*. Hardware limits and data ingestion bottlenecks constrain which algorithms are practical, so the book first establishes the physical operating envelopes of each deployment setting and the data pipeline, then checks each algorithm’s resource demands against those envelopes. Accelerator design itself is studied in detail later, once the models it must run have been built. Readers establish operational boundaries and vocabulary (Part I) before constructing models (Part II), optimizing computational efficiency (Part III), and deploying systems under production service-level agreements (Part IV), the progression summarized in [[01 Books/Volume I - Foundations/00 Introduction/01 Introduction/V1-01.11 Book Organization#^tbl-book-structure|table 5]].

Table 5: **Book Organization**: The four parts progress from foundations through model construction and training to optimization, deployment, and operations. This introduction precedes them and **[[01 Books/Volume I - Foundations/04 Deployment/16 Conclusion/V1-16 Conclusion#^sec-conclusion|Conclusion]]** follows them. Each part builds on the vocabulary and methods of its predecessors.

^tbl-book-structure

Each part opens with the named principles it develops. These are numbered across the book so later chapters can refer back to them. The deployment part, for example, opens with the verification gap, which this chapter introduced with the ImageNet example.

This book focuses on the **single-node** regime of one host with one to eight accelerators, each typically using local device memory and communicating through an on-node interconnect such as PCIe or NVLink, NVIDIA’s direct link between accelerators. The limiting constraint depends on the workload and may be memory capacity, memory bandwidth, compute throughput, or communication. Larger fleets add coordination and network constraints across many hosts. For reading paths, learning outcomes, prerequisites, and guidance on using the textbook, [[01 Books/Volume I - Foundations/Frontmatter/V1 Preface|the preface]] provides the orientation.
