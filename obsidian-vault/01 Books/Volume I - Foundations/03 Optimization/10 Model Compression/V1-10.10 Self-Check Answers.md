1.  **The chapter’s optimization framework organizes model compression along three abstraction levels. Which sequence matches the stack from most software-level to most hardware-level?**

    1.  Efficient numerics representation → efficient model representation → efficient hardware implementation
    2.  Efficient hardware implementation → efficient model representation → efficient numerics representation
    3.  Efficient model representation → efficient numerics representation → efficient hardware implementation
    4.  Efficient hardware implementation → efficient numerics representation → efficient model representation

    *Answer*: The correct answer is C. The framework moves from changing the model graph itself, to changing how surviving values are represented, to changing how the resulting graph executes on hardware. An ordering that starts with hardware implementation confuses abstraction level with execution chronology: hardware constraints guide all three levels, but the figure presents a stack, not a compulsory workflow.

    *Learning Objective*: Identify the three abstraction levels in the chapter’s optimization framework from model representation down to hardware implementation

2.  **A $7\text{-billion}$-parameter language model in FP16 occupies $14\text{ GB}$ of weight memory alone. The target deployment platform is a smartphone with $8\text{ GB}$ of shared RAM. Explain how quantizing weights to INT4 addresses both the physical memory capacity ceiling and the memory-bandwidth bottleneck during autoregressive token generation.**

    *Answer*: INT4 cuts the raw weight payload from about $14\text{ GB}$ in FP16 to about $3.5\text{ GB}$, which can make the model a candidate for an $8\text{ GB}$ phone where memory is shared with the OS, runtime, KV cache, activations, and metadata. In low-batch autoregressive decoding, latency can be dominated by streaming dense weights, so reducing weight bytes by $4\times$ can reduce that weight traffic by about $4\times$. The practical consequence is that INT4 can relieve both fit and bandwidth pressure, but it does not guarantee full runtime fit or a $4\times$ end-to-end throughput gain because other memory and kernel costs remain.

    *Learning Objective*: Apply capacity and bandwidth reasoning to evaluate when INT4 weight quantization is a strong candidate for edge LLM deployment

3.  **True or False: When a model cannot be deployed because its parameter footprint exceeds the device’s physical RAM capacity, operator fusion is an effective direct substitute for pruning or quantization.**

    *Answer*: False. Fusion primarily reduces intermediate-tensor traffic and launch overhead by keeping adjacent operations on chip. If the dominant problem is the raw weight footprint itself, fusion does not remove enough stored parameter bytes to substitute for pruning or quantization, though some parameter folding patterns such as batch normalization folding can slightly change stored parameters.

    *Learning Objective*: Distinguish execution optimizations that reduce intermediate traffic from techniques that reduce the dominant stored weight footprint

4.  **A \_\_\_\_ is the memory, time, and energy that a target device grants to each result a model produces, and model compression is the work of bringing a trained model’s demands inside it.**

    *Answer*: deployment budget. Memory capacity bounds the bytes of weights and activations that can stay resident, a frame rate or token rate bounds the milliseconds available for each result, and a battery or thermal envelope bounds the joules each result may consume. A trained model’s demands were set by the accelerators it trained on, not by the device it must run on.

    *Learning Objective*: Define the deployment budget and name the three resources it bounds.

5.  **Across the deployment contexts analyzed in the chapter, which platform most clearly makes model compression a feasibility requirement rather than mainly a throughput or cost optimization?**

    1.  TinyML microcontrollers, where SRAM and storage budgets are so small that some models cannot be placed at all without compression or redesign
    2.  Cloud inference clusters, where only cloud systems face hard capacity limits and all smaller devices can compensate in software
    3.  Autonomous edge servers, where continuous thermal throttling is preferred over changing the model
    4.  Mobile smartphones, where unified memory architecture eliminates meaningful capacity constraints for large neural networks

    *Answer*: The correct answer is A. TinyML devices can have only hundreds of kilobytes of SRAM plus separate flash or storage limits, so a model may simply not fit unless its weights and working set are reduced enough. Capacity limits also matter on mobile and cloud systems, but the chapter uses microcontrollers to illustrate the clearest hard feasibility boundary. Claims that only cloud has hard limits or that phone memory is effectively unconstrained contradict the section’s deployment-budget comparison.

    *Learning Objective*: Compare deployment contexts to identify where compression is most directly required for basic model feasibility

6.  **A mobile video-conferencing feature requires $30\text{ FPS}$ background segmentation, but baseline FP32 MobileNetV2 runs at only $8\text{ FPS}$. Applying INT8 quantization accelerates the model to $35\text{ FPS}$ with a minor $0.4\%$ drop in mIoU, satisfying the shipping requirement. Which region of the chapter’s compression-accuracy Pareto frontier best describes this outcome?**

    1.  Region 1 (little or no quality loss), because achieving 35 FPS proves that INT8 quantization incurs zero loss in segmentation boundary fidelity
    2.  Region 3 (steep quality loss), because any reduction in numerical precision destabilizes temporal consistency in video processing
    3.  An unfeasible operating point outside the Pareto frontier, because 35 FPS exceeds the maximum display refresh rate
    4.  Region 2 (a moderate trade), because a modest, acceptable drop in segmentation accuracy unlocks a 4.4× frame rate increase that satisfies the 30 FPS real-time shipping threshold

    *Answer*: The correct answer is D. Region 2 (a moderate trade) represents the practical operational sweet spot where an engineer trades a small, tolerable accuracy concession for a massive efficiency gain ($8\text{ FPS} \to 35\text{ FPS}$) that moves the application across a hard production requirement ($30\text{ FPS}$). Placing it in region 1 (little or no quality loss) overlooks that INT8 rounding introduces real numerical quantization error, while placing it in region 3 (steep quality loss) confuses a successful deployment trade-off with catastrophic accuracy failure.

    *Learning Objective*: Classify real-world deployment trade-offs into the three characteristic regions of the compression-accuracy Pareto frontier

1.  **A team prunes ResNet-50 to $50\%$ sparsity using unstructured magnitude pruning and observes only a $1.1\times$ speedup on a commodity GPU. Switching to structured channel pruning at the exact same $50\%$ sparsity yields a $1.8\times$ speedup. Which systems mechanism best explains this difference?**

    1.  Structured pruning removes more total weight parameters than unstructured pruning at any given nominal sparsity percentage
    2.  Structured pruning removes entire contiguous channels or filters, allowing smaller dense kernels to execute efficiently, whereas unstructured sparsity needs sparse storage, metadata, and irregular activation access
    3.  Unstructured magnitude pruning requires zero retraining or fine-tuning, whereas structured channel pruning requires full retraining from scratch
    4.  Commodity GPU memory controllers automatically coalesce random non-zero memory addresses into single-cycle burst transfers

    *Answer*: The correct answer is B. Structured channel pruning produces smaller dense tensors that still map well to standard dense kernels. Unstructured sparsity can reduce nonzeros, but exploiting it requires sparse encodings and matching kernels, which add metadata handling, irregular activation gathers, and possible load imbalance. The idea that random sparse accesses are automatically coalesced ignores the execution problem the section emphasizes, and equal nominal sparsity does not mean structured pruning removes more weights.

2.  **Order the stages of finding a winning lottery ticket in a neural network according to the Lottery Ticket Hypothesis (LTH): (1) Reset surviving weights to their original initialization values ($W_0$), (2) Train the dense unpruned network to convergence, (3) Retrain the sparse subnetwork to convergence, (4) Prune the lowest-magnitude weights to create a sparse mask.**

    *Answer*: The correct order is: (2) Train the dense unpruned network to convergence, (4) Prune the lowest-magnitude weights to create a sparse mask, (1) Reset surviving weights to their original initialization values ($W_0$), (3) Retrain the sparse subnetwork to convergence. First, dense training allows gradient descent to differentiate parameter importance. Second, magnitude pruning isolates the most critical connections to form a binary mask. Third, resetting surviving parameters to their exact initial values ($W_0$) isolates the subnetwork’s topological initialization. Finally, retraining the sparse subnetwork validates whether it can match or exceed the original dense model’s accuracy.

    *Learning Objective*: Design an experimental procedure that sequences the iterative steps used to evaluate winning lottery tickets under the Lottery Ticket Hypothesis

3.  **A team must compress a large transformer model for deployment across a fleet of commodity GPUs that lack dedicated sparse-matrix acceleration kernels. Which structural optimization technique is the strongest candidate for producing a smaller model that still executes efficiently on this hardware?**

    1.  Unstructured magnitude pruning, because sparse matrix multiplication routines run with zero memory overhead on all standard GPUs
    2.  Extreme binary weight quantization, because 1-bit representations eliminate all memory traffic without degrading language model perplexity
    3.  Knowledge distillation, because it transfers teacher behavior into a compact dense student architecture that runs well on standard dense GPU kernels
    4.  Low-rank factorization without fine-tuning, because mathematical decomposition guarantees zero loss in representation capacity

    *Answer*: The correct answer is C. Distillation trains a new compact dense student, so the deployed model can use ordinary dense kernels that commodity GPUs already execute efficiently. That makes it a strong candidate when sparse acceleration support is absent. Unstructured pruning still depends on sparse formats and kernels, low-rank factorization is an approximation rather than a zero-loss guarantee, and the section does not claim pruning can never remove layers or that binary quantization is broadly safe for this setting.

    *Learning Objective*: Evaluate distillation as a structural optimization candidate when deployment hardware favors dense execution

4.  **A square weight matrix of size $4096 \times 4096$ in a transformer layer is decomposed using low-rank factorization at rank $r = 128$. Calculate the theoretical reduction factor in both parameter count and multiply-accumulate (MAC) operations, and explain what trade-off this structural approximation introduces.**

    *Answer*: The original matrix contains $4096 \times 4096 = 16{,}777{,}216$ parameters ($16.78\text{M}$ MACs per vector product). Factoring into two matrices of dimensions $4096 \times 128$ and $128 \times 4096$ requires $2 \times (4096 \times 128) = 1{,}048{,}576$ parameters ($1.05\text{M}$ MACs). This yields an exact theoretical reduction factor of $\frac{4096^2}{2 \times 4096 \times 128} = \frac{4096}{256} = 16\times$ for both parameter storage and arithmetic operations. The trade-off is that factorization restricts the layer’s representational capacity to a low-dimensional subspace of rank 128, which can degrade model expressiveness and task accuracy unless recovered through subsequent fine-tuning, while introducing the runtime overhead of launching two consecutive matrix multiplication kernels.

    *Learning Objective*: Calculate parameter and arithmetic reduction factors for low-rank matrix factorization and evaluate the resulting rank-capacity trade-off

5.  **An engineering organization is deciding between running a custom Neural Architecture Search (NAS) from scratch versus adopting an established NAS-discovered family (such as MobileNetV3 or EfficientNet). Which circumstance most strongly justifies investing in custom NAS?**

    1.  Novel or custom hardware accelerators with unique memory hierarchies or massive production deployment scale where small per-inference efficiency gains amortize large one-time search costs
    2.  Standard GPU clusters running established vision benchmarks where off-the-shelf architectures like MobileNetV3 already fit latency budgets
    3.  Rapid prototyping projects with a total engineering timeline under one week and fewer than 10 available GPUs
    4.  Small-scale enterprise applications processing fewer than 1,000 queries per day on cloud instances

    *Answer*: The correct answer is A. Custom Neural Architecture Search (NAS) incurs substantial compute expenditure (historically hundreds to thousands of GPU-days), making it justifiable primarily when targeting novel hardware accelerators whose physical constraints are not served by existing architectures, or when extreme deployment scale (billions of daily inferences) allows modest per-query latency and energy gains to rapidly amortize the upfront search cost. For standard hardware, existing NAS-designed architectures (e.g., EfficientNet, MobileNetV3) provide proven efficiency out of the box without incurring search expenses. Fast prototyping and low-volume applications cannot justify the substantial time and compute cost required by NAS.

    *Learning Objective*: Evaluate the economic and architectural conditions that justify custom Neural Architecture Search versus adopting established efficient architectures

6.  **Compare one-shot pruning with an iterative schedule that removes 10 percentage points of the original weights in each of 8 rounds with recovery between rounds. Explain why staged recovery can help, and what controlled comparison is needed before concluding that the iterative schedule is better.**

    *Answer*: Iterative pruning removes capacity in stages, giving the surviving weights chances to recover after each cut, so it is often a strong candidate when high sparsity is the goal. For example, eight rounds of removing $10$ percentage points of the original weights each can reach $80\%$ total sparsity while interleaving recovery. But the chapter does not claim this always beats one-shot pruning at the same final target: the outcome depends on the recovery budget, architecture, and pruning procedure. The practical implication is to compare schedules fairly at matched recovery effort instead of assuming staged pruning is universally superior.

    *Learning Objective*: Compare one-shot and iterative pruning while recognizing that recovery quality depends on schedule and recovery budget, not a universal rule

What explains this operation-level energy dividend?**

    2.  INT8 quantization automatically prunes zero-valued parameters before they reach the execution units
    3.  The 8-bit integer adder circuit requires significantly fewer logic gates, capacitance, and switching energy per operation than a 32-bit floating-point adder with exponent alignment and normalization logic
    4.  Floating-point operations require continuous synchronization with host CPU DRAM on every instruction

The $30\times$ arithmetic energy disparity ($0.03\text{ pJ}$ for INT8 add vs. $0.9\text{ pJ}$ for FP32 add based on Horowitz constants) stems directly from silicon circuit complexity: an 8-bit integer addition requires a compact adder circuit with minimal logic gates and switching capacitance, whereas a 32-bit floating-point adder requires extensive barrel shifters for exponent alignment, mantissa addition, normalization, and rounding logic. 2.  **In affine (asymmetric) quantization, the integer parameter \_\_\_\_ shifts the quantized grid so that real-valued zero maps exactly to an integer representation, ensuring that zero-padded tensor regions introduce no numerical bias.**

    *Answer*: zero-point. The zero-point (or zero point, $Z$) provides an integer offset that ensures the real floating-point value $0.0$ is mapped precisely to an integer without rounding error, which is crucial for preserving exact zero representations in padded convolutional feature maps and ReLU activations.

3.  **Order the stages of a standard post-training quantization workflow with static activation calibration: (1) quantize the finalized weights and export the deployment artifact, (2) run representative floating-point calibration inputs through the model and collect activation statistics, (3) choose activation clipping bounds from the collected statistics, (4) derive activation scales and zero-points from those chosen bounds.**

    *Answer*: The correct order is: (2) run representative floating-point calibration inputs through the model and collect activation statistics, (3) choose activation clipping bounds from the collected statistics, (4) derive activation scales and zero-points from those chosen bounds, (1) quantize the finalized weights and export the deployment artifact. Calibration data must be observed before clipping bounds can be chosen, and those bounds must be fixed before scales and zero-points can be derived. Export belongs last because the deployment artifact should reflect the completed quantization parameters rather than precede them. Swapping calibration with export would freeze an artifact before the activation ranges needed to define it were established.

    *Learning Objective*: Sequence the main stages of static-calibrated post-training quantization from calibration through export

4.  **Compare two validation settings for low-bit quantization: (1) candidate INT4 weight-only quantization for autoregressive decoding when profiling shows weight traffic dominates, and (2) candidate low-bit quantization for large-batch training of the same model. Explain why these two settings require different validation conditions before concluding the quantization is worthwhile.**

    *Answer*: In low-batch autoregressive decoding, each generated token can be dominated by streaming dense model weights, so cutting weight bytes from FP16 toward INT4 can substantially reduce weight traffic and improve latency when the runtime has a matching kernel. The ideal bound is set by the weight-byte reduction, not an automatic $4\times$ end-to-end speedup, because KV-cache traffic, activations, and dequantization overhead remain. Large-batch training is different: it is not automatically accelerated by weight-only INT4, because training is often compute-heavy and also requires a low-precision training recipe, supported execution units, and numerical validation rather than just compressing stored weights.

    *Learning Objective*: Contrast why weight-only low-bit quantization is most compelling for weight-bandwidth-bound decoding rather than automatically for training

5.  **During post-training quantization of a convolutional network, activation profiling reveals that values are heavily concentrated near zero with a small set of extreme positive outliers. Which calibration strategy best preserves numerical resolution for the bulk of typical activations?**

    1.  Max-absolute-value calibration, because extending the quantization grid to include extreme outliers guarantees zero clipping error across all layers
    2.  Uncalibrated uniform quantization, because activation distributions in neural networks always follow a perfectly uniform probability density
    3.  Static symmetric quantization with range \[-128, +127\] mapped unconditionally to \[-1.0, +1.0\] across every layer
    4.  Percentile or KL-divergence (entropy) calibration, which can clip extreme tails so more integer levels represent the dense bulk of activations

    *Answer*: The correct answer is D. When a tensor has a dense bulk near zero plus a rare outlier tail, percentile or KL-based calibration can trade some clipping of that tail for better resolution where most values actually lie. A percentile method such as keeping $99.9\%$ of values clips the remaining tail by design. That trade can improve typical representation quality, but it is not harmless by definition because rare outliers may still matter for task accuracy. Max calibration instead spends range on those extremes and can waste bins on mostly empty space.

    *Learning Objective*: Compare calibration strategies for long-tailed activation distributions by analyzing the trade-off between clipping and resolution

6.  **A team quantizing a deep convolutional network finds that per-channel (filter-wise) quantization achieves significantly higher accuracy than per-tensor (layer-wise) quantization at the same INT8 bit-width. Which mechanism explains this accuracy advantage?**

    1.  Per-channel quantization eliminates the need to compute or store scale factors and zero-points
    2.  Individual convolutional filters within a layer often exhibit drastically different weight magnitude ranges; per-channel quantization assigns an independent scale factor to each filter, preventing wide-range filters from degrading the precision of narrow-range filters
    3.  Per-tensor quantization can only be executed on CPUs, whereas per-channel quantization is restricted to edge microcontrollers
    4.  Per-channel quantization automatically converts float operations into sparse matrix multiplications

    *Answer*: The correct answer is B. In deep convolutional neural networks, different filters within the same layer specialize in distinct feature patterns, often resulting in weight distributions with variances that differ by orders of magnitude. Under per-tensor (layer-wise) quantization, a single clipping range must encompass all filters, forcing narrow-distribution filters into a tiny subset of quantization bins. Per-channel (per-filter) quantization assigns an independent scale factor $S_c$ and zero-point $Z_c$ to each output channel, giving narrow-range filters finer numerical resolution when their ranges differ. This can explain the measured quality advantage, but scale metadata, kernel support, and the calibration policy still determine the deployment trade-off.

    *Learning Objective*: Explain why per-channel quantization granularity preserves accuracy in convolutional networks compared to per-tensor quantization

    2.  Fusion retrains the network to use lower numerical precision during the forward pass

3.  **A compressed neural network achieves a $50\%$ reduction in total floating-point operations (FLOPs), yet on the deployment accelerator, end-to-end inference latency decreases by only $10\%$. Explain two distinct hardware and architectural mechanisms that cause this discrepancy.**

    *Answer*: First, Amdahl’s Law at the pipeline level limits overall speedup: if model execution accounts for only a fraction of the end-to-end request pipeline (with data ingestion, preprocessing, tokenization, and postprocessing consuming the remainder), accelerating model arithmetic yields a diminished system-level improvement. Second, within the model itself, many non-compute-intensive layers (such as LayerNorm, Softmax, residual additions, and activation functions) are memory-bandwidth bound or latency-bound rather than compute-bound; cutting FLOPs in the compute-heavy layers leaves memory-bound execution time largely unchanged, capping measured speedup.

    *Learning Objective*: Explain why theoretical FLOP reductions fail to produce proportional latency gains using Amdahl’s law and memory-bound layer analysis

4.  **True or False: Commodity SIMD vector units automatically achieve proportional latency reductions on weight matrices with $50\%$ unstructured sparsity because vector lanes automatically skip zero values without overhead.**

    *Answer*: False. A dense masked tensor still moves and processes zeros. To skip them, the runtime needs a compact sparse representation and a matching kernel, but that path adds metadata handling, irregular activation accesses, and possible load imbalance. Whether sparse execution wins depends on format, shape, batch size, and hardware; there is no universal sparsity percentage that guarantees proportional speedup.

    *Learning Objective*: Reject the misconception that unstructured sparsity automatically accelerates dense SIMD hardware

4.  **The chapter’s illustrative BERT compression pipeline compresses a $440\text{ MB}$ FP32 model down to $28\text{ MB}$ (roughly $16\times$) by sequencing pruning, distillation, and INT8 quantization. Why do these techniques compound multiplicatively rather than substituting for one another?**

    1.  The techniques duplicate each other’s reductions, causing total compression to saturate at the performance of the single strongest method
    2.  Pruning produces the smaller student graph, distillation recovers its quality at the same parameter count, and quantization reduces numerical bit-width per parameter; because these operate on orthogonal resource axes, their compression ratios multiply ($4\times \text{ structural} \times 4\times \text{ precision} \approx 16\times \text{ total}$)
    3.  Applying quantization automatically converts the pruned network into a student model without requiring teacher supervision
    4.  Multiplicative gains occur only when the pipeline starts with operator fusion on uncompressed weights

    *Answer*: The correct answer is B. The stipulated pruned graph has 27.5M parameters, one quarter of the 110M teacher. Distillation recovers quality at that count; INT8 then stores each weight in one byte instead of four. The raw payload falls from 440 MB to 27.5 MB (rounded to 28 MB), a 16× reduction. Fusion changes execution rather than supplying either weight-storage factor. These arithmetic savings do not guarantee latency gains.

    *Learning Objective*: Explain why combining orthogonal compression techniques across structural and numerical dimensions yields multiplicative compression ratios

5.  **In a modeled scenario, one compression order loses $0.6\%$ accuracy while the reversed order loses $2.1\%$. Propose a plausible pruning-quantization interaction that could explain this gap, and state what a fair comparison should hold fixed before concluding the ordering matters.**

    *Answer*: The modeled result illustrates one plausible interaction: pruning changes the surviving weight and activation distributions, so quantization ranges chosen earlier may no longer match the final artifact well. Quantizing first can also distort the fine-grained information used by importance scoring. Pruning first preserves full-precision information during structure selection, after which calibration or retraining can target the pruned model actually being deployed. The practical implication is not that one ordering is universally best, but that schedules should be compared under matched recovery and calibration budgets because pruning and quantization interact through shared distributions.

    *Learning Objective*: Analyze why pruning and quantization order can matter by changing the distributions seen by importance scoring and calibration

6.  **A measured compression-quality curve shows a clear knee: before it, each extra compression step saves substantial resource with small quality loss; after it, additional compression yields much smaller resource savings for noticeably larger quality loss. Explain how an engineer should use that knee when choosing an operating point for a deployment with explicit quality and resource constraints.**

    *Answer*: The knee marks the region where marginal savings start to shrink relative to the quality penalty, so it is a warning that the trade-off is worsening. For example, one deployment may stop near the knee if it already meets its memory or latency target there, while another may compress past it if stricter resource limits require that sacrifice. The practical implication is that the knee helps interpret the curve, but the chosen operating point must still be the one that satisfies the deployment’s stated quality and resource constraints.

    *Learning Objective*: Explain how the knee of a measured quality-efficiency curve informs operating-point selection under explicit deployment constraints

7.  **An engineering team evaluates TensorFlow Model Optimization Toolkit (TFMOT) and PyTorch’s `torch.ao` APIs for a pipeline compressing hundreds of production models per month. What is the primary systems value these framework toolkits provide?**

    1.  They eliminate the need for engineers to benchmark or validate models on physical target hardware
    2.  They automate the insertion and state management of complex compression primitives—such as fake-quantization observers, dynamic range trackers, and sparsity masking hooks—making compression scalable and reproducible across hundreds of models
    3.  They automatically discover optimal hyperparameter architectures from scratch without compute overhead
    4.  They guarantee identical execution performance across all CPU, GPU, and TPU backends without requiring hardware-specific compilers

    *Answer*: The correct answer is B. Production-grade model compression requires managing thousands of observer nodes, tracking dynamic activation ranges, inserting fake-quantization operators for QAT, and scheduling sparsity masks across training steps. Framework APIs (such as PyTorch `torch.ao` and TensorFlow Model Optimization Toolkit) automate this tedious and error-prone structural plumbing, enabling scalable, reproducible compression workflows. They do not replace empirical hardware benchmarking, eliminate search compute, or bypass the need for hardware-specific runtime lowering.

    *Learning Objective*: Explain how framework-level optimization toolkits automate structural compression workflows while preserving the need for hardware-aware validation

8.  **A model is pruned and quantized inside a training framework, but the exported deployment shows almost no speedup on the target accelerator. Explain why a hardware-specific compiler or runtime is still needed, and why framework-level masks or fake-quant operations are not enough evidence of real acceleration.**

    *Answer*: Framework-level pruning masks and fake-quant or graph annotations do not by themselves create a fast execution path. A hardware-specific runtime or compiler lowers the exported graph to supported kernels, fuses adjacent operators, chooses hardware-friendly layouts, and maps low-precision or sparse patterns onto the target’s actual execution units. Some deployment stacks integrate compiler and runtime functions, but the key requirement is still proof that the exported path really executes the compressed form efficiently. The practical implication is that compression inside the framework can remain only a logical transformation until the deployment runtime proves that the exported operators, layouts, and kernels really exploit it.

    *Learning Objective*: Explain why deployment compilers or runtimes are needed to convert framework-level compression into actual hardware acceleration

3.  **True or False: If an INT8-quantized classifier achieves the exact same top-1 accuracy as its full-precision baseline, its output probability distributions and confidence calibration are guaranteed to be equally reliable for downstream safety thresholds.**

    *Answer*: False. Top-1 accuracy counts correct argmax predictions; equal aggregate accuracy does not require the same examples to be correct. Even when every argmax prediction stays unchanged, quantization can alter logit magnitudes and output probabilities, changing confidence calibration. In safety-critical systems, an uncalibrated quantized model may output overconfident or miscalibrated probabilities despite maintaining identical top-1 accuracy.

    *Learning Objective*: Compare top-1 classification accuracy with confidence calibration and probability reliability in quantized models

1.  **Which statement best captures the chapter’s analysis regarding the interaction between multiple model compression techniques?**

    1.  Compression techniques compose strictly linearly, so combining a $2\times$ pruning gain and a $2\times$ quantization gain always yields a $4\times$ latency reduction regardless of hardware
    2.  Quantization is the only technique that interacts with other methods, while pruning and distillation can always be designed in isolation
    3.  Compression techniques interact nonlinearly through shared hardware bottlenecks (cache capacity, memory bandwidth) and competing accuracy budgets; their combined efficacy depends heavily on pipeline sequencing and joint on-target validation
    4.  Applying more than one compression technique is never recommended because accuracy degradation is always strictly additive

    *Answer*: The correct answer is C. The chapter emphasizes that compression techniques do not operate in a vacuum: they share physical hardware resources (memory bandwidth, cache capacity, register pressure) and draw from the same underlying model error tolerance. For instance, aggressive pruning reduces the numerical headroom available for subsequent quantization, and uncoalesced sparse memory access can negate quantization bandwidth savings. Therefore, techniques interact nonlinearly and must be evaluated and validated jointly. Claiming linear composition ignores hardware realities, while declaring multi-technique pipelines unviable contradicts proven multiplicative compounding.

    *Learning Objective*: Analyze how compression techniques interact nonlinearly through shared physical resources and joint accuracy budgets

2.  **True or False: If a neural network’s parameter count is reduced by $4\times$ via magnitude pruning, its deployed end-to-end inference latency on a standard mobile CPU is guaranteed to improve by approximately $4\times$.**

    *Answer*: False. A $4\times$ parameter reduction does not imply a $4\times$ latency reduction because sparse execution depends on layout, kernel support, tensor shape, and device behavior. On a standard mobile CPU, unstructured sparsity may still incur dense-like traffic or sparse-format overhead, and end-to-end latency also includes work outside the pruned layers.

    *Learning Objective*: Reject the assumption that parameter-count reduction guarantees proportional end-to-end latency improvement

3.  **Explain two distinct hidden runtime overheads—such as dynamic dequantization on unsupported hardware and uncoalesced memory access from unstructured sparsity—that can cause a model with an $8\times$ theoretical compression ratio to exhibit virtually no wall-clock speedup when deployed in production.**

    *Answer*: One hidden cost is conversion overhead: if an exported graph crosses unsupported low-precision boundaries, the runtime may insert extra quantize or dequantize work and additional launches, increasing traffic and synchronization instead of reducing them. A fused weight-only path may still save weight traffic, so the real question is what the deployed operator path actually does. A second cost is sparse-execution overhead: unstructured sparsity can require metadata, irregular memory access, and weak cache or SIMD utilization. The practical consequence is that theoretical compression must be validated against the actual exported kernel path, not inferred from bytes or nonzeros alone.

    *Learning Objective*: Analyze how conversion overhead and irregular sparse execution can erase theoretical compression gains in deployment
