# V1-05.04 Neural Network Fundamentals

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05 Neural Computation|V1-05 Neural Computation]]

^sec-neural-computation-neural-network-fundamentals-07e4

Each of the 109,184 MACs that classify a single digit belongs to some neuron combining its inputs. Individually those operations are trivial. At network scale, a processor spends more time waiting for operands than computing whenever its memory system cannot supply them fast enough. An accelerator such as a graphics processing unit (GPU) outruns a CPU on suitable neural workloads because it devotes silicon to wide arithmetic arrays and high-bandwidth memory rather than to branch prediction. The structure of the network primitives determines how data flows through that hardware and how memory demands scale during training and inference.

Those primitives (weighted sums, nonlinear activations, and gradient-based learning) anchor the feed-forward networks of this chapter and recur inside the larger architectures that later chapters introduce, which add operators and execution patterns this simple model does not contain. In all of them, many simple units operate simultaneously on shared inputs, weights change during training, and layers compose low-level features into high-level ones. Parallelism and the memory wall, the pressures traced through the paradigm comparison, follow from that structure, which begins with the artificial neuron.[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn4|⁴]] The neuron is to a neural network what the transistor is to a processor.

### One Neuron

^sec-neural-computation-artificial-neuron-computing-primitive-45b4

To test whether a $28{\times}28$ image contains a particular stroke, a single computing unit must weigh all 784 pixel intensities, sum the evidence, and decide how strongly to fire. That basic unit of neural computation, the **artificial neuron** (or node), began as a simplified mathematical model of nervous activity ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-mcculloch1943|McCulloch and Pitts 1943]]) before digital implementations turned it into a standard arithmetic primitive.

[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-bio-nn2ai-nn|Figure 4]] sets the biological cell and its mathematical counterpart side by side. The left panel draws a biological cell, with branching dendrites that receive signals, a cell body that holds the nucleus, and an axon that carries the output away. The right panel draws the mathematical model. Its inputs ${x}_1$, ${x}_2$, and onward, plus a constant input of one that carries the bias, flow along weighted edges into a node. The node first forms a linear sum ${z}$ and then applies an activation function ${f}$ to emit the output ${y}$. The column of labels between the panels pairs each biological structure with its arithmetic counterpart: dendrites with inputs, synapses with weights, the soma (cell body) with the linear sum, and axon firing with the activation.

![[90 Assets/Volume I/05 Nn Computation/Generated Figure adbc7932ec.svg]]

Figure 4: **Biological-to-Artificial Neuron Mapping**: Each biological structure on the left has an arithmetic counterpart on the right. Read the mapping as an abstraction rather than a resemblance claim, since it keeps only what reduces to arithmetic and discards the electrochemistry that produced the behavior.

^fig-bio-nn2ai-nn

Read from left to right, the right panel of [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-bio-nn2ai-nn|figure 4]] carries one signal through four stages, and each stage takes its name from one label pair in the column between the panels:

1.  **Input Reception** (Dendrites → ${x}_1, {x}_2, \dots, {x}_n$): The column of circles on the left of the panel is the vector of input features ${\mathbf{x}}$ that the artificial neuron receives. In MNIST digit recognition, these represent pixel intensities. The dendrite analogy captures reception of many signals without claiming biological equivalence.
2.  **Weighted Modulation** (Synapses → ${w}_1, {w}_2, \dots, {w}_n$): Each input is multiplied by a learnable weight ${w}_i$, just as synaptic strengths modulate biological signals. These weights act as “gain” controls, determining how much influence each feature has on the final decision. A bias term ${b}$ (shown as the top input ${x}_0 = 1$ in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-bio-nn2ai-nn|figure 4]]) shifts the activation threshold. Across a network, learned behavior is distributed over many such parameters rather than stored in one weight.
3.  **Signal Aggregation** (Cell Body → Linear Function ${z}$): The left half of the split node, labeled ${z}$, integrates the weighted signals, producing a single scalar value ${z}= \sum ({x}_i \cdot {w}_i) + {b}$. This mirrors how a biological cell body sums incoming electrochemical signals to determine whether the neuron has received enough evidence for a particular pattern.
4.  **Nonlinear Activation** (Axon → Activation Function ${f}$): In the right half of the node, labeled ${f}$, the aggregated signal passes through an activation function ${f}({z})$ and leaves along the output arrow, producing the activation output ${a}= {f}({z})$, the same quantity the figure labels as the output ${y}$. This mirrors the axon’s all-or-nothing firing decision, since the nonlinearity determines whether the neuron “fires” a signal to the next layer. Unlike the biological case, ${f}$ can produce graded outputs (ReLU, for example, passes positive values through and zeroes negatives), but the principle of thresholding followed by propagation is the same.

For the machine, one neuron costs ${d_{\text{in}}}$ MAC[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn5|⁵]] operations. A direct scalar evaluation loads ${d_{\text{in}}}$ inputs, ${d_{\text{in}}}$ weights, and a bias before writing one output, so without reuse it moves about two values per MAC. A *kernel* is the compiled routine the hardware runs for one operation on whole tensors, such as one layer’s matrix product. Kernels that process a whole batch of examples at once, or that work through the matrices in small tiles held in fast on-chip memory, reuse inputs and weights across many neuron evaluations and cut that traffic per MAC, which is why performance at network scale depends on how well the implementation reuses data as much as on how many operations it performs.

Once neurons are composed into a network, three constraints appear that a single unit hides. Inside any one layer, neurons can evaluate in parallel, yet moving their parameters and activations across memory often limits throughput before arithmetic capacity runs out. Across layers, layer ${\ell}+1$ cannot start until layer ${\ell}$ finishes, placing a sequential floor under end-to-end latency. Numerical precision cuts across both limits, because narrower formats move fewer bytes and run on denser arithmetic units, provided task quality survives the search for minimum viable precision that **[[01 Books/Volume I - Foundations/03 Optimization/10 Model Compression/V1-10 Model Compression#^sec-model-compression|Model Compression]]** develops. The perceptron formalization in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^sec-neural-computation-perceptron-weighted-sum-9b3e|section 5.3.2.1]] turns the four stages into the equations that this accounting counts.

### From Neurons to Layers

^sec-neural-computation-network-architecture-fundamentals-1f58

A single artificial neuron can only score one weighted combination of its inputs, so recognizing handwritten digits requires composing hundreds of units into layers whose collective activation choices fix the computational workload. In the running network of Example [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.02 From Logic to Arithmetic#^exmp-nn-computation-running-example-mnist-digit-recognition|5.1]], every unit in a layer runs the same scalar inner product and then applies the nonlinear activation chosen for that layer.

#### The Perceptron’s Weighted Sum

^sec-neural-computation-perceptron-weighted-sum-9b3e

In the first hidden layer of the MNIST network, a single unit combines all 784 pixel intensities into one score that responds to a learned stroke pattern, such as a vertical edge shared by “one” and “seven.” That unit is the **perceptron**,[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn6|⁶]] which Rosenblatt introduced as a trainable form of the artificial neuron ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-rosenblatt1958|Rosenblatt 1958]]). Inside one unit ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-perceptron|figure 5]]), input features ${x}_i$ travel along weighted channels ${w_{ij}}$ and accumulate into a scalar sum with bias ${b}_j$, and the resulting linear score ${z}_j$ passes through an activation ${f}$ to produce output ${\hat{y}}$. Repeating that calculation across 128 units with different learned weights lets the first layer test 128 candidate stroke patterns against the same image in parallel.

![[90 Assets/Volume I/05 Nn Computation/Generated Figure 7781615c19.svg]]

Figure 5: **Perceptron Architecture**: Inputs enter on the left, each scaled by its own weight, and the weighted products plus a bias meet at the summation node before a single activation function produces the output. The multiplies and the accumulation along this path are the per-neuron unit of work that the chapter’s layer-cost calculations multiply out.

^fig-perceptron

Each input ${x}_i$ has a corresponding weight ${w_{ij}}$, and the perceptron multiplies each input by its matching weight. The intermediate output, ${z}_j$, is computed as the weighted sum of inputs in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-weighted-sum|equation 1]]:

$$
{z}_j = \sum_i ({x}_i \cdot {w_{ij}}) \tag{1}
$$

^eq-weighted-sum

Here, ${j}$ identifies the receiving neuron once perceptrons are assembled into a layer, and the sum runs over all input indices ${i}$. In plain terms, each input feature is scaled by how important it is (its weight), and the results are summed into a single score. This is the **dot product** of two vectors.

A bias term ${b}_j$ shifts the linear output up or down, giving the model additional flexibility to fit the data. Thus, the intermediate linear combination computed by the perceptron including the bias becomes [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-weighted-sum-bias|equation 2]]:

$$
{z}_j = \sum_i ({x}_i \cdot {w_{ij}}) + {b}_j \tag{2}
$$

^eq-weighted-sum-bias

The formalization turns the neuron’s cost into a layer’s. A dense layer of ${d_{\text{out}}}$ neurons repeats the weighted sum ${d_{\text{out}}}$ times, so its arithmetic cost is ${d_{\text{in}}} \times {d_{\text{out}}}$ MACs. Placing each neuron’s weights side by side as the columns of one weight matrix ${\mathbf{W}}$ turns those weighted sums into the single matrix multiplication ${\mathbf{x}}{\mathbf{W}}$ that hardware must execute, and that product is the form in which the rest of this chapter counts work. The dot product is the operation that accelerators are built to execute at maximum throughput, which is why neural network performance is quoted in MACs or FLOPs completed per second. How those machines are organized around it is developed in **[[01 Books/Volume I - Foundations/03 Optimization/11 Hardware Acceleration/V1-11.04 Compute Primitives#^sec-hardware-acceleration-matrix-operations-neural-networks-527a|Matrix operations in neural networks]]**. A weighted sum alone, however, can only draw straight boundaries, and the activation applied to it decides what the layer can represent.

#### Nonlinear Activation Functions

^sec-neural-computation-nonlinear-activation-functions-38bc

Without a nonlinearity between layers, a stack of linear weight matrices collapses into a single linear transformation, because multiplying two weight matrices yields just one more weight matrix. Such a stack can only draw straight decision boundaries, no matter how many intermediate matrices the machine evaluates. **Activation functions** break that collapse by converting each neuron’s linear weighted sum into a nonlinear output, making them the point where expressiveness, gradient flow, and hardware cost meet. Applying an activation ${f}$ to the weighted sum of [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-weighted-sum-bias|equation 2]] yields the generic artificial-neuron computation in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-perceptron|equation 3]]:

$$
{\hat{y}}_j = {f}({z}_j) = {f}\left(\sum_i ({x}_i \cdot {w_{ij}}) + {b}_j\right) \tag{3}
$$

^eq-perceptron

In [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-nonlinear|figure 6]], a network without activation functions is constrained to a straight decision boundary (left panel) that misclassifies overlapping point clusters, whereas nonlinear activations allow curved boundaries (right panel) that separate the two classes cleanly. The plot illustrates representational capacity rather than an optimization guarantee; training dynamics and sample coverage still govern whether optimization finds that boundary.

![[90 Assets/Volume I/05 Nn Computation/Generated Figure 83e6082c91.svg]]

Figure 6: **Linear vs. Nonlinear Decision Boundaries**: Two scatter plots compare the decision boundary a network draws on the same points with and without an activation function.

^fig-nonlinear

XOR is the classic function that no single weighted sum can compute, and its four input pairs show why a hidden nonlinear layer changes what a network can represent.

**Example 5.2: Building intuition: The XOR problem**

Consider a network learning the XOR function, a classic problem that requires nonlinearity. With inputs ${x}_1$ and ${x}_2$ that can be 0 or 1, XOR outputs 1 when inputs differ and 0 when they are the same.

**Setup**: Two inputs → two hidden neurons → one output

**Example**: With hidden units ${h}_1 = \text{ReLU}({x}_1 + {x}_2)$ and ${h}_2 = \text{ReLU}({x}_1 + {x}_2 - 1)$, the output ${y}= {h}_1 - 2{h}_2$ gives 0, 1, 1, 0 for inputs $(0,0)$, $(0,1)$, $(1,0)$, $(1,1)$. The input $(1,1)$ drives both hidden units, and the second one cancels the first. No single weighted sum of ${x}_1$ and ${x}_2$ can produce that pattern.

**Systems insight**: Hidden layers do not merely add capacity; they change the class of functions the system can represent. XOR, which no single-layer perceptron can compute ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-minsky1969perceptrons|Minsky and Papert 1969]]), is the small example that makes depth a structural requirement rather than a decorative design choice.

^exmp-nn-computation-building-intuition-xor-problem

The XOR network is the smallest case of a general result. The **universal approximation theorem**[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn7|⁷]] establishes that sufficiently wide networks with suitable activation functions can approximate broad classes of functions arbitrarily well. The theorem, however, states a pure existence result under the assumption of unlimited width; it says nothing about the accelerator executing the computation. Hardware limits both routes to more capacity, one very wide layer or a deep stack of narrower ones. A single hidden layer wide enough to approximate a complex function requires parameter storage and activation memory that can exhaust the accelerator’s device memory (VRAM) entirely, and a very deep network may be unable to hold in that memory the activations it must save for the backward pass. The engineering problem is therefore not whether a network of sufficient width or depth exists, but whether it fits within the memory and bandwidth envelope of the target hardware.

Comparing activation functions requires one idea from training, which [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.05 Learning Process#^sec-neural-computation-learning-process-0b83|section 5.4]] develops fully. Training adjusts each weight by its gradient, the measure of how much the loss would change if that weight moved slightly. That signal travels backward through the network, a pass called *backpropagation*, and is multiplied at each layer by the activation’s slope, so an activation whose slope is near zero passes almost no learning signal to the layers before it.

The choice of activation function therefore affects both learning and computational efficiency. ReLU[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn8|⁸]] ($\max(0, {z})$) became a common hidden-layer activation for feed-forward networks because it is inexpensive, has local derivative one for positive inputs, and can produce sparse activations ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-nair2010rectified|Nair and Hinton 2010]]; [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-glorot2011deep|Glorot et al. 2011]]). Earlier differentiable deep networks often used sigmoid or tanh. Their smooth S-curves saturate, a failure the sigmoid discussion below develops. That contrast is not a simple ranking: sigmoid remains appropriate for some binary outputs, tanh remains useful when bounded zero-centered activations are desired, and modern architectures use additional activation families. The relevant design question is which function supplies the required output semantics and gradient behavior at an acceptable execution cost. [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-activation-functions|Figure 7]] charts the response curves and output ranges of three standard element-wise nonlinearities alongside the vector-level softmax function, contrasting their saturation regimes.

![[90 Assets/Volume I/05 Nn Computation/Generated Figure 68ee73e854.svg]]

Figure 7: **Common Activation Functions**: Four panels plot nonlinear activation functions with their output ranges. Sigmoid maps inputs to $(0,1)$ with smooth gradients, tanh provides zero-centered outputs in $(-1,1)$, and ReLU outputs zero for negative inputs. Softmax (bottom-right) shows one component of a 3-element vector while the other two logits are fixed at 13 and 0. ##### Sigmoid

^sec-neural-computation-sigmoid-a98f

The logistic sigmoid function[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn9|⁹]] squashes continuous inputs onto the open interval $(0,1)$ ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-sigmoid|equation 4]]):

$$
{\sigma}({z}) = \frac{1}{1 + e^{-{z}}} \tag{4}
$$

^eq-sigmoid

The S-shaped curve maps logits, the raw unnormalized scores a layer produces, to $(0,1)$, so sigmoid can parameterize a binary probability. It approaches one for large positive inputs and zero for large negative inputs. Sigmoid is smooth and differentiable everywhere. Gradient-based learning does not require that smoothness; ReLU, introduced below, has a corner at zero, and implementations simply assign it a slope there.

Sigmoid’s main limitation is saturation. For inputs with large absolute values (far from zero), its gradient becomes extremely small, a phenomenon called the **vanishing gradient problem** ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-bengio1994learning|Bengio et al. 1994]]). Even at its peak, sigmoid’s derivative is only 0.25, so each sigmoid layer can shrink the activation-derivative part of the gradient by at least a factor of four. During backpropagation these small activation derivatives multiply with weight-dependent factors across layers, the compounding that the chapter’s opening footnote evaluated over 20 layers. Repeated saturation can make early-layer gradients and weight updates negligibly small, preventing useful learning along those paths.

##### Tanh

^sec-neural-computation-tanh-e981

The hyperbolic tangent[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn10|¹⁰]] centers output activations around zero over the interval $(-1,1)$ ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-tanh|equation 5]]):

$$
\tanh({z}) = \frac{e^{z}- e^{-{z}}}{e^{z}+ e^{-{z}}} \tag{5}
$$

^eq-tanh

Tanh produces an S-shaped curve similar to sigmoid but centered at zero: negative inputs map to negative outputs and positive inputs to positive outputs, a symmetry that balances gradient flow during training and often yields faster convergence than sigmoid. Like sigmoid, tanh is smooth and differentiable everywhere, and it saturates near -1 and 1, so it shares the vanishing gradient problem for inputs with large magnitudes. Even so, its zero-centered outputs usually make it the better of the two S-curves. Both S-curves therefore carry two costs, saturation during training and an exponential evaluation in hardware, whereas ReLU removes saturation for positive inputs and replaces the exponential with a comparison.

##### ReLU

^sec-neural-computation-relu-7184

ReLU sets negative values to zero while maintaining linear identity for positive inputs ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-relu|equation 6]]):

$$
\text{ReLU}({z}) = \max(0, {z}) = \begin{cases} {z}& \text{if } {z}> 0 \\ 0 & \text{if } {z}\leq 0 \end{cases} \tag{6}
$$

^eq-relu

ReLU’s characteristic shape, a straight line for positive inputs and zero for negative inputs, provides three advantages. First, its local derivative is one for positive inputs, avoiding activation saturation on that branch; the complete network gradient can still shrink or grow through weights and other operations. Second, ReLU introduces deterministic activation sparsity by setting negative values to zero. Third, ReLU uses a comparison and selection, `output = (input > 0) ? input : 0`, rather than an exponential approximation. These are local properties of the operator, while end-to-end performance depends on how it is combined with neighboring work.

ReLU is not without drawbacks. The **dying ReLU problem** occurs when neurons become stuck in the inactive state, permanently outputting zero and ceasing to learn. If a neuron’s weights evolve during training such that the preactivation ${z}= {\mathbf{x}}{\mathbf{w}}+ {b}$ is consistently negative across all training examples, the neuron outputs zero for every input. Since ReLU’s gradient is also zero for negative inputs, no gradient flows back through this neuron during backpropagation. The weights cannot update, and the neuron remains dead. This can happen when the learning rate, the step size that scales each weight update, is large enough to push weights into unfavorable regions. Careful initialization ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-he2015|He et al. 2015]]), moderate learning rates, leaky ReLU variants, and normalization layers[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn11|¹¹]] help mitigate dying ReLUs by keeping preactivation distributions well scaled.

##### Softmax

^sec-neural-computation-softmax-ebe5

Unlike *element-wise* activation functions that operate independently on each value, softmax[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn12|¹²]] is a *vector-level* function that considers all values together to produce a probability distribution. In simple classifiers, softmax is commonly used in the output layer rather than as an element-wise hidden activation; it also normalizes learned importance-score vectors in attention architectures. The softmax function is defined in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-softmax|equation 7]]:

$$
\text{softmax}({z}_i) = \frac{e^{{z}_i}}{\sum_{j=1}^{K} e^{{z}_j}} \tag{7}
$$

^eq-softmax

For a vector of ${K}$ values (often called logits[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn13|¹³]]), softmax transforms arbitrary real-valued scores into ${K}$ normalized predicted probabilities that sum to 1, although those values are not necessarily calibrated confidence estimates. As plotted in the bottom-right panel of [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-activation-functions|figure 7]], individual softmax components grow exponentially across logit values while the denominator couples all vector elements so that the class with the largest logit receives the highest probability. Because this mapping from logits to probabilities is differentiable, gradients flow cleanly back through softmax during training, and combining softmax with cross-entropy loss ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.05 Learning Process#^sec-neural-computation-loss-functions-6fc2|section 5.4.3]]) yields simple gradient expressions that guide learning effectively.

Activation choice also carries a silicon cost, a **transistor tax** paid in circuit complexity, area, and switching energy. A ReLU datapath needs only a sign-bit comparator and a multiplexer, roughly 50 transistor equivalents. An exponential approximation for sigmoid or tanh is modeled here as a stylized budget of 2,500 transistor equivalents, 50× the comparator, an order-of-magnitude teaching ratio rather than a constant across manufacturing nodes.

Logic area is only half the cost. An element-wise activation run as its own kernel is limited by memory traffic rather than arithmetic, a gap the forward-pass analysis later quantifies, so compilers fuse it into the preceding matrix multiplication, merging the two into one kernel so that the intermediate values never travel back to main memory.

ReLU’s zeros carry their own memory and work consequences. Because the ReLU derivative is either 0 or 1, evaluating it in the backward pass of training ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.05 Learning Process#^sec-neural-computation-backpropagation-algorithm-steps-6871|section 5.4.5.1]]) takes only one bit per unit from the forward pass, recording whether the unit was active. A dead ReLU unit still occupies weight memory and still costs MACs on every inference while contributing nothing to the output, and ReLU’s zeros save no work in a dense kernel unless sparse hardware or routines exploit them. One neuron is now complete, and the next question is how many of them run side by side.

#### Layers and Connections

^sec-neural-computation-layers-connections-76c3

Neurons run side by side in layers, collections of units that execute in parallel across shared inputs, and the power of neural networks comes from that organization rather than from any single unit. An input layer ingests raw feature tensors; one or more hidden layers transform those representations through successive matrix multiplications and nonlinear activations; and an output layer emits task-specific predictions or decision logits.

In the feedforward schematic of [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-layers|figure 8]], the task fixes only the two ends. The input layer’s width matches the four input features and the output layer’s width matches the two predictions. The hidden layers between them can widen and narrow freely, which is why hidden width is a design decision rather than a property of the data. Each hidden layer applies a parameterized linear transformation followed by an element-wise nonlinearity, progressively constructing higher-level abstractions from raw input signals.

![[90 Assets/Volume I/05 Nn Computation/Generated Figure a0fe778c4e.svg]]

Figure 8: **Layered Network Architecture**: Deep neural networks transform data through successive layers, enabling the extraction of increasingly complex features and patterns. Each layer applies nonlinear transformations to the outputs of the previous layer, ultimately mapping raw inputs to desired outputs.

^fig-layers

As data flows through the network, it is transformed at each layer to extract meaningful patterns. Each layer applies the neuron’s weighted sum and activation in parallel across all its neurons, and its outputs become the next layer’s inputs. Simple features detected in early layers combine into increasingly complex patterns in deeper layers.

On the machine, a layer is one matrix multiplication over all of its neurons at once, and the boundary between layers is where data moves and waits. Each layer writes its output as an activation tensor that the next layer must read. Inference can discard that tensor once the next layer has consumed it, and training must keep it until the backward pass. The next layer cannot start until that tensor exists, which is the source of the latency floor that no amount of parallel hardware inside a layer removes.

[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-neuron-to-machine|Figure 9]] traces the translation from neuron to machine in three steps. One neuron is a dot product of ${d_{\text{in}}}$ MACs. Stacking a layer’s neurons and a batch of ${B}$ examples (inputs processed together in one pass) turns those dot products into one matrix multiply of ${B}\cdot{n_{\ell-1}}\cdot{n_{\ell}}$ MACs, where each neuron’s input width is the previous layer’s width ${n_{\ell-1}}$ and ${n_{\ell}}$ counts the layer’s neurons (for the first MNIST layer at batch 32, $(32{\times}784)\cdot(784{\times}128)$). The hardware executes that multiply by holding a tile of weights in an array of multiply-accumulate units while rows of inputs stream past, so each weight fetched from memory serves every example in the batch.

![[90 Assets/Volume I/05 Nn Computation/Generated Figure 2f7228b752.svg]]

Figure 9: **From Neuron to Machine**: One neuron is a dot product between an input row and a weight column. A layer applied to a batch stacks those dot products into one matrix multiply whose cost is the product of batch size, input width, and output width. On an accelerator, a tile of the weight matrix stays inside an array of multiply-accumulate units while input rows stream through, so the batch, not the neuron, sets how much arithmetic each fetched weight pays for.

^fig-neuron-to-machine

### Parameters

^sec-neural-computation-parameters-connections-27c9

Each of those multiplications reads the layer’s learnable parameters,[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn14|¹⁴]] its weights and biases, alongside the incoming activations. The parameters decide which transformation a layer applies, and their organization fixes both what the network can learn and how many bytes every pass must move.

#### Weight Matrices

^sec-neural-computation-weight-matrices-9f9a

In a dense layer with ${d_{\text{in}}}$ input features and ${d_{\text{out}}}$ neurons, the weights form a matrix ${\mathbf{W}}\in \mathbb{R}^{{d_{\text{in}}} \times {d_{\text{out}}}}$ whose column ${j}$ holds neuron ${j}$’s weights, so the layer computes all ${d_{\text{out}}}$ preactivations as the single product in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-layer-linear|equation 8]]:

$$
{\mathbf{z}}= {\mathbf{x}}{\mathbf{W}}+ {\mathbf{b}} \tag{8}
$$

^eq-layer-linear

The canonical case studied here connects each neuron in a layer to every neuron in the previous layer, forming a “dense” or “fully connected” layer. This pattern allows each neuron to use all features from the previous layer. Fully connected layers establish the mathematical principles needed here, while alternative connectivity patterns exploit structure in the data and can reduce work or improve statistical efficiency.

[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-connections|Figure 10]] details this dense interconnect topology on a concrete two-layer network ($3 \to 4 \to 2$ units). Layer counts in this chapter count layers of weights, not layers of units, so this network has two and the MNIST network ($784 \to 128 \to 64 \to 10$) has three. The figure labels every scalar weight ${w_{ij}}$ and layer bias ${b}_j$ alongside intermediate node activations. Reading the incoming edges for any single destination neuron isolates one column of the weight matrix, while evaluating all destinations in parallel forms the complete matrix-vector multiplication. The numerical values illustrate parameter placement rather than an active inference pass; the essential systems property is the matrix dimension. For layers of widths $({n}_0, {n}_1, {n}_2)$, with ${n}_0$ the input width, the weight matrices span ${\mathbf{W}}^{(1)} \in \mathbb{R}^{{n}_0 \times {n}_1}$ and ${\mathbf{W}}^{(2)} \in \mathbb{R}^{{n}_1 \times {n}_2}$, requiring ${n}_0{n}_1+{n}_1{n}_2$ weights before biases.

![[90 Assets/Volume I/05 Nn Computation/Generated Figure e2a0fe603e.svg]]

Figure 10: **Fully Connected Layers**: A two-layer network (three layers of units) connects every neuron to all neurons in the preceding layer. Labeled edges and nodes illustrate the organization of weights, biases, and activations; they are not a worked numerical forward pass.

^fig-connections

These weight-matrix multiplications account for most of the work in a dense feed-forward network; whether they are compute bound or memory bound depends on their dimensions, batch size, precision, implementation, and target hardware. The layer looks elementary, yet it reappears inside the lighthouse models of later chapters. Every layer of a transformer, the architecture behind language models such as GPT-2, contains a feed-forward block made of dense layers, and the deep learning recommendation model (DLRM) stacks dense layers into towers, so the arithmetic counted here is the arithmetic those models spend. In a GPT-2 layer, which passes vectors of 1,600 values from one layer to the next, the dense feed-forward block holds about 20.5M of the layer’s 30.7M weights, or 67 percent. **[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06 Network Architectures#^sec-network-architectures|Network Architectures]]** develops both architectures in full.

#### Bias Terms

^sec-neural-computation-bias-terms-d450

Alongside its column of weights, each neuron in a layer carries one more parameter, a bias term[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.13 Footnotes#^fn15|¹⁵]]. For a layer with ${d_{\text{out}}}$ neurons, these parameters form a vector ${\mathbf{b}}\in \mathbb{R}^{{d_{\text{out}}}}$ added to the weighted sum in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-layer-linear|equation 8]]: while weights determine the relative importance of inputs, each entry of ${\mathbf{b}}$ shifts its neuron’s activation threshold independently at the cost of one addition per output value. That arithmetic is negligible beside the layer’s matrix multiply.

The organization of weights and biases across a feed-forward network follows a systematic pattern. For each parameterized affine layer ${\ell}$ (a weighted sum plus a bias, a linear map shifted by a constant), three components define its computation; the weights and biases are learned, while the activation function is usually chosen by the designer:

- A weight matrix ${\mathbf{W}}^{({\ell})}$
- A bias vector ${\mathbf{b}}^{({\ell})}$
- An activation function ${f}^{({\ell})}$

This yields the complete layer computation in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-layer-activation|equation 9]]:

$$
{\mathbf{a}}^{({\ell})} = {f}^{({\ell})}({\mathbf{z}}^{({\ell})}) = {f}^{({\ell})}({\mathbf{a}}^{({\ell}-1)}{\mathbf{W}}^{({\ell})} + {\mathbf{b}}^{({\ell})}) \tag{9}
$$

^eq-layer-activation

Here, ${\mathbf{a}}^{({\ell})}$ (written as ${\mathbf{A}}^{({\ell})}$ for batches) represents the layer’s activation output. The row-vector convention is adopted throughout: each sample is a row, and the weight matrix ${\mathbf{W}}^{({\ell})} \in \mathbb{R}^{{n_{\ell-1}} \times {n_{\ell}}}$ maps from the previous layer’s width ${n_{\ell-1}}$, the input width ${d_{\text{in}}}$ of [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-layer-linear|equation 8]], to the current layer’s width ${n_{\ell}}$, its output width ${d_{\text{out}}}$. With [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-layer-activation|equation 9]], one layer is fully specified, and what remains is choosing the layers themselves: how many, how wide, and how connected.

### Choosing a Topology

^sec-neural-computation-architecture-design-523c

A single layer of neurons cannot even compute XOR (Example [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^exmp-nn-computation-building-intuition-xor-problem|5.2]]), yet adding or widening hidden layers to gain capacity immediately multiplies the parameters and activations the machine must store and move. Network topology, how neurons organize into layers and connect across them, fixes both what the network can represent and what it costs to run. The chapter’s MNIST digit recognizer shows how problem structure fixes the input and output dimensions while leaving the hidden layers as a systems design choice.

#### Feedforward Network Architecture

^sec-neural-computation-feedforward-network-architecture-d2cf

For the running MNIST classifier, the data format and task fix the two ends of the three-layer architecture before any hidden-layer design begins. In [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-mnist-topology-1|figure 11]], Panel (a) sets a $28{\times}28$ grayscale image of a “7” beside the input units and ten digit outputs (`0`–`9`), while Panel (b) shows how those 784 pixels flatten into a contiguous one-dimensional column vector before entering the first dense layer. Because a fully connected layer assigns an independent weight to every coordinate of that 784-element vector, flattening discards two-dimensional pixel adjacency altogether. Convolutional architectures instead wire spatial locality directly into the layer. That structural assumption is an *inductive bias* (here, that nearby pixels belong together), which restricts the functions a model can learn toward those suited to images ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-mitchell1980need|Mitchell 1980]]). Making almost no spatial assumption leaves the fully connected network to learn pixel relationships from data alone, at the price of a weight for every input-to-hidden pair.

↪ How spatial locality and weight sharing replace the parameter overhead of fully connected layers is developed as a spatial inductive bias in **[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.04 CNNs Spatial Pattern Processing#^sec-network-architectures-cnns-spatial-pattern-processing-5b8d|CNNs: Spatial Pattern Processing]]**.

Between the fixed 784-unit input layer and the 10-unit logit layer, the number of hidden layers and their widths remain open engineering choices. Adding layers increases depth so that successive transformations can compose simple edges into strokes and digit parts, whereas widening a layer expands how many distinct features the network can represent at the same level of abstraction.

Widening both hidden layers from 100 to 1000 neurons, comparing a $784 \to 100 \to 100 \to 10$ network with a $784 \to 1000 \to 1000 \to 10$ network, increases parameters from ~89.6K to ~1.8M (~358 KB vs. ~7 MB in FP32). Whether the wider network improves accuracy requires training and evaluation; the storage increase alone already matters for mobile deployment budgets.

#### Layer Connectivity Design Patterns

^sec-neural-computation-layer-connectivity-design-patterns-c66e

Widening both hidden layers jumped the parameter count by an order of magnitude because the architecture of [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^sec-neural-computation-parameters-connections-27c9|section 5.3.3]] connects every unit in one layer to every unit in the next. Connectivity itself is an architectural choice: dense, sparse, and skip patterns trade all-to-all flexibility against parameter count, spatial locality, and gradient flow.

In dense connectivity, each unit receives a weight from every unit in the preceding layer, which is why wiring 784 inputs to 128 hidden units requires 100,352 weight parameters ($784{\times}128$) in the first layer alone. All-to-all wiring lets a layer learn arbitrary linear combinations of its inputs (extended to nonlinear relationships by the activations between layers) and maps directly onto the dense matrix-multiplication kernels that hardware accelerators execute best. Because parameter count grows as the product of adjacent layer widths, however, widening one layer scales parameters linearly while widening both scales them quadratically.

Sparse connectivity cuts that parameter growth by restricting each neuron to a subset of the inputs in the adjacent layer, much as biological neurons connect only to nearby cells. In visual processing tasks like MNIST, neurons might connect only to nearby pixels to reflect the local nature of visual features. Although sparse connections reduce theoretical parameter counts and FLOPs, a sparse weight matrix does not automatically execute faster than a dense one on standard hardware. Skipping arbitrary zeros means storing an index with each surviving weight and looking up its input in memory, a step that hardware built for dense blocks performs poorly. Unless the hardware supports a regular, structured sparsity pattern that its kernels can predict (developed in **[[01 Books/Volume I - Foundations/03 Optimization/11 Hardware Acceleration/V1-11.05 Compute Units#^sec-hardware-acceleration-nm-structured-sparsity-mechanics-9a71|N:M structured sparsity mechanics]]**), the arithmetic reduction does not translate into a proportional reduction in execution time.

Whereas sparse connections prune links within a layer, skip connections add direct paths between nonadjacent layers ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-he2016|He et al. 2016]]) to keep deeper networks trainable. A skip connection routes an earlier layer’s activation tensor around one or more intermediate layers and adds it directly to a later layer’s output, which gives the training signal a shorter path back to the early layers. For the machine, that earlier tensor must stay in memory until the later layer has consumed it. **[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.05 Skip Connections and Normalization#^sec-network-architectures-evolution-dense-spatial-processing-2761|Skip connections and gradient flow]]** develops why the shortcut keeps deep networks trainable.

#### Model Size and Computational Complexity

^sec-neural-computation-model-size-computational-complexity-1f0f

Every connectivity choice ends in a parameter count. How parameters (weights and biases) are arranged determines both learning capacity and computational cost. The parameter count, its numerical precision, and the operations it requires are the concrete terms of the model’s side of the silicon contract. Parameter count grows with network width and depth, and [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^tbl-nn-computation-mnist-params|table 5]] lays it out for the running network layer by layer.

| **Layer**             |        **Weights**         | **Biases** | **Parameters** | **MACs per Image** |
|:----------------------|:--------------------------:|:----------:|:--------------:|:------------------:|
| **Input → Hidden1**   | $784{\times}128$ = 100,352 |    128     |    100,480     |      100,352       |
| **Hidden1 → Hidden2** |  $128{\times}64$ = 8,192   |     64     |     8,256      |       8,192        |
| **Hidden2 → Output**  |    $64{\times}10$ = 640    |     10     |      650       |        640         |
| **Total**             |          109,184           |    202     |  **109,386**   |    **109,184**     |

Table 5: **MNIST Parameters and MACs by Layer**: Weight, bias, parameter, and per-image multiply-accumulate counts for the 784-128-64-10 network. A dense layer performs one MAC per weight for each input, so the weight and MAC columns match. Layer 1 (Input → Hidden1) dominates both because it multiplies the 784-dimensional input by 128 hidden units; deeper layers shrink rapidly as the representation compresses toward the 10-class output.

^tbl-nn-computation-mnist-params

The first layer alone holds 100,352 of the 109,184 weights. Because a dense layer performs one multiply-accumulate per weight for each input, the same table also counts the arithmetic per image, and the parameter and MAC columns differ only by the 202 biases. At four bytes per FP32 value, the 109,386 parameters occupy 438 KB. Each must be stored in memory, read on every forward pass, and updated during learning, and the training and inference memory estimates later in this chapter start from this table rather than recounting it. What the table does not yet explain is why the network splits those parameters across three narrower layers instead of placing them in a single wide one.

### Why Depth Matters

^sec-neural-computation-depth-matters-power-hierarchical-representations-f83c

A single-layer network attempting to classify handwritten digits must map all 784 raw pixels directly to ten class labels in one step, relearning every stroke pattern separately for each digit. The running network spreads its weights over three layers instead so that deeper layers can exploit **compositionality**, in which complex patterns decompose into simpler patterns that themselves decompose further. In image recognition, learned representations can progress from local edges and textures toward parts and objects; such hierarchical regularities occur in many datasets and motivate layered models, although a trained network need not recover this exact sequence.

Consider recognizing the digit “seven” in the MNIST example. Rather than mapping all 784 pixel values directly to a decision, a deep network can compute the decision more parameter-efficiently by reusing intermediate features:

- **Layer 1** learns simple edge detectors: vertical lines, horizontal lines, diagonal strokes
- **Layer 2** combines edges into shapes: the horizontal top stroke of a “seven,” the diagonal downstroke
- **Layer 3** combines shapes into complete digit patterns

Each layer builds on the previous, allowing later computations to reuse earlier features. The same edge detectors learned for “seven” can also contribute to recognizing “one,” “four,” and other digits. This **feature reuse** helps explain why depth is an effective design choice without implying a fixed parameter advantage for every task. The choice between adding layers and widening existing ones is not symmetric, however, because depth and width contribute to representational capacity through different mechanisms and cost the machine different things.

**Systems Perspective 5.2: The depth vs. width trade-off**

For certain function classes, depth provides an exponential representational advantage: a network with ${N_L}$ layers can represent functions that require exponentially more units in a shallow network ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.12 Source References#^ref-telgarsky2016benefits|Telgarsky 2016]]). This restricted theoretical result explains why nonlinear composition can be parameter-efficient; it is not a universal guarantee for every task.

Modern architectures balance depth against width. A network with 10 layers of 100 neurons has the same 1,000 total hidden units as one with 2 layers of 500, but not the same parameter count, function class, or execution graph. Both expose parallelism within each layer; the deeper network adds sequential dependencies and may represent some compositional functions more efficiently.

The cost side of that trade-off follows from counting. For a fully connected network with layer widths running from ${n}_0$ (the input) to ${n_{N_L}}$ (the output), each layer ${\ell}$ holds a ${n_{\ell-1}}{\times}{n_{\ell}}$ weight matrix and ${n_{\ell}}$ biases, and its forward pass performs one MAC per weight for every example. Training must also retain each layer’s output for every example in a batch of ${B}$, because the backward pass reuses those outputs ([[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.05 Learning Process#^sec-neural-computation-backpropagation-algorithm-steps-6871|section 5.4.5.1]]), so the parameter count ${P}$, the forward operations per example ${O}$ (two FLOPs per MAC), and the retained activation memory ${M_{\text{activations}}}$ follow [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^eq-depth-width-cost|equation 10]]:

$$
{P} = \sum_{{\ell}=1}^{{N_L}} ({n_{\ell-1}} + 1)\,{n_{\ell}}, \qquad {O} = 2\sum_{{\ell}=1}^{{N_L}} {n_{\ell-1}}\,{n_{\ell}}, \qquad {M_{\text{activations}}} \propto {B} \sum_{{\ell}=1}^{{N_L}} {n_{\ell}} \tag{10}
$$

^eq-depth-width-cost

When every hidden layer has the same width ${d}$, the sums collapse. Parameters and operations grow as ${N_L}{d}^2$, linear in depth and quadratic in width, while retained activations grow as ${B}{N_L}{d}$, linear in both. [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.04 Neural Network Fundamentals#^fig-depth-width-scaling|Figure 12]] plots the two sweeps on the running network’s input and output widths. Holding the network at two hidden layers and doubling their width from 2,048 to 4,096 multiplies MACs per example by 3.4×, short of four only because the input layer’s share still grows linearly. Holding the width at 512 and doubling depth from 16 to 32 hidden layers multiplies MACs by 2.0× and retained activations by 1.9×.

![[90 Assets/Volume I/05 Nn Computation/Depth Width Scaling Plot Output 1 b555ba08dd.png]]

Figure 12: **Width Costs Quadratically, Depth Costs Linearly**: Forward multiply-accumulate operations (MACs) per example for fully connected networks on the MNIST input (784) and output (10) widths. Left: two hidden layers whose shared width sweeps from 64 to 4,096 on log-log axes; once the hidden-to-hidden matrix dominates, the curve follows the dashed slope-two guide, and the running 784-128-64-10 network sits near the narrow end. Right: hidden width fixed at 512 while depth sweeps from 1 to 32 hidden layers; MACs per example (left axis) and activations retained per example for training (right axis) both rise in a straight line.

^fig-depth-width-scaling

Depth and width add capacity on different terms. Depth adds capacity at linear cost in parameters, operations, and activation memory. Every added layer is also another step that must finish before the next begins. Depth therefore raises the latency floor of a single example, lengthens the list of activations that training must hold until the backward pass, and lengthens the path a gradient must survive on its way back to the first layer. Width adds capacity at quadratic cost in parameters and operations (activation memory still grows only linearly). All of that added work lands inside one matrix multiplication whose rows and columns can be spread across parallel hardware, so a wider layer keeps an accelerator busy without adding a sequential step. Choosing between them is therefore a choice between paying in serialized steps and memory or paying in arithmetic. The batch size ${B}$, which multiplies only the activation term, decides how heavily the memory side weighs during training.

Network architecture, neurons, and parameters are now in place, but nothing yet explains how randomly initialized parameters become useful.
