# V1-05.10 Summary

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05 Neural Computation|V1-05 Neural Computation]]

^sec-neural-computation-summary-f263

Neural computation turns layer equations into physical work on a processor. Linear algebra and calculus determine operation cost under the iron law of ML systems (${T} = \frac{{D_{\text{vol}}}}{{\text{BW}}} + \frac{{O}}{{R_{\text{peak}}} \cdot {\eta_{\text{hw}}}} + {L_{\text{lat}}}$). Forward propagation establishes the computational work ${O}$, often dominated by matrix multiplications, while the complete training step adds backward computation and optimizer updates. Backpropagation needs saved or recomputed forward values and gradient storage; the optimizer may add persistent state. Architecture, batch size, precision, optimizer, and recomputation strategy determine the state footprint. Residency, reuse, and execution then determine the bytes transferred, ${D_{\text{vol}}}$, which need not equal that footprint. These mechanics make memory footprints, arithmetic intensities, and latency limits estimable before deployment. [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.02 From Logic to Arithmetic#^tbl-nn-computation-stage-costs|Table 1]], from the chapter’s opening, now reads as a summary of where each stage spends its operations, bytes, and overhead, and every row has been derived for the running network.

Replacing hand-written decision rules with parameters learned from data turns feature engineering into matrix arithmetic. Layered compositions of weighted sums, nonlinear activations, and gradient updates form hierarchical representations that convert raw inputs into predictions. Training adjusts connection weights through iterative optimization, while inference applies fixed parameters to incoming data. The two phases make different demands on the machine. In this chapter’s FP32 estimate, a batch-32 training step requires ~3.4× the memory of batch-32 inference because training retains saved activations and gradients alongside the optimizer’s additional buffers. In production, as the document-recognition case study demonstrated, these mathematical kernels do not run in isolation; preprocessing, neural inference, rejection, and postprocessing must jointly satisfy a single end-to-end latency and reliability budget.

**Key Takeaways: The math behind the model**

- **Each paradigm shift changes the systems cost of representation**: In this $28{\times}28$ digit example, the operation count rises from ~100 comparisons (rule-based) through ~8,000 operations (classical ML) to 109,184 MACs (deep learning), a 1,100× scenario increase that reshapes hardware requirements.
- **Layer shapes fix cost before code runs**: A network composes matrix products with element-wise activations, so widths set parameters, operations, and retained activations, and width costs quadratically while depth costs linearly but adds sequential steps. Matrix kernels exceed 99 percent of FLOPs in the running network, so specialized matrix hardware can substantially outperform general-purpose execution.
- **Batching raises intensity by reusing weights**: A batched dense layer is a matrix-matrix product in which one read of each weight serves every example, raising the running network’s arithmetic intensity from ~0.5 FLOP/byte at batch 1 to ~11.9 FLOP/byte at batch 32. Memory bandwidth can still limit the workload at that higher intensity.
- **The loss is cheap but seeds every update**: Cross-entropy costs a few operations per class score, yet its gradient, the predicted probability minus the target, is the error signal from which every gradient update descends. What the system must protect is the loss’s numerical range, which is why runtimes fuse softmax with cross-entropy.
- **Backpropagation needs the path**: Solving credit assignment requires retaining or recomputing the values used by the backward pass, so memory cost often determines whether a model can be trained on a given device and motivates techniques that reduce, recompute, or partition training state.
- **Training holds four kinds of state**: Training keeps weights, gradients, optimizer state, and saved activations, while inference keeps only the weights and the largest adjacent pair of activation buffers. A larger batch leaves the first three fixed and multiplies the saved activations, so batch size decides which term limits training memory.
- **The complete ML pipeline determines end-to-end performance**: Preprocessing, neural computation, and postprocessing all contribute to latency and reliability. The document-recognition examples demonstrated that production success depends on the entire pipeline operating within real-world constraints, not on model accuracy on a test set alone.

The escalation from hand-written rules to learned features is the algorithm axis of the D·A·M taxonomy made concrete. Learning representations instead of writing them spends arithmetic and memory in place of human design effort, and every systems dimension in [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.03 Computing with Patterns#^tbl-evolution|table 2]] shifts as a result. The bitter lesson predicts that this exchange wins once computation is cheap enough to afford it, but making the exchange still requires a measured gain that justifies its cost on the intended machine.

The multilayer perceptrons analyzed in this chapter expose a direct resource law, in which dense connectivity forces both parameter storage and multiply-accumulate count to scale with the product of adjacent layer dimensions. That dense connectivity contains no explicit prior for spatial locality, so the model must learn from data which nearby and distant pixel relationships matter, while paying memory bandwidth and storage to evaluate every connection.

Reading the code reveals what a network is asked to do; reading the math reveals what it will cost to execute. That arithmetic is where the algorithm meets the machine: weights must be stored and transferred, dense layers map to matrix execution engines, and saved activations claim accelerator memory that determines whether training fits on device. Under the silicon contract (principle [[01 Books/Volume I - Foundations/02 Development/V1 Development Principles#^pri-silicon-contract|4]]), the math commits in advance to operations the machine must execute. Auditing that contract allows systems engineers to calculate bottlenecks from first principles before profiling confirms where the execution stalls.

**What’s Next: From universal to specialized**

Real-world data is rarely structureless. Images have spatial locality, text contains sequential dependencies, and audio signals follow temporal patterns, yet a fully connected layer charges memory volume ${D_{\text{vol}}}$ and compute work ${O}$ for every connection regardless. **[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06 Network Architectures#^sec-network-architectures|Network Architectures]]** assembles the same weighted sums, activations, and gradients into architectures shaped like their data, from convolutional and recurrent networks to transformers and embedding-heavy recommenders, each encoding its structural assumption as an inductive bias. Tailoring network topology to data structure reduces redundant data movement and improves weight reuse, but introduces new trade-offs in activation storage, arithmetic intensity, and accelerator parallelization.
