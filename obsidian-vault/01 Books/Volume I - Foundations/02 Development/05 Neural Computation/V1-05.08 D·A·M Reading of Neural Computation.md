# V1-05.08 D·A·M Reading of Neural Computation

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05 Neural Computation|V1-05 Neural Computation]]

^sec-neural-computation-deep-learning-ai-triad-09cb

In the D·A·M taxonomy, each axis fixes one of the running network’s headline numbers, and the data axis fixed the largest weight matrix before any design choice was made. A $28{\times}28$ image flattens to 784 inputs, so the first layer holds 100,352 weights and performs 91.9 percent of the network’s arithmetic. The same digits scanned at $56{\times}56$ would quadruple that matrix to 401,408 weights without changing the model’s depth or the task. Data also decides whether those weights are worth learning. USPS ZIP images, MNIST digits, and check images share digit semantics but come from different scanners, thresholds, and layouts, and no preprocessing step can synthesize handwriting styles that the training set never contained.

The algorithm axis set how that matrix meets the machine. Batch size is an algorithmic choice, and it moved the forward pass’s arithmetic intensity from about 0.5 FLOP/byte at batch 1 to about 11.9 FLOP/byte at batch 32, because one read of each weight now serves 32 images. The same choice multiplied the activations that training must keep, which is why training holds 3.4× the memory of inference at matched batch size.

The machine axis decided whether learning survives at all. A gradient smaller than its format’s smallest normal value, $6.10 \times 10^{-5}$ in FP16 against $1.18 \times 10^{-38}$ in FP32, loses precision or flushes to zero and stops updating its weight, and a value beyond the format’s maximum overflows to `Inf`. Narrower formats halve or quarter memory traffic and unlock faster matrix units, but only while gradients and activations still fit the format’s range.

No axis can be tuned alone. A larger input improves fidelity but grows the first weight matrix, a larger batch improves reuse but grows training memory, and a narrower format speeds the machine but endangers the gradients. Diagnosing an accuracy shortfall, a latency violation, or an out-of-memory fault therefore starts with a hypothesis on each axis and ends with a measurement of the quantity that sets the limit. An intervention on one axis routinely moves the limiting constraint to another. Teams that skip that measurement tend to fall into a small set of recurring traps.

↪ Screening heuristics that narrow these competing hypotheses, each confirmed against profiler traces and hardware counters, are collected for reference in **[[05 Reference/Volume I - Foundations/V1 The D·A·M Taxonomy#^sec-appdx-dam-taxonomy-rules-thumb-f94f|Screening rules of thumb]]**.
