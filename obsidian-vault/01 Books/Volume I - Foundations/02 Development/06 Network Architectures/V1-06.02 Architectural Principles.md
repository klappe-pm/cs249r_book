# V1-06.02 Architectural Principles

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06 Network Architectures|V1-06 Network Architectures]]

^sec-network-architectures-architectural-principles-engineering-tradeoffs-362e

Three requests reach the same accelerator: a camera frame for an image classifier, a prompt for a language model, and a click for a recommender. The silicon is identical, yet the first request keeps the arithmetic units busy, the second leaves them waiting on memory bandwidth, and the third cannot begin until the system decides where its multi-gigabyte embedding tables can live. What differs is the network architecture: how each model arranges the same arithmetic around the structure of its data.

**[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05 Neural Computation#^sec-neural-computation|Neural Computation]]** built the operations that every network shares (matrix multiplication, activation functions, and gradient computation) and assembled them into a dense multilayer perceptron (MLP) that pays for a weight between every pixel and every hidden unit, including relationships an image rarely needs. Images have spatial locality, language has sequential dependencies, and tabular records often lack a fixed spatial or sequential organization. Architectures remove dense waste by arranging those shared operations into computational graphs shaped like the data. The structural assumptions that each architecture encodes are its **inductive biases**,[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn1|¹]] and each family in this chapter is defined by the bias it chooses.

**Definition 6.1: Inductive bias**

***Inductive bias*** is a structural constraint built into a model architecture that restricts the hypothesis space, enabling generalization from finite data by encoding domain-specific assumptions (such as spatial locality or sequential ordering) directly into the computational graph.

1.  **Significance**: Inductive bias can reduce the dataset size $({D})$ required for generalization. A detector that looks for a small pattern, such as an edge, can either give every pixel of the image its own weight or apply one small set of weights at every position. For a $224{\times}224$ RGB image, a shared $3{\times}3$ filter uses roughly 5,575× fewer parameters than one dense feature detector, reducing parameter storage and often the data required to avoid overfitting.
2.  **Distinction**: Unlike regularization (which penalizes hypothesis complexity at training time via L1/L2 terms), inductive bias restricts the hypothesis space at architecture design time, before any training begins.
3.  **Common pitfall**: A frequent misconception is that stronger inductive bias is always better. A strong locality bias (CNN) excels on spatial data but represents long-range dependencies in language less directly than global attention.

![[90 Assets/Volume I/06 Nn Architectures/Nn Architectures Inductive Bias b17ea2dc1d.svg]]

*Vertical ordinal axis with arrowheads at both ends, labeled Strong prior, less data at the top and Weak prior, more data at the bottom. Three dots sit on the axis from dark to light: CNN near the top, Transformer in the middle, MLP near the bottom.*

*A stronger prior substitutes engineered structure for data and compute.*

A convolutional neural network (CNN) encodes an inductive bias of spatial locality, assuming nearby pixels matter more than distant ones, whereas a transformer lets each element attend to any other at quadratic score-computation cost. Restricting the space of functions a model can represent lets it learn with less data and compute; relaxing those priors assumes that data and compute will grow large enough to compensate, which is the bitter lesson seen from inside a single architecture.

↩︎ The bitter lesson, that general methods which scale with computation outpace hand-built structure, is established in **[[01 Books/Volume I - Foundations/00 Introduction/01 Introduction/V1-01.05 The Bitter Lesson#^sec-introduction-bitter-lesson-79c7|The Bitter Lesson]]**.

That exchange sets up a core engineering trade-off between **representational power vs. computational efficiency**. Under the iron law of ML systems (principle [[01 Books/Volume I - Foundations/02 Development/V1 Development Principles#^pri-iron-law|3]]), architectural choice is the primary determinant of the algorithmic work per sample ($\text{FLOPs/Sample}$), and thus of the operation-count term ${O}$. Global attention buys long-range connectivity at quadratic score cost, while spatial locality keeps a CNN’s operations linear in the number of spatial positions. Architecture selection means matching the bias to the data while staying inside an operation budget, an ordering that [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.10 Comparing and Choosing Architectures#^sec-network-architectures-architecture-selection-framework-a442|section 6.9]] turns into a selection procedure.

Under the silicon contract (principle [[01 Books/Volume I - Foundations/02 Development/V1 Development Principles#^pri-silicon-contract|4]]), an architecture’s computational graph is also an implicit agreement with hardware, which makes architecture selection a systems engineering problem. Choosing an architectural backbone sets the primary memory layout and compute pattern for downstream hardware. [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.02 Architectural Principles#^tbl-architecture-families|Table 1]] contrasts the five major neural network families across the data structure each targets, its core innovation, and the system bottleneck it exposes in representative regimes.

| **Architecture** | **Data Type**                 | **Core Innovation**            | **System Bottleneck**                             |
|:-----------------|:------------------------------|:-------------------------------|:--------------------------------------------------|
| **MLPs**         | Tabular/Unstructured          | Dense connectivity             | Bandwidth with streamed weights at small batch    |
| **CNNs**         | Spatial (images)              | Local filters + weight sharing | Compute throughput with sufficient reuse          |
| **RNNs**         | Sequential (time series)      | Recurrent state                | Sequential dependencies                           |
| **Transformers** | Relational (language)         | Dynamic attention              | Quadratic score compute; optional ${S}^2$ storage |
| **DLRM**         | Categorical (recommendations) | Embedding tables               | Capacity when tables exceed device memory         |

Table 1: **Neural Architecture Families**: Each family targets a data structure and exposes characteristic resource demands. The bottleneck column names representative regimes: streamed dense weights stress bandwidth, convolutional reuse raises arithmetic intensity, recurrence creates serial dependencies, dense attention computes quadratic score interactions, and large embedding tables stress capacity. Batch size, precision, kernel implementation, and the target machine determine which demand sets the limit in a deployment.

^tbl-architecture-families

The five lighthouse models introduced with the iron law return here with their architectures exposed: ResNet-50 for compute throughput, GPT-2 for memory bandwidth, the Deep Learning Recommendation Model (DLRM) for memory capacity, MobileNetV2 for compute within a mobile power envelope, and keyword spotting (KWS) for an always-on power envelope. Earlier chapters used them as named workloads and mapped them onto workload archetypes (**[[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.04 Analyzing Workloads#^sec-ml-systems-workload-archetypes-fd10|Workload archetypes]]**), such as the compute-bound and bandwidth-bound archetypes. This chapter opens each one up inside the family that builds it, to show which architectural choice puts it in its archetype.

MobileNetV2 sits on the empirical Pareto frontier plotted in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.02 Architectural Principles#^fig-efficiency-frontier|figure 1]], the set of models that no other plotted model beats on both accuracy and compute at once, while ResNet-50 sits well below it. The frontier bounds ImageNet[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn2|²]] top-1 accuracy against logarithmic compute cost, measured in GMACs (billions of multiply-accumulate operations) per image. The other three lighthouses sit off this plot because they were chosen for the bottlenecks they isolate rather than for image-classification accuracy.

↩︎ The five lighthouse models, and the bottleneck each one isolates, are established in **[[01 Books/Volume I - Foundations/00 Introduction/01 Introduction/V1-01.08 Iron Law of ML Systems#^sec-introduction-lighthouse-models-9b1c|Lighthouse models put the iron law into practice]]**.

^fig-efficiency-frontier

Across the frontier plotted in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.02 Architectural Principles#^fig-efficiency-frontier|figure 1]], successive architecture families occupy distinct computational cost regimes, from dense CNNs that prioritized accuracy regardless of operation count, through compact mobile networks engineered to minimize GMACs, to vision transformers, which apply the attention mechanism developed later in this chapter to images and spend more compute on each one. The plotted models are historical milestones rather than case studies; only ResNet-50 and MobileNetV2 receive detailed architectural breakdowns in this chapter. Architectural choices made at design time dictate where a system lands along this frontier.

Each family section that follows reads its architecture through the same four questions: the data pattern it targets, the computation it performs, how that computation maps onto hardware, and the bottleneck it exposes. The cost answers reduce to the same three counts for every family: the weights it stores, the multiply-accumulates it performs, and the bytes that must move or stay resident. Together these counts form the family’s cost signature, which predicts the iron-law term that dominates.

The sequence begins with the family that assumes the least about its data, the dense multilayer perceptron, then moves through spatial CNNs and the skip connections and normalization that make depth trainable, on to recurrent networks, the attention primitive and the transformers built on it, and sparse recommendation models, before the closing section compares all five families on one machine and turns the comparison into a selection procedure.

**Self-Check: Question**

1.  A team must choose between an MLP and a CNN for classifying $224 \times 224$ pixel RGB medical images. A single dense first layer would require $224 \times 224 \times 3 = 150{,}528$ input weights per output unit (yielding roughly 150 million weights for a 1,000-unit layer), whereas a CNN uses a shared $3 \times 3 \times 3$ filter (27 weights). Using the chapter’s framing of inductive bias, which statement best explains why the CNN is the superior starting point?

    1.  The CNN is strictly more expressive than the MLP, allowing it to approximate non-continuous functions that the Universal Approximation Theorem forbids.
    2.  The MLP is mathematically incapable of representing any 2D spatial feature mapping due to lack of convolutional instruction support.
    3.  The CNN eliminates gradient descent during optimization because convolutional spatial filters are deterministic, handcrafted operators.
    4.  The CNN’s spatial locality and weight-sharing prior directly matches image structure: convolution is translation equivariant, later pooling or aggregation can provide invariance for classification, and each feature detector uses far fewer weights than a dense detector.

2.  Because an inductive bias restricts the hypothesis space to a smaller set of representable functions, machine learning systems engineers should always select the architecture with the strongest possible inductive bias for every workload.

3.  Why does the chapter describe selecting a neural network architecture as ‘signing a contract with physics’ rather than merely selecting a mathematical modeling preference? Explain how architectural graph structure shapes or constrains the terms in the iron law of ML systems ($T_{\text{exec}} = D_{\text{vol}}/\text{BW} + O/(R_{\text{peak}} \cdot \eta_{\text{hw}}) + L_{\text{lat}}$) without making those terms fully fixed.
