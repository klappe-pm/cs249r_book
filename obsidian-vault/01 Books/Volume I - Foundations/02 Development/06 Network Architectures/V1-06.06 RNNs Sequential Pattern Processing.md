# V1-06.06 RNNs Sequential Pattern Processing

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06 Network Architectures|V1-06 Network Architectures]]

^sec-network-architectures-rnns-sequential-pattern-processing-f804

An MLP requires a fixed-width input vector and a CNN sees only a bounded spatial window, so neither can process a continuous audio stream or a sentence of arbitrary length without padding, truncating, or stacking layers until activation memory overflows. Where convolutional networks exploit *spatial* structure, many real-world signals carry *temporal* structure, in which sequential order and prior context determine meaning. Recurrent networks process these variable-length streams within a fixed memory budget by carrying and updating a persistent state vector from one time step to the next.

**Definition 6.4: Recurrent neural networks**

***Recurrent neural networks (RNNs)*** are sequence-processing architectures that maintain a hidden state ${\mathbf{h}}_t = {f}({\mathbf{h}}_{t-1}, {\mathbf{x}}_t)$ updated at each time step, encoding the assumption that the current output depends on all prior inputs through this fixed-size state vector.

1.  **Significance**: The fixed-size state provides $\mathcal{O}(1)$ inference state memory regardless of sequence length (processing a 10,000-token sequence requires the same state memory as a 10-token sequence), but the sequential update rule forces all ${S}$ recurrent transitions to execute in order. Each step runs as its own small accelerator routine (a kernel), and starting each one adds fixed overhead, the iron law’s ${L_{\text{lat}}}$ term; fusing routines reduces those starts but leaves the serial dependency chain in place.
2.  **Distinction**: Unlike MLPs, which require a fixed-dimensional input vector, or CNNs, which restrict context to a fixed spatial window, RNNs compress an unbounded history into a fixed-size bottleneck state, so they accept sequences of any length without widening the input layer. Gradient signals pass back through the recurrent steps, where repeated Jacobian products can attenuate or amplify them (derived below).
3.  **Common pitfall**: A frequent misconception is that RNNs are obsolete. For streaming inference on resource-constrained hardware, such as keyword spotting on a microcontroller, a model that must keep every past input to see the whole stream needs memory that grows with stream length, which can be prohibitive. An RNN’s $\mathcal{O}(1)$ state size makes it a candidate when a fixed state budget is required.

Recurrent architectures, from simple recurrent networks to gated variants such as long short-term memory (LSTM) networks ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-elman1990|Elman 1990]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-hochreiter1997|Hochreiter and Schmidhuber 1997]]), encode a temporal inductive bias in which execution order follows causal time and history compresses into that recurring state. Instead of widening or deepening a window to reach distant tokens, the network reuses one transition operator at every step. That choice trades parallelism for bounded state. It provides variable-length temporal context within a fixed memory footprint, but it introduces loop-carried data dependencies that serialize execution on parallel accelerator hardware.

### Pattern Processing Needs

^sec-network-architectures-pattern-processing-needs-241d

A word like “bank” cannot be disambiguated on its own; “river bank” refers to a shoreline, whereas “investment bank” refers to a financial institution. Only the preceding words resolve which meaning applies. Acoustic waveforms and sensor telemetry behave the same way: a single audio sample or temperature reading is ambiguous without the history that came before it.

Data with this sequential structure imposes three requirements on a model:

1.  **Variable-length inputs**: Sequences arrive with different lengths ${S}$, ruling out a single fixed-width input layer.
2.  **Long-range memory**: The model must carry relevant signals across many time steps without requiring a fixed window size.
3.  **Continuous state updates**: Internal representations must update as each new token arrives, folding in new evidence while dropping stale history.

Meeting all three streaming requirements without growing the model alongside the input length requires turning the feedforward graph into a state machine whose output at step ${t}-1$ feeds step ${t}$.

### Algorithmic Structure

^sec-network-architectures-algorithmic-structure-9dea

To meet the requirements of [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.06 RNNs Sequential Pattern Processing#^sec-network-architectures-pattern-processing-needs-241d|section 6.5.1]], recurrent neural networks introduce directed cycles in their computational graph. Rather than mapping inputs directly to outputs through feedforward layers, an RNN maintains a persistent vector, the **hidden state**, that updates iteratively at each time step. The hidden state is a running summary of the past.

The fundamental state transition in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.06 RNNs Sequential Pattern Processing#^eq-rnn|equation 10]] computes the current hidden state ${\mathbf{h}}_t$ by combining the incoming token vector ${\mathbf{x}}_t$ with the preceding state ${\mathbf{h}}_{t-1}$:

$$
{\mathbf{h}}_t = {\phi}({\mathbf{W}_{\text{hh}}}{\mathbf{h}}_{t-1} + {\mathbf{W}_{\text{hx}}}{\mathbf{x}}_t + {\mathbf{b}_{\text{h}}}) \tag{10}
$$

 where ${\mathbf{h}}_t$ denotes the hidden state at time ${t}$, ${\mathbf{x}}_t$ denotes the input at time ${t}$, ${\mathbf{W}_{\text{hh}}}$ contains the recurrent weights, ${\mathbf{W}_{\text{hx}}}$ contains the input weights, ${\mathbf{b}_{\text{h}}}$ is the hidden-state bias vector, and ${\phi}$ is the activation function. The equation uses column vectors; the later listings use row-major batched tensors, so their weight multiplications appear on the right. Unrolled across time ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.06 RNNs Sequential Pattern Processing#^fig-rnn|figure 8]], right), the loop becomes a chain of transitions ${\mathbf{h}}_{t-1} \to {\mathbf{h}}_t \to {\mathbf{h}}_{t+1}$ in which every link reuses the same recurrent weight matrix ${\mathbf{W}_{\text{hh}}}$, so no step can begin until the one before it has finished.

^eq-rnn

![[90 Assets/Volume I/06 Nn Architectures/Generated Figure 3beea3e6ca.svg]]

Figure 8: **Recurrent Neural Network Unfolding**: The compact recurrent loop (left) unfolds into one copy of the cell per time step (right). Three weight matrices are shared across all steps: ${\mathbf{W}_{\text{hx}}}$ (input-to-hidden), ${\mathbf{W}_{\text{hh}}}$ (hidden-to-hidden), and ${\mathbf{W}_{\text{yh}}}$ (hidden-to-output). These matrices are reused at every step, so the parameter count is independent of sequence length. For a 128-dimensional hidden state and a 100-dimensional input, each time step requires 16,384 MACs for recurrent connections plus 12,800 for input projection.

^fig-rnn

Unfolding the recurrent loop across ${S}$ steps reveals the algorithmic properties of recurrence. Parameter count remains independent of sequence length ${S}$ because the weight matrices ${\mathbf{W}_{\text{hh}}}$ and ${\mathbf{W}_{\text{hx}}}$ are shared across all time steps. However, feeding each state into the next establishes a loop-carried dependency: step ${t}$ cannot evaluate ${\mathbf{h}}_t$ until step ${t}-1$ finishes producing ${\mathbf{h}}_{t-1}$. This dependency forms a critical path of length $\mathcal{O}({S})$ serial operations that prevents hardware accelerators from parallelizing across the sequence dimension.

This sequential structure produces different memory characteristics in inference and in training. During streaming inference, an RNN evaluates one step at a time, discarding prior raw inputs and retaining only the current hidden state. State memory overhead remains strictly $\mathcal{O}({d})$ in the hidden dimension ${d}$, regardless of whether the sequence spans 10 or 10,000 steps. In contrast, training via backpropagation through time (BPTT) ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-werbos1990backpropagation|Werbos 1990]]) unrolls the graph across the entire sequence of length ${S}$. Computing gradients via the chain rule requires evaluating the Jacobian product across all intermediate transitions:

$$
\frac{\partial {\mathcal{L}}}{\partial {\mathbf{h}}_0} = \frac{\partial {\mathcal{L}}}{\partial {\mathbf{h}_{S}}} \prod_{t=1}^{{S}} \frac{\partial {\mathbf{h}}_t}{\partial {\mathbf{h}}_{t-1}}
$$

 Ordinary BPTT retains the intermediate activations ${\mathbf{h}}_1, {\mathbf{h}}_2, \dots, {\mathbf{h}_{S}}$ for these Jacobian products. This retained-state scheme converts an $\mathcal{O}({d})$ runtime state into an $\mathcal{O}({S} \cdot {d})$ training footprint; recomputing saved intermediates trades additional work for memory. Because every factor in the product combines activation derivatives with ${\mathbf{W}_{\text{hh}}}$, the backpropagated signal attenuates or amplifies exponentially over long horizons, preventing a plain RNN from learning dependencies across more than a few dozen time steps unless the recurrence gives the state a selective bypass around ${\mathbf{W}_{\text{hh}}}$.

### Gated Recurrence

^sec-network-architectures-evolution-sequence-processing-d809

Gated recurrent architectures prevent long-horizon gradients from vanishing by replacing the unconditional state overwrite of [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.06 RNNs Sequential Pattern Processing#^eq-rnn|equation 10]] with learned **gates**, elementwise valves that decide at each step how much of the stored state to keep, overwrite, or expose. Each gate applies a sigmoid to a learned projection of the current input and previous state, producing values between zero and one that multiply the quantity it controls. A value near one passes that quantity through, and a value near zero blocks it. LSTMs[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn19|¹⁹]] ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-hochreiter1997|Hochreiter and Schmidhuber 1997]]) maintain a separate cell state beside the hidden state and govern it with input, forget, and output gates plus a candidate update. When the forget gate stays near one, the cell state passes from step to step almost unchanged, giving gradients a path across long horizons without being multiplied by ${\mathbf{W}_{\text{hh}}}$ at every transition. GRUs[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn20|²⁰]] ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-cho2014|Cho et al. 2014]]) merge the same mechanism into two gates.

For the machine, an LSTM step computes four affine transformations of the input and previous state instead of one, so it holds four times the recurrent weights, performs four times the multiply-accumulates per step, and carries twice the state (hidden and cell). Runtimes fuse the four projections into one matrix multiply four times as wide, which raises its arithmetic intensity without shortening the serial chain of steps.

### Computational Mapping

^sec-network-architectures-computational-mapping-701d

In hardware, a recurrent step is two matrix products followed by an elementwise update. Convolution reuses each weight across a grid of positions available all at once ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.04 CNNs Spatial Pattern Processing#^sec-network-architectures-data-movement-36f6|section 6.3.4.3]]); a recurrent step reuses its weights only across time, and each step must wait for the state the previous step produces.

[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.06 RNNs Sequential Pattern Processing#^lst-rnn-layer-step-94881fde|Listing 5]] demonstrates the single-time-step mechanism using framework-level matrix operations: combine the previous hidden state with the current input, add the bias, and apply the activation to produce the next hidden state. The code is intentionally local to one step because the systems cost is not the step itself, but the dependency chain that prevents parallel execution across time.

``` python
def rnn_layer_step(x_t, h_prev, W_hh, W_hx, b):
    # x_t: input at time t (batch_size × input_dim)
    # h_prev: previous hidden state (batch_size × hidden_dim)
    # W_hh: recurrent weights (hidden_dim × hidden_dim)
    # W_hx: input weights (input_dim × hidden_dim)
    h_t = activation(matmul(h_prev, W_hh) + matmul(x_t, W_hx) + b)
    return h_t
```

Listing 5: **RNN Layer Abstraction**: Framework-level implementation combining two matrix multiplications, ${\mathbf{h}}_{t-1}{\mathbf{W}_{\text{hh}}}$ and ${\mathbf{x}}_t{\mathbf{W}_{\text{hx}}}$, per time step. For 128-dimensional hidden state and 100-dimensional input, each step requires 16,384 + 12,800 = 29,184 MACs, but sequential dependencies prevent parallelization across time.

^lst-rnn-layer-step-94881fde

At the framework level, `rnn_layer_step` hides the underlying loop structure and memory traffic behind high-level matrix multiplications (`matmul`). In hardware, evaluating this step requires moving weights and activations through the memory hierarchy. To see where execution serializes and where parallelism remains, [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.06 RNNs Sequential Pattern Processing#^lst-rnn-layer-compute-9c45022e|listing 6]] expands the matrix operations into explicit loop nests down to scalar multiply-accumulate operations.

``` python
def rnn_layer_compute(x_t, h_prev, W_hh, W_hx, b):
    # Initialize next hidden state
    h_t = np.zeros_like(h_prev)

    # Loop 1: Process each sequence in the batch
    for batch in range(batch_size):
        # Loop 2: Compute recurrent contribution (h_prev × W_hh)
        for i in range(hidden_dim):
            for j in range(hidden_dim):
                h_t[batch, i] += h_prev[batch, j] * W_hh[j, i]

        # Loop 3: Compute input contribution (x_t × W_hx)
        for i in range(hidden_dim):
            for j in range(input_dim):
                h_t[batch, i] += x_t[batch, j] * W_hx[j, i]

        # Loop 4: Add bias and apply activation
        for i in range(hidden_dim):
            h_t[batch, i] = activation(h_t[batch, i] + b[i])

    return h_t
```

Listing 6: **RNN Layer Computation**: Nested loops expose the sequential dependency structure. Loop 1 enables batch parallelism, but Loops 2-3 must complete before Loop 4’s activation; because each time step depends on the previous step’s output, the resulting $\mathcal{O}({S})$ sequential depth prevents GPU parallelization across the time dimension.

^lst-rnn-layer-compute-9c45022e

The loop structure exposes the concurrency boundaries of recurrent execution. Batch instances in Loop 1 are independent, so sequences within a batch parallelize across accelerator cores without cross-talk. Within each batch instance, Loops 2 and 3 execute the recurrent transformation (${\mathbf{h}}_{t-1}{\mathbf{W}_{\text{hh}}}$) and input projection (${\mathbf{x}}_t{\mathbf{W}_{\text{hx}}}$). Both reductions must accumulate fully before Loop 4 can apply the elementwise bias addition and activation function to produce ${\mathbf{h}}_t$.

For an input dimension of 100 and a hidden state dimension of 128, each step executes two matrix multiplications: a $100{\times}128$ input projection and a $128{\times}128$ recurrent transformation. When batch size is large (${B}\gg 1$), these operations execute as general matrix-matrix multiplications (GEMM) that reuse each loaded weight across all ${B}$ samples. When batch size is small (${B}=1$, typical of real-time streaming inference), they collapse into the same weight-streaming matrix-vector products as the batch-one dense layer of [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.03 MLPs Dense Pattern Processing#^eq-dense-intensity|equation 2]], which leave accelerator compute units idle.

### System Implications

^sec-network-architectures-system-implications-18c3

The hard physical constraint that recurrent architectures impose is sequential dependency. In the update ${\mathbf{h}}_t = \tanh({\mathbf{W}_{\text{hh}}}{\mathbf{h}}_{t-1} + {\mathbf{W}_{\text{hx}}}{\mathbf{x}}_t)$, the recurrent transformation at time step ${t}$ needs the state produced by step ${t}-1$. An input sequence of length ${S}= 1{,}000$ therefore requires $1{,}000$ ordered state updates, even when a fused kernel executes several or all updates within one launch. Hardware can parallelize across batch instances and within each matrix operation; input projections can also be computed across time when the inputs are available. Faster arithmetic or memory shortens individual steps, while the recurrent dependency chain remains.

During inference, recurrent networks need little state memory. Because the recurrent state compresses history into a fixed-size vector ${\mathbf{h}}_t$, inference state memory scales as $\mathcal{O}({d})$ (for example, 2 KB for a 512-dimensional FP32 state), remaining completely flat whether sequence length ${S}$ is 10 or 10,000 tokens. This constant memory footprint contrasts sharply with attention mechanisms ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-attention-mechanisms-dynamic-pattern-processing-22df|section 6.6]]), whose stored context grows with every token generated, an $\mathcal{O}({S}\cdot {d})$ store that the transformer section sizes. For streaming deployments on memory-constrained edge hardware, such as microcontrollers, an RNN’s $\mathcal{O}(1)$ runtime state avoids the growing context store that limits attention-based models.

Recurrent execution splits the memory hierarchy between two behaviors: high temporal locality for parameters, and low arithmetic intensity under standard framework dispatch. Weight matrices ${\mathbf{W}_{\text{hh}}}$ and ${\mathbf{W}_{\text{hx}}}$ are reused at every time step, residing comfortably in SRAM or L2 cache if the model fits on-chip. However, naively launching separate kernels for input projection, recurrent projection, bias addition, and activation at each time step incurs severe kernel-launch overhead and forces intermediate tensors back and forth across HBM. To mitigate this memory-bandwidth bottleneck, production recurrent runtimes fuse the projections, bias addition, and activation into a single monolithic kernel that maintains ${\mathbf{h}}_t$ in on-chip memory throughout the sequence execution. At batch one, each recurrent step is the dense layer’s matrix-vector product again, with the same energy profile, which is a second reason streaming runtimes keep those weights on chip. A recurrent layer’s cost signature is therefore a dense layer’s counts per step, a small fixed state, and a serial floor of one ordered update per token.

**Checkpoint 6.3: Recurrent state and the serial chain**

Recurrence trades parallelism for a fixed memory budget. Check your understanding:

**Serial chain**: why can a faster accelerator not remove the 1,000 ordered updates of a 1,000-step sequence, and which parts of the work can still run in parallel?

**Fixed state**: why does an RNN’s inference memory stay flat as a stream grows, while training through time stores state for every step?

**Gates**: what does an LSTM step cost the machine compared with a plain recurrent step, and what does fusing its four projections change?

This architectural tension between fixed-capacity state and serialized execution defined sequence processing before transformers. While recurrent networks maintain constant memory overhead regardless of sequence length, the sequential dependency prevents hardware from parallelizing across time steps. The fixed-capacity state also becomes an information bottleneck in which early inputs fade over long spans, and gradients through long chains of recurrent steps vanish or explode (the vanishing gradient problem) ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-bengio1994learning|Bengio et al. 1994]]). Some recent designs, such as the state-space model Mamba ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-gu2023mamba|Gu and Dao 2023]]), return to recurrence for exactly its systems strength, a fixed-size state that does not grow with the length of the input. Overcoming the serial chain and the fading state in general, however, required an architecture capable of establishing direct, content-addressable links across arbitrary sequence positions without intervening recurrent steps: the attention mechanism ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-attention-mechanisms-dynamic-pattern-processing-22df|section 6.6]]).
