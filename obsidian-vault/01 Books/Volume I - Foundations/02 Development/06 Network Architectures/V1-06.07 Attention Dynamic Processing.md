# V1-06.07 Attention Dynamic Processing

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06 Network Architectures|V1-06 Network Architectures]]

^sec-network-architectures-attention-mechanisms-dynamic-pattern-processing-22df

Recurrent networks serialize execution along the sequence dimension and compress all historical context into a fixed-capacity hidden state vector ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.06 RNNs Sequential Pattern Processing#^sec-network-architectures-system-implications-18c3|section 6.5.5]]). In a sentence such as “The cat, which was sitting by the window overlooking the garden, was sleeping,” the subject “cat” and predicate “sleeping” are separated by ten intervening words, yet they form the core syntactic and semantic relationship. An RNN must process all intervening tokens sequentially, risking information loss across intermediate recurrent transitions while preventing hardware from parallelizing across time steps. This constraint motivates an alternative computational pattern: an operation that directly computes relevance between any two positions regardless of distance.

Attention mechanisms[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn21|²¹]] address this limitation ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-bahdanau2015neural|Bahdanau et al. 2015]]) by introducing dynamic connectivity patterns that adapt to input content. The setting was sequence-to-sequence translation, built as an encoder-decoder pair. An encoder network reads the input sentence into one representation per input position, and a decoder network generates the output sentence one token at a time, carrying its own recurrent decoder state. Recurrent versions of that pair passed only the encoder’s final state to the decoder. Rather than forcing all context through that single fixed-capacity vector, encoder-decoder attention computes similarity scores between the decoder state at each output step and all encoder positions, routing information dynamically across the sequence.

Every form of attention makes the same comparison. A query vector describes what one position is looking for, a key vector describes what each position offers, and the score between a query and a key sets how much of that position’s value vector, the information it passes on, flows into the output. A single decoder step compares one query with every encoder position. In full-sequence self-attention, each position queries all positions in the same sequence, so the number of score interactions grows quadratically with sequence length.

**Definition 6.5: Attention mechanisms**

***Attention mechanisms*** are neural network operations that compute a weighted sum of value vectors, where the weights are derived from learned similarity scores between a query vector and a set of key vectors, enabling dynamic, content-dependent information routing between any two positions in a sequence.

1.  **Significance**: Attention connects any two tokens in $\mathcal{O}(1)$ depth but computes ${S}^2$ score interactions. If those scores are materialized, a 4,096-token sequence with 16-bit scores consumes 33.6 MB per layer per head (about 16.8M scores at 2 bytes each), directly increasing the iron law’s ${D_{\text{vol}}}$ term.
2.  **Distinction**: Unlike RNNs, which compress all prior context into a single fixed-size state vector, attention mechanisms retain every token’s representation and compare tokens directly. When a model generates text one token at a time, it keeps the key and value vectors of earlier tokens rather than recomputing them, and that **key-value (KV) cache** grows as $\mathcal{O}({S} {d})$, linearly in sequence length for a fixed model; the transformer section explains generation and sizes the cache.
3.  **Common pitfall**: A frequent misconception is that attention is a general-purpose weighting scheme that can be applied freely. Quadratic score computation is a hard scaling constraint: doubling the context quadruples score interactions. Naive implementations also quadruple score storage; tiled exact algorithms such as FlashAttention avoid the full matrix, while sparse variants reduce the scores computed ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-child2019generating|Child et al. 2019]]).

The ability of attention to connect any position to any other made the recurrent structure unnecessary for many sequence tasks. The transformer[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn22|²²]] ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-vaswani2017|Vaswani et al. 2017]]) removed recurrence entirely, trading the RNN’s $\mathcal{O}({S})$ sequential path for constant path length between positions within one attention layer and thereby enabling parallelization across sequence positions on high-throughput accelerators.

Attention functions as a computational primitive rather than an independent architecture family. The transformer ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^sec-network-architectures-transformers-attentiononly-architecture-1b56|section 6.7]]), the family built around it, inherits its core systems properties directly from attention: content-dependent routing, parallel sequence execution, and quadratic score scaling. Evaluating those properties begins with the dynamic pattern-processing problem that attention addresses.

### Pattern Processing Needs

^sec-network-architectures-pattern-processing-needs-4b64

In “the trophy did not fit in the suitcase because it was too big,” the word “it” refers to “trophy,” but if “big” changes to “small,” “it” refers to “suitcase.” The same positions, at the same distances, need different links depending on what the words mean. Neither a CNN’s fixed spatial window nor an RNN’s step-by-step hidden state can route information directly between arbitrary positions based on content. Dynamic sequence processing needs an operation that scores relationships from the tokens themselves, letting each word draw directly on the words that matter to it regardless of how far apart they sit ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^fig-transformer-attention-visualized|figure 9]]).

^fig-transformer-attention-visualized

The bipartite connection lines in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^fig-transformer-attention-visualized|figure 9]] illustrate how the pronoun “they” could receive information from “student” and “finish.” The hypothetical weights demonstrate a direct routing path, not a measured coreference result. Pairwise connections can be evaluated in parallel, allowing a single layer to connect these positions without propagating intermediate state across intervening tokens.

Input-dependent processing extends well beyond language. In protein structure prediction, amino-acid interactions depend on chemical properties and spatial arrangement, not only chain position; in document analysis, connections between sections depend on semantic content rather than proximity. Graph convolutional networks ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-kipf2016semi|Kipf and Welling 2017]]), a family outside this chapter’s five, route information only along the edges of an input graph, which shows that input dependence does not imply all-to-all connectivity.

Dense attention, by contrast, scores every pair of sequence elements. The common systems challenge is that the computation or memory-access pattern responds to the input rather than following a fixed stencil. Even when tensor dimensions stay fixed, content-dependent scores determine which information is emphasized. Attention provides one mechanism for learning such relationships, and dense self-attention forms the foundation of the transformer architecture.

### Algorithmic Structure

^sec-network-architectures-algorithmic-structure-8468

To route information dynamically ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-pattern-processing-needs-4b64|section 6.6.1]]), the network needs an operator that turns a variable-length sequence into content-dependent weights ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-bahdanau2015neural|Bahdanau et al. 2015]]). Attention works on vectors, so text is first cut into tokens (words or word pieces), and each token’s ID selects one learned row of a table, the token’s embedding. Stacking those rows for the whole sequence gives the token representations that attention takes as input. The transformer architecture computes the content-dependent weights with the scaled dot-product attention operator introduced by Vaswani et al. ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-vaswani2017|2017]]):

$$
\text{Attention}({\mathbf{Q}}, {\mathbf{K}}, {\mathbf{V}}) = \text{softmax} \left(\frac{{\mathbf{Q}}{\mathbf{K}}^T}{\sqrt{{d_{\text{head}}}}}\right){\mathbf{V}}
$$

For this self-attention case, the inputs ${\mathbf{Q}}$ (queries), ${\mathbf{K}}$ (keys), and ${\mathbf{V}}$ (values)[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn23|²³]] are learned linear projections of the token representations (${\mathbf{Q}}= {\mathbf{X}}{\mathbf{W}_{Q}}$, ${\mathbf{K}}= {\mathbf{X}}{\mathbf{W}_{K}}$, ${\mathbf{V}}= {\mathbf{X}}{\mathbf{W}_{V}}$). Attention uses three separate projection matrices rather than computing dot-product affinities directly between raw tokens (${\mathbf{X}}{\mathbf{X}}^T$) for two architectural reasons:

1.  **Asymmetric relationships**: Direct token dot products ${\mathbf{x}}_i \cdot {\mathbf{x}}_j$ are symmetric (${\mathbf{x}}_i \cdot {\mathbf{x}}_j = {\mathbf{x}}_j \cdot {\mathbf{x}}_i$), whereas relationships in language are not. In “the chef cooked the meal,” the verb “cooked” looks for its direct object (“meal”), while “meal” plays a different role, so the two directions of the pair need different scores. Splitting the projection into a query (what a token looks for) and a key (what a token offers) lets ${\mathbf{q}_{\text{cooked}}}\cdot {\mathbf{k}_{\text{meal}}}$ be high while ${\mathbf{q}_{\text{meal}}}\cdot {\mathbf{k}_{\text{cooked}}}$ stays low.
2.  **Separating where to look from what to pass on**: The dot products ${\mathbf{Q}}{\mathbf{K}}^T$ decide *where* to look (routing weights), while the value projection ${\mathbf{V}}$ decides *what* information to retrieve. Without a separate value projection, a token that serves mainly as a structural marker (such as a preposition or punctuation mark) would pass its entire raw embedding into later layers. Projecting through ${\mathbf{W}_{V}}$ lets the network strip away surface token identity and pass along only the features downstream layers need.

For an input sequence of length ${S}$ projected to a dimension ${d_{\text{head}}}$ (here the full width ${d}$; the transformer’s multi-head attention later splits that width across several parallel attention computations called heads), the dot product ${\mathbf{Q}}{\mathbf{K}}^T$ computes all ${S}^2$ pairwise token similarities. Scaling by $1/\sqrt{{d_{\text{head}}}}$ prevents dot products from growing large in magnitude at high dimensions, which would push softmax into regions with vanishingly small gradients. The softmax operator[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn24|²⁴]] normalizes each row of the score matrix into a probability distribution over key positions. Finally, multiplying these normalized weights by ${\mathbf{V}}$ produces output vectors formed as weighted combinations of the value representations.

↪ The dot product as a similarity measure is collected for reference in **[[05 Reference/Volume I - Foundations/V1 Algorithm Foundations#^sec-appdx-algorithm-foundations-dot-product-similarity-7957|The dot product as similarity]]**.

[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^fig-attention|Figure 10]] traces this dataflow for a sequence of length ${S}= 6$: cyan query rows match against red key columns to populate the $6{\times}6$ similarity matrix, whose rows subsequently weight the green value vectors to produce the contextualized output vectors on the right. Each row of the resulting ${S}{\times}{S}$ matrix determines how strongly an individual token attends to every token in the sequence. In a trained model, the largest affinity values reflect strong contextual dependencies, while near-zero entries suppress irrelevant positions.

While attention weights vary dynamically with the input tokens, generating the query, key, and value vectors requires static linear projections against learned parameter matrices. In accelerator implementations, these three operations are fused into a single batched matrix multiplication to maximize Tensor Core saturation and reduce kernel launch overhead. Packing the three weight matrices side by side turns three projections into one ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^fig-attention-weightcalc|figure 11]]). The $6{\times}768$ token embedding matrix (one learned 768-value vector per token) multiplies a $768{\times}2304$ weight matrix whose three 768-column blocks hold the query, key, and value weights. Adding the bias yields a $6{\times}2304$ output that contains all three projections, computed in a single kernel pass.

![[90 Assets/Volume I/06 Nn Architectures/Generated Figure f0ba598601.svg]]

Figure 11: **QKV Projection Computation**: The embedding matrix ($6{\times}768$) multiplies with QKV weight matrices ($768{\times}2304$) plus bias to produce combined projections ($6{\times}2304$). The 2304 output columns hold the query, key, and value projections side by side, 768 each, colored as in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^fig-attention|figure 10]]; only the first token’s output row is drawn. This single batched matrix multiplication, requiring $6{\times}768{\times}2304$ = 10.6 million MACs, replaces three separate projection operations for efficiency. ### Computational Mapping

^sec-network-architectures-computational-mapping-13cd

Lowering the attention operator $\text{Attention}({\mathbf{Q}}, {\mathbf{K}}, {\mathbf{V}}) = \text{softmax}({\mathbf{Q}}{\mathbf{K}}^T/\sqrt{{d_{\text{head}}}}){\mathbf{V}}$ to physical execution exposes the system cost of data-dependent connectivity. Evaluating pairwise alignments requires two distinct matrix multiplications per attention head: the score GEMM (${\mathbf{Q}}{\mathbf{K}}^T$) and the context GEMM (${\mathbf{A}}{\mathbf{V}}$, where ${\mathbf{A}}= \text{softmax}({\mathbf{Q}}{\mathbf{K}}^T/\sqrt{{d_{\text{head}}}})$). For an input of sequence length ${S}$ and head dimension ${d_{\text{head}}}$, each phase executes ${S}^2 {d_{\text{head}}}$ multiply-accumulate operations, yielding $\mathcal{O}({S}^2 {d_{\text{head}}})$ computational complexity per head.

[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^lst-attention-layer-compute-9fe309c9|Listing 7]] contrasts the high-level matrix formulation with an explicit loop implementation that exposes this quadratic scaling. The matrix version lowers to optimized GEMM routines on accelerator Tensor Cores, whereas the loop version reveals the underlying physical execution structure: batch iterations, quadratic query-key inner products, row-wise softmax reductions, and the final value accumulation pass across all sequence positions.

``` python
def attention_layer_matrix(Q, K, V):
    # Q, K, V: (batch_size × seq_len × d_head)
    # Compute attention scores
    scores = matmul(Q, K.transpose(-2, -1)) / sqrt(d_head)
    weights = softmax(scores)  # Normalize scores
    output = matmul(weights, V)  # Combine values
    return output

def attention_layer_compute(Q, K, V):
    # Initialize outputs
    scores = np.zeros((batch_size, seq_len, seq_len))
    outputs = np.zeros_like(V)

    # Loop 1: Process each sequence in batch
    for b in range(batch_size):
        # Loop 2: Compute attention for each query position
        for i in range(seq_len):
            # Loop 3: Compare with each key position
            for j in range(seq_len):
                # Compute attention score
                for d in range(d_head):
                    scores[b, i, j] += Q[b, i, d] * K[b, j, d]
                scores[b, i, j] /= sqrt(d_head)

        # Apply softmax to scores
        for i in range(seq_len):
            scores[b, i] = softmax(scores[b, i])

        # Loop 4: Combine values using attention weights
        for i in range(seq_len):
            for j in range(seq_len):
                for d in range(d_head):
                    outputs[b, i, d] += scores[b, i, j] * V[b, j, d]

    return outputs
```

Listing 7: **Attention Computation**: Two implementations showing the same $\mathcal{O}({S}^2\times {d_{\text{head}}})$ complexity. The matrix form (top) uses optimized GEMM, while the nested loops (bottom) expose the quadratic pairwise comparisons: for sequence length 512 and head dimension 64, computing attention scores requires $512{\times}512{\times}64$ = 16.8M MACs per attention head, plus another 16.8M MACs for value aggregation.

### System Implications

^sec-network-architectures-system-implications-05a3

Attention eliminates the latency-bound serial path of RNNs, but a naive implementation replaces it with an ${S}{\times}{S}$ attention-score matrix that grows quadratically with sequence length ${S}$. In iron law terms, dense attention trades serial recurrent steps for pairwise score arithmetic and heavy intermediate data movement. Some of these costs are inherent to computing all-to-all interactions; others come only from materializing the full score matrix in memory. Attention’s cost signature therefore pairs the dense counts of its projections with quadratic score arithmetic; the score matrix in memory is optional, the arithmetic is not.

#### Memory Requirements

^sec-network-architectures-memory-requirements-72c3

Materializing an ${S}{\times}{S}$ attention-weight matrix for every sequence and head creates a quadratic memory bottleneck that quickly dwarfs both the ${S}{\times}{d}$ activations and the fixed-size projection weights on long inputs. Tiled exact-attention kernels such as FlashAttention stream score blocks through on-chip SRAM and avoid writing the full score matrix to HBM. They still compute all ${S}^2$ dense interactions (**[[01 Books/Volume I - Foundations/02 Development/08 Model Training/V1-08.07 Pipeline Optimizations#^sec-model-training-flash-attention-ioaware-attention-optimization-3da0|FlashAttention: IO-aware attention optimization]]** develops the I/O-aware tiling in full, and **[[05 Reference/Volume I - Foundations/V1 Algorithm Foundations#^sec-appdx-algorithm-flash-attention|Tiled attention and online softmax]]** collects the online softmax recurrence for reference). This distinction separates the unavoidable quadratic compute cost of dense attention from the avoidable quadratic memory footprint of storing the full score matrix in HBM.

**Napkin Math 6.1: The quadratic bottleneck**

**Problem**: How much memory does a materialized attention matrix require at sequence length ${S} =$ 100,000 (context window)?

**Math**:

1.  **Matrix size**: The attention score matrix $({\mathbf{Q}}{\mathbf{K}}^T)$ has dimensions ${S}{\times}{S}$ per head, across ${N_{\text{heads}}}$ heads (12 heads in this example).
2.  **Elements**: 100,000 $\times$ 100,000 $\times$ 12 heads = 1.2 × 10¹¹ elements.
3.  **Memory**: At FP16 (2 bytes/element): 1.2 × 10¹¹ $\times$ 2 bytes = 240 GB.
4.  **Retained layers**: 240 GB per layer $\times$ 32 retained layers = 7,680 GB.

**Systems insight**: A materialized attention matrix consumes 240 GB per layer. Naive training that retains all 32 layers’ scores for backward would require 7,680 GB, far exceeding any single accelerator’s memory. This memory wall motivates two broad implementation strategies: avoid materializing the full matrix by tiling the computation, or reduce the number of scores computed in the first place.

#### Computation and Data Movement

^sec-network-architectures-computation-needs-7a5d

Attention computation splits into two primary GEMM phases interleaved by a row-wise reduction: generating pairwise query-key scores and computing weighted sums over values. Query-key inner products require ${B} \times {N_{\text{heads}}} \times {S}^2 \times {d_{\text{head}}}$ MAC operations, mirrored symmetrically by the value-aggregation stage. The intervening softmax requires row-wise maximum finding, exponentiation, and summation. Unlike static weight convolutions where filter weights are reused across fixed grid positions, attention computes transient, input-dependent affinity matrices that must be refreshed for every input sequence.

Data movement in attention creates memory access patterns distinct from fixed-stencil operations. Evaluating attention requires projecting and streaming query, key, and value tensors, then routing value vectors according to dynamically evaluated scores. In naive implementations, staging the intermediate ${S} \times {S}$ score matrix in global HBM/DRAM turns score materialization into the dominant bandwidth bottleneck. While static convolutions benefit from deterministic cache lines and RNNs reuse weights across time, naive attention generates large, short-lived activation footprints that challenge standard on-chip cache capacities.

**Checkpoint 6.4: Quadratic scaling intuition**

Long-context scaling is shaped by the cost of attention. Verify your intuition:

**Quadratic growth**: can you explain why doubling sequence length quadruples dense score interactions and a materialized score matrix?

**Tiling boundary**: can you explain why long-context dense attention remains more expensive even when tiling removes full-matrix storage?

Attention replaces the serialized hidden-state bottleneck of recurrent models with dynamic, constant-depth routing, but shifts the system burden to score arithmetic and memory bandwidth traffic. Built into a full architecture without recurrence, this primitive enables end-to-end parallel sequence processing on modern accelerators. The transformer architecture ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^sec-network-architectures-transformers-attentiononly-architecture-1b56|section 6.7]]) builds directly on this foundation, establishing the dominant architecture for modern large-scale machine learning systems.

**Self-Check: Question**

1.  Why does scaled dot-product attention divide the query-key dot product $\mathbf{Q}\mathbf{K}^T$ by $\sqrt{d_{\text{head}}}$ prior to applying the softmax normalization function?

    1.  To convert the matrix multiplication into a sparse graph lookup that reduces compute complexity from $\mathcal{O}(S^2)$ to $\mathcal{O}(S)$.
    2.  Scaling limits the magnitude of attention scores as $d_{\text{head}}$ grows, helping keep softmax from saturating too sharply; it does not remove quadratic score computation or guarantee universal overflow protection.
    3.  To force the sum of all elements in the unnormalized query-key matrix to equal exactly 1.0 before applying softmax.
    4.  To eliminate the need for Key weight matrices by making Query and Value representations mathematically identical.

2.  Consider a single transformer self-attention layer processing a sequence of length $S = 4{,}096$ with $N_{\text{heads}} = 12$ attention heads in FP16 precision (2 bytes per score). Calculate the memory required to store the materialized attention score matrices $(\mathbf{Q}\mathbf{K}^T)$ for this single layer, and explain why doubling the context length to $S = 8{,}192$ creates a super-linear memory wall.

3.  True or False: IO-aware algorithms like FlashAttention reduce the computational complexity of dense self-attention from $\mathcal{O}(S^2)$ down to $\mathcal{O}(S)$ floating-point operations.

4.  In the scaled dot-product attention mechanism, the input sequence is projected into three distinct learned representations known as Queries, Keys, and \_\_\_\_, drawing a direct analogy to content-addressable retrieval systems.

5.  In an attention layer with sequence length $S = 512$ and per-head feature dimension $d_k = 64$, how many multiply-accumulate (MAC) operations are required to compute the query-key attention scores $(\mathbf{Q}\mathbf{K}^T)$ for a single attention head, excluding softmax normalization and value aggregation?

    1.  32,768 MACs, calculated as $512 \times 64$.
    2.  262,144 MACs, calculated as $512 \times 512$.
