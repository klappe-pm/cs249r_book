# V1-06.08 Transformers Parallel Sequence Processing

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06 Network Architectures|V1-06 Network Architectures]]

^sec-network-architectures-transformers-attentiononly-architecture-1b56

Attention provides the computational primitive of dynamic, content-dependent routing between positions, yet it was originally layered on top of recurrent architectures, inheriting their sequential bottleneck. The transformer architecture removes recurrence and makes attention the operation that mixes information between positions in every layer, which enables parallel computation across sequence positions during full-sequence processing, such as training or prompt processing (reading a user’s whole input at once), while retaining dynamic connectivity. Removing recurrence also introduces distinct physical costs: quadratic attention-score cost over long inputs, a store of per-token state that grows while the model generates text, and memory-bandwidth pressure when it generates one token at a time.

**Definition 6.6: Transformers**

***Transformers*** are neural network architectures that combine self-attention, feed-forward layers, residual connections, normalization, and positional information without recurrence, enabling parallel processing across sequence positions during training and prompt processing.

1.  **Significance**: Parallelism is the systems payoff. An RNN processing an ${S}$-token sequence executes ${S}$ sequentially dependent steps. A transformer processes all positions of a sequence concurrently, mapping token interactions to large matrix multiplications (GEMMs) that maximize accelerator compute utilization. Dense self-attention retains the pairwise score cost ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-memory-requirements-72c3|section 6.6.4.1]]).
2.  **Distinction**: Unlike attention used inside a recurrent backbone, which inherits the host architecture’s $\mathcal{O}({S})$ sequential path, transformers use attention as the primary mixing operation between positions, alternating it with position-wise feed-forward networks.
3.  **Common pitfall**: A frequent misconception is that transformers have “infinite context.” Two distinct memory footprints matter: the $\mathcal{O}({S}^2)$ attention-score activation matrix when it is materialized over a long input, and the $\mathcal{O}({S})$ key-value (KV) cache that accumulates while the model generates text. At long sequence lengths, the KV cache footprint can rival or exceed the static model weights, turning KV cache management and memory-bandwidth efficiency into dominant engineering constraints.

### Pattern Processing Needs

^sec-network-architectures-pattern-processing-needs-9daf

The recurrent sequence-to-sequence hybrids that first carried attention ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-sutskever2014sequence|Sutskever et al. 2014]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-bahdanau2015neural|Bahdanau et al. 2015]]) fixed the single-vector information bottleneck of [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.06 RNNs Sequential Pattern Processing#^sec-network-architectures-system-implications-18c3|section 6.5.5]], yet step ${t}$ still waited on step ${t}-1$, so a 1,000-token input still paid 1,000 ordered state updates no matter how many matrix units the accelerator offered. Dropping the recurrent loop so all 1,000 tokens can be processed at once places three pattern-processing demands on the replacement block. It must link any two positions within the same sequence in a single parallel pass. It must inject sequence order explicitly, because without step-by-step state updates an all-to-all operation cannot tell whether one word came before or after another. It must also apply nonlinear feature transformations within each position after routing information between them. The transformer architecture ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-vaswani2017|Vaswani et al. 2017]]) meets those three requirements by pairing self-attention with positional encodings and position-wise feed-forward networks, trading the spatial parameter efficiency of CNNs and the bounded $\mathcal{O}(1)$ step state of RNNs for unconstrained sequence parallelism during training and prompt processing.

### Algorithmic Structure

^sec-network-architectures-algorithmic-structure-60ef

To link tokens within a single sequence in one parallel pass, the transformer uses the self-attention projection introduced in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-algorithmic-structure-8468|section 6.6.2]]. Whereas encoder-decoder attention draws queries from a target sequence and keys and values from a separate source sequence, self-attention applies all three learned projection matrices (${\mathbf{W}_{Q}}$, ${\mathbf{W}_{K}}$, and ${\mathbf{W}_{V}}$) to the same input sequence ${\mathbf{X}}$, as [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^eq-self-attention|equation 11]] writes in full:

$$
\text{SelfAttention}({\mathbf{X}}) = \text{softmax} \left(\frac{{\mathbf{X}}{\mathbf{W}_{Q}}({\mathbf{X}}{\mathbf{W}_{K}})^T}{\sqrt{{d_{\text{head}}}}}\right){\mathbf{X}}{\mathbf{W}_{V}} \tag{11}
$$

^eq-self-attention

Without positional information or a mask that hides some positions (such as the causal mask introduced below), matrix multiplication and row-wise softmax operate symmetrically across the token dimension, which makes self-attention permutation-equivariant. Shuffling the rows of ${\mathbf{X}}$ merely shuffles the output rows identically, treating the sequence as an unordered set. Positional encodings inject sequence order and relative distance. The original transformer adds a position-dependent vector to each token’s embedding before the first block; its entries are sine and cosine waves of the position at different frequencies, so every position receives a distinct pattern and nearby positions receive similar ones. Rotary position embeddings ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-su2024|Su et al. 2024]]) instead build position into the query and key vectors, so a query-key score reflects how far apart the two tokens sit.

Conceptually, attention implements a differentiable content-addressable memory. Whereas conventional memory architectures retrieve stored values at explicit addresses, self-attention uses the query vector ${\mathbf{q}}_i$ to score similarity against all candidate keys ${\mathbf{K}}\in \mathbb{R}^{{S}\times {d_{\text{head}}}}$. The resulting softmax distribution generates a continuous interpolation over the value vectors ${\mathbf{V}}\in \mathbb{R}^{{S}\times {d_{\text{head}}}}$, functioning as a differentiable lookup operation. The $\sqrt{{d_{\text{head}}}}$ divisor rests on a variance argument. If query and key components are independent random variables with zero mean and unit variance, their inner product ${\mathbf{q}}_i \cdot {\mathbf{k}}_j = \sum_{{m}=1}^{{d_{\text{head}}}} {q_{im}} {k_{jm}}$ has zero mean and variance ${d_{\text{head}}}$, so dividing by $\sqrt{{d_{\text{head}}}}$ restores unit variance at any head dimension and so keeps softmax away from the vanishingly small gradients that large scores produce.[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn25|²⁵]]

Transformers extend single-head self-attention by executing multiple attention operations in parallel through multi-head attention. Instead of computing a single set of attention weights over ${d}$ dimensions, the architecture projects queries, keys, and values into ${N_{\text{heads}}}$ distinct lower-dimensional subspaces of dimension ${d_{\text{head}}} = {d}/ {N_{\text{heads}}}$. Each head can learn a different pattern. Their outputs are concatenated and projected through an output matrix ${\mathbf{W}_{O}}$. In [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^eq-multihead-attention|equation 12]], ${\mathbf{X}_{Q}}$, ${\mathbf{X}_{K}}$, and ${\mathbf{X}_{V}}$ denote the source representations before the head-specific projections. For self-attention, all three are ${\mathbf{X}}$:

$$
\text{MultiHead}({\mathbf{X}_{Q}}, {\mathbf{X}_{K}}, {\mathbf{X}_{V}}) = \text{Concat}(\text{head}_1, \ldots, \text{head}_{{N_{\text{heads}}}}){\mathbf{W}_{O}} \tag{12}
$$

 where each head applies its own projections to the sources once and then attends:

$$
\text{head}_i = \text{Attention}({\mathbf{X}_{Q}}{\mathbf{W}_{Q,i}}, {\mathbf{X}_{K}}{\mathbf{W}_{K,i}}, {\mathbf{X}_{V}}{\mathbf{W}_{V,i}})
$$

^eq-multihead-attention

Although individual attention heads often specialize in distinct syntactic or semantic patterns ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-clark2019|Clark et al. 2019]]), adapting the effective connectivity graph to each input sequence, empirical analyses find substantial redundancy among heads, so many can be removed with little loss; **[[01 Books/Volume I - Foundations/03 Optimization/10 Model Compression/V1-10 Model Compression#^sec-model-compression|Model Compression]]** examines that removal and the other compression techniques applied to attention.

To build deep networks from these dynamic projections, the transformer places self-attention inside a repeating block ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^fig-transformer|figure 12]]). Each block wraps multi-head attention and position-wise feed-forward sublayers with residual connections and layer normalization. The original transformer stacks these blocks into two towers, an encoder that reads the input sequence and a decoder that generates the output. Positional encodings combine with token embeddings at the base of both towers, and each tower repeats multi-head attention and feed-forward stages. The encoder’s output feeds the decoder’s attention, and only the decoder ends in a final linear layer and softmax that turn each output vector into probabilities over the vocabulary. Because all positions can be processed in parallel rather than sequentially, the architecture trades recurrent state for large matrix operations that map well to accelerator training.

A decoder-only model such as GPT-2 keeps only the right-hand tower of this figure, without the attention that reads an encoder’s output. Tokens enter as embedding vectors, pass through the stack of blocks, and leave as a probability distribution over the vocabulary for the next token. The residual paths and normalization layers in this stack are shared building blocks rather than transformer inventions; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.05 Skip Connections and Normalization#^sec-network-architectures-evolution-dense-spatial-processing-2761|section 6.4.1]] and [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.05 Skip Connections and Normalization#^sec-network-architectures-normalization-layers-mathematical-foundations-0fb7|section 6.4.2]] explain why they make deep stacks trainable and what each costs the machine.

^fig-transformer

Language models built from this block are usually *autoregressive*: they produce text one token at a time and feed each new token back as input for the next. Given the prompt “The cat sat on,” a model predicts “the,” appends it, predicts “mat” from the longer context, and continues until it emits an end token. A *causal mask* keeps that process honest. It sets the attention scores for later positions to negative infinity before the softmax, so each position attends only to itself and earlier tokens, exactly the information that will exist when the model generates.

The same mask is what lets training run in parallel. During next-token training the whole target sequence is already known, so shifting it right by one position pairs every input token with its successor ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^fig-transformer|figure 12]]), and the mask guarantees that position ${t}$ cannot see later tokens. An accelerator therefore evaluates every position at once with dense matrix multiplications instead of stepping through a serial time loop as an RNN must.

Generation splits into two phases with different machine profiles, drawn in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^fig-prefill-decode|figure 13]]. *Prefill* processes the whole prompt in one pass. Every prompt token is known, so the model evaluates them in parallel, as in training, and stores each token’s keys and values. *Decode* then produces the remaining tokens one per step. Each step feeds a single token through the model, so its projections shrink from matrix-matrix to matrix-vector products, and its attention reads the stored keys and values of every earlier token instead of recomputing them. That store is the key-value (KV) cache, and [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^sec-network-architectures-inference-memory-bandwidth-wall-98d1|section 6.7.4.2]] shows why decode, not prefill, usually sets a language model’s serving cost.

![[90 Assets/Volume I/06 Nn Architectures/Generated Figure 0bfefa039b.svg]]

Figure 13: **Prefill and Decode**: Prefill (left) runs the whole prompt through the model in one pass of matrix-matrix products, reusing every weight across all prompt tokens, and writes each prompt token’s keys and values to the KV cache. Decode (right) then generates one token per step: each output becomes the next input, each step runs matrix-vector products that re-read every weight, and each step reads the whole cache and appends one entry. The first phase is usually compute-bound; the second is usually bandwidth-bound at small batch.

### Computational Mapping

^sec-network-architectures-computational-mapping-aea3

In code, self-attention is three projections of the same input followed by the attention operator, and multi-head attention runs several smaller copies side by side before a final projection ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^lst-self-attention-layer-17a1544d|listing 8]]). Writing both layers side by side shows how the multi-head variant partitions the hidden dimension across heads without changing the per-head attention kernel.

``` python
def self_attention_layer(X, W_Q, W_K, W_V, d_head):
    # X: input tensor (batch_size × seq_len × d_model)
    # W_Q, W_K, W_V: weight matrices (d_model × d_head)

    Q = matmul(X, W_Q)
    K = matmul(X, W_K)
    V = matmul(X, W_V)

    scores = matmul(Q, K.transpose(-2, -1)) / sqrt(d_head)
    attention_weights = softmax(scores, dim=-1)
    output = matmul(attention_weights, V)

    return output

def multi_head_attention(X, W_Q, W_K, W_V, W_O, num_heads, d_head):
    outputs = []
    for i in range(num_heads):
        head_output = self_attention_layer(
            X, W_Q[i], W_K[i], W_V[i], d_head
        )
        outputs.append(head_output)

    concat_output = concat(outputs, axis=-1)
    final_output = matmul(concat_output, W_O)

    return final_output
```

Listing 8: **Self-Attention and Multi-Head Attention**: Self-attention (top) derives ${\mathbf{Q}}$, ${\mathbf{K}}$, and ${\mathbf{V}}$ from the same input ${\mathbf{X}}$ through three projections, then computes attention as before. Multi-head attention (bottom) runs ${N_{\text{heads}}}$ parallel attention heads with dimension ${d_{\text{head}}} = {d}/{N_{\text{heads}}}$, then concatenates and projects. For GPT-2 (768-dim, 12 heads), each head operates on 64 dimensions, partitioning the projected feature dimension across heads while enabling diverse relationship patterns.

^lst-self-attention-layer-17a1544d

The attention listing accounts for information mixing across positions, but a complete block also transforms features within each position. An ordinary position-wise feed-forward network applies a dense projection from hidden width ${d}$ to an intermediate layer output width ${d_{\text{out}}}$, a nonlinear activation, and a second dense projection back to ${d}$. For a sequence of length ${S}$, its tensor shapes follow ${S}{\times}{d} \to {S}{\times}{d_{\text{out}}} \to {S}{\times}{d}$. The same two weight matrices apply independently at every position, so the MLP accounting gives $2{S}{d}{d_{\text{out}}}$ MACs and an intermediate tensor with ${S}{d_{\text{out}}}$ elements.

For one full-sequence block at batch one, with one standard multi-head self-attention sublayer and that two-layer feed-forward network, the query, key, value, and output projections together require $4{S}{d}^2$ MACs. The two attention products add $2{S}^2{d}$ MACs across all heads, whose widths sum to ${d}$. Adding the feed-forward cost completes the block’s matrix-product account. These counts omit biases, softmax, normalization, nonlinear activations, and residual additions, and assume dense evaluation of all position pairs. At fixed widths, projections and the feed-forward network grow linearly with sequence length, while the pairwise products grow quadratically. Which part dominates therefore depends on both the sequence length and the chosen widths, even before memory traffic is measured.

During autoregressive inference, generating output tokens step-by-step reintroduces sequential serialization. At batch one, projection matrix multiplications become matrix-vector operations with less weight reuse, making off-chip bandwidth a likely limit when weights exceed cache capacity, as quantified in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^sec-network-architectures-system-implications-77ac|section 6.7.4]] via the GPT-2 XL lighthouse.

### System Implications

^sec-network-architectures-system-implications-77ac

The quadratic bottleneck analyzed in [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-system-implications-05a3|section 6.6.4]] manifests differently across execution regimes. Because full-sequence training and prompt prefill operate on known token sequences under causal masking, accelerators evaluate all positions concurrently using dense matrix multiplications. Autoregressive decoding, by contrast, must generate each token before predicting the next. That loss of token concurrency reduces weight reuse and can shift the primary performance limit from arithmetic throughput to memory bandwidth and state retrieval. Sequence length, batch size, and memory hierarchy limits determine whether that transition occurs.

#### Training and Prefill

^sec-network-architectures-training-quadratic-compute-wall-de9d

During training and prompt prefill, all token positions are processed in parallel, allowing accelerator Tensor Cores to achieve high floating-point utilization, but dense attention’s score computation grows as $\mathcal{O}({S}^2)$ with sequence length ${S}$. I/O-aware tiling such as FlashAttention ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-dao2022|Dao et al. 2022]]) keeps the score matrix out of HBM ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-memory-requirements-72c3|section 6.6.4.1]]), so the quadratic arithmetic, not its storage, is the wall that remains.

That wall arrives later than its name suggests. By the block account of [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^sec-network-architectures-computational-mapping-aea3|section 6.7.3]], with a feed-forward width four times the hidden width, a block’s projections and feed-forward network cost $12{S}{d}^2$ multiply-accumulates against $2{S}^2{d}$ for the attention products. The twelve counts four square projections (query, key, value, and output) plus eight for the feed-forward network, whose two layers each connect width ${d}$ with width $4{d}$; the two attention products, scores and weighted values, each cost ${S}^2{d}$. Setting the two totals equal gives a sequence length of six times the hidden width. Attention’s arithmetic therefore dominates only once the sequence passes about six times the hidden width, near 9,600 tokens for GPT-2 XL. Shorter training sequences are bound by the ordinary dense matrix multiplies, and the quadratic wall is a long-context phenomenon.

Deployed models, however, now operate well inside that long-context regime. Product context windows grew from 2K tokens to beyond 128K and into the 1M-token range within a few years ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-openai2023devday|OpenAI 2023]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-anthropic2023claude21|Anthropic 2023]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-google2024gemini15|Google 2024]]), and the decoding discussion below sizes what that growth demands of memory. Longer context windows shift complexity from external retrieval and document chunking pipelines into accelerator memory capacity and bandwidth budgets. Exact tiling changes how much attention state is stored; sparse attention instead reduces the interactions computed ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-memory-requirements-72c3|section 6.6.4.1]]).

**Example 6.4: The quadratic wall**

**Scenario**: BERT, a transformer that keeps only the encoder tower because it reads text rather than generates it, was pretrained with one learned position embedding (a trained vector in place of the sinusoidal formula) for each of 512 positions, so its deployments enforced a hard 512-token input limit ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-devlin2019|Devlin et al. 2019]]).

**Diagnosis**: The limit was chosen partly because attention cost grows quadratically with sequence length. Extending from 512 to 4,096 tokens would multiply materialized score memory by 64×. Once pretraining fixed the limit, it became absolute, because inputs beyond the pretrained positions are undefined for the model, however much memory is available.

**Systems lesson**: Super-linear scaling turns algorithmic complexity into a hardware constraint that becomes fixed in the model itself once pretraining chooses it. No serving-time memory fix extends BERT past 512 positions, so its longer inputs must be truncated or split into windows. A model meant for long inputs must be pretrained with longer positions, and tiled or sparse attention is what keeps that training and its serving within the HBM activation budget.

#### Autoregressive Decoding

^sec-network-architectures-inference-memory-bandwidth-wall-98d1

Autoregressive decoding generates one token at a time and often becomes memory-bandwidth bound at batch one (${B} = 1$) or small batch sizes when weights exceed on-chip memory. During prompt prefill or training, weight reuse across many token positions produces dense GEMMs with much higher arithmetic intensity. A large request batch (${B} \gg 1$) supplies many such positions, but prefill can obtain this reuse even for a single request with a long prompt.

During single-token generation (${B} = 1$), however, each projection layer collapses into a matrix-vector multiplication (GEMV). In the streamed-weight regime, the processor reads each projection weight from DRAM to multiply it by a single new token vector. This is the batch-one regime that [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.03 MLPs Dense Pattern Processing#^eq-dense-intensity|equation 2]] already derived for the MNIST layer at 0.5 FLOP/byte in FP32. Halving the weight width to 2 bytes in FP16, while still executing one multiply-accumulate operation ($1\text{ MAC} = 2\text{ FLOPs}$) per weight read, doubles that weight-only arithmetic intensity to exactly:

$$
{I_{\text{GEMV}}}= \frac{2\text{ FLOPs}}{2\text{ bytes}} = 1.0\text{ FLOP/byte}
$$

↩︎ The 1.0 FLOP/byte intensity of batch-one GEMV in 16-bit precision, and 0.5 FLOP/byte in FP32, is established in **[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05.06 Inference Pipeline#^sec-neural-computation-performance-enhancement-techniques-692f|Optimizing inference throughput and latency]]**.

Because modern accelerators require tens to hundreds of FLOPs per byte to reach peak compute throughput, running at $1.0\text{ FLOP/byte}$ leaves compute cores idling for the vast majority of execution time, waiting for weights to arrive across the memory bus. To generate each token, the system must first stream every model parameter from off-chip memory into registers (for example, a 70B-parameter model streams 140 GB of FP16 weights per token, and GPT-2 XL makes that cost concrete below). It then executes the projection matrix-vector products at an arithmetic intensity capped at $1.0\text{ FLOP/byte}$. Finally, it appends the new key and value vectors to the KV cache while streaming all historical keys and values from memory. Prefill pays the weight traffic once for the whole prompt, whereas decode pays it again for every generated token, which is why decode usually sets the serving cost.

The KV cache[[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.15 Footnotes#^fn26|²⁶]] introduced with prefill and decode grows linearly with sequence length ($\mathcal{O}({N_L} \times 2 \times {N_{\text{heads}}} \times {S}\times {d_{\text{head}}})$ per request, distinct from the $\mathcal{O}({S}^2)$ attention score matrix during training). It stores the key and value vectors for all previous tokens to avoid recomputing them ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-pope2023efficiently|Pope et al. 2023]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-kwon2023|Kwon et al. 2023]]). Keys and values from past tokens are retained because the newly generated token’s query (${\mathbf{q}}_{t}$) must attend across all historical context (${\mathbf{k}}_1 \dots {\mathbf{k}}_{t-1}$ and ${\mathbf{v}}_1 \dots {\mathbf{v}}_{t-1}$) to compute its next representation. Prior queries (${\mathbf{q}}_1 \dots {\mathbf{q}}_{t-1}$) are safely discarded because past tokens never attend forward to future tokens, while caching past keys and values avoids re-running the entire model forward pass over the full prompt at every generated token. For long contexts, this cache can become large (for example, 100+ GB), and each decoding step reads prior keys and values. The resulting bandwidth pressure depends on context length, batching, attention architecture, cache layout, and hardware.

↪ Budgeting KV cache memory across concurrent requests on a serving node is developed in **[[01 Books/Volume I - Foundations/04 Deployment/13 Model Serving/V1-13.10 LLM Serving#^sec-model-serving-memory-kv-cache-d1ea|Memory and KV cache]]**.

For one model shape, the three memory regimes diverge sharply as context grows ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^fig-context-memory|figure 14]]). The weights do not grow with context at all, the KV cache grows linearly with every token a request keeps, and materialized attention scores grow with the square of the context. The cache overtakes the weights near 10,000 tokens, and one layer’s scores alone would fill an accelerator near 41,000 tokens, which is why serving systems size the cache per request and training kernels never materialize the scores.

GPT-2 ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-radford2019language|Radford et al. 2019]]) anchors the chapter’s bandwidth-bound language lighthouse. It is a decoder-only transformer, the same design as today’s large language models such as Llama, yet small enough that every weight and every byte of its decoding traffic can be counted by hand. Unlike BERT, an encoder-style transformer that reads its whole context in both directions, GPT-2 generates text one token at a time, so batch-one decoding reads every weight for every token it produces.

GPT-2 keeps more cache than current decoders do. It gives every attention head its own keys and values, so it stores 307.2 KB of KV cache per token in FP16, while newer models share keys and values across groups of heads ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-ainslie2023|Ainslie et al. 2023]]) and store several times less per parameter. Batching does not shrink that cache. It amortizes weights across requests but not caches, because each sequence keeps its own, which is why serving at scale is limited by KV bytes as well as weight bytes.

The lighthouse below counts only weight traffic, and it assumes that each decoding step runs as fused kernels, as production decoders do. The assumption matters at GPT-2 XL’s size. One decoding step reads its weights in about 0.9 ms on a data-center accelerator, a few times shorter than the kernel start-up (launch) overhead of running the step’s many small kernels one by one (**[[01 Books/Volume I - Foundations/02 Development/07 ML Frameworks/V1-07 ML Frameworks#^sec-ml-frameworks|ML Frameworks]]**), so without fusion that launch overhead, not bandwidth, would set the per-token time. With that overhead removed, GPT-2 XL shows, at countable size, the mechanism that sets the decoding cost of its larger descendants, in which every decode step re-reads every weight.

**Lighthouse 6.4: GPT-2 XL (bandwidth lighthouse)**

**Why it matters**: GPT-2 XL exemplifies **memory-bandwidth-bound** batch-one decoding. In the weight-only model used here, which assumes launch overhead has been fused away, each decoding step reads 6 GB of FP32 weights and performs matrix-vector operations. The resulting arithmetic intensity is about 0.5 FLOP/byte with FP32 weights or 1 FLOP/byte with FP16 weights. Batching can amortize this weight traffic, while KV-cache and activation traffic add to it. [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^tbl-nn-architectures-gpt2-profile|Table 5]] summarizes the bandwidth lighthouse’s quantitative properties:

| **Property**   | **Value**                              | **System Implication**                                               |
|:---------------|:---------------------------------------|:---------------------------------------------------------------------|
| **Parameters** | 1.5B                                   | Weight loading dominates inference latency.                          |
| **Model Size** | 6 GB (FP32)                            | Fits on one GPU but saturates HBM bandwidth.                         |
| **Compute**    | 3 GFLOP/token                          | Low per-token compute; bottleneck is data movement, not math.        |
| **Constraint** | Memory Bandwidth                       | Weight-bound batch-one tokens/s depends strongly on HBM bandwidth.   |
| **Profile**    | Bandwidth-Bound (small-batch decoding) | Larger batches can amortize weight traffic and shift the bottleneck. |

Table 5: **GPT-2 XL Systems Profile**: Weight-only estimates for batch-one autoregressive decoding. Under these assumptions, each step reads the model weights at roughly 0.5–1 FLOP/byte, so HBM bandwidth strongly constrains generation throughput.

Across training and inference, transformers expose different opportunities for reuse. Full-sequence processing parallelizes across token positions while dense attention adds pairwise score cost, whereas small-batch autoregressive decoding stresses memory bandwidth when weights stream from off-chip memory.

**Two regimes**: why is the same transformer limited by arithmetic during prefill but by memory bandwidth during batch-one decoding?

Yet dense, spatial, and sequence models do not cover the full spectrum of production workloads. Large-scale recommendation systems depart from standard arithmetic-dominated pipelines by coupling sparse embedding lookups (where memory capacity and irregular access distributions govern throughput) with downstream dense interaction layers. This hybrid matters at production scale. Meta reported that recommendation models accounted for most of its AI inference cycles ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-gupta2020architectural|Gupta et al. 2020]]), even though such workloads receive less academic attention than language or vision models.
