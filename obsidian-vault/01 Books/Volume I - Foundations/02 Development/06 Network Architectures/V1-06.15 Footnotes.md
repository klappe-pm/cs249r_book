# V1-06.15 Footnotes

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06 Network Architectures|V1-06 Network Architectures]]

^footnotes

<sup>1</sup> **Inductive bias**: From Latin *inducere*, “to lead into.” Encoding a structural assumption “leads” the model toward a smaller solution space, and every architecture discussed here (multilayer perceptron (MLP), convolutional neural network (CNN), recurrent neural network (RNN), and transformer) is defined by its choice of bias. A CNN’s locality bias cuts parameters by orders of magnitude vs. an equivalent MLP, directly shrinking the iron law’s ${O}$ and ${D_{\text{vol}}}$ terms, while global attention trades quadratic score computation (one relevance score for every pair of elements) for long-range connectivity.

^fn1

<sup>2</sup> **ImageNet**: The image-classification benchmark on which convolutional networks first proved themselves at scale. AlexNet’s 2012 victory in the ImageNet Large Scale Visual Recognition Challenge posted 15.3 percent top-5 error against 26.2 percent for the second-place entry, on the 1000-class challenge with roughly 1.3 million training images ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-krizhevsky2012imagenet|Krizhevsky et al. 2012]]); the original ImageNet release contained 3.2 million images across 5,247 categories ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-deng2009|Deng et al. 2009]]). Subsequent architectures improved accuracy through changes in architecture, optimization, data, and compute budgets, illustrating the interaction between inductive bias and infrastructure cost.

^fn2

<sup>3</sup> **Perceptron**: Formed from “perception” and the device suffix “-tron” (as in *cyclotron* and *klystron*), coined by Frank Rosenblatt ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-rosenblatt1957perceptron|Rosenblatt 1957]]) for the atomic unit of neural computation: a weighted sum followed by a nonlinear activation, extending the earlier McCulloch-Pitts neuron. MLPs are composed entirely of these units arranged in fully-connected layers, so the efficiency of this single operation, a multiply-accumulate, determines system throughput. Modern accelerators execute over $10^{14}$ of these operations per second, making the perceptron the computational primitive that the entire ML hardware ecosystem is optimized around.

^fn3

<sup>4</sup> **Universal approximation theorem (UAT)**: This theorem establishes representational capacity for continuous functions on a compact domain, given suitable nonlinear activations. The systems-level catch is that the existence guarantee supplies neither an efficient training procedure nor a practical width for a particular task. For a target with no further structure, the width needed to reach a fixed accuracy can grow exponentially with the number of inputs, so the guarantee alone says little about a $256{\times}256$ image; useful structure in the target is what keeps practical networks small.

^fn4

<sup>5</sup> **Manifold hypothesis**: The assumption that high-dimensional data lies near a low-dimensional surface embedded within the full space; a $256{\times}256$ image lives in a 65,536-dimensional space, but “valid cat images” may occupy a much smaller structured region. Learned representations can expose that structure. The systems consequence is a potential reduction in the data and computation needed for learning; useful structure can also take other forms, such as a target depending on only a few input features.

^fn5

<sup>6</sup> **No free lunch theorem**: Wolpert and Macready’s 1997 result showed that, averaged over every conceivable problem, no optimization algorithm outperforms any other, random search included. The ML systems consequence is that an inductive bias (locality, equivariance, attention) can improve performance on problems matching that bias while hurting performance when its assumptions do not hold, making architecture selection an engineering commitment to a problem class.

^fn6

<sup>7</sup> **MAC (multiply-accumulate)**: The per-weight unit of work counted throughout **[[01 Books/Volume I - Foundations/02 Development/05 Neural Computation/V1-05 Neural Computation#^sec-neural-computation|Neural Computation]]**. In Horowitz’s 45 nm reference, an FP32 multiply plus add costs about 4.6 pJ, while a 32-bit off-chip DRAM access costs about 640 pJ ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-horowitz2014|Horowitz 2014]]). These technology-specific values illustrate why data movement can dominate arithmetic energy; they are not universal constants for current hardware.

^fn7

<sup>8</sup> **BLAS (basic linear algebra subprograms)**: This standard API for matrix operations enables the use of highly optimized libraries (for example, cuBLAS) to accelerate the 784 multiply-accumulates per neuron. The $784{\times}128$ matrix in the MNIST example may use the hardware less efficiently than larger, well-aligned transformer matrices because utilization depends on matrix shape, batching, datatype, library, and accelerator.

^fn8

<sup>9</sup> **Tensor Cores**: Specialized units in NVIDIA GPUs that execute thousands of multiply-accumulate operations as one matrix instruction. They run most efficiently when matrix dimensions match the hardware’s block size. Across vendors, specialized matrix units reward dense, well-shaped GEMM workloads and penalize small, irregular shapes that cannot keep the units full.

^fn9

<sup>10</sup> **Systolic array**: Named for the heart’s rhythmic contraction ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-kung1982|Kung 1982]]), the array’s lockstep “pulse” of data through a grid of multiply-accumulate processors directly implements the data reuse that matrix multiplication and convolution require. By passing input values between neighboring processors, an expensive round-trip to off-chip DRAM is avoided for every single multiplication. This is critical for efficiency, because an off-chip memory access costs far more energy than the arithmetic it feeds.

^fn10

<sup>11</sup> **Convolution**: From Latin *convolvere* (“to roll together”), describing a filter that slides across an input, combining local elements at each position. This “rolling together” enforces a locality constraint that is the source of the operation’s efficiency: a single $5{\times}5$ kernel reuses its 25 weights at every spatial position instead of learning a separate weight for every pixel.

^fn11

<sup>12</sup> **Translation equivariance**: An inherent property of the convolution operation where shifting the input guarantees a corresponding spatial shift in the resulting feature map. This is distinct from *invariance*, which pooling or later aggregation can approximate by discarding precise positional data. For example, $2{\times}2$ max pooling over non-overlapping windows returns the same value when the strongest activation moves anywhere inside its window, while reducing the number of spatial elements by 75 percent.

^fn12

<sup>13</sup> **Yann LeCun and LeNet**: LeCun’s architecture directly addressed the intractable scaling of applying dense networks to images by enforcing the principles of local connectivity and parameter sharing. These constraints reduced the parameter count for an image-like input layer by over 95 percent relative to fully connecting the same input and output, enabling LeNet-5 to achieve production-grade accuracy on commercial tasks like check reading with only ~60,000 total parameters.

^fn13

<sup>14</sup> **Receptive field**: The input region influencing a particular output neuron. With $3{\times}3$ filters, receptive fields grow by 2 pixels per layer, so a neuron at layer 3 “sees” a $7{\times}7$ region. This growth rate constrains architecture depth: detecting objects spanning 100+ pixels in a $224{\times}224$ image requires either deep stacks of small filters (more layers, more memory for activations) or larger kernels (more parameters per layer), a fundamental depth-vs.-width trade-off in CNN design.

^fn14

<sup>15</sup> **im2col (image to column)**: Rather than being a new learning algorithm, im2col-style lowering is an implementation technique used by CNN frameworks and libraries such as Caffe and cuDNN ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-chellapilla2006high|Chellapilla et al. 2006]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-jia2014|Jia et al. 2014]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-chetlur2014cudnn|Chetlur et al. 2014]]): it converts convolutions into standard GEMM calls by unfolding each overlapping patch into one line of a matrix, a column in the layout that named the transform and a row in this chapter’s example. The trade-off is memory: in a simple fully materialized stride-1 ${K}{\times}{K}$ transform, interior input elements can appear in up to ${K}^2$ rows (9 times for $3{\times}3$ filters), though borders, stride, padding, tiling, and direct-convolution algorithms reduce the realized expansion. This memory-for-simplicity exchange explains why memory-constrained mobile frameworks prefer direct convolution, while data center GPUs with abundant HBM may use GEMM-oriented lowering when it improves throughput.

^fn15

<sup>16</sup> **SIMD (single instruction, multiple data)**: CPU instructions that apply the same operation to multiple data elements simultaneously. For CNN inference on edge CPUs without GPU access, SIMD utilization can affect whether a model meets real-time latency targets.

^fn16

<sup>17</sup> **Batch normalization (BatchNorm)**: The original normalization layer ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-ioffe2015batch|Ioffe and Szegedy 2015]]), which re-scales activations using per-mini-batch statistics. In one ImageNet experiment, it reached the target accuracy with 14$\times$ fewer training steps. Its batch-size dependency and training-serving skew (switching from batch statistics to running averages at inference) are systems limitations that motivated alternatives: LayerNorm removed batch dependency for transformers, and RMSNorm removed mean centering.

^fn17

<sup>18</sup> **RMSNorm (root mean square normalization)**: Introduced by Zhang and Sennrich ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-zhang2019root|2019]]) at NeurIPS, RMSNorm simplifies LayerNorm by normalizing with the root mean square alone, dropping the mean-centering step. Across the paper’s tested models and implementations, RMSNorm reduced overall running time by 7–64 percent relative to LayerNorm. LLaMA-family and Mixtral-style transformer reports use RMSNorm ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-touvron2023llama|Touvron, Lavril, et al. 2023]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-touvron2023llama2|Touvron, Martin, et al. 2023]]; [[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-jiang2024mixtral|Jiang et al. 2024]]), illustrating why a simpler normalization kernel matters at large language model scale.

^fn18

<sup>19</sup> **LSTM (long short-term memory)**: Invented by Hochreiter and Schmidhuber in 1997, LSTMs introduced a “Constant Error Carousel,” a gated cell state that protects error signals from exponential decay during backpropagation through time. The systems cost is that a standard LSTM computes input, forget, and output gates plus a candidate cell update, giving roughly four affine transformations per time step vs. one in a vanilla RNN. Transformers replaced LSTMs in many large-scale language workloads not because attention costs less arithmetic, since it costs more, but because it parallelizes across sequence positions where a recurrence cannot.

^fn19

<sup>20</sup> **GRU (gated recurrent unit)**: Cho et al. ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-cho2014|2014]]) describes a gated hidden unit for encoder-decoder translation that uses reset and update gates to control how the hidden state is updated. Relative to an LSTM’s input, forget, and output gates plus candidate cell update, this gives a simpler gated recurrence. The broader systems lesson: architectural simplification can reduce state and matrix operations when it preserves task performance, a principle that recurs in efficiency-oriented designs from MobileNet to distilled transformers.

^fn20

<sup>21</sup> **Bahdanau attention**: This approach broke the “fixed-length vector” bottleneck of prior sequence-to-sequence models. The core trade-off was accepting a linear, $\mathcal{O}({S})$ memory cost to store all input states in exchange for overcoming the information loss inherent in a single vector.

^fn21

<sup>22</sup> **Transformer**: The founding paper, “Attention Is All You Need,” made the explicit systems claim that a parallel attention mechanism could fully replace sequential recurrent processing. This architectural trade eliminates an RNN’s $\mathcal{O}({S})$ path length constraint on parallelism but introduces $\mathcal{O}({S}^2)$ dense score computation, a quadratic cost that continues to shape context-window engineering.

^fn22

<sup>23</sup> **Query-key-value (QKV)**: The terminology is borrowed from information retrieval, explaining why the equation uses three distinct learned projections to calculate pairwise scores. Creating these projections requires three independent weight matrices, costing $3 \times {d}^2$ parameters per layer. Storing the key and value projections of earlier tokens is what produces the key-value (KV) cache of autoregressive serving ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.08 Transformers Parallel Sequence Processing#^sec-network-architectures-inference-memory-bandwidth-wall-98d1|section 6.7.4.2]]).

^fn23

<sup>24</sup> **Softmax**: Named as a “soft” (differentiable) version of argmax, with mathematical roots in Boltzmann’s statistical mechanics, softmax normalizes each query row over all ${S}$ scores and therefore requires a reduction over each row. Online softmax lets that reduction run over tiles with running statistics, which is why it need not force quadratic storage ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.07 Attention Dynamic Processing#^sec-network-architectures-memory-requirements-72c3|section 6.6.4.1]]).

^fn24

<sup>25</sup> **Attention scaling $(\sqrt{{d_{\text{head}}}})$**: This normalization counteracts the linear growth in variance $({d_{\text{head}}})$ of the query-key dot product. The systems consequence is most acute in 16-bit training: when activations grow large, unscaled dot products can produce scores that overflow the 16-bit float range, destabilizing or halting learning entirely.

^fn25

<sup>26</sup> **KV cache memory scaling**: For a 7-billion-parameter transformer in FP16, model weights consume ~14 GB; a single request’s cache requires 32 layers $\times$ 2 (K,V) $\times$ 32 heads $\times$ 2,048 positions $\times$ 128 dimensions $\times$ 2 bytes, or about 1.07 GB. At 8 concurrent users, the cache is ~8.6 GB, a substantial addition to the weights. Because the cache grows linearly with context and concurrency, serving at scale must limit it, for example by sharing keys and values across heads ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-ainslie2023|Ainslie et al. 2023]]), shortening contexts, or storing the cache in fixed-size pages that can be allocated on demand or moved off the accelerator ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-kwon2023|Kwon et al. 2023]]); **[[01 Books/Volume I - Foundations/04 Deployment/13 Model Serving/V1-13.10 LLM Serving#^sec-model-serving-memory-kv-cache-d1ea|Memory and KV cache]]** develops these choices.

^fn26

<sup>27</sup> **Embedding**: Deriving from the mathematical embedding of one space into another, neural embeddings map discrete tokens (such as user IDs or vocabulary words) into continuous vector spaces where geometric proximity captures semantic similarity. Word2vec popularized neural word embeddings in 2013. For systems, embedding tables create a distinctive memory access pattern: each lookup is an irregular read into a potentially terabyte-scale table, producing a sparse, bandwidth-bound workload that makes DLRM different from compute-bound architectures like ResNet.

^fn27

<sup>28</sup> **Vision transformers (ViTs)**: Google’s 2020 ViT paper split $224{\times}224$ images into $16{\times}16$ patches (196 “tokens”) and applied standard transformer attention. ViTs replace CNN’s local convolutions with $\mathcal{O}({S}^2)$ global attention over patch tokens. In the original study, large-scale pretraining improved ViT’s competitiveness, illustrating how data and compute can compensate for weaker spatial inductive bias ([[01 Books/Volume I - Foundations/02 Development/06 Network Architectures/V1-06.14 Source References#^ref-dosovitskiy2021image|Dosovitskiy et al. 2021]]).

^fn28
