# V1 Notation

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]]

^notation

Machine learning systems span *machine learning* (computer science and statistics) and *systems* (computer architecture and hardware). Each field developed its notation independently, and many symbols mean different things across communities and publications. This collision creates real confusion when the disciplines merge. The notation below distinguishes quantities used in both fields.

Consider a simple statement: *“Increasing ${B}$ improves throughput.”* To an ML researcher, ${B}$ means batch size. To a hardware engineer, ${B}$ means bandwidth. Both interpretations are correct in their respective fields, but in machine learning systems we need both concepts in the same equation, which is why a single, consistent convention is needed.

## The Iron Law of ML Systems

^sec-notation-conventions-iron-law-ml-systems-ce9d

Across the Data · Algorithm · Machine (D·A·M) axes, execution time factors into the product of workload scale, algorithmic operations per sample, and realized machine time per operation:

$$
{T} = \underbrace{\left(\frac{\text{Samples}}{\text{Task}}\right)}_{\text{Data}} \times \underbrace{\left(\frac{\text{FLOPs}}{\text{Sample}}\right)}_{\text{Algorithm}} \times \underbrace{\left(\frac{\text{Seconds}}{\text{FLOP}}\right)}_{\text{Machine}}
$$

where the first two factors multiply to set total floating-point operations ${O}$. For serialized execution phases on physical hardware, unpacking how the machine executes those operations gives the three-term iron-law performance decomposition. Each variable is chosen deliberately to avoid collision with standard ML terminology:

$$
{T} = \underbrace{\frac{{D_{\text{vol}}}}{{\text{BW}}}}_{\text{Memory Time}} + \underbrace{\frac{{O}}{{R_{\text{peak}}} \cdot {\eta_{\text{hw}}}}}_{\text{Compute Time}} + \underbrace{{L_{\text{lat}}}}_{\text{Latency Overhead}}
$$

| **Symbol**               | **Definition**     | **Unit** | **Notes**                                                                                                                                                                                                                                                                                                                                                                                         |
|:-------------------------|:-------------------|:---------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **${T}$**                | **Execution Time** | seconds  | Total execution time in the iron-law performance decomposition.                                                                                                                                                                                                                                                                                                                                   |
| **${D_{\text{vol}}}$**   | **Data Volume**    | bytes    | **Avoids collision with ${D}$ (Dataset Size)**. In scaling laws and the D·A·M product, ${D}$ counts logical training samples or tokens. Here we need physical bytes moved through memory. The subscript disambiguates.                                                                                                                                                                            |
| **${\text{BW}}$**        | **Bandwidth**      | bytes/s  | **Avoids collision with ${B}$ (Batch Size)**. Systems literature often uses ${B}$ for bandwidth, while ML literature often uses ${B}$ for batch size. The notation preserves the ML convention.                                                                                                                                                                                                   |
| **${O}$**                | **Operations**     | FLOPs    | Total floating-point operations, the product of $\text{Samples/Task}$ and $\text{FLOPs/Sample}$. Clean in equations (vs. “$\text{Ops}$”).                                                                                                                                                                                                                                                         |
| **${R_{\text{peak}}}$**  | **Peak Rate**      | FLOP/s   | **Avoids collision with ${P}$ (Parameters)**. Roofline presentations often use ${P}$ for performance, while ML literature commonly uses ${P}$ for parameter count. The notation preserves the ML convention.                                                                                                                                                                                      |
| **${\eta_{\text{hw}}}$** | **Efficiency**     | —        | Hardware utilization $(0 \le {\eta_{\text{hw}}} \le 1)$. Measures compute-unit utilization in the three-term decomposition, or end-to-end model FLOPs utilization when data movement and overhead are folded into the single-term training law (**[[01 Books/Volume I - Foundations/02 Development/08 Model Training/V1-08 Model Training#^sec-model-training\|Model Training]]**). Avoids collision with learning rate $({\eta})$. |
| **${L_{\text{lat}}}$**   | **Latency**        | seconds  | **Avoids collision with ${\mathcal{L}}$ (Loss)**. Fixed overhead time (kernel launch, network RTT). The subscript distinguishes from the loss function.                                                                                                                                                                                                                                           |

### Why These Choices Matter

^sec-notation-conventions-choices-matter-0c16

Without careful notation, sentences become ambiguous:

> *“Reducing ${D}$ improves performance.”*

The sentence has two possible readings:

- Reducing **dataset size** (fewer training samples) can speed training but may reduce accuracy.
- Reducing **data volume moved** (for example, through compression or quantization) can speed inference, with accuracy effects that depend on the technique and calibration.

With our notation, we can write precisely and eliminate this ambiguity so that a statement like *“${\text{BW}}$ limits throughput”* has only one reading:

> *“Reducing ${D_{\text{vol}}}$ through FP32-to-INT8 quantization cuts parameter memory traffic to one quarter while ${D}$ (training data) remains unchanged.”*

### Subscripted Variants

^sec-notation-conventions-subscripted-variants

The root names the quantity, and an upright subscript names which instance of it is meant. The convention distinguishes closely related quantities:

- ${\text{BW}_{\text{disk}}}$, ${\text{BW}_{\text{network}}}$, ${\text{BW}_{\text{accelerator}}}$: bandwidth at three points on the data path
- ${D_{\text{vol}}}$, ${R_{\text{peak}}}$, ${L_{\text{lat}}}$, ${\eta_{\text{hw}}}$: iron-law terms, each held clear of a common ML symbol
- ${E_{\text{move}}}$, ${E_{\text{compute}}}$, ${E_{\text{total}}}$: one energy budget split into components

The subscript identifies where a measurement applies. Disk and accelerator bandwidth differ by orders of magnitude, so a reported bandwidth is meaningful only if readers know where it was measured.

## The Degradation Equation

^sec-notation-conventions-degradation-equation-ad12

The degradation equation is an approximation fitted to observed outcomes over a limited range. Divergence alone does not determine whether accuracy rises or falls, so estimate ${\lambda}$ from labeled outcomes. Some symbols below, such as ${\tau}$, appear in chapter prose rather than in the equation.

$$
{\text{Accuracy}}({t}) \approx {\text{Accuracy}_0} - {\lambda} \cdot {\mathcal{D}(P_t \| P_0)}
$$

| **Symbol**                      | **Definition**                            | **Type or unit** | **Notes**                                                                                                                                                                                           |
|:--------------------------------|:------------------------------------------|:-----------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **${\text{Accuracy}}({t})$**    | **Accuracy at Time ${t}$**                | Scalar           | Model accuracy after the model has been deployed for time ${t}$.                                                                                                                                    |
| **${\text{Accuracy}_0}$**       | **Initial Accuracy**                      | Scalar           | Model accuracy at deployment time.                                                                                                                                                                  |
| **${\lambda}$**                 | **Fitted Sensitivity**                    | Scalar           | Local coefficient estimated from outcomes over a stated range; not a universal constant. *(Not wavelength.)*                                                                                        |
| **${P_t}$**                     | **Current Distribution**                  | Distribution     | The data distribution at time ${t}$. *(Not parameters—use ${P}$ for parameter count.)*                                                                                                              |
| **${P_0}$**                     | **Training Distribution**                 | Distribution     | The data distribution at training time.                                                                                                                                                             |
| **${\mathcal{D}(P_t \Vert  P_0)}$** | **Statistical Divergence**                | Scalar $\ge 0$   | Measures how far ${P_t}$ has drifted from ${P_0}$. Common choices: KL divergence, total variation, Wasserstein. *(Calligraphic to avoid collision with ${D}$ = dataset size.)*                      |
| **${\tau}$**                    | **Response Threshold**                    | Scalar $> 0$     | Operational threshold for investigation; it does not automatically trigger retraining. The same symbol marks a classifier’s decision threshold.                                                     |
| **${\mathcal{D}}$**             | **Divergence Measure**                    | Function         | Divergence function that measures how far one probability distribution lies from another, with the specific measure left open.                                                                      |
| **${\mathcal{D}_{\text{KS}}}$** | **Kolmogorov Smirnov Statistic**          | Dimensionless    | Two-sample Kolmogorov-Smirnov statistic, the largest absolute difference between two empirical cumulative distribution functions.                                                                   |
| **${F_{P_0}}$**                 | **Training Empirical CDF**                | Function         | Empirical cumulative distribution function of a feature in the training-baseline sample.                                                                                                            |
| **${x_{\text{feat}}}$**         | **Monitored Feature Level**               | Varies           | One value of a monitored feature, the argument at which its distribution or empirical cumulative distribution function is evaluated. The maximization variable of the Kolmogorov-Smirnov statistic. |
| **${F_{P_t}}$**                 | **Serving Empirical CDF**                 | Function         | Empirical cumulative distribution function of a feature in the current serving sample.                                                                                                              |
| **${c_{\text{crit}}}$**         | **Kolmogorov Smirnov Critical Threshold** | Dimensionless    | Critical threshold that the two-sample Kolmogorov-Smirnov statistic must exceed to reject equal distributions at a given significance level.                                                        |
| **${n}$**                       | **Drift Test Sample Size**                | Integer          | Number of observations in one of the two samples a two-sample drift test compares.                                                                                                                  |
| **${\mathcal{D}_{\text{KL}}}$** | **KL Divergence**                         | Function         | Kullback-Leibler divergence, the expected extra code length from encoding one distribution with a code built for another.                                                                           |
| **${H}$**                       | **Shannon Entropy**                       | bits or nats     | Average uncertainty of a probability distribution, the expected negative log probability of its outcomes. The log base sets the unit: base 2 gives bits, natural log nats.                          |

## The Energy Corollary

^sec-notation-conventions-energy-corollary-a1da

Effective costs per byte moved and per operation give the following approximation for workload energy. The symbols in the table below separate data-movement energy from arithmetic energy and list the circuit-level quantities that govern dynamic power:

$$
{E_{\text{total}}} \approx {D_{\text{vol}}} \times {E_{\text{move}}} + {O} \times {E_{\text{compute}}}
$$

| **Symbol**                 | **Definition**            | **Unit**    | **Notes**                                                                                                                             |
|:---------------------------|:--------------------------|:------------|:--------------------------------------------------------------------------------------------------------------------------------------|
| **${E_{\text{total}}}$**   | **Total Energy**          | joules      | Total energy consumed by an ML workload, decomposed into data-movement and compute terms.                                             |
| **${E_{\text{move}}}$**    | **Energy per Byte Moved** | joules/byte | Effective movement cost; total energy also depends on bytes moved and operations executed.                                            |
| **${E_{\text{compute}}}$** | **Energy per Operation**  | joules/FLOP | Energy cost of a single arithmetic operation.                                                                                         |
| **${C}$**                  | **Switched Capacitance**  | farads      | Capacitance of the wires and gates a circuit charges when it switches.                                                                |
| **${V}$**                  | **Supply Voltage**        | volts       | Supply voltage that powers a digital circuit, the quantity dynamic voltage and frequency scaling lowers.                              |
| **${f}$**                  | **Clock Frequency**       | hertz       | Rate at which a processor’s clock ticks, setting how many switching cycles occur per second.                                          |
| **${P_{\text{cluster}}}$** | **Cluster Power**         | watts       | Power drawn by a training cluster, including accelerators and hosts. Average power multiplied by training time gives training energy. |
| **${P_{\text{device}}}$**  | **Device Power**          | watts       | Electrical power one device draws. Integrated over time it gives the device’s energy.                                                 |
| **${P_{\text{dynamic}}}$** | **Dynamic Power**         | watts       | Power a chip draws switching its transistors, proportional to switched capacitance, supply voltage squared, and clock frequency.      |
| **${P_{\text{avg}}}$**     | **Average Power**         | watts       | Power drawn averaged over a stated period.                                                                                            |

| **${n_{\text{keep}}}$**                   | **Structured Sparsity Nonzero Count**     | Integer                         | Number of values kept nonzero in each group of an N:M structured-sparsity pattern.                                                                                                              |
| **${m_{\text{group}}}$**                  | **Structured Sparsity Group Size**        | Integer                         | Number of consecutive values in one group of an N:M structured-sparsity pattern.                                                                                                                |
| **${K_h}$**                               | **Kernel Height**                         | Integer                         | Height of a convolution kernel, in input positions.                                                                                                                                             |
| **${K_w}$**                               | **Kernel Width**                          | Integer                         | Width of a convolution kernel, in input positions.                                                                                                                                              |
| **${k}$**                                 | **Top Class Count**                       | Integer                         | Number of highest-scoring classes a top-k prediction returns or checks for the correct label.                                                                                                   |
| **${\mu}$**                               | **Service Rate**                          | items/s                         | Rate at which one server, such as a worker, consumer, or model endpoint, completes items or calls.                                                                                              |
| **${\hat{y}}$**                           | **Model Prediction**                      | Dimensionless                   | Prediction a model outputs for one example, compared with its label by the loss.                                                                                                                |
| **${\mathbf{Y}}$**                        | **Layer Output Matrix**                   | Matrix                          | Output matrix of a layer’s matrix multiplication of the input matrix by the weight matrix, one row per example. Shape batch size by layer output width; before any bias or activation function. |
| **${m}$**                                 | **Softmax Row Maximum**                   | Dimensionless                   | Largest score in a softmax row or block, subtracted before exponentiation to prevent overflow.                                                                                                  |
| **${x}$**                                 | **Softmax Input Score**                   | Dimensionless                   | One entry of the score vector the online softmax normalizes. Written with an index and a block superscript, ${x}_j^{(1)}$.                                                                      |
| **${\alpha_{\text{sym}}}$**               | **Symmetric Clipping Threshold**          | Varies                          | Largest magnitude a symmetric quantizer represents, so values are clipped to plus or minus this bound.                                                                                          |

Latin matrices and vectors are set in bold (${\mathbf{W}}$, ${\mathbf{x}}$); scalars, dimensions, indices, and individual matrix entries stay italic (${N}$, ${d}$, ${i}$, ${W_{ij}}$). The generic parameter symbol ${\theta}$ is the one conventional exception and stays italic.

Local matrix algebra follows the same bold rule. Matrix operands are bold (${\mathbf{A}}$, ${\mathbf{B}}$, ${\mathbf{C}}$), as in general matrix multiply (GEMM) ${\mathbf{C}}={\alpha} {\mathbf{A}}{\mathbf{B}}+{\beta} {\mathbf{C}}$. The bold form marks a matrix operand and is distinct from the italic scalar batch size ${B}$, which remains batch size in scalar contexts.

A GEMM’s scalar dimensions are ${M}$, ${N}$, and ${K}$ (${\mathbf{A}}$ is ${M} \times {K}$, ${\mathbf{B}}$ is ${K} \times {N}$). Asymptotic cost is written $\mathcal{O}(\cdot)$, which keeps it distinct from the operation count ${O}$.

## Performance, Serving, and Memory Notation

^sec-notation-conventions-performance-serving-memory

Reusable performance and serving quantities follow the same collision-avoidance rule as the iron law. Rates use ${R}$ or descriptive Greek symbols; request counts use ${Q_{\text{req}}}$ rather than overloading ${N}$; queue utilization uses a subscripted ${\rho}$ so bare ${\rho}$ remains available for other ratio models.

| **${I_{\text{ridge}}}$**               | **Roofline Ridge Point**         | FLOP/byte        | ${I_{\text{ridge}}} = {R_{\text{peak}}}/{\text{BW}}$. Prefer this explicit form over starred shorthand so the meaning remains clear in prose.                                                                                |
| **${R_{\text{attain}}}$**              | **Attainable Compute Rate**      | FLOP/s           | Roofline bound: ${R_{\text{attain}}} \leq \min({R_{\text{peak}}}, {I} \times {\text{BW}})$. | **${\text{MFU}}$**                     | **Model FLOPs Utilization**      | Dimensionless    | Useful model FLOP/s divided by available peak FLOP/s. Text acronym avoids overloading ${\eta}$.                                                                                                                              |
| **${Q_{\text{req}}}$**                 | **Request Concurrency**          | requests         | Average in-flight requests in a stable serving system (${Q_{\text{req}}} = {\lambda_{\text{arr}}} \cdot {T_{\text{lat}}}$ via Little’s Law). ## Units and Precision

^sec-notation-conventions-units-precision-fdaf

- **Physical units**: This book uses SI (metric) units throughout, including meters, kilograms, seconds, watts, and °C, consistent with standard engineering and scientific practice. Where source data was originally reported in imperial units, the book converts to SI and notes the original values parenthetically. A space always separates the number from the unit (for example, 100 ms, 2 TB/s).
- **Data and memory**: This book uses **decimal SI prefixes only**: KB = $10^3$ bytes, MB = $10^6$, GB = $10^9$, TB = $10^{12}$. Binary-prefixed units do not appear in prose; model sizes, activation footprints, throughputs, and transfer volumes are reported in decimal units (for example, 2 TB/s, 102 MB). Hardware memory capacities retain the vendor’s nameplate figure and label. Calculations requiring an exact byte count use the device’s documented capacity.
- **Compute**: The notation distinguishes operation counts from rates. Total work uses FLOPs (for example, GFLOPs, TFLOPs), while throughput uses FLOP/s with decimal prefixes (for example, GFLOP/s, TFLOP/s).
  - 1 TFLOP = $10^{12}$ FLOPs
  - 1 TFLOP/s = $10^{12}$ FLOPs per second
  - Arithmetic intensity conventionally uses FLOP/byte as a unit ratio (floating-point operations per byte moved). This is a ratio unit, not a total-work symbol or throughput symbol.
- **Power**: Power carries a subscript (${P_{\text{avg}}}$, ${P_{\text{device}}}$, ${P_{\text{cluster}}}$); bare ${P}$ remains parameter count.
- **Latency percentiles**: Written p50, p95, and p99 in upright type, inside math as well as in prose.
- Currency: Dollar amounts use the dollar sign (`$`); unless otherwise noted, dollar-denominated costs are U.S. dollars (USD).
- **Precision**:
  - **FP64**: Double precision (8 bytes)
  - **FP32**: Single precision (4 bytes)
  - **TF32**: TensorFloat-32 (19-bit Tensor Core compute mode; inputs and storage remain FP32)
  - **FP16**: Half precision (2 bytes, standard range)
  - **BF16**: Brain float (2 bytes, wide dynamic range)
  - **FP8**: Quarter precision (1 byte, E4M3 or E5M2 format)
  - **FP4**: 4-bit floating-point format
  - **INT8**: 8-bit integer (1 byte)
  - **INT4**: 4-bit integer; lower integer precisions follow the same uppercase `INTn` pattern (for example, INT3, INT2)

## Quick Reference: Resolving Collisions

^sec-notation-conventions-quick-reference-resolving-collisions-a9cf

| **Symbol**   | **ML Meaning**  | **Systems Meaning** | **Book Convention**                                             |
|:-------------|:----------------|:--------------------|:----------------------------------------------------------------|
| **${B}$**    | Batch Size      | Bandwidth           | **Batch Size**. Use ${\text{BW}}$ for bandwidth.                |

| **${D}$**    | Dataset Size    | Data Volume         | **Dataset Size**. Use ${D_{\text{vol}}}$ for bytes moved.       |
| **${L}$**    | Loss            | Latency             | **Loss** $({\mathcal{L}})$. Use ${L_{\text{lat}}}$ for latency. |
| **${\eta}$** | Learning Rate   | Efficiency          | **Learning Rate**. Use ${\eta_{\text{hw}}}$ for efficiency.     |
