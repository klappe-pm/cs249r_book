# V1-02.02 Four Deployment Regimes Across Nine Orders of Magnitude

[[Home|Home]] · [[01 Books/Volume I - Foundations/Volume 1 Overview|Volume Overview]] · [[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02 System Paradigms|V1-02 System Paradigms]]

^sec-ml-systems-deployment-paradigm-framework-0d25

A wake-word detector on a smartwatch operates inside milliwatt power budgets and kilobyte memory limits, whereas a recommendation engine in a data center draws on terabytes of embedding tables and megawatt-scale infrastructure. The two sit at opposite ends of the range of machines that run ML. The introduction’s D·A·M taxonomy (**[[01 Books/Volume I - Foundations/00 Introduction/01 Introduction/V1-01.06 Defining ML Systems#^fig-ai-triad|The D·A·M Intersection Landscape]]**) treated Data, Algorithm, and Machine as three interacting dimensions of one design problem, and across real deployments the machine is the dimension that changes most sharply. Its physical limits decide which data and algorithmic choices remain open.

![[90 Assets/Volume I/02 System Paradigms/System Paradigms Dam Locator e525c33bae.svg]]

*D·A·M locator triangle with the Machine node highlighted and the Data and Algorithm nodes shown in gray.*

*The machine axis sets the deployment envelope.*

Those physical constraints govern where a model can run in ways no algorithmic choice can override, and they constrain the entire system rather than the model weights alone. Data ingestion pipelines, feature extraction, serving runtimes, telemetry, and hardware resource managers must all fit inside the host platform’s physical envelope.

![[90 Assets/Volume I/02 System Paradigms/System Paradigms Deployment Span 92b63426dc.svg]]

*Vertical bar ladder of four deployment tiers by power on a log scale: Cloud 3 MW, Edge 200 W, Mobile 5 W, TinyML 1 mW, spanning megawatts to milliwatts.*

*Power falls from megawatts in the cloud to milliwatts in TinyML.*

Three physical limits, namely latency, power dissipation, and memory, organize that span from megawatts to milliwatts into four deployment paradigms.[[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.17 Footnotes#^fn1|¹]] The pairing of a workload with its target platform determines which limit is reached first. Centralizing computation in Cloud ML provides elastic compute and large memory capacity, at the cost of wide-area network latency on every inference. Moving workloads to Edge ML eliminates that network round trip and keeps sensitive data on premises ([[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.16 Source References#^ref-shi2016|Shi et al. 2016]]), but it caps available compute at local site power and cooling budgets. Stepping onto battery-powered devices, Mobile ML delivers responsive interaction directly on handsets and tablets, within a passive thermal envelope where sustained computation triggers throttling, the chip slowing itself down to shed heat. At the low-power extreme, TinyML runs on microcontrollers ([[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.16 Source References#^ref-janapa-reddi2022-012788b4|Janapa Reddi et al. 2022]]) whose milliwatt power budgets and kilobyte memories require compact models and integer arithmetic.

The four categories overlap, because edge describes physical proximity to data whereas mobile and TinyML distinguish local devices by their resource envelopes. Arranged along one physical continuum, these tiers run from warehouse-scale megawatts in data centers down to milliwatts on embedded microcontrollers ([[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.02 Four Deployment Regimes Across Nine Orders of Magnitude#^fig-cloud-edge-TinyML-comparison|figure 1]]). The figure draws spans for TinyML, edge AI, and cloud AI; mobile ML sits at the intelligent-device position, between the ultra-low-power sensors and the gateway.

![[90 Assets/Volume I/02 System Paradigms/Generated Figure c073474dc6.svg]]

Figure 1: **Distributed Intelligence Spectrum**: Deployment tiers form a continuum governed by physical constraints, spanning nine orders of magnitude in power. Moving from centralized cloud infrastructure to on-device TinyML trades raw computational capacity and elastic scale for shorter communication paths, data locality, and network independence.

^fig-cloud-edge-TinyML-comparison

While [[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.02 Four Deployment Regimes Across Nine Orders of Magnitude#^fig-cloud-edge-TinyML-comparison|figure 1]] traces the continuous progression from embedded sensors to data centers, [[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.02 Four Deployment Regimes Across Nine Orders of Magnitude#^tbl-deployment-paradigms-overview|table 1]] quantifies conceptual operating envelopes across processing location, round-trip latency, power draw, and memory capacity. The cloud row describes facility power; the other rows describe local systems or devices. These envelopes compare deployment scales, whose physical basis is developed in [[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.03 Physical Constraints on Deployment#^sec-ml-systems-deployment-spectrum-71be|section 2.2]].

| **Paradigm**  | **Where**        | **Latency (ms)** | **Power** | **Memory** | **Best For**                 |
|:--------------|:-----------------|:----------------:|:---------:|:----------:|:-----------------------------|
| **Cloud ML**  | Data centers     |     100-500      |    MW     |     TB     | Training, complex inference  |
| **Edge ML**   | Local servers    |      10-100      |   100 W   |     GB     | Real-time inference, privacy |
| **Mobile ML** | Smartphones      |       5-50       |   3–5 W   |     GB     | Personal AI, offline         |
| **TinyML**    | Microcontrollers |       1-10       |    mW     |     KB     | Always-on sensing            |

Table 1: **The Deployment Spectrum (Conceptual)**: Four paradigms span nine orders of magnitude in power (MW to mW) and memory (TB to KB). This conceptual overview defines each paradigm by its operating regime, and each power entry names a typical class rather than a bound; the concrete hardware spectrum in [[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.05 System Balance and Hardware#^tbl-representative-systems|table 4]] grounds these categories in specific platforms and quantitative decision thresholds. The hardware specifications and physical constants underpinning these numbers are catalogued in **[[05 Reference/Volume I - Foundations/V1 System Assumptions#^sec-appdx-system-assumptions|System Assumptions]]**.

^tbl-deployment-paradigms-overview

At every tier, the hardware offers a **silicon contract**: a compute rate, a memory bandwidth, and an execution overhead. Each of these enters one term of the iron law of ML systems (**[[01 Books/Volume I - Foundations/00 Introduction/01 Introduction/V1-01.08 Iron Law of ML Systems#^sec-introduction-iron-law-ml-systems-c32a|Iron Law of ML Systems]]**, restated in this chapter as [[01 Books/Volume I - Foundations/01 Foundations/02 System Paradigms/V1-02.04 Analyzing Workloads#^eq-iron-law|equation 4]]), which decomposes end-to-end execution time into data movement, computation, and fixed overhead. Memory bandwidth sets the data-movement time, the compute rate sets the computation time, and the execution overhead is the fixed time a request pays regardless of its size, such as scheduling and runtime dispatch. A remote deployment adds network round trips to that overhead. Different tiers offer different budgets for these resources, because physical constraints set them. The contract also carries a memory capacity, which is not a term of execution time but a precondition that decides whether a workload fits on the tier at all. On battery-powered tiers it carries a second precondition, an energy budget, which decides whether the tier can afford to run the workload as often as the application needs.

The hardware itself spans a continuum, but three physical limits each take over in a different part of that range: the speed of light, thermal dissipation, and memory signaling, the time and energy needed to move data between memory and the processor. Those shifting limits are why deployment paradigms exist as distinct engineering regimes rather than arbitrary points on a continuous slider.
