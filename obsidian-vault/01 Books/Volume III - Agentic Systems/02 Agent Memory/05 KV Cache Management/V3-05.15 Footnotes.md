# V3-05.15 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05 KV Cache Management|V3-05 KV Cache Management]]

^footnotes

<sup>1</sup> **Memory-Limited Inference**: Caching keys and values trades quadratic recomputation for persistent memory capacity, and that memory quickly becomes the primary serving bottleneck. An analytical study of large-model serving revealed that sharing a single key-value head across all query heads allowed an identical deployment to serve contexts more than an order of magnitude longer, precisely because retained attention state, rather than compute throughput, bounded context length and batch concurrency ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-pope2023efficiently|Pope et al. 2023]]).

^fn1

<sup>2</sup> **Multi-Query Attention**: Motivated primarily by memory bandwidth rather than storage capacity (incremental decoding reloads stored key and value tensors at each generation step), sharing key-value tensors across query heads drastically reduces memory bus traffic alongside physical storage with minimal quality loss ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-shazeer2019fast|Shazeer 2019]]). Grouped-query attention subsequently recovered nearly all multi-head attention quality while preserving the bulk of these memory savings ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-ainslie2023gqa|Ainslie et al. 2023]]).

^fn2

<sup>3</sup> **Latent KV Compression**: Multi-head latent attention compresses keys and values into a single low-rank latent vector per token and dynamically reconstructs per-head tensors during attention, exchanging additional projection arithmetic for a substantially smaller memory footprint ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-deepseek2024v2|DeepSeek-AI et al. 2024]]). Although this technique modifies the calculation of ${m_{\text{token}}}$ in [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^eq-mem-token|equation 1]], it preserves the same system dynamics: latent cache tensors must still be paged, allocated, retained across idle periods, and evicted under memory pressure.

^fn3

<sup>4</sup> **Internal and External Fragmentation**: The analysis of storage allocation that named the two losses also measured their trade: rounding requests up to fewer standard sizes cost more storage in internal fragmentation than it recovered in external fragmentation ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-randell1969fragmentation|Randell 1969]]). Paged KV allocation makes the same trade on purpose, accepting at most one partial block per sequence in exchange for a pool in which any free block fits any request.

^fn4

<sup>5</sup> **Copy-on-Write**: The TENEX time-sharing system of the early 1970s gave each page a status bit that let processes share large parts of an address space and obtain private copies of only the pages they changed ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-bobrow1972tenex|Bobrow et al. 1972]]). Forked candidates reuse the idea at block granularity, which is why a fan-out of sampled repairs costs private blocks in proportion to what each candidate writes, not to the prefix they share.

^fn5

<sup>6</sup> **Compressed Prefix Tree**: The trie stored one symbol per edge, so a shared prefix was found by walking from the root ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-fredkin1960|Fredkin 1960]]). PATRICIA collapsed chains of single-child nodes into one edge, so index size grows with the number of stored keys rather than their length ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-morrison1968patricia|Morrison 1968]]). The same compression matters for KV reuse, because agent prefixes run to thousands of tokens and a one-token-per-edge index would spend a node on each of them.

^fn6

<sup>7</sup> **Replacement with Foresight**: The classic study of page replacement showed that the optimal policy evicts the page whose next use lies furthest in the future, a rule no online system can apply because it needs the future reference string ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-belady1966study|Belady 1966]]). Recency-based policies approximate it. An agent harness sometimes holds part of that future, such as a tool launch that will idle a prefix for minutes, which is why a retention hint from the caller can beat recency alone.

^fn7

<sup>8</sup> **Thrashing**: Multiprogrammed virtual-memory systems of the 1960s encountered this exact pathology: when the aggregate working sets of resident programs exceeded main memory, page faults forced continuous eviction of recently used pages, and processors spent their execution cycles servicing I/O rather than executing instructions ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-denning1968thrashing|Denning 1968b]]). The solution was explicit load control: restricting the multiprogramming level until the working sets of admitted programs fit comfortably in physical memory. In agentic KV cache serving, the corresponding remedy is admission control against the retained state of active trajectories, rather than tuning eviction algorithms to page faster.

^fn8
