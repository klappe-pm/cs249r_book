# V3-05.03 The Footprint of Retained Attention State

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05 KV Cache Management|V3-05 KV Cache Management]]

^sec-vol3-kvcache-geometry

The r18 request’s 32,768 tokens do not reach the accelerator as raw text. During causal self-attention in a Transformer decoder, each newly generated token attends to earlier tokens through their key and value projections ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-vaswani2017|Vaswani et al. 2017]]). Recomputing these projections at every decode step would repeat the linear transformations over the entire historical prefix, creating an unsustainable quadratic compute bottleneck. Serving engines avoid this recomputation by retaining the computed key and value tensors in accelerator memory across decode cycles.[[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.15 Footnotes#^fn1|¹]] While autoregressive decoding relies on retained attention state, sustaining long-horizon agent execution requires managing its physical capacity, allocation overhead, and multi-tenant residency.

↩︎ Retained attention state in autoregressive decoding is established in **[[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.05 Autoregressive Generation#^sec-vol3-foundation-model-conditional-token-selection|Token-by-token generation]]**.

**Definition 5.1: KV cache**

***KV cache*** is the per-sequence store of attention keys and values that the model has computed for already processed tokens, retained so that later tokens can attend to them without recomputing their projections.

1.  **Significance**: Its payload scales linearly with retained tokens; consequently, sequence context length, rather than static model parameter count, determines how many concurrent requests can share the memory pool remaining after loading model weights.
2.  **Distinction**: It represents intermediate projected state rather than a raw copy or semantic compression of input text. Reconstructing it requires executing the exact token sequence through identical model weights and layer configurations.
3.  **Common pitfall**: Budgeting only for input prompts. Every newly decoded output token appends key and value states at every layer, so a request reaches its maximum memory footprint at completion rather than during initial prefill.

For a decoder employing causal self-attention with uniform layer geometry, every retained token contributes both a key vector and a value vector across all layers. Let ${N_L}$ represent the number of layers, ${H_{\text{KV}}}$ the number of key-value heads per layer, ${d_{\text{head}}}$ the dimension of each head, and ${s_{\text{elem}}}$ the storage size in bytes per element. Accounting for both vectors yields the memory footprint per token:

$$
{m_{\text{token}}} = 2 \cdot {N_L} \cdot {H_{\text{KV}}} \cdot {d_{\text{head}}} \cdot {s_{\text{elem}}} \tag{1}
$$

^eq-mem-token

A sequence retaining attention state across ${S}$ tokens requires an aggregate cache payload of ${M_{\text{KV}}} = {S} \cdot {m_{\text{token}}}$. Here ${S}$ counts only the tokens whose keys and values have already been evaluated; each newly sampled token increments ${S}$ once the model completes its forward pass.

The key-value head count ${H_{\text{KV}}}$ in [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^eq-mem-token|equation 1]] represents the number of stored attention heads, which often falls below the query head count. Multi-query attention pushed this reduction to its structural extreme by sharing a single key-value head across all query heads[[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.15 Footnotes#^fn2|²]] ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-shazeer2019fast|Shazeer 2019]]). **Grouped-query attention** strikes an intermediate balance: several query heads share one key-value head, dividing the stored key-value head count by the group size relative to a standard multi-head design ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.14 Source References#^ref-ainslie2023gqa|Ainslie et al. 2023]]), a scaling quantified across attention designs in **[[05 Reference/Volume III - Agentic Systems/V3 Inference Cost Foundations#^tbl-appdx-kv-cache-scaling|Attention State by Attention Design]]**. Because this head grouping is established during pretraining, a serving allocator cannot dynamically drop heads from an existing checkpoint without changing the model’s computations.

While [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^eq-mem-token|equation 1]] accounts for the raw tensor payload under dense causal attention, physical memory consumption in production serving engines exceeds this theoretical bound. Allocation block granularities, memory alignment, page table metadata, and quantization scales all add runtime overhead. Non-uniform architectures, such as sliding-window attention or compressed latent representations, require their own capacity models.

None of the r18 context’s internal structure survives into [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^eq-mem-token|equation 1]]. In [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^fig-vol3-context-window-anatomy|figure 1]], the prompt zones follow the change-rate order of context staging: a shared invariant prefix of system instructions, tool schemas, and slow-changing workspace description, followed by the growing trajectory state of turn history and the active turn’s latest observation. Once processed, every zone becomes identical-format key and value tensors at every layer, so the entire 32,768-token context occupies 10.7 GB regardless of what its zones contain.

To translate that per-context payload into node capacity, the worked estimate below uses a representative configuration: the Llama 3 70B model geometry, with 70.6B parameters, and a DGX H100 node containing 8 accelerators. While specific hardware platforms and checkpoint dimensions vary, the underlying capacity arithmetic remains unchanged. Unlike the single-device, 8-bit illustration in **[[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.09 The Cost of a Model Call#^sec-vol3-foundation-model-per-call-work-estimate|Estimating per-call hardware work]]**, both weights and KV cache tensors use 16-bit storage here, with the model weights sharded across the node’s accelerators by tensor parallelism. The aggregate high-bandwidth memory remaining after provisioning model weights and a runtime reserve constitutes the **KV pool**. The number of active sequences whose KV payloads can reside simultaneously within this pool defines the **resident-fit bound**. This aggregate derivation assumes perfectly balanced shards without redundant weight replication; in production, memory limits must be satisfied on every individual accelerator device.

**Napkin Math 5.1: Sizing the attention state of an agent trajectory**

**Problem**: Consider a server node of 8 accelerators, each with 80 GB (vendor-rated in binary gigabytes, about 85.9 GB in the decimal units used throughout this chapter), for 687.2 GB of aggregate accelerator memory. Model weights occupy 141.2 GB, and the runtime reserves 20 GB for dynamic activations and scratch buffers. Under full causal attention without prefix sharing, how many independent sequences can simultaneously reside in the remaining memory across different context lengths?

**Math**: Evaluating [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^eq-mem-token|equation 1]] for this architecture yields ${m_{\text{token}}} = 2 \times 80 \times 8 \times 128 \times 2 = 327,680\;\text{bytes/token}$. For an agent trajectory retaining 32,768 tokens, the footprint becomes ${M_{\text{KV}}} = 32,768 \times 327,680\;\text{bytes} \approx 10.7\;\text{GB}$.

Subtracting model parameters and runtime buffers isolates the usable capacity: $687.2 - 141.2 - 20 \approx 526.0\;\text{GB}$. Dividing this available pool by the footprint per sequence and taking the floor determines the resident-fit bound. Using exact floating-point values prior to display rounding yields $\left\lfloor 525.994767360 / 10.737418240 \right\rfloor = 48$. [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^tbl-vol3-kv-payload-fit|Table 1]] evaluates this bound across three operational context regimes.

| **Retained tokens** | **KV payload per sequence** | **Sequences that fit** |
|:-------------------:|:---------------------------:|:----------------------:|
|        8,192        |           2.7 GB            |          195           |
|       32,768        |           10.7 GB           |           48           |
|       131,072       |           42.9 GB           |           12           |

Table 1: **Payload and resident fit**: Each sequence stores its own full-attention state; the calculation excludes allocator overhead and additional headroom.

^tbl-vol3-kv-payload-fit

**Systems insight**: Resident capacity scales inversely with retained context length. Because model weights occupy a fixed memory slice regardless of context, expanding sequence length directly cannibalizes the cache pool. Each fourfold increase in sequence length (from 8,192 to 32,768, and onward to 131,072 tokens) reduces the resident sequence capacity by roughly 75 percent. Retained context length is the primary control lever governing serving capacity, and the agent runtime directly governs it. Maintaining an active working set rather than accumulating unbounded historical observations (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-attention-working-set|4]]) keeps requests operating in the high-density rows of [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^tbl-vol3-kv-payload-fit|table 1]]. These figures are raw tensor payloads; physical memory allocators, page fragmentation, and safety headroom further reduce actual capacity, while translating instantaneous resident capacity into sustainable request throughput requires analyzing sequence residence times ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.09 Capacity for Agent Workloads#^sec-vol3-kv-workload-dynamics|section 5.8.2]]).

Because model weights incur a one-time memory cost amortized across all concurrent requests, every independent sequence adds its private attention state to the pool unless the serving engine caches and reuses common prefixes across turns. Within each sequence, model architecture and numerical precision set the per-token payload before memory allocation even begins. An architecture trained with fewer key-value heads or compressed latent representations[[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.15 Footnotes#^fn3|³]] reduces the state generated per token. Quantizing keys and values to 8-bit or 4-bit representations halves or quarters the raw element bytes ${s_{\text{elem}}}$. It does so at the cost of dequantization scale metadata and potential numerical degradation, which engineers must validate against target task benchmarks. Regardless of compression, every retained byte remains allocated physical memory tied to an active execution lifecycle. How much the architecture moves that payload is easiest to see across published geometries. [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^fig-vol3-kv-footprint-by-architecture|Figure 2]] evaluates [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^eq-mem-token|equation 1]], and its latent-attention counterpart, for six registered models: one with full multi-head attention, four with grouped-query attention, and one with multi-head latent attention.

The spread in [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^fig-vol3-kv-footprint-by-architecture|figure 2]] is fixed at pretraining; the serving engine can work within it but cannot change it. Full multi-head attention in the GPT-3 (175B) geometry retains 4,718.6 KB per token, 67× the 70.3 KB of the latent-attention DeepSeek-V3; even the grouped-query Llama-3.1-70B of the worked estimate retains 4.7× as much. At the 131,072 tokens of the long regime, that is 42.9 GB against 9.2 GB for one session. The choice of model therefore fixes the slope of every capacity line in this chapter, and the runtime’s levers (retained tokens, sharing, precision, and eviction) act only along that slope. Whatever the slope, each retained byte stays allocated for as long as its sequence holds the prefix, which is where the lifecycle decisions begin.

Model geometry and numerical precision fix the raw tensor payload per token, setting an idealized ceiling on how many sequences fit in the KV pool at once. Reaching that ceiling in a live service, however, requires translating theoretical tensor footprints into physical memory allocations for sequences whose final length is unknown when they arrive. If the allocator statically pre-allocates contiguous buffers for each request’s maximum potential context, unused reservation slack exhausts the memory pool long before actual tensor payloads fill device capacity.
