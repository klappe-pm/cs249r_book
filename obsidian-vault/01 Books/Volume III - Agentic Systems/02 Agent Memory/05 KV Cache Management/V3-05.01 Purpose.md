*Why can an agent that is generating nothing still exhaust the memory of the machine serving it?*

An agent spends much of its life waiting. While a test suite runs or a remote service responds, the model generates nothing, yet the attention state computed from the request’s prefix can stay resident in accelerator memory, holding capacity that another request could put to work. That state is large, it grows with every token the trajectory carries, and its size is fixed by the model’s geometry rather than by any choice the agent makes. A serving engine that reserves room for the longest request it might see strands much of its memory, and one that copies a shared prefix into every branch pays for the same state many times over. At each pause the engine must choose among keeping the state resident, moving it to slower memory, and dropping it to rebuild from the tokens when the agent resumes. Each option trades memory against the delay before the next output token, and the right one depends on how long the wait will last. Capacity is therefore set less by how many contexts fit at once than by how long each one stays, because a context that holds memory through a long tool wait serves no turns while it keeps its place. Managing retained attention state turns the state an agent carries into a priced claim on the machine serving it, sized against the turn rate the service must sustain.

**Learning Objectives**

- Calculate retained attention-state memory and resident fit from model geometry, token count, and storage precision
- Calculate the memory that block allocation and prefix sharing recover from full-cap reservation and duplicated prefixes
- Distinguish compatible, available prefix reuse from the applicability of the underlying information
- Calculate the token-weighted prefix hit rate of a radix prefix cache under leaf-first eviction
- Select a chunked-prefill token budget that bounds the gap between output tokens for ongoing requests
- Evaluate keep, move, and recompute policies for paused state against memory pressure, resume latency, and lossy approximation risk
- Analyze how residence time converts a memory-fit bound into a sustainable turn rate
