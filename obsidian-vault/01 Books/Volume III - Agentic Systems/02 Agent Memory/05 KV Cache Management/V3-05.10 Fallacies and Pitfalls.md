# V3-05.10 Fallacies and Pitfalls

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05 KV Cache Management|V3-05 KV Cache Management]]

^sec-vol3-kv-cache-fallacies

Most KV-cache failures in production agent deployments come from two mistakes. The first is treating an instantaneous memory-fit count as a throughput guarantee while idle tool waits hold slots for tens of seconds. The second is treating a fast prefix-cache hit as proof that the underlying environment state is still current. Each fallacy and pitfall below pairs the failure mode with its concrete cost on the reference node.

**Fallacy**: *Model size, not retained context, decides how many sequences a node can serve.*

Static model weights consume a fixed footprint allocated at initialization, leaving a 526.0 GB pool dedicated to dynamic attention state on the reference node. While model parameters establish the initial baseline headroom, the active context length of running sequences governs dynamic memory consumption. Holding the model constant, that memory pool accommodates 195 unshared sequences when context is kept to 8,192 tokens, but capacity plunges to just 12 concurrent sequences once context expands to 131,072 tokens ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.03 The Footprint of Retained Attention State#^sec-vol3-kvcache-geometry|section 5.2]]). Retained context length serves as the primary operational lever governing system concurrency, and the agent harness dictates that length through its prompt construction, tool history, and conversation buffering. Swapping in a smaller model only increases concurrent serving capacity to the extent that it reduces the per-token memory footprint ${m_{\text{token}}}$ or frees up additional accelerator memory for the KV pool.

**Pitfall**: *Reserving every request’s maximum context.*

Allocating contiguous memory upfront for each request’s worst-case context length severely throttles system throughput through internal fragmentation. When a serving system sizes every slot for a 32,768-token cap while requests average a final length of only 2,048 tokens, barely 6.25 percent of the allocated memory actually holds valid attention state upon completion. Under this static reservation regime, the reference pool can admit only 48 concurrent sequences. In contrast, paged virtual memory allocation dynamically allocates physical blocks on demand, giving the final-length snapshot estimate of approximately 780 over the same physical memory ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.05 Paged KV Allocation#^sec-vol3-kvcache-pagedattention|section 5.4]]). Systems should allocate memory blocks incrementally as tokens arrive during prefill and generation, reserving the output allowance the admission controller promises, as the capacity notebook does, rather than the full context cap.

**Fallacy**: *Compatible cached attention state proves that its evidence is current.*

Prefix caching operates strictly at the level of token identifiers and model configurations, without semantic awareness of environment state or external reality. On the reference node, a prefix match on the agent repair loop’s 4,096-token invariant prompt saves roughly 169 ms of prefill computation per turn ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.06 Prefix Caching Across Turns#^sec-vol3-kvcache-radix-tree|section 5.5]]). The inference engine achieves that speedup regardless of whether those cached tokens reflect stale diagnostics from revision 17 (r17) or up-to-date observations from the current repository source. Prefix match compatibility only confirms that the token sequence and attention architecture match bit-for-bit. Determining whether an earlier r17 failure supports a claim about revision 18 (r18) requires semantic validation in the agent harness before serializing the prompt. Updating the prompt with fresh r18 observations breaks prefix reuse at the first modified token and forfeits part of that computational saving. That forfeited saving is the correct price of grounding the next decision in current evidence (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-source-authority|6]]). Under that principle, no cached, staged, or derived copy supersedes the designated source for the claim it represents, which here is the repository at r18.

↪ Every staged or cached claim is validated against a designated source of record, whose role is developed in **[[01 Books/Volume III - Agentic Systems/02 Agent Memory/06 Long-Term Memory/V3-06.03 Persistent Records#^sec-vol3-long-term-memory-record-roles|Record roles]]**.

**Pitfall**: *Always moving paused state out of accelerator memory.*

Blindly offloading KV cache blocks to host memory whenever an agent pauses to execute an external tool wastes interconnect bandwidth and inflates resumption latency. Evacuating the 10.74 GB attention state for a paused repair agent requires 42 ms of link transfer, which adds 21 ms of overhead before the model can resume generation. When the memory pool contains plenty of free blocks, this offload latency provides zero benefit to the system. Conversely, under heavy contention, offloading that same state frees valuable high-bandwidth accelerator memory for 44.98 s across an extended 45 s tool invocation ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.08 Paused-State Policies#^sec-vol3-kvcache-swapping|section 5.7]]). Serving schedulers must evaluate eviction dynamically based on uniquely reclaimable blocks, active queue pressure, and expected resumption deadlines. An external tool call marks an opportunity for scheduling decisions rather than an automatic eviction trigger.

**Fallacy**: *A resident-fit count is a throughput guarantee.*

Calculating how many concurrent request snapshots fit into physical accelerator memory establishes an instantaneous capacity limit, not a sustained throughput guarantee. The reference node fits 41 unshared repair trajectories in memory simultaneously. However, if those sessions hold their memory allocations across an idle 45 s tool pause, the node sustains a maximum of only 0.82 turns/s from memory alone. If the engine instead releases those memory slots during the pause, the memory-only throughput bound rises to 8.2 turns/s (notebook [5.4](https://mlsysbook.ai/vol3/05_kv_cache/05_kv_cache.html#nbk-05-residency-tax)). Memory fit dictates maximum concurrency (${\bar{N}_{\text{slot}}}$), but Little’s law (${\bar{N}_{\text{slot}}} = {\lambda_{\text{arr}}} {\bar{T}_{\text{hold}}}$) dictates that arrival throughput (${\lambda_{\text{arr}}}$) is governed equally by mean residence time (${\bar{T}_{\text{hold}}}$). When agent turns involve long execution pauses or queueing delays, residence time inflates and throughput collapses even though memory looks full. Occupancy stays high, but most of the resident state is idle, so the turn rate is low. Schedulers must validate admission against offered traffic distributions, burst arrivals, and latency targets rather than relying on static slot counts.

**Pitfall**: *Treating KV storage as the authoritative task record.*

The KV cache is a hardware-bound optimization artifact, not a durable system of record. Dropping the 10.74 GB repair state from accelerator memory costs approximately 1.3 s of prefill compute to rebuild from raw tokens, and it forfeits zero evidence needed by the task. Retaining or serializing KV cache tensors preserves only intermediate, activation-level computation tied to a specific hardware layout, model architecture, and numerical precision. It does not record the authoritative code revisions, environment observations, or validation evidence that govern an agent’s task progression. Systems must persist trajectory history, tool outputs, and verification state in a durable application runtime. The KV cache should always be treated as an ephemeral, recomputable cache over that authoritative token log, reproducible up to floating-point differences across distinct implementations.
