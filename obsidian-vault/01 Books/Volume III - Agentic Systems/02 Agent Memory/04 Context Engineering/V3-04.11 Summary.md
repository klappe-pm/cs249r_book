# V3-04.11 Summary

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04 Context Engineering|V3-04 Context Engineering]]

^sec-vol3-context-engineering-summary

Fitting an execution trace within a model’s context window does not ensure that the model will make a sound decision. Throughout this chapter, the repair agent’s most instructive failures rarely stemmed from context window exhaustion. Instead, they occurred when the context representation severed causal relationships. A discarded hypothesis remained displayed alongside contradictory evidence, and a passing reproducer lost its revision metadata. An automated summary silently dropped an operational constraint, and a cached code excerpt persisted after the underlying file had changed. Each case reflects a failure of context state management rather than token capacity. Solving these breakdowns requires runtime bookkeeping outside the model (explicit working-set management, dependency tracking, cache-aware layout, and artifact versioning), not a larger context window or more elaborate prompt wording. **Key Takeaways: Context is selected information for the next decision**

- **Context budgets require explicit working-set management**: Every serialized request must preserve sufficient headroom for generation, but staying within token limits does not guarantee that the prompt supplies the necessary evidence. Naively appending every tool observation quickly exhausts the context window. In the reference repair agent, uncontrolled logging overflows the context window at turn 21 of 30. Effective runtimes actively bound and select per-turn observations to match the execution horizon while measuring decision quality directly.
- **Prefix stability governs cache reuse rather than semantic authority**: Placing static instructions and tool definitions in a stable prefix eliminates redundant prefill computation through KV-cache reuse. Across the repair trajectory, under the chapter’s stated reuse and price assumptions, an unstable layout’s input bill came to 3.2× that of a cache-aligned layout. Cache layout, however, should never be confused with authority. Message roles, cache boundaries, and data provenance are separate architectural concerns, and staging content in a privileged prefix does not validate untrusted tool outputs.
- **Compaction mechanisms must enforce strict schema retention**: Truncation and summarization inevitably discard detail. Because small per-round losses compound geometrically over long trajectories, compaction policies must explicitly safeguard the exact fields required by downstream tools and decisions. Runtimes should validate generated summaries against their original records at every compaction boundary, retaining raw-payload handles so the agent can deterministically retrieve omitted evidence on demand.
- **Observation validity must be bound to artifact versions**: Every tool observation reflects the specific system environment and artifact revision present when the tool ran. When an agent modifies source code or configuration files, earlier test results cease to validate claims about the current state, even though they remain historically accurate records of prior turns. Runtime managers must track revisions explicitly, invalidating stale claims while preserving observations that remain tied to untouched components.
- **Context policies must be evaluated on end-to-end task outcomes**: Intermediate metrics such as compression ratio, token count, and field retention provide useful diagnostics, but they do not measure decision quality. A compaction or retrieval strategy improves a system only if it reduces the effective cost per accepted task completion, accounting for the overhead of compaction calls, retries, and failed trajectories across all evaluated trials.

^callout-takeaways--4-2-8a8922fd

Treating prompt context as an active working set (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-attention-working-set|4]]) turns context engineering from ad hoc prompt assembly into a repeatable systems discipline. Rather than assuming that a larger window will resolve ambiguity, engineers must verify whether an assembled prompt contains the dependencies needed for the next decision step. Scoping observations by artifact revision reinforces the rule that authority remains with the external source of truth (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-source-authority|6]]), enabling the runtime to invalidate superseded evidence without corrupting historical audit logs. Working together, these principles ensure that context preparation is transparent about its cache costs, accountable for the evidence it provides, and explicit about unresolved dependencies.
