# V3-04.15 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04 Context Engineering|V3-04 Context Engineering]]

^footnotes

<sup>1</sup> **Optimal Replacement (MIN)**: Belady ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-belady1966study|1966]]) evaluated page-replacement algorithms against an optimal offline baseline that evicts the page whose next reference lies farthest in the future. Practical operating systems approximate this unattainable ideal using historical access patterns such as least recently used (LRU). An agent context runtime lacks even that access history. The model interface reports no reference bits for the tokens it processes, so working-set selection must rely on explicit domain heuristics and structured task state rather than on observed cache reuse.

^fn1

<sup>2</sup> **Interleaved Observations**: ReAct prompting interleaves reasoning traces, tool actions, and observation payloads within an ever-expanding prompt transcript ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-yao2023react|Yao et al. 2023]]). While keeping full execution history visible simplifies early prototyping, it carries a steep cost, because the unchecked growth of ${S_{\text{obs}}}$ consumes prompt capacity and raises input token costs on every subsequent call.

^fn2

<sup>3</sup> **Needle-in-a-Haystack Probes**: The best-known isolated retrieval probe plants a short fact, the needle, in long distractor text and asks the model to return it. Hsieh et al. ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-hsieh2024ruler|2024]]) found that models scoring nearly perfectly on this probe degraded sharply as length grew on tasks that require multi-hop tracing and aggregation, and that only about half of the models tested held satisfactory performance at the context length all of them claimed to support. The gap between the probe and the harder tasks is the gap between nominal capacity and usable working context.

^fn3

<sup>4</sup> **Distracting Context**: Shi et al. ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-shi2023distracted|2023]]) added irrelevant sentences to grade-school arithmetic problems and found that model accuracy fell dramatically, although the added text changed nothing about the answer. Because the distractors were irrelevant by construction, the drop measures interference rather than missing information. That interference is the cost an agent pays for every superseded log line and stale file read it keeps in the request.

^fn4

<sup>5</sup> **Why- and Where-Provenance**: Database research distinguishes why-provenance, the source records that justify a result’s existence, from where-provenance, the source locations its values were copied from ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-buneman2001why|Buneman et al. 2001]]). The scope rule demands both for every observation: which execution and artifact versions justify its existence, and which payload spans supplied its values. A result that loses either becomes an unattributed claim that later compaction can silently generalize.

^fn5

<sup>6</sup> **Automatic Prefix Reuse**: Serving systems such as SGLang index cached attention state by token prefix within a radix tree, allowing an incoming request that shares an existing token prefix to reuse cached KV blocks transparently ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-zheng2024sglang|Zheng et al. 2024]]). Because radix tree lookups evaluate exact token equality rather than semantic equivalence, two requests that diverge on an early timestamp share zero cache entries past that offset. Layout discipline directly determines cache hit rates.

^fn6

<sup>7</sup> **Unfaithful Summaries**: In a human evaluation of neural abstractive summarizers, Maynez et al. ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-maynez2020faithfulness|2020]]) found hallucinated content (statements unsupported by the source document) in the output of every model studied. A progress record written by a model inherits this failure mode. The record audit of [[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.07 Structured Progress Records#^sec-vol3-context-engineering-record-audit|section 4.6.2]] therefore compares each claimed milestone with its recorded event instead of trusting the summarizer’s account.

^fn7

<sup>8</sup> **Watermark Pairs**: Operating-system page reclaim uses the same two-threshold pattern. A reclaim thread wakes when free memory falls below a low watermark and stops only after restoring a higher one, allowing reclamation to run in batches rather than on every allocation. The gap balances batch size against invocation frequency, a trade-off that [[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.06 Context Compaction#^eq-vol3-hysteretic-compaction-cadence|equation 3]] quantifies for context compaction.

^fn8

<sup>9</sup> **Invalidation Is Not Retraction**: A truth maintenance system ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-doyle1979truth|Doyle 1979]]) retracts a belief when its premise fails, which suits a candidate plan whose refuted diagnosis should simply disappear. An executed observation is different, because the `r17` failure stays true of `r17`. The runtime graph therefore marks an affected observation historical, removing only its support for current-state claims, and reserves retraction for derived conclusions such as a hypothesis.

^fn9

<sup>10</sup> **Timestamps vs. Content Hashes**: Make’s timestamp rule ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-feldman1979make|Feldman 1979]]) rebuilds a target whose file was touched but not changed and can miss a real change whose timestamp moved backward. Modern build engines record cryptographic hashes of input contents and rebuild only when a dependency hash diverges ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-mokhov2018build|Mokhov et al. 2018]]). Context runtimes face the same trade-off, since a timestamp records when an inspection occurred, while a content hash confirms whether the artifact is unchanged.

^fn10

<sup>11</sup> **Leases**: Gray and Cheriton ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-gray1989leases|1989]]) converted temporal bounds into formal consistency guarantees through leases. In a distributed cache, a lease grants a client exclusive or shared read rights over a datum for a fixed term, during which the server guarantees it will not permit conflicting writes until every lease expires or is explicitly released. This guarantee hinges on server-coordinated consensus. Because standard filesystems and external web services provide no such cooperative write locks to an agent runtime, a local observation TTL remains a heuristic rather than a consistency guarantee.

^fn11

<sup>12</sup> **Optimistic Validation**: In optimistic concurrency control, transactions execute reads and computations without acquiring locks, validating prior to commit that no conflicting transaction mutated their read set ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-kung1981optimistic|Kung and Robinson 1981]]). If the validation check fails, the transaction aborts. Preconditions at the agent tool boundary follow the same structure. The assembled prompt supplies the version snapshot the model evaluated, and the tool runner verifies that version’s integrity before applying side effects to disk.

^fn12

<sup>13</sup> **Tombstones in Storage Engines**: Log-structured storage engines like Bigtable record deletions by writing tombstones, which actively mask superseded values during read scans until major compaction discards both the tombstone and the deleted record ([[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.14 Source References#^ref-chang2008|Chang et al. 2008]]). The storage engine’s read path mechanically enforces this masking. By contrast, an appended advisory notice in a language model prompt has no read filter, so the superseded text remains visible in the attention matrix, leaving the model to resolve the contradiction on its own.

^fn13
