# V3-06.13 Summary

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/02 Agent Memory/06 Long-Term Memory/V3-06 Long-Term Memory|V3-06 Long-Term Memory]]

^sec-vol3-long-term-memory-summary

A software repair agent needs far more than an index that matches text embeddings against a bug report. Reliable long-term memory requires the system to determine what each retained record represents, which authoritative source supports it, how context budgets constrain its entry into later requests, and how downstream state changes when that underlying support is modified. Retrieval methods locate candidates under an explicit operational contract. The write lifecycle governs which records survive to become candidates. Comprehensive evaluation ensures that engineers do not mistake improved search recall for genuine task performance. **Key Takeaways: Persistent information needs a lifecycle**

- **Records retain different kinds of evidence**: Primary source records, agent observations, synthesized lessons, and retrieval indexes serve different roles in an evidence chain. Explicit provenance and scope allow downstream systems to distinguish an empirical execution outcome from a speculative hypothesis. System deployers remain strictly accountable when an aggregated summary or derived heuristic contradicts its underlying source of record.
- **A retrieval result has a contract**: Scope boundaries, access controls, version validity, payload budgets, and completion status dictate what enters prompt context. Formatting envelope overhead and metadata fields consume token allowances alongside record bodies, directly capping candidate capacity. An empty response from a partial or approximate search does not prove absence. Only a completed exhaustive search supports that conclusion within its declared scope and snapshot.
- **Search strategy follows the information need**: Key-value lookups, lexical ranking, dense vector similarity, and structural graph traversal address distinct retrieval requirements. An exact scan supplies the recall baseline under the chosen metric. Its bandwidth floor (${N} {d}{s_{\text{elem}}}/{\text{BW}}$) rules out infeasible scans, while measured full-request latency determines whether it meets the search budget. Every auxiliary vector index or inverted list introduces ongoing write amplification and synchronization overhead, which pays off only when it delivers measurable gains in task accuracy.
- **Relationships need evidence and a budget**: Explicit graph edges connect scattered records into cohesive multi-hop evidence chains. Because candidate neighborhoods expand exponentially with traversal depth ($(\text{children}^{\text{depth}+1}-1)/(\text{children}-1)$), retrieval pipelines must enforce strict depth and branching limits before scoring nodes. Traversal paths indicate topological reachability rather than verified runtime execution traces, so the agent must treat discovered paths as structural hypotheses that require independent corroboration.
- **Memory must change as its support changes**: Updates, supersession, time-to-live expiration, and deletion policies dictate whether a record remains eligible for future prompts. Modifying or evicting a primary record invalidates all downstream summaries, embeddings, and inverted postings. Records that describe a user carry the consent and retention period under which they were admitted, and withdrawn consent or an elapsed retention period starts the same deletion procedure as an explicit request. Apparent near-duplicates frequently represent critical real-world state mutations rather than redundant text. Moreover, frequent read access indicates frequent use, but read volume alone does not validate the ongoing factual accuracy of stored state.
- **Exclusion and rebuilding incur different work**: In the stipulated scenario, local exclusion lookups take microseconds while replacement indexing takes milliseconds to seconds. Durable coordination and fallback costs remain separate. Decoupling invalidation from background re-indexing through version-aware visibility windows (${g_{\text{birth}}}({c}) \le {g_q} < {g_{\text{death}}}({c})$) shields readers from stale state while asynchronous maintenance pipelines converge.
- **Evaluate memory policies across multi-session lifecycles**: Offline ranking benchmarks reveal candidate retrieval precision, but multi-session evaluations expose how agents compound diagnostic errors or accumulate stale context over time. Assess competing memory architectures by their end-to-end task completion rate (${p_{\text{acc}}}$), lifecycle contract compliance, and amortized cost per accepted task (${C_{\text{eff}}}$), using isolated search metrics primarily to diagnose local failure modes.

^callout-takeaways--6-2-b89dc2c9

Authority always resides with the source of record (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-source-authority|6]]). Retrieval therefore operates as an enforceable contract governing scope, freshness, and context allowances, rather than an unconstrained similarity lookup, and locating a candidate record does not grant permission to inject it uncritically into downstream execution. The write lifecycle extends this discipline to all derived artifacts that agents generate across sessions, including summaries, graph entities, vector embeddings, and cached lessons. Every transformation must preserve the explicit provenance, boundary conditions, and uncertainty of the original evidence rather than silently amplifying tentative diagnostic guesses into durable facts.
