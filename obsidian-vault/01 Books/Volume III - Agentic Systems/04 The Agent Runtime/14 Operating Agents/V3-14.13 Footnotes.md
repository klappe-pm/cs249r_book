# V3-14.13 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/14 Operating Agents/V3-14 Operating Agents|V3-14 Operating Agents]]

^footnotes

<sup>1</sup> **Happened-Before Order in a Trace**: The partial order that **[[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/11 Durable Execution/V3-11.07 Recorded Trajectory Replay#^sec-vol3-durable-execution-harness-regression-replay|Harness regression replay]]** used to match replayed requests applies to spans as well. Parent and link relations recorded at dispatch carry causal order between spans on different hosts; cross-host timestamps without an alignment model do not, so two spans that appear to overlap may be ordered, and two that appear ordered may be concurrent.

^fn1

<sup>2</sup> **Critical Path Method**: Critical-path planning was formalized in 1959 for scheduling large engineering projects, computing for each activity the float by which it can slip without delaying completion ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/14 Operating Agents/V3-14.12 Source References#^ref-kelley1959critical|Kelley and Walker 1959]]). The notebook measures a related quantity, the duration gap between the critical branch and the next-longest parallel path.

^fn2

<sup>3</sup> **Uniform Trace Sampling**: The first production version of one large-scale tracing system sampled uniformly, averaging one traced request per 1,024 candidates, which sufficed for high-traffic services because events of interest recurred often enough to be captured; lower-traffic workloads could miss important events at that rate ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/14 Operating Agents/V3-14.12 Source References#^ref-sigelman2010dapper|Sigelman et al. 2010]]). Its later adaptive scheme targeted a rate of sampled traces per unit time and recorded the sampling probability with each trace, the inclusion-probability bookkeeping that population estimates require.

^fn3

<sup>4</sup> **Blameless Postmortem**: Site reliability engineering conducts blameless postmortems to identify contributing causes without indicting any individual or team ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/14 Operating Agents/V3-14.12 Source References#^ref-beyer2016sre|Beyer et al. 2016]], ch. 15). Agent incidents extend this stance from people to components: a model, an observation adapter, and an admission gate can each contribute, and naming one culprit early hides the conditions the corrective change must address.

^fn4

<sup>5</sup> **Canary Release**: The name borrows from coal miners, who carried canaries underground as an early warning of toxic gas. The analogy holds in one respect and misleads in another: a canary detects a hazard by meeting it first, so a small allocation warns early but does not protect the tasks it exposes.

^fn5

<sup>6</sup> **Sequential Probability Ratio Test**: This is the sequential stopping rule of **[[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.07 Bounded Search#^sec-vol3-test-time-compute-early-exit|When to stop searching early]]** applied to release rather than to search. Because sampling stops as soon as the evidence is decisive, the test typically reaches a decision with substantially fewer observations than a fixed-sample test with the same error targets, which for a canary means fewer candidate tasks exposed before the decision.

^fn6
