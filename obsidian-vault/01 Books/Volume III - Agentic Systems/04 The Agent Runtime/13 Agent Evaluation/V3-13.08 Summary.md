# V3-13.08 Summary

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/13 Agent Evaluation/V3-13 Agent Evaluation|V3-13 Agent Evaluation]]

^sec-vol3-evaluation-summary

An agent run concludes by emitting an artifact and an execution trace, but evaluation determines what that run actually proves. The discipline developed across this chapter holds every claim about a configuration accountable to the evidence that generated it. A passing unit assertion verifies only that isolated check rather than end-to-end task completion. A successful run in a test fixture validates behavior only within that harness. Agreement among automated raters reflects consistency rather than ground truth. An accuracy reported without its cost ranks designs partly by how much they were allowed to spend. When observational evidence is incomplete or ambiguous, the verdict is recorded as pending, unknown, or inconclusive rather than granted as an unearned pass. The worked candidate shows the consequence. It accepted more paired tasks than the baseline, yet its paired interval cannot rule out a loss larger than the declared tolerance, so the offline comparison holds it back. Such a hold is the evaluation harness working as intended, because a comparison sized to its noise can be audited and repeated with a powered sample, whereas an uncalibrated scorecard conceals the risk it was meant to measure.

The quantitative decisions developed across this chapter rely on the mathematical relationships summarized in [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/13 Agent Evaluation/V3-13.08 Summary#^tbl-vol3-13-evaluation-key-equations-dfb999c2|table 7]]. Each formulation either sizes the empirical evidence required to support a claim about a configuration or prices the acceptance that evidence reports.

**Key Takeaways: Match every evaluation claim to its evidence**

- **Acceptance is a contract, not a completion claim**: A trial counts as successful only when recorded execution evidence satisfies pre-declared criteria across functional outcomes, operational processes, resource budgets, and residual side effects. Unresolved, crashed, or timed-out runs must remain in the evaluation denominator. Dropping inconclusive tasks artificially alters the target population and deceptively deflates the reported effective cost per accepted task (${C_{\text{eff}}}$) without reducing actual system expenditure.
- **A grader establishes only what it covers**: Isolated test fixtures and secured grading boundaries prevent an untrusted agent artifact from manipulating its own evaluation harness, yet any automated check validates only the specific invariants it exercises. Furthermore, strong agreement between automated or human judges reflects rater consistency rather than ground-truth correctness. Detecting false acceptances requires calibrating automated graders against verified reference evaluations.
- **Tasks carry the evidence; pairing multiplies it**: Once repeats exceed the variance ratio ${\sigma_{\text{run}}}^2/{\sigma_{\text{task}}}^2$, the between-task component dominates. Only new tasks reduce that component, but fixture cost still enters the allocation; repeats continue to reduce the run component. Pairing preserves the configurations’ within-task dependence. Positive covariance reduces the difference variance, as in the worked comparison.
- **The deployment policy picks the metric**: Availability across a candidate pool ($\operatorname{pass@}{k}$) fits workflows where an automated checker can retry failed attempts cheaply, whereas recurrence consistency ($\operatorname{pass}^{k}$) is mandatory when an agent must succeed reliably on every invocation without external intervention. For example, a single-run success rate of 90 percent achieves all 8 consecutive recurrences only 43 percent of the time.
- **Acceptance has a price that belongs in the comparison**: Policies are compared under a fixed task distribution, criteria, and resource envelope, with every failed attempt charged to the accepted tasks. Under sequential selection the cost per accepted task depends on the single-candidate pass probability rather than on the candidate cap, so the lever that lowers it is a better generator, not more retries.

^callout-takeaways--13-2-0f3d8f12

The statistical half of causal and statistical release evidence (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-release-evidence|12]]) requires an evaluation protocol to state its task criteria, the population its tasks were drawn from, and the uncertainty of every comparison before it collects data. Its causal half, which ties a claim to retained traces and controlled interventions, belongs with the exposure policy for a release in **[[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/14 Operating Agents/V3-14 Operating Agents#^sec-vol3-operations|Operating Agents]]**.
