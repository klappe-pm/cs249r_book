# V3-10.16 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10 The Agent Harness|V3-10 The Agent Harness]]

^footnotes

<sup>1</sup> **Guarded Transition**: Harel’s statecharts ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10.15 Source References#^ref-harel1987|Harel 1987]]) labeled each transition with the event that triggers it and a condition that must hold for it to fire, and added hierarchy and concurrency so that reactive controllers stayed readable as their state counts grew. The harness uses the flat core of that formalism: an event proposes an edge, and the guard, evaluated against the record at that moment, decides whether it fires. Keeping the guard on the edge, rather than in whichever handler happens to receive the event, is what lets one table govern every path into `CALLING_MODEL`.

^fn1

<sup>2</sup> **Record Lock as a Monitor**: Hoare’s monitors ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10.15 Source References#^ref-hoare1974monitors|Hoare 1974]]) bundled shared data with the only procedures allowed to touch it and ran those procedures one at a time, so every invariant on the data could be checked at procedure entry and exit. The trajectory record is a monitor in this sense: controllers, schedulers, and result handlers all reach it through short guarded procedures. The register-before-send rule adds one constraint for a record whose procedures front slow remote services: no procedure waits on a model or tool call while holding the lock.

^fn2

<sup>3</sup> **Why Batching Does Not Shorten the Wait**: The reference rate charges each generated token one full read of the weights, the single-request case. A serving engine that batches many requests shares that read among them, which raises throughput but still advances each request by one token per ordinary decode step, so batching cannot bring the per-request wait below this estimate. Techniques that emit several tokens per step change the rate, not the wait’s linear growth with the output allowance.

^fn3

<sup>4</sup> **Event-Driven Waiting**: Internet servers faced the thread-per-request version of this problem when a request could wait far longer than it computed. SEDA ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10.15 Source References#^ref-welsh2001seda|Welsh et al. 2001]]) split services into event-driven stages joined by explicit queues and applied admission control at each queue, so load was visible and bounded where work waited rather than hidden in blocked threads. A harness whose tool jobs run for minutes while a model call takes seconds has the same shape, and the trajectory record is its queue entry.

^fn4

<sup>5</sup> **Ironies of Automation**: Bainbridge observed that automating most of a process leaves the human operator the residual job of monitoring it, and that people sustain attention poorly on a stream in which almost nothing goes wrong ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10.15 Source References#^ref-bainbridge1983ironies|Bainbridge 1983]]). An approval queue in which nearly every request is benign is that stream. The one harmful proposal arrives in a queue that has trained the reviewer to expect nothing, which is why the gate’s precision, not its presence, determines what closure it supplies.

^fn5

<sup>6</sup> **From Fair Queueing to Deficit Round-Robin**: Fair queueing for packet networks ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10.15 Source References#^ref-demers1989analysis|Demers et al. 1989]]) emulated a bit-by-bit round-robin across flows, ensuring that high-volume sources could not exceed their fair shares, but it required ordering packets by computed finish times. Deficit round-robin reached comparable fairness with constant work per packet by giving each queue a quantum and carrying unspent credit forward ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10.15 Source References#^ref-shreedhar1995efficient|Shreedhar and Varghese 1995]]). Because model-call charges span orders of magnitude, deficit carryover, rather than simple queue rotation, is what enforces proportional fairness here.

^fn6

<sup>7</sup> **Reservation Against an Invariant**: Database systems solved a version of this problem for shared quantities such as account balances and inventory counts. O’Neil’s escrow method (where escrow names a set-aside quantity, not the held action of this chapter’s approval escrow) let a transaction set aside part of a quantity only after testing that the quantity’s invariant would hold whichever concurrent transactions later committed or aborted ([[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10.15 Source References#^ref-oneil1986escrow|O’Neil 1986]]). Bounded-liability admission applies the same test to a trajectory’s allowance, with the operation’s maximum possible charge standing in for an exact decrement.

^fn7
