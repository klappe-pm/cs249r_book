# V3-10.12 Summary

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10 The Agent Harness|V3-10 The Agent Harness]]

^sec-vol3-agent-harness-summary

Because an agent loop possesses no intrinsic stopping condition, the decision to continue execution must rest with an external supervisor that the language model cannot manipulate or bypass. The agent harness serves this supervisory role. It reduces every operational decision to two invariants evaluated against a single, runtime-owned record. First, before initiating any new unit of work, the harness verifies whether active control signals, delegation grants, provider capacity, and reserved budget allowances still permit dispatch. Second, whenever an asynchronous operation completes or halts, the harness determines whether verified evidence has genuinely settled the in-flight liability, or whether the outstanding obligation still requires an owner. Operator pauses, human-in-the-loop approvals, fair-share scheduling, and hard budget ceilings are these two checks applied at different stages of the execution lifecycle.

The synchronization cost of this discipline is modest: a brief critical section to update the state machine and several accounting fields per transition. Conversely, omitting these harness boundaries introduces subtle failure modes that model-level metrics obscure. Prompt instructions that hold reliably on single turns compound into unacceptable failure rates over long horizons. Naive retrospective spend checks admit model invocations that deplete remaining funds mid-generation. Releasing budget reservations prematurely permits concurrent steps to overshoot cost ceilings. **Key Takeaways: Control lives outside the model**

- **Instructions cannot substitute for architectural controls**: A freeze directive honored on 99 percent of individual turns survives across a 30-turn trajectory only 74 percent of the time. In contrast, an invariant enforced at the dispatch boundary holds across every turn because the harness inspects the concrete operation rather than relying on model compliance.
- **Control signals must decouple from generation completion**: Checking for pause or cancellation signals only after a generation finishes can delay a pause by approximately 86.3 s for a 4,096-token allowance, even under zero queueing. Turn boundaries combined with streaming cancellation decouple supervisory latency from generation length.
- **Halting execution does not settle in-flight obligations**: A pause, timeout, or cancellation revokes an operation’s permission to advance the trajectory into the next turn, but it neither terminates external execution nor refunds committed spend. Only correlated, authenticated evidence from the remote provider can formally settle the liability; until that evidence arrives, the harness must preserve explicit ownership and state tracking for the outstanding task.
- **Asynchronous waits release execution threads, not system resources**: Moving a trajectory into an asynchronous wait or human approval queue releases the active worker thread, but the trajectory retains proposal and evidence references, unresolved reservations, and its advancing deadline. Workspace and KV-cache residency continue only under their respective lease and cache policies. By Little’s law (${N_{\text{held}}} = {\lambda_{\text{arr}}}\,{T_{\text{wait}}}$), human review latency multiplies directly into the volume of concurrently suspended trajectories and their retained resource footprints.
- **Fairness, quota allocation, and budget affordability operate as independent gates**: Scheduling weights allocate relative shares of provider capacity, meaning that request payload sizes rather than weights alone determine invocation frequency under deficit round-robin. Provider rate limits protect shared infrastructure against burst exhaustion, whereas task-level budget ceilings bound total lifetime consumption for an individual agent run.
- **Budget ceilings require upfront reservation of in-flight liabilities**: A naive retrospective spend check reports \$0.92 of available headroom, whereas bounded-liability admission, which counts unsettled in-flight tool executions and the finalization reserve, reveals only \$0.12. Reserving conservative worst-case liabilities prior to dispatch is the only mechanism that converts an informational budget tracker into an enforceable upper bound.
- **Size budget ceilings by cost per accepted task**: A restrictive budget ceiling appears deceptively economical if failed and exhausted runs are omitted from post hoc accounting. Sizing budget ceilings by effective cost per accepted task (${C_{\text{eff}}} = \mathbb{E}[{C_{\text{attempt}}}]/{p_{\text{acc}}}$), which amortizes failed attempts over accepted outcomes, and treating differences within measurement error as ties, aligns harness admission thresholds with production economics.

Trajectory-level encapsulation (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-trajectory-encapsulation|10]]) establishes the runtime-owned record as the authoritative foundation for supervision. By storing immutable references to external state rather than attempting to duplicate it, the harness decouples admission control and execution governance from model cooperation. Both responsibilities function within explicit resource and evidence boundaries, ensuring that every transition (a normal dispatch, a staged escalation, or an ungraceful abort) preserves an unambiguous owner for every effect still in flight.
