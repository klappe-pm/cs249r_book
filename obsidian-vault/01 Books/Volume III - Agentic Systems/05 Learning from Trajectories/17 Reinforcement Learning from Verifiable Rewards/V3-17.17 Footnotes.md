# V3-17.17 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17 Reinforcement Learning from Verifiable Rewards|V3-17 Reinforcement Learning from Verifiable Rewards]]

^footnotes

<sup>1</sup> **Tests as Reward**: Executed unit tests served as the reward for a code-generating model before the name existed: Le et al. ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-le2022coderl|2022]]) trained a pretrained code model with reinforcement learning on test outcomes and added a learned critic that predicts functional correctness. That pairing anticipates this chapter’s central tension, since the test outcome is the trustworthy signal while the denser learned critic is itself a model that optimization can exploit.

^fn1

<sup>2</sup> **Credit Assignment Problem**: Minsky ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-minsky1961steps|1961]]) named the problem for learning systems that receive one success signal for a strategy built from many internal decisions, with games and program writing as his examples. The repair agent poses the same question at the scale of tool calls: a failed acceptance check arrives after many turns, and every turn is a candidate for blame, which is why the estimators of this chapter differ mainly in how they spread one outcome across those turns.

^fn2

<sup>3</sup> **Goodhart’s Law Under Training**: **[[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.05 Verifying Candidates#^sec-vol3-test-time-compute-selection-pressure|How search exploits imperfect checks]]** showed best-of-${N}$ selection pressing on an imperfect check, where a larger pool favors candidates the proxy overrates. An RL loop applies the same pressure at every update and then writes the result into the weights, so a gap between reward and task is searched far more persistently than any selection step or human-managed target ever searches it.

^fn3

<sup>4</sup> **Reward Shaping**: Ng et al. ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-ng1999policy|1999]]) showed that an added shaping reward is guaranteed to leave the optimal policy unchanged when it takes the form of a difference of potentials over states, and that other additions can change which policy is optimal. Format and length terms are not of that form, so they change the objective itself; their weights therefore need the priority bound derived here rather than an assumption that they merely speed learning.

^fn4

<sup>5</sup> **Generalized Advantage Estimation**: GAE computes an exponentially weighted average of future residuals parameterized by a decay factor ${\lambda} \in [0, 1]$ (distinct from the shaping weights ${\lambda_{\text{fmt}}}$ and ${\lambda_{\text{len}}}$). At ${\lambda}=0$, it uses a single one-step residual, which minimizes variance but incurs substantial bias if the value model contains errors. At ${\lambda}=1$, it recovers the empirical return minus the baseline, which is unbiased with respect to the value model but inherits all the variance of subsequent interaction turns ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-schulman2016high|Schulman et al. 2016]]). For a multi-turn agent with an imperfect critic, ${\lambda}$ governs how much credit relies on neural value predictions rather than verified environment execution.

^fn5

<sup>6</sup> **Sampled Baselines**: Scoring each sample against the other samples for the same input predates GRPO. Kool et al. ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-kool2019buy|2019]]) drew several samples per input and used the others as each one’s baseline, obtaining variance reduction without a learned critic, and Ahmadian et al. ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-ahmadian2024back|2024]]) found that such REINFORCE-style estimators could outperform PPO when fine-tuning language models from human feedback. GRPO adds division by the group’s reward dispersion, a weighting choice analyzed in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.06 Group Relative Policy Optimization#^sec-vol3-rlvr-grpo-length-normalization|section 17.5.3]].

^fn6

<sup>7</sup> **Trust Region**: The clipped surrogate originated in trust region policy optimization, which explicitly constrained each policy step to keep the average KL divergence between updated and behavior policies below a target threshold ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-schulman2015trust|Schulman et al. 2015]]). PPO replaced this constrained optimization step with a clipped objective to simplify implementation and distributed scaling ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-schulman2017proximal|Schulman et al. 2017]]). Because clipping provides no mathematical guarantee against large policy shifts, production training pipelines must monitor probability ratios and empirical divergence metrics directly.

^fn7

<sup>8</sup> **Complete Mediation of the Verdict**: The tool boundary of **[[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.03 Tool Subsystem Architecture#^sec-vol3-tool-calling-complete-mediation|Complete mediation]]** checks every access to every protected object; verifier isolation applies the same rule, with least privilege, to the reward path. The policy never needs write access to test definitions or score records, so the runtime grants none, and every route to a verdict, including module resolution paths and test runner binaries, passes through the authoritative controller.

^fn8

<sup>9</sup> **V-trace**: IMPALA’s correction weights each step by the ratio of learner to actor probabilities, truncated at a ceiling, accepting some bias to keep the variance of long products of ratios in check ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/17 Reinforcement Learning from Verifiable Rewards/V3-17.16 Source References#^ref-espeholt2018impala|Espeholt et al. 2018]]). Truncation matters more for agent rollouts than for short episodes, because a product of per-token ratios over thousands of tokens is otherwise dominated by a few extreme values.

^fn9
