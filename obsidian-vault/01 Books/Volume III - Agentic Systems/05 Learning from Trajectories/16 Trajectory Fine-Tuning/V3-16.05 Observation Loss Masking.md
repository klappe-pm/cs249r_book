# V3-16.05 Observation Loss Masking

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16 Trajectory Fine-Tuning|V3-16 Trajectory Fine-Tuning]]

^sec-vol3-fine-tuning-loss-masking

In `serialization_v1`, the token array for the repair trajectory still contains the prompt, the malformed proposal `e2`, the runtime refusal, the returned schema, and the check summary `e5` alongside the selected responses `e3`, `e4`, and `e6`. A loader that selects every assistant token trains the model on the malformed proposal `e2` alongside its correction `e4`, undoing curation, while a loader that computes loss across all tokens trains the policy to predict environment replies. Serialization turns the interaction into tokens; the loss mask decides which of those tokens drive gradient updates.

### The Masked Objective

^sec-vol3-fine-tuning-masked-objective

Let ${X}=({x}_1,\ldots,{x}_{{S}})$ be one serialized example, with an initial context or boundary token at ${x}_1$, and let ${\mathcal{P}_{\text{elig}}}\subseteq\{2,\ldots,{S}\}$ contain the policy-token positions selected for imitation. Which positions belong to ${\mathcal{P}_{\text{elig}}}$ depends on the admitted response spans and the training objective rather than token authorship alone. With the binary mask ${m}_{t}={\mathbb{I}}\{{t}\in{\mathcal{P}_{\text{elig}}}\}$ and ${m}_1=0$, the mean masked cross-entropy for an example with at least one selected target is

$$
{\mathcal{L}_{\text{SFT}}}({\theta})=-\frac{1}{{N_{\text{active}}}}\sum_{t=2}^{{S}}{m}_{t}\log{\pi_\theta}({x}_t\mid {x_{<t}}),\qquad {N_{\text{active}}}=\sum_{t=2}^{{S}}{m}_{t}>0. \tag{1}
$$

^eq-vol3-sft-masked-objective

Each selected token is predicted from the recorded prefix ${x_{<t}}$, which includes earlier actions, observations, and admitted mistakes, rather than from fresh rollouts sampled during training. This regime is **teacher forcing**[[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.19 Footnotes#^fn1|¹]] ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-williams1989learning|Williams and Zipser 1989]]), and it lets recovery prefixes that contain earlier failures serve as conditioning context whenever the trajectory satisfies the curation contract.

In the running repair trajectory, `target_mask_v1` maps the reviewed response spans onto the token array of `serialization_v1`, separating target positions from conditioning context ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^tbl-vol3-loss-masking-strata|table 3]]). Because changing a tokenizer vocabulary, chat template, or text transformation can shift token boundaries, the pipeline regenerates and checks masks against the final serialized tokens rather than copying offsets from an earlier stage.

| Token segment                                              | Target policy for this imitation objective                                                 | What remains as conditioning input                                                   |
|:-----------------------------------------------------------|:-------------------------------------------------------------------------------------------|:-------------------------------------------------------------------------------------|
| Prompt and supplied tool contracts                         | ${m}_{t}=0$                                                                                | The actual task, current interfaces, and supplied constraints                        |
| Selected policy response                                   | ${m}_{t}=1$ on its admitted target positions                                               | Earlier tokens of the response and its available prefix                              |
| Unselected policy response, including the refused proposal | ${m}_{t}=0$                                                                                | History needed to interpret a selected correction                                    |
| Tool or environment observation                            | ${m}_{t}=0$                                                                                | Delivered results, errors, and evidence available before the next response           |
| Optional authorized rationale                              | Chosen by the declared target policy                                                       | Retained rationale remains visible whether or not it is selected                     |
| Termination boundary                                       | Select an authentic policy-generated terminator when teaching the selected response to end | Do not substitute a tool-role boundary or invent a terminator for a cut-off response |

Table 3: **Loss Masking by Token Segment**: The loss mask specifies which serialized tokens generate gradient updates. It acts as an optimization filter rather than an attention barrier or provenance record.

^tbl-vol3-loss-masking-strata

When an example has no selected targets (${N_{\text{active}}}=0$), the loss in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^eq-vol3-sft-masked-objective|equation 1]] is undefined, so the loader must drop the example or route it to a declared fallback rather than counting it as a completed demonstration. How examples of different lengths are weighted against one another inside a batch is a separate choice developed in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.06 Batching Variable-Length Trajectories#^sec-vol3-fine-tuning-batching|section 16.5]].

**Definition 16.1: Observation loss masking**

***Observation loss masking*** excludes supplied observations from the direct token-prediction loss while retaining the permitted observation context needed to train selected policy responses.

1.  **Significance**: Focuses the optimization objective on the policy’s conditional distribution ${\pi_\theta}({a}_{t}\mid {s}_{t})$, so verbose environment output cannot dilute the gradient on policy actions regardless of how much context observations occupy (notebook [16.1](https://mlsysbook.ai/vol3/16_fine_tuning/16_fine_tuning.html#nbk-15-gradient-budget-and-compute-allocation) quantifies this dilution).
2.  **Distinction**: Masked tokens stay in the input context and participate in self-attention; only their next-token loss terms are zeroed. Policy authorship alone does not make a token a target, because refused attempts or unsafe actions are also masked even when emitted in the assistant role.
3.  **Common pitfall**: Selecting an entire multi-turn tool exchange only because the tool call succeeded, which trains the model to predict external environment responses.

A deployed agent trajectory interleaves two different generators: the agent policy and the external environment. Training without observation masking forces one set of weights to fit both distributions at once:

1.  The **agent policy** ${\pi_\theta}({a}_{t}\mid {s}_{t})$, which maps prior observations and instructions to tool calls or answers.
2.  An **environment dynamics model** ${p}({s}_{t+1}\mid {s}_{t}, {a}_{t})$, which predicts the outputs returned by shells, databases, or remote APIs.

Because real tools run during deployment and return actual outputs, spending model capacity to predict environment returns is wasted work, and supervising the environment distribution causes two concrete failures:

1.  **Loss dilution**: Under token-averaged cross-entropy, unmasking expands the denominator from ${N_{\text{active}}}$ to all ${S}-1$ causal prediction terms (every stored position after the initial boundary). Each decision token’s gradient weight shrinks by the ratio of selected targets to predicted positions (computed in notebook [16.1](https://mlsysbook.ai/vol3/16_fine_tuning/16_fine_tuning.html#nbk-15-gradient-budget-and-compute-allocation)), while the rest of the loss budget goes to file paths, stack traces, compiler dumps, and JSON payloads. Repetitive boilerplate pulls the average loss down, while novel stack traces or file contents dominate the gradient; in either case, the average stops measuring the policy.
2.  **Role confusion**: When trained to predict the tokens that follow a tool call, the policy learns that tool outputs continue the same autoregressive stream. At serving time, it can keep generating past its own tool call and write a fabricated tool result instead of emitting the stop token that hands control back to the runtime. Because the runtime rejects unauthenticated observations ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.04 Serializing Trajectories#^sec-vol3-fine-tuning-serialization|section 16.3]]), those fabricated tokens are discarded, wasting output budget and stalling the turn.

The full repair record selects three responses (`e3`, `e4`, and `e6`). In the simplified view of [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^fig-vol3-loss-masking|figure 1]], which omits the schema request `e3` and its returned schema, only two of the seven segments shown (the corrected tool call and the final response) carry ${m}_{t}=1$ and receive direct imitation loss. The prompt, task statement, refused proposal, rejection message, and tool result carry ${m}_{t}=0$ and stay as conditioning context, where gradients from later selected targets still update the weights that encode them.

![[90 Assets/Volume III/16 Fine Tuning/Fig Vol3 Loss Masking fa0f58a0a4.svg]]

Figure 1: **Observation Loss Masking**: The mask over a simplified view of the serialized repair example that omits the schema request (selected) and its returned schema (context). Of the segments shown, only the corrected tool call and the final response carry ${m}_{t}=1$ and receive a direct loss term. The prompt, task, refused proposal, rejection message, and tool result carry ${m}_{t}=0$, yet every one of them is still read through attention, so gradients from later selected targets update the parameters that encode it. Selecting only policy responses fits the policy’s conditional distribution; unmasking the observations would also ask the same weights to fit the environment’s.

^fig-vol3-loss-masking

Observation masking prevents both loss dilution and role confusion at the objective level, while closed-loop trials verify that the trained model stops at tool boundaries. Realizing that masked objective in code requires aligning every mask bit ${m}_{t}$ with the exact prediction step that generates token ${x}_t$.

### Causal Label Alignment

^sec-vol3-fine-tuning-label-alignment

An off-by-one shift between input tokens and target masks silently corrupts every tool boundary in a corpus, masking the first token of each selected response while training the policy to predict the first token of the following tool observation. Many training frameworks shift labels by one position inside their own loss function, so shifting them once in the loader and a second time in the loss misaligns every target mask across the dataset. In a causal autoregressive model,[[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.19 Footnotes#^fn2|²]] the hidden state at input position ${t}-1$ produces the logits that predict token ${x}_t$, so the loader must pair the logits at ${t}-1$ with target label ${x}_t$ and target mask ${m}_{t}$ rather than with the mask of input token ${x}_{t-1}$ ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^tbl-vol3-mask-causal-shift|table 4]]). Checking the aligned labels and masks on a short synthetic example before launching a run catches this bug immediately.

| Logits computed from a prefix ending at…          | Next-token label                          | Target mask |
|:--------------------------------------------------|:------------------------------------------|:------------|
| The final supplied prompt token                   | First token of a selected policy response | $1$         |
| The final content token of that selected response | Its authentic policy-generated end token  | $1$         |
| The end token before a delivered tool observation | First token of that observation           | $0$         |

Table 4: **The Causal Label Shift at a Tool Boundary**: Target selection applies to the predicted token rather than the input token driving the hidden state. Exact boundary encodings depend on the serialized chat template.

^tbl-vol3-mask-causal-shift

Let ${o}_{t-1,{v}}$ denote the logit for vocabulary token ${v}$ produced from ${x_{<t}}$, using an ordinary softmax and no label smoothing. Differentiating [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^eq-vol3-sft-masked-objective|equation 1]] gives

$$
\frac{\partial{\mathcal{L}_{\text{SFT}}}}{\partial {o}_{t-1,{v}}}=\frac{{m}_{t}}{{N_{\text{active}}}}\left({\pi_\theta}({v}\mid {x_{<t}})-{\mathbb{I}}\{{v}={x}_t\}\right).
$$

When ${m}_{t}=0$, the prediction at position ${t}-1$ contributes zero direct gradient, yet token ${x}_t$ still shapes later representations through causal self-attention, so gradients from later active targets update the weights that read it. The model conditions on tool outputs without spending capacity trying to generate them, which carries verified trajectory post-training (principle [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/V3 Trajectory Learning Principles#^pri-vol3-trajectory-post-training|13]]) down to individual token positions.

### Selected Targets and Compute

^sec-vol3-fine-tuning-selected-targets

![[90 Assets/Volume III/16 Fine Tuning/Vol3 Sft Margin Targets df7daa47e2.svg]]

*One horizontal stacked bar. A long green segment labeled observations 77.1% fills most of it, a gray segment labeled ctx follows, and a thin dark segment at the right end is labeled targets 4.9%.*

*Observations fill 77.1 percent of the input; the loss sits on 4.9 percent.*

Because every masked observation token still passes through self-attention, zeroing its loss term removes almost none of the forward-pass compute. The number of selected positions ${N_{\text{active}}}$ sets the denominator of the loss and the gradient weight on each target token, whereas the full stored sequence length ${S}$ sets the attention and projection FLOPs. Comparing ${N_{\text{active}}}$ against the ${S}-1$ causal prediction terms gives the dilution factor an unmasked loss would suffer, while ${N_{\text{active}}}/{S}$ gives the fraction of stored positions that carry a target. Notebook [16.1](https://mlsysbook.ai/vol3/16_fine_tuning/16_fine_tuning.html#nbk-15-gradient-budget-and-compute-allocation) computes both quantities under two target policies on the same serialized trajectory.

**Napkin Math 16.1: Stored tokens and selected targets**

**Problem**: A hypothetical serialized example has the segment counts in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^tbl-vol3-mask-token-inventory|table 5]]. Its curation record excludes some policy-response positions from imitation while retaining them as context. If the optional rationale is either selected or kept as context only, how many positions receive direct loss, what fraction of the stored input do they occupy, and by how much would an unmasked loss dilute each of them?

| Input segment                                             | Stored tokens |
|:----------------------------------------------------------|--------------:|
| System prompt and schemas, including the initial boundary |         1,200 |
| Task statement                                            |           184 |
| Optional authorized rationale                             |         1,400 |
| Other policy responses, including authentic end tokens    |           960 |
| Delivered observations                                    |        12,640 |

Table 5: **Hypothetical Input Inventory**: These disjoint counts include every stored position. They are not measurements of the shared repair run.

^tbl-vol3-mask-token-inventory

**Variables**: Exactly 160 of the other-policy-response positions belong to the refused proposal and stay context; every other response position is selected. The rationale is reviewed for either target policy, both policies see the same input, the initial position belongs to the prompt, and there is no padding.

**Math**: The disjoint segments sum to 16,384 stored tokens, of which observations occupy 77.1 percent. Removing the refused positions leaves 960 $-$ 160 $=$ 800 selected response targets, and selecting the rationale adds 1,400 more. The first stored boundary has no preceding-position prediction, so an unmasked causal average divides by 16,383 prediction terms instead of ${N_{\text{active}}}$. Each selected target’s coefficient therefore shrinks by 16,383/800, a factor of 20.5× (7.4× when the rationale is selected). Under each target policy, [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^tbl-vol3-mask-target-counts|table 6]] sets ${N_{\text{active}}}$ against the stored input it is drawn from.

| Target policy                                          | Selected positions, ${N_{\text{active}}}$ | Selected share of stored input |
|:-------------------------------------------------------|------------------------------------------:|-------------------------------:|
| Selected responses plus reviewed rationale             |                                     2,200 |                          13.4% |
| Selected responses; rationale retained as context only |                                       800 |                           4.9% |

Table 6: **Two Target Policies on One Input**: Excluding a segment from the objective does not shorten the conditioning sequence.

^tbl-vol3-mask-target-counts

**Result**: Both masks place the whole loss on a small minority of stored positions and leave the context identical; they differ only in whether the rationale is a target.

**Systems insight**: Because the dilution factor scales inversely with the selected fraction of predicted positions, it expands rapidly as environment interactions accumulate. Doubling the observation volume while holding response lengths constant escalates dilution from 20.5× to 36.3×. Consequently, observation masking becomes increasingly essential as agents tackle deep, tool-intensive reasoning traces. Masking, however, yields negligible reductions in FLOPs: every masked token must still pass through causal attention layers to form context for subsequent predictions. Only the final language model head projection and cross-entropy loss computation can be bypassed at masked positions.

Recorded repair trajectories show that the hypothetical inventory’s proportions are realistic. Across the 5 configurations and 2,100 runs, observations make up 56 to 72 percent of the transcript, and model output only 12 to 31 percent. These shares count each message once. Serializing one example per invocation repeats the growing prefix in every example, so the observation share of the stored training input is larger still, approaching the inventory’s proportion. The mask is therefore not a refinement applied to a few verbose tool calls; in recorded repair work it decides the fate of most of the sequence.

### Optional Rationale as Target or Context

^sec-vol3-fine-tuning-optional-rationale

Even within the model-generated share of a trajectory, masking out a chain-of-thought scratchpad during training while expecting the deployed policy to act without any scratchpad at serving time trains the model on conditioning context it will not have in production. When a dataset includes intermediate reasoning traces or tool-use plans alongside tool calls, the loader must therefore choose among three masking regimes ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^tbl-vol3-reasoning-mask-regimes|table 7]]) that match how the model will be served. Supervising the rationale trains the model to generate its own reasoning before invoking tools. Retaining the rationale under a loss mask treats the reasoning as supplied conditioning context, training the model to act on plans provided by an external orchestrator or user. Stripping the rationale entirely changes the conditional distribution so the policy acts from context alone.

Formally, given context prefix ${c}_{t}$, rationale tokens ${z}$, and action tokens ${a}=({a}_1,\ldots,{a}_n)$, response-only supervision fits the conditional distribution ${\pi_\theta}({a}_j\mid {c}_{t}, {z}, {a_{<j}})$. If the production serving environment does not supply ${z}$, the deployed model instead evaluates ${\pi_\theta}({a}_j\mid {c}_{t}, {a_{<j}})$. Because those are distinct conditional distributions, omitting rationale at serving time is a distillation step that must be evaluated directly against the unconditioned target.

| Treatment                                        | Input and direct targets                                                    | Serving question to evaluate                                                                          |
|:-------------------------------------------------|:----------------------------------------------------------------------------|:------------------------------------------------------------------------------------------------------|
| Select reviewed rationale                        | Retain $[{c}_{t},{z},{a}]$; selected ${z}$ and ${a}$ positions receive loss | Does generated rationale improve the declared outcomes enough to justify its output and latency cost? |
| Retain rationale as context only                 | Retain $[{c}_{t},{z},{a}]$; only selected ${a}$ positions receive loss      | How will appropriate rationale become available, and how do errors in it affect the response?         |
| Remove rationale under a reviewed transformation | Use $[{c}_{t},{a}]$; selected ${a}$ positions receive loss                  | Does the policy perform adequately without the removed conditioning information?                      |

Table 7: **Rationale Treatment Changes Targets or Inputs**: The choice requires a compatible serving protocol and evaluation, not a universal model-size threshold.

^tbl-vol3-reasoning-mask-regimes

At serving time, either an external planner or the policy’s own autoregressive decoder supplies the reasoning text. When the model generates its own rationale, that text can drift from the training demonstrations, so closed-loop evaluation must measure whether the generated rationale helps enough to earn its output tokens and latency.

### Termination and Truncated Responses

^sec-vol3-fine-tuning-termination

Whether a response carries rationale or only a tool call, its mask must also handle how the turn ends. To teach an agent when to yield control, the training loss must include the authentic policy-generated stop token (such as `<|eom_id|>` or `<|im_end|>`) at the end of each complete selected response, rather than confusing it with host delimiters that mark incoming tool payloads. Without direct supervision on the stop token, the policy can keep generating past the end of a valid tool call until it hits the output limit, returning `TRUNCATED` instead of `COMPLETED` so the runtime’s quarantining rule withholds the proposal.

↩︎ The normalized `TRUNCATED` status and the quarantining rule that withholds an incomplete candidate are established in **[[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.06 The Invocation Contract#^sec-vol3-foundation-model-status-envelope|The normalized status envelope]]**.

Appending a synthetic end-of-turn token to a response cut short by a context window or timeout is the training-side twin of the hazard the quarantining rule blocks at serving time, where a truncated `rm -rf` argument still parses as a complete and broader command. The training-side version is worse, because a policy that has learned to emit the terminator after a partial command produces a `COMPLETED` status, which the quarantining rule admits. When a turn was truncated in the recorded trace, the loader has two sound options:

1.  **Conservative exclusion**: Mask the truncated turn entirely (${m}_{t}=0$) while keeping earlier complete turns in the trajectory.
2.  **Prefix-only supervision**: Supervise the valid initial tokens of the truncated turn up to the truncation point, and omit any terminating token.

Whenever trajectories undergo truncation, sliding-window packing, or template changes, the data pipeline recomputes target masks and checks that ${N_{\text{active}}} > 0$. Automated assertions verify the first token of each agent response, the closing turn terminator, the transition into tool observations, refused recovery attempts, and truncated turns before the serialized dataset enters the training loop.

**Checkpoint 16.1: Defend the target mask**

**Curation to tokens**: Which of `e2`, `e3`, the tool reply to `e3`, `e4`, and `e6` carry ${m}_{t}=1$ under `recovery_targets_v1`, and what would training the others teach?

**Causal alignment**: Which input position’s logits predict the first selected response token, and which token’s mask must accompany that prediction?

**Masked vs. removed**: How can a masked observation affect parameter updates through a later selected response?

**Dilution estimate**: If the observations in notebook [16.1](https://mlsysbook.ai/vol3/16_fine_tuning/16_fine_tuning.html#nbk-15-gradient-budget-and-compute-allocation) grew to 30,000 tokens with every other segment unchanged, by roughly what factor would an unmasked token average dilute each selected response target, and why would masking save far less compute than that factor?

**Termination**: A response was cut off at the output limit. Which of its positions remain eligible for selection, and what must the loader refuse to append?

With per-example loss masking in place, the loader separates conditioning context from imitation targets inside each sequence. Training at scale, however, combines trajectories of widely varying lengths into batches across device buffers, and the batching pipeline must preserve that per-example contract without leaking context across examples or silently skewing their weights.
