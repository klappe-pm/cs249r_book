# V3-16.06 Batching Variable-Length Trajectories

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16 Trajectory Fine-Tuning|V3-16 Trajectory Fine-Tuning]]

^sec-vol3-fine-tuning-batching

Consider a batch where a 30-turn debugging and code-repair trace shares a training buffer with a brief, one-turn file lookup. Under an ordinary lower-triangular causal mask, the lookup can attend directly to the repair trace’s intermediate file contents and tool outputs, context that the lookup policy will never have at serving time. Under token averaging, the multi-turn repair trace also outweighs the brief lookup by the ratio of their active target tokens.

Constructing a batch of variable-length trajectories therefore pairs two systems choices: how much gradient weight each trajectory receives in the batch loss, and how multiple sequences share physical buffer memory without leaking context across sequence boundaries. Sequence packing is only a memory layout; a faithful implementation keeps both the declared loss weighting and each example’s isolated predictive context.

### Loss Normalization Across Variable-Length Examples

^sec-vol3-fine-tuning-loss-normalization

Let a batch contain ${B}$ examples, where example ${n}$ has stored length ${S}^{({n})}$ (including context) and ${{N_{\text{active}}}}_{{n}}>0$ selected target tokens under the mask of [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^sec-vol3-fine-tuning-loss-masking|section 16.4]], with mean masked negative log-likelihood ${\mathcal{L}}_{{n}}$. The two standard batch objectives weight the long repair trace and the one-turn file lookup differently:

$$
{\mathcal{L}_{\text{token}}}= \sum_{{n}=1}^{{B}}\frac{{{N_{\text{active}}}}_{{n}}}{\sum_{k=1}^{{B}}{{N_{\text{active}}}}_k}{\mathcal{L}}_{{n}}, \tag{2}
$$

^eq-vol3-loss-token

$$
{\mathcal{L}_{\text{example}}}=\frac{1}{{B}}\sum_{{n}=1}^{{B}}{\mathcal{L}}_{{n}}. \tag{3}
$$

^eq-vol3-loss-example

**Token averaging** in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.06 Batching Variable-Length Trajectories#^eq-vol3-loss-token|equation 2]] gives equal weight to every selected token loss, whereas **example averaging** in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.06 Batching Variable-Length Trajectories#^eq-vol3-loss-example|equation 3]] gives equal weight to every example mean. Both count only selected targets, never context or padding, and any record with no selected targets is excluded from both objectives. Because a serialized example may be a single invocation rather than a full task, example averaging equalizes serialized records rather than underlying tasks, while token averaging weights each record in proportion to its active target count.

The difference becomes critical when per-invocation serialization splits one multi-turn interaction into separate training records. If one of ${B}$ initial examples is split into ${H}$ per-invocation records while every other example stays unsplit, example averaging raises that trajectory’s share of the batch loss from $1/{B}$ to ${H}/({B}-1+{H})$, giving it ${H}$ times the weight of each unsplit example. Under token averaging, the trajectory’s aggregate share stays unchanged as long as its selected targets are partitioned disjointly across the ${H}$ records. Even though the record for a later turn repeats earlier assistant responses inside its conditioning prefix, the loader masks those earlier responses (${m}_{t}=0$) and sets ${m}_{t}=1$ only on that invocation’s final response, so repeating prefix context does not repeat active targets. A corpus mixture specified in selected target tokens, the unit in which **[[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/15 Trajectory Curation/V3-15.07 Recovery Demonstration Curation#^sec-vol3-trajectory-curation-token-accounting|Records, stored tokens, and selected targets]]** fixes class shares, therefore reaches the parameter update unchanged only under token averaging. Example averaging, or a per-invocation split that leaves earlier assistant turns unmasked and selects the same target twice, changes the realized mixture ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.06 Batching Variable-Length Trajectories#^tbl-vol3-loss-normalization-comparison|table 8]]).

| Property                                          | Token averaging                                              | Example averaging                     |
|:--------------------------------------------------|:-------------------------------------------------------------|:--------------------------------------|
| Coefficient on example mean ${\mathcal{L}}_{{n}}$ | ${{N_{\text{active}}}}_{{n}}/\sum_k {{N_{\text{active}}}}_k$ | $1/{B}$                               |
| Coefficient on a selected token loss              | $1/\sum_k {{N_{\text{active}}}}_k$                           | $1/({B} {{N_{\text{active}}}}_{{n}})$ |
| Quantity treated equally                          | Selected token losses                                        | Example mean losses                   |

Table 8: **Loss normalization for variable-length examples**: Equal coefficients specify the objective, not equal gradient norms or equal representation of underlying tasks.

^tbl-vol3-loss-normalization-comparison

Preserving the coefficients in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.06 Batching Variable-Length Trajectories#^tbl-vol3-loss-normalization-comparison|table 8]] across a cluster requires matching distributed reduction. A large batch is split into microbatches (slices processed sequentially before a parameter step) and spread across data-parallel workers (each holding a model copy and processing its shard of the batch). Computing a true global token average therefore requires summing active token losses and active token counts across all microbatches and workers before dividing. Averaging local microbatch means directly matches the global token average only when every microbatch has the exact same active token count. When variable-length trajectories make those counts differ, workers must reduce the raw numerators and denominators before taking their ratio.

### Example Isolation in Packed Buffers

^sec-vol3-fine-tuning-packed-isolation

Accurate loss reduction settles how the batch weights the file lookup and the 30-turn repair trace, but not how they share device memory. Packing both trajectories into one contiguous buffer under an ordinary causal mask lets every query in the lookup read the repair trace’s file contents and tool observations. That leak across packed sequences is *cross-contamination*,[[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.19 Footnotes#^fn3|³]] and preventing it is the primary correctness obligation of sequence packing ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-krell2021efficient|Krell et al. 2021]]).

**Definition 16.2: Sequence packing**

***Sequence packing*** places several variable-length training examples in shared buffers while preserving their intended information boundaries and loss targets.

1.  **Significance**: Uniform padding allocates the longest example’s length to every row, reducing batch occupancy to the ratio of mean to maximum sequence length. Sequence packing reclaims this wasted capacity (notebook [16.2](https://mlsysbook.ai/vol3/16_fine_tuning/16_fine_tuning.html#nbk-vol3-packing-occupancy)).
2.  **Distinction**: Independent trajectories share physical memory buffers without sharing predictive context; multi-turn interactions within an individual trajectory retain access to their complete history.
3.  **Common pitfall**: Applying a standard causal mask across concatenated sequences, allowing later examples to attend illegitimately to earlier ones.

Let ${i}$ and ${j}$ denote buffer positions, ${\mathbf{q}}_i$ and ${\mathbf{k}}_j$ their query and key vectors, and ${d_{\text{head}}}$ the attention-head dimension. The pre-softmax attention scores $\text{score}_{i,j}$ enforce both causality and example membership:

$$
\text{score}_{i,j}=\begin{cases} {\mathbf{q}}_i{\mathbf{k}}_j^T/\sqrt{{d_{\text{head}}}} & \text{if }\operatorname{example}({i})=\operatorname{example}({j})\text{ and }{j}\le {i},\\ -\infty & \text{otherwise}. \end{cases} \tag{4}
$$

^eq-vol3-block-diagonal-attention

Under an ordinary causal mask, every query in a later example can score keys in an earlier one. The block-diagonal mask sets each of those cross-example entries to $-\infty$ before the softmax, and excludes trailing padding keys the same way ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.06 Batching Variable-Length Trajectories#^fig-vol3-block-diagonal-mask|figure 3]]). Variable-length attention kernels ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-dao2023flashattention2|Dao 2023]]) enforce this without materializing a dense $-\infty$ matrix. The loader hands the kernel the example boundaries as cumulative offsets, $0$, ${s}_1$, ${s}_1+{s}_2$, and so on through the buffer’s total length (${B}+1$ entries for ${B}$ examples), so that example ${k}$ occupies one contiguous interval of positions. The kernel then computes scores only for query and key pairs that fall inside the same interval. Whether a given kernel also skips the computation for cross-example blocks of the score matrix, and how much time that saves, is an implementation property to measure on the target accelerator. The mask is the correctness requirement; skipped work is a throughput bonus that must be shown, not assumed.

![[90 Assets/Volume III/16 Fine Tuning/Ch13 Block Diagonal Mask b7f4fddf61.svg]]

Figure 3: **Block-Diagonal Attention for Packed Examples**: Two independent examples share one buffer. Under an ordinary causal mask (a), every query in the second example scores keys in the first, so the second example can use context it will not have when served. The block-diagonal mask (b) keeps causal scores only inside each example and sets every cross-example entry to $-\infty$ before the softmax, as in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.06 Batching Variable-Length Trajectories#^eq-vol3-block-diagonal-attention|equation 4]]. The boundary offsets define the blocks; whether a kernel also skips the masked blocks is an implementation property.

Loss computation needs the same boundary isolation: shifting next-token labels across a concatenated buffer without resetting at example boundaries trains the final token of one example to predict the initial prompt token of the next. Each packed example’s initial prompt context must stay unselected (${m} = 0$), and every shifted prediction-target pair must stay inside its own example. The block-diagonal attention mask isolates visible context, while the per-example target mask isolates the loss gradient.

**Napkin Math 16.2: Stored occupancy and target weighting**

**Problem**: A batch holds one long trajectory among short ones. How much allocated sequence space does packing save over uniform padding, and how differently do the two loss normalizations weight a long and a short example?

**Variables**: Eight hypothetical examples have stored lengths $[32{,}768,\ 8{,}192,\ 4{,}096,\ 2{,}048,\ 1{,}024,\ 1{,}024,\ 512,\ 512]$. Each packed buffer holds $32{,}768$ positions. Separately, two examples have $256$ and $8{,}192$ selected targets.

**Math**: Padding eight rows to the maximum allocates $8\times32{,}768$ positions, or 262,144, for 50,176 stored tokens. Packing places the longest example alone in one buffer and the remaining 17,408 tokens in a second buffer. The two buffers allocate $2\times32{,}768$ positions, or 65,536. Dividing stored tokens by allocated positions gives an occupancy of 19.1 percent with padding (the mean length of 6,272 divided by the maximum of 32,768) and 76.6 percent with packing. Packing allocates 4× fewer positions.

For the separate target-count illustration, token averaging gives coefficients $256/(256+8{,}192)$ and $8{,}192/(256+8{,}192)$, or 3.03 percent and 96.97 percent on the example means. Their ratio, $8{,}192/256$, is 32×. Example averaging instead assigns each mean $1/2$.

**Systems insight**: Padded occupancy is the ratio of mean to maximum length, so the single longest trajectory sets the waste: one 32,768-token example holds this batch to 19.1 percent, and packing raises it to 76.6 percent. Occupancy counts context and targets together, so the throughput it buys is measured on the actual attention kernel. Normalization is a separate knob with an equally large effect. Token averaging gives the long example 32× the short one’s weight, and example averaging gives them equal weight. Choose token averaging when every selected token should count equally, and example averaging when a few long trajectories should not dominate the update.

### Position Conventions and Equivalence Checks

^sec-vol3-fine-tuning-position-conventions

Attention and label masks settle what each packed position reads and predicts, but each token also carries a position index. If the loader leaves buffer-wide position indices unreset, the second packed example starts at offset ${s}_1$ instead of zero, which shifts its logits under any position scheme that is not shift-invariant. Resetting positions to zero at each example boundary avoids the shift directly: for zero-based buffer offsets ${b}_k$ and ${b}_{k+1}$ bounding example ${k}$,

$$
\operatorname{pos}[{t}]={t}-{b}_k\quad\text{for }{t}\in[{b}_k,{b}_{k+1}).
$$

Rotary position embeddings (RoPE), a widely used scheme that encodes position by rotating query and key vectors through position-dependent angles, are the case where the offset provably makes no difference, so for them resetting is an operational convention rather than a mathematical requirement. In the fixed-frequency formulation, position ${i}$ applies a rotation ${\mathbf{R}}_i$ to a query or key vector. Shifting both positions by a common offset ${\Delta}$ leaves their relative rotation unchanged:

$$
{\mathbf{R}}_{i+{\Delta}}^T{\mathbf{R}}_{j+{\Delta}}={\mathbf{R}}_{j-i}={\mathbf{R}}_i^T{\mathbf{R}}_j.
$$

A common offset therefore leaves within-example attention scores unchanged, a direct consequence of the relative-position construction of RoPE ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-su2024|Su et al. 2024]]). Absolute-position features, position-dependent frequency scaling, and floating-point non-associativity can still compromise equivalence for a particular architecture, so no position scheme is exempt from checking.

The general answer is therefore a test rather than a proof. The correctness test compares selected-token logits and the evaluated loss for the same examples processed separately and packed, with stochastic layers disabled and numerical tolerances explicitly stated. Perturbing one example must leave every other example’s logits unchanged. This test exercises attention boundaries, label shifting, position IDs, and the chosen denominator together. When it passes, the loader trains the demonstrated problem cleanly. The trained policy, however, still has to act in contexts its own choices produce.
