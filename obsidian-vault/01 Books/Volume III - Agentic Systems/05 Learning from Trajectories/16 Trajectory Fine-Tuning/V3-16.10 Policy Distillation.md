# V3-16.10 Policy Distillation

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16 Trajectory Fine-Tuning|V3-16 Trajectory Fine-Tuning]]

^sec-vol3-fine-tuning-distillation

Consider an automated repair agent whose system prompt carries a detailed debugging checklist and worked examples showing how to inspect a stack trace before revising a tool call. In production, the agent resends this entire prompt prefix on every turn of every trajectory, consuming context-window capacity and raising time-to-first-token latency even though the procedural workflow belongs in the weights under [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.03 Scope of Supervised Fine-Tuning#^tbl-vol3-fine-tuning-scope|table 1]]. Training the model to internalize the procedure lets the runtime drop the checklist from the prompt and reclaim those tokens on every call. **Policy distillation** transfers behavior from an expensive teacher configuration, whether a larger model family, a long procedural prompt, or a broader test-time search budget, into a cheaper student configuration, provided the teacher’s trajectories pass the same target admission filters as any other demonstration before entering training.

### Context Distillation

^sec-vol3-fine-tuning-context-distillation

To move that debugging checklist out of the repair agent’s system prompt, the pipeline first samples candidate demonstrations under the expanded prompt containing the full checklist, diagnostic routines, or few-shot examples, and keeps only trajectories that pass the admission filters. **Context distillation**[[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.19 Footnotes#^fn7|⁷]] then strips the static procedural guidance from the prompt and trains the student to emit the same selected actions from the shortened prefix, without removing the dynamic evidence the policy still needs at serving time. Because this transformation intentionally changes the conditioning input rather than replaying the teacher’s exact prompt, the lineage record preserves both prompt versions and the transformation rule ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.04 Serializing Trajectories#^sec-vol3-fine-tuning-serialization|section 16.3]]).

Stripping static procedural guidance differs from stripping dynamic environment feedback, such as an authorization refusal or a schema error that justified a corrective call. Removing causal observations leaves the corrected action unmotivated by its prefix and trains the student to guess state changes without evidence. When a recorded trace such as `trace_r19_01_redacted_v1` is shortened for context distillation, the pipeline records a new derived artifact with its own target review while keeping the historical runtime verdict attached to the original long-prompt trace.

The division of responsibilities in [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.03 Scope of Supervised Fine-Tuning#^tbl-vol3-fine-tuning-scope|table 1]] decides both what may be distilled and when to retrain. Stable procedures can move into weights, whereas current task facts, tool schemas, and authorization rules must stay in the prompt so an interface update does not break the model. By the same token, any rule that changes faster than the team can curate data, run fine-tuning, and clear the release gate, such as a business policy updated weekly, behaves as a contract in practice and stays in context.

The distilled student is evaluated with the abbreviated production prompt it will actually receive at serving time, checking that task acceptance and tool-calling accuracy hold while prompt tokens fall. Because end-to-end latency also depends on KV-cache prefix reuse, output length, tool execution time, and recovery turns, latency savings must be measured on closed-loop runs rather than inferred from prompt token counts alone. A distilled policy that reads fewer input tokens but takes an extra tool round-trip to recover from a bad argument can lose the prefill saving immediately.

### Teacher Distillation

^sec-vol3-fine-tuning-teacher-distillation

When the teacher is a stronger model family or a multi-sample search harness rather than a longer prompt on the same model, **teacher distillation** transfers its verified trajectories into a smaller student. In classical knowledge distillation, a student trains on the teacher’s full probability distribution over classes[[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.19 Footnotes#^fn8|⁸]] ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-bucilua2006model|Buciluă et al. 2006]]; [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-hinton2015distilling|Hinton et al. 2015]]). Because trajectory collectors that call a frontier model or search harness over an API receive discrete sampled tool calls and messages rather than full-vocabulary logits, agent teacher distillation works by filtered imitation on verified trajectories rather than soft-target matching.

Whether the teacher is a larger model, a test-time search loop (such as tree search or best-of-${N}$ sampling), or the student’s own base model run with a long prompt, its candidate rollouts must pass the consumer’s admission checks before training. Fluent reasoning or high self-reported confidence is never a substitute for verification. Training smaller models on verified trajectories from stronger teachers reliably improves tool-use accuracy and multi-step stability over zero-shot prompting ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-chen2023fireact|Chen et al. 2023]]; [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-zeng2023agenttuning|Zeng et al. 2023]]). The same filtered-imitation loop can even use the model’s own verified rollouts, as in STaR ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.18 Source References#^ref-zelikman2022star|Zelikman et al. 2022]]), subject to the self-selection narrowing risks of **[[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/15 Trajectory Curation/V3-15.08 The Self-Improvement Loop#^sec-vol3-trajectory-curation-self-improvement|The Self-Improvement Loop]]**. Because curation keeps only verified successes, the student trains on a cleaner distribution than the teacher’s raw rollouts and is not capped at the unguided teacher’s pass rate. However, it will also absorb any inefficient tool habits or biases in the teacher that slip past the admission filter.

Distillation settles where the training trajectories come from, independently of the loss objective and the parameter artifact ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.03 Scope of Supervised Fine-Tuning#^sec-vol3-fine-tuning-adaptation-choices|section 16.2.2]]). Whether the run updates every weight or a compact adapter, the learned behavior is only as good as the admitted demonstrations. What the artifact choice changes is the memory and storage cost of holding the update, especially when a deployment maintains several specialized agent roles.
