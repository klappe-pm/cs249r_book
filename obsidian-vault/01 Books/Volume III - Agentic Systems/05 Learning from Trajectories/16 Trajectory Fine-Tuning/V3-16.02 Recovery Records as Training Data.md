# V3-16.02 Recovery Records as Training Data

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16 Trajectory Fine-Tuning|V3-16 Trajectory Fine-Tuning]]

^sec-vol3-fine-tuning-introduction

![[90 Assets/Volume III/01 Introduction/Hsa Locator Origin 574b033854.svg]]

*H·S·A locator with no axis highlighted and the origin dot highlighted in purple.*

*Fine-tuning reshapes each model call but leaves every exposure to the runtime.*

Consider a recovery demonstration admitted by the curation pipeline for the repair agent (**[[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.05 The H·S·A Exposure Space#^sec-vol3-intro-lighthouses|Four lighthouse workloads]]**) into `repair_demonstrations_v1`. During the recorded session, the agent generated a malformed edit proposal that the runtime validator refused prior to tool dispatch. In response to the failure notification, the model inspected the tool schema, generated a corrected edit, and produced candidate patch `ws_r20`. From this multi-turn trajectory, the target-selection policy `recovery_targets_v1` marks three assistant turns as supervised targets: the schema inspection request (`e3`), the corrected edit (`e4`), and the scoped final summary (`e6`). The malformed proposal (`e2`) and the runtime’s refusal remain in the input history as conditioning context. The member that entered the corpus is the redacted view `trace_r19_01_redacted_v1`, and the corpus manifest binds it to those role assignments, its lineage, and its split membership.

The raw event log of an admitted record is not yet in a form a training loop can safely ingest, because it interleaves model generations, runtime observations, and tool responses in the order they occurred. If a data loader treats every assistant message as a supervised target, it computes loss on the malformed edit proposal alongside the correction and reinforces the initial mistake. If the training pipeline computes loss across all sequence tokens indiscriminately, the model spends parameter capacity predicting deterministic environment replies, such as compiler diagnostics or directory listings, that it will never emit during inference. Finally, if the batching pipeline packs multiple trajectories into a shared context window without attention masking, self-attention heads attend across sample boundaries and leak private workspace contents into unrelated training examples. Standard cross-entropy loss fails silently under each of these mistakes. The training loss falls steadily as the optimizer fits the data, hiding the corrupted behavior from offline metrics. While curation contracts decide which actions show desirable behavior and evaluation contracts measure the deployed agent, neither specifies how to turn a multi-turn execution trace into isolated, causal gradient updates.

The path from an admitted record to an evaluated policy update begins with a question curation leaves open, namely which parts of the repair behavior belong in weights at all ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.03 Scope of Supervised Fine-Tuning#^sec-vol3-fine-tuning-scope|section 16.2]]). The answer fixes what the data pipeline must protect. Serialization reconstructs each model input exactly as the agent received it ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.04 Serializing Trajectories#^sec-vol3-fine-tuning-serialization|section 16.3]]), loss masking places the gradient on the selected responses and nowhere else ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.05 Observation Loss Masking#^sec-vol3-fine-tuning-loss-masking|section 16.4]]), and batching shares buffers without letting examples read one another or skew one another’s weight ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.06 Batching Variable-Length Trajectories#^sec-vol3-fine-tuning-batching|section 16.5]]). Masking and batching guard directly against those three silent failures, and serialization guards the premise both rely on, that each prefix is the one the model actually saw.

A faithful loader still trains on recorded prefixes, and the deployed policy acts on prefixes its own choices produce. Exposure bias prices that gap over the horizon and decides when labeling the learner’s own states pays ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.07 Exposure Bias#^sec-vol3-fine-tuning-exposure-bias|section 16.6]]), and schema robustness asks the same question of the tool interfaces the policy is shown ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.08 Schema Robustness#^sec-vol3-fine-tuning-schemas|section 16.7]]). The remaining sections vary the update itself along three independent choices. The first is the objective, where preference optimization contrasts valid alternatives that imitation cannot rank ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.09 Trajectory Preference Optimization#^sec-vol3-fine-tuning-dpo|section 16.8]]). The second is the behavior source, where distillation moves a costlier configuration’s behavior into a cheaper one ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.10 Policy Distillation#^sec-vol3-fine-tuning-distillation|section 16.9]]). The last is the parameter artifact, where adapters change what a run must store ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.11 Parameter-Efficient Fine-Tuning#^sec-vol3-fine-tuning-peft|section 16.10]]). Closed-loop evaluation decides whether any of them earned a release ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.12 Evaluating a Fine-Tuned Agent#^sec-vol3-fine-tuning-benchmarking|section 16.11]]), and a training manifest for the repair policy assembles the whole chain ([[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/16 Trajectory Fine-Tuning/V3-16.13 Case Study Training the Repair Policy#^sec-vol3-fine-tuning-synthesis|section 16.12]]).
