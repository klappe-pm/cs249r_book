# V3-19.12 Summary

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19 Agent Economics|V3-19 Agent Economics]]

^sec-vol3-agent-economics-summary

An agent service is judged and funded by its accepted outcomes rather than its raw token consumption. Every operational expense the runtime incurs, on successful and failed attempts alike, is amortized across the cohort of accepted tasks under a given service contract. The central economic objective is therefore the effective cost per accepted task, ${C_{\text{eff}}}$, evaluated across a settled cohort while explicitly accounting for cutoff thresholds and in-flight work. Any proposed optimization earns its keep only if it lowers ${C_{\text{eff}}}$ or meets a latency deadline that the system objective values. Evaluating such changes requires a strictly matched comparison that holds the task contract constant while the underlying policy varies.

The largest cost component identifies a target worth evaluating. The most effective intervention also depends on what it costs to change that component. Token pricing governs the largest cost term only when inference charges dominate the task account. In many production systems, the primary expense lies elsewhere: container sandboxes, test-suite execution, human review, or a depressed acceptance rate that multiplies all other costs. A rigorous cost accounting reveals this governing term before an engineering team spends resources optimizing the wrong bottleneck. **Key Takeaways: Price the accepted task, not the token**

- **Acceptance divides the whole bill**: A token discount reduces only the model’s direct share of an attempt, whereas the acceptance rate ${\alpha}$ scales every operational expense. In addition, each successful task must absorb the amortized cost of $(1-{\alpha})/{\alpha}$ nonaccepted tasks. In the repair cohort, the configuration with the lower nominal token price ultimately cost 2.4× as much per accepted repair.
- **Reuse and retries are investments, not free savings**: Prefix caching reduces the slope of quadratic context growth but does not eliminate the re-read penalty. Context compaction pays off only after surviving beyond its payback horizon ${N_{\min}}$. Similarly, when a human fallback resolves every ticket the loop leaves, an additional execution turn makes economic sense only when the fallback spend it expects to avoid, ${q}_t{C_{h}}$, exceeds the full cost of that turn.
- **Speed pays only on the critical path**: Accelerating a model component shortens only its own spans along the trajectory’s execution graph; generation acceleration acts on decode spans. In the hypothetical serial repair episode, a 4× model speedup yielded only a 1.08× end-to-end speedup for the overall episode, because sandbox lifecycle operations and test suite runs formed the dominant latency floor.
- **A cascade is only as cheap as its gates**: Tiered routing saves money only when every exit tier fulfills the identical acceptance contract. If an upstream gate erroneously accepts invalid outputs, even a tiny false-acceptance rate can completely erase the cascade’s cost advantage once downstream remediation and task failure costs enter the balance sheet.
- **Utilization is paid for in queueing delay**: System throughput scales linearly with load, but mean queue wait grows nonlinearly as ${\rho_{\text{serv}}} / (1 - {\rho_{\text{serv}}})$. Because an agent trajectory pays this queueing latency across every sequential step, operating at excessive utilization quickly destroys interactive responsiveness. Moreover, falling acceptance forces the runtime to admit $1/{\alpha}$ tasks per accepted outcome to sustain target goodput, directly coupling capacity planning to task reliability.
- **A spending limit holds only if reserved first**: Admission control must atomically reserve an enforceable bound before execution begins, releasing unused funds only upon task settlement. Because terminating a child process does not instantly extinguish its pending provider billing, runtime tracking must strictly separate settled costs from in-flight liabilities. Monitoring burn rates merely observes cost overruns after the fact; strict upfront reservation prevents them.
- **The largest term identifies a target to evaluate**: Trajectory horizon, working state size, and external authority determine which subsystem dominates execution cost. Token generation dominates in deep research agents, sandbox holding in code repair, human review delays in infrastructure remediation, and cross-system handoffs in customer workflows. An optimization that cuts total cost in half for one agent architecture may yield negligible savings for another.

^callout-takeaways--19-2-97fefdc9

Evaluating an agent system by trajectory goodput (principle [[01 Books/Volume III - Agentic Systems/06 Agents at Scale/V3 Agents at Scale Principles#^pri-vol3-trajectory-goodput|15]]) establishes a financial metric, the effective cost per accepted task, ${C_{\text{eff}}}$, and its operational reciprocal, goodput per dollar. This principle requires system designers to account for resource residence and queueing overheads rather than focusing solely on active generation. In parallel, trajectory-level encapsulation (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-trajectory-encapsulation|10]]) preserves spending discipline across child tasks through two-phase reservation and settlement, maintaining a separation between reusable operational capabilities and consumable financial budgets.
