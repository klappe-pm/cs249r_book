# V3-19.16 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19 Agent Economics|V3-19 Agent Economics]]

^footnotes

<sup>1</sup> **Prefix Reuse**: Serving systems make cross-request reuse practical by storing attention state in paged memory blocks that requests sharing a prefix can share ([[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19.15 Source References#^ref-kwon2023|Kwon et al. 2023]]), and by indexing retained state in a radix tree so subsequent calls locate their longest cached prefix ([[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19.15 Source References#^ref-zheng2024sglang|Zheng et al. 2024]]). A discounted cached-input tariff reflects this underlying mechanism directly: only an exact, resident token prefix qualifies for the discount.

^fn1

<sup>2</sup> **Recovering the Dependency Graph**: The critical-path method and its float are introduced with agent traces in **[[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/14 Operating Agents/V3-14.03 Distributed Trajectory Tracing#^sec-vol3-evaluation-tracing-latency|Span overlap and latency attribution]]**. What pricing adds is the reconstruction step: distributed-systems work recovered the dependency model of production requests from existing component logs, precisely so that critical-path analysis could say which component’s speedup would shorten end-to-end latency ([[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19.15 Source References#^ref-chow2014mystery|Chow et al. 2014]]). An agent trace needs the same reconstruction, from dispatch and join records rather than span nesting, before any acceleration is priced.

^fn2

<sup>3</sup> **Draft-then-Verify Decoding**: The idea predates large language models. Blockwise parallel decoding predicted several future positions at once and backed off to the longest prefix a scoring model validated ([[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19.15 Source References#^ref-stern2018blockwise|Stern et al. 2018]]). Speculative decoding moved the proposals into a separate small draft model and added an acceptance rule under which sampled outputs keep the target model’s distribution, which is why its savings are purely a cost and latency question rather than a quality trade.

^fn3

<sup>4</sup> **Generating Cascade**: The verifier cascade of **[[01 Books/Volume III - Agentic Systems/05 Learning from Trajectories/15 Trajectory Curation/V3-15.06 Staged Verifier Cascades#^sec-vol3-flywheel-verification|Staged Verifier Cascades]]** already borrowed the classifier-cascade economics of cheap early rejection. A model cascade inverts the roles: each tier generates a candidate rather than only filtering one, so a task that escalates has paid for generation at every tier it reached, and the savings come only from a high early-exit rate.

^fn4

<sup>5</sup> **Counterfactual Logs**: Learning from the logs of a deployed selection policy is an off-policy causal inference challenge, studied extensively in online ad placement where a platform observes outcomes only for selected actions ([[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19.15 Source References#^ref-bottou2013counterfactual|Bottou et al. 2013]]). Estimating what an alternative policy would have achieved requires that the logging policy explored with known, nonzero probabilities: if a router never sends an easy-looking task to the frontier tier, the historical logs contain no empirical evidence about what that frontier route would have achieved.

^fn5

<sup>6</sup> **Squared Coefficient of Variation**: The scale-free measure of burstiness, defined as ${c}^2 = {\sigma}^2 / {\bar{T}}^2$. Exponential interarrival or service times, characteristic of a Poisson stream, have a squared coefficient of variation of exactly one, whereas perfectly periodic events yield zero. Values exceeding one describe arrivals and service durations burstier than Poisson, which is the standard profile for agent traffic arriving in cohorts with divergent prompt lengths.

^fn6

<sup>7</sup> **Heavy Traffic**: Kingman’s 1961 note showed that as load approaches saturation (${\rho_{\text{serv}}} \to 1$), the steady-state waiting-time distribution of the single-server queue, appropriately normalized, converges to an exponential distribution ([[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19.15 Source References#^ref-kingman1961single|Kingman 1961]]). This property extends beyond the mean: near saturation, the entire waiting-time distribution, and with it every tail percentile, stretches by the factor ${\rho_{\text{serv}}}/(1-{\rho_{\text{serv}}})$, so percentile-based latency targets degrade just as rapidly as the mean.

^fn7

<sup>8</sup> **Pay-as-You-Go Economics**: Mirroring the foundational economic argument for cloud computing, renting capacity on demand can cost less than owning dedicated infrastructure even at a higher hourly rate, because owned capacity must be financed across its average utilization while utility pricing shifts provisioning risk to the provider ([[01 Books/Volume III - Agentic Systems/06 Agents at Scale/19 Agent Economics/V3-19.15 Source References#^ref-armbrust2010view|Armbrust et al. 2010]]). A per-token API carries that logic to its finest granularity.

^fn8

<sup>9</sup> **Trailing Window vs. Token Bucket**: Standard network and API rate limiters often employ token buckets, which permit an initial burst equal to the bucket capacity followed by a steady refill rate; over a short interval ${\Delta} {t}$, maximum consumption can reach capacity plus rate times ${\Delta} {t}$. In contrast, the trailing-window sum strictly caps committed liabilities across every continuous window of duration ${T_{\text{win}}}$ at ${C_{\text{win}}}$, irrespective of burst shape, at the modest implementation cost of retaining timestamped admission records until they age out of the window.

^fn9
