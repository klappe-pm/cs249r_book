# V3-18.12 Summary

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/06 Agents at Scale/18 Multi-Agent Coordination/V3-18 Multi-Agent Coordination|V3-18 Multi-Agent Coordination]]

^sec-vol3-multi-agent-summary

Delegation turns one trajectory into several. Every boundary it adds must carry explicitly what a single trajectory carried implicitly: the inputs a worker may rely on, the authority and allowance it may spend, the evidence it must return, and the obligations that outlive it. The runtime, not the workers, owns those boundaries. It separates claims from execution records, revalidates dependencies before anything publishes, treats agreement among similar reviewers as one correlated signal, and keeps every admitted operation owned until it settles.

Whether those boundaries are worth building is a measurement question. Delegation lowers cost per accepted task only when it raises acceptance by more than it multiplies spend; otherwise it must be bought as reduced wall-clock time or broader coverage that the declared objective explicitly values. **Key Takeaways: Delegation must earn and preserve its boundaries**

- **Coordination overhead sets the useful fleet size**: Serial execution constraints cap parallel speedup at $1/{\sigma_{\text{cont}}}$, while pairwise reconciliation costs cause effective system throughput to fall beyond ${N_{\text{workers}}}^*=\sqrt{(1-{\sigma_{\text{cont}}})/{\kappa_{\text{coh}}}}$. Shrinking serial planning and integration overhead raises the scalability ceiling far more than merely shaving latency off individual handoffs. Empirical profiling across realistic workloads, rather than casual inspection of isolated agent trajectories, must calibrate these parameters.
- **Task dependencies govern completion makespan**: Communication topologies, scheduling precedence, and fault-supervision hierarchies address distinct systems requirements. Once a schedule attains its critical-path bound, further latency reductions require shortening that path; before it does, additional slots or reduced contention may also shorten runtime. Furthermore, any agent endowed with recursive delegation authority requires hard runtime limits on fan-out, nesting depth, and aggregate token reservations.
- **Delegation handoffs require explicit runtime contracts**: A handoff envelope must establish immutable task inputs, granted execution authority, resource budgets, and required evidence before worker execution begins. The returned receipt must strictly isolate ground-truth execution records from the worker’s unverified self-assessment, truncating narrative explanations rather than audit telemetry whenever context limits bind.
- **Disjoint writes do not guarantee semantic compatibility**: Non-overlapping file edits establish only that parallel workers avoided concurrent modification conflicts; they do not prove that combined changes preserve system-wide behavioral invariants. Safe publication requires revalidating dependencies against the latest branch head, testing the integrated candidate in isolation, and advancing branch pointers through conditional atomic updates.
- **Correlated reviewer errors impose an irreducible accuracy floor**: When automated reviewers evaluate an intrinsically challenging artifact, shared model blind spots cause their errors to correlate, preventing majority-voting failure rates from dropping to zero. Beyond this floor, spending additional tokens on reviewers of the same kind yields negligible benefit. Runtimes must instead incorporate independent checks, such as deterministic test suites or static analyzers, because peer consensus cannot manufacture authoritative correctness.
- **Resource obligations outlive parent caller lifecycles**: Canceling a parent agent halts the dispatch of new downstream tasks, but it does not automatically terminate remote tool operations, network sockets, or asynchronous child processes already in flight. Each in-flight bound has its own mechanism. Credit windows bound the volume of queued work and support mean-residence sizing. Attenuated grants and atomic reservations bound authority and spend. The settlement record, not cancellation or credit release, keeps every admitted effect owned until its outcome and charges settle.
- **Multi-agent execution must outperform a capable single-agent baseline**: A meaningful evaluation benchmarks multi-agent architectures against an equally optimized single-agent controller provisioned with identical parallel tool access, context allowances, and wall-clock budgets. System accounting must price every failed attempt, speculative invocation, and rollback, justifying multi-agent coordination only when the resulting increase in task success or latency reduction offsets its marginal token overhead.

The coordination tax (principle [[01 Books/Volume III - Agentic Systems/06 Agents at Scale/V3 Agents at Scale Principles#^pri-vol3-coordination-tax|14]]) manifests in the serialized handoffs, validation barriers, and residual dependencies that remain after decomposing a task. Invariant closure (principle [[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.06 Invariant Closure#^pri-invariant-closure|1]]) mandates that these architectural boundaries maintain strict external validation and effect gating, ensuring that peer consensus among models is never mistaken for authoritative execution rights. Finally, trajectory-level encapsulation (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-trajectory-encapsulation|10]]) extends from one trajectory to a tree of them. Every child is a separately owned trajectory whose derived grants only narrow, whose consumable allowance is reserved against its ancestors’ shared allowance, and whose unsettled side effects remain accounted for by the runtime after its parent stops.
