# V3-02.12 Summary

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02 The Foundation Model|V3-02 The Foundation Model]]

^sec-vol3-foundation-model-summary

A repair agent interacts with a foundation model through a bounded request-response contract. The request bundles messages, tool schemas, token and time limits, and sampling settings into a serialized payload without handing any execution authority to the model. On the way back, the normalized status envelope separates completed proposals from truncated, refused, or failed calls, leaving the runtime to authorize side effects and verify results against the task contract. That division of work is invariant closure (principle [[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.06 Invariant Closure#^pri-invariant-closure|1]]) applied to a single model call, the baseline that every later chapter builds on. **Key Takeaways: A model call is a bounded proposal interface**

- **Budget the representation the service receives**: Count serialized requests using the target model’s tokenizer and reserve explicit headroom for generated tokens. Context window limits, provider message caps, and network timeouts restrict distinct dimensions of the invocation; raw character counts never reliably predict actual token consumption or admission success.
- **Completion admits a candidate, not an action**: Inspect the response kind and normalized status before consuming the payload. While an incomplete generation provides useful diagnostic data for debugging, syntactic parseability alone never promotes a partial string into a valid candidate, nor does it grant permission to execute tool actions.
- **Structural guarantees have a stated scope**: Grammar constraints enforce syntactic validity under their schema assumptions, whereas permission checks govern permissible side effects and verifiers supply empirical acceptance evidence. A passing test supports only the properties exercised; model self-review remains a candidate assessment rather than independent confirmation.
- **Output and repeated input incur different costs**: One output token costs about 295 prompt tokens at the reference hardware floors. Generation length dominates the illustrated unbatched repair estimate; prompt length and queueing can bind under other conditions. An append-only conversational history causes re-sent input tokens to scale quadratically with the trajectory horizon. Compatible prefix reuse turns that quadratic growth into linear work, but cached key-value states must never serve as the authoritative record of task state.
- **Compare accepted results within the same budget**: Full-file replacements and localized patch edits trade generation volume against patch applicability constraints. Evaluate these alternatives by measuring end-to-end task completion, total token expenditure, and identical acceptance checks, rather than treating serialization format or schema parse rates as an engineering verdict.
