# V3-02.16 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02 The Foundation Model|V3-02 The Foundation Model]]

^footnotes

<sup>1</sup> **Homogenization**: The same report that named foundation models warned that, because many applications adapt one shared base model, a defect in that model passes into every system built on it ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-bommasani2021opportunities|Bommasani et al. 2021]]). For autonomous agents the warning is concrete. Every runtime that invokes the same model and serving path inherits the same failure modes at once, so the runtime, rather than the model, must hold the operational checks.

^fn1

<sup>2</sup> **Byte-Pair Encoding (BPE)**: The algorithm began as a data-compression scheme that repeatedly replaces the most frequent pair of adjacent bytes with an unused symbol ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-gage1994bpe|Gage 1994]]); Sennrich et al. ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-sennrich2016subword|2016]]) repurposed the same merge rule to build open vocabularies for neural translation. Because the merges are learned from the training corpus’s frequencies, the token cost of a string reflects how common it was in that corpus, so an unusual identifier or path can split into more tokens than a common word of the same length, and the runtime must count rather than estimate.

^fn2

<sup>3</sup> **Key-Value (KV) Cache**: In causal attention, key and value vectors at a given position depend solely on that token and its predecessors, so once computed they remain static throughout subsequent sequence expansion. Retaining them in device memory turns each new decode step from full-sequence recomputation into a single new row projection per layer alongside a read of stored rows. Consequently, cache capacity and memory bandwidth, rather than floating-point arithmetic, become the primary operational constraints as context windows expand.

^fn3

<sup>4</sup> **Speculative Decoding**: The target distribution is preserved by a modified rejection-sampling rule that accepts each drafted token with exactly the probability needed for the accepted sequence to follow the target model’s distribution ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-leviathan2023fast|Leviathan et al. 2023]]; [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-chen2023accelerating|Chen et al. 2023]]). The guarantee is distributional, not bitwise. Speculative decoding reduces accelerator passes per generated token without changing which candidates can appear, so it leaves the reproducibility questions of [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.05 Autoregressive Generation#^sec-vol3-foundation-model-repetition-replay|section 2.4.3]] unchanged.

^fn4

<sup>5</sup> **Temperature**: The term comes from statistical mechanics, where the Boltzmann distribution weights a state of energy ${E}$ by $\exp(-{E}/{k_B} {T})$; reading each negative logit as an energy makes [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.05 Autoregressive Generation#^eq-temperature-softmax|equation 3]] identical in form. In a physical system, high temperature spreads particles across many states, whereas low temperature concentrates them near the ground state. In language model decoding, scaling temperature trades candidate diversity against concentration on the mode without changing which token scores highest.

^fn5

<sup>6</sup> **Floating-Point Reduction Order**: Floating-point addition is not associative because each intermediate sum rounds ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-goldberg1991|Goldberg 1991]]). Parallel attention and reduction kernels that sum dot products across different thread-block layouts or dynamic batch sizes add numbers in different orders, so the same request can produce logits that differ in their low bits depending on which other requests share its batch.

^fn6

<sup>7</sup> **Remote Call Semantics**: Remote procedure call designers met this ambiguity first. In the design Birrell and Nelson ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-birrell1984rpc|1984]]) describe, a call that returns normally executed exactly once, but a call that ends in a failure report may have executed once or not at all, because the caller cannot tell a lost request from a lost reply. A model call inherits the same gap: a timed-out generation may still have run to completion and been billed, which is why the normalized status for a failed delivery, `TRANSPORT_FAILURE` ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.06 The Invocation Contract#^tbl-vol3-invocation-status|table 2]]), records an unknown remote outcome rather than a call that never happened.

^fn7

<sup>8</sup> **Complete Mediation**: One of the design principles that Saltzer and Schroeder ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-saltzer1975|1975]]) set out for protection systems: every access to every object is checked against current authority at the moment of access, not remembered from an earlier decision. The tool handler applies the same rule to a model’s proposal, so a path validated when the request was composed is checked again when the read executes, closing the gap in which the grant or the file could have changed.

^fn8

<sup>9</sup> **Legal (Viable) Prefix**: The viable-prefix concept comes from classical compiler theory. The LR parsers introduced by Knuth ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.15 Source References#^ref-knuth1965translation|1965]]) read input strings left to right and report an error at the first symbol that cannot extend the prefix into any valid sentence of the language. A grammar mask applies the same property constructively, pruning invalid tokens from the vocabulary before sampling instead of catching syntax errors after generation finishes.

^fn9
