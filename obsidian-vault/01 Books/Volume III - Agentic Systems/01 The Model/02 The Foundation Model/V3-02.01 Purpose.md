*Why does a capable model still need a precise contract around every call?*

A model call can return a response that parses cleanly yet violates the tool schema, arrives past its deadline, or claims a file edit succeeded before any tool has run. Because every capability an agent adds, from tool dispatch and memory retrieval to sandboxed execution and recovery, is built from individual model calls, any ambiguity at the call boundary spreads into every subsystem downstream. A foundation model is an ungrounded token predictor that emits candidate proposals across an untrusted boundary, not a verified state transition. The surrounding runtime must therefore enforce reliability at each call through token budgets, schema checks, and independent verification. Within the H·S·A exposure space, the single call sits at the origin: one bounded turn, zero carried state, and zero ambient authority.

**Learning Objectives**

- Explain the separate responsibilities of the foundation model, inference service, and agent runtime
- Construct a token-bounded request containing task messages, advertised tools, and generation limits
- Calculate how temperature and nucleus truncation reshape candidates without establishing correctness, and explain why only a recorded call replays exactly
- Diagnose response outcomes using completion status, structural validity, permission checks, and external evidence that self-review cannot supply
- Distinguish the guarantees of grammar-constrained decoding from learned formatting and correct task values
- Estimate call latency and repeated-input work under explicit serving and prefix-reuse assumptions
- Evaluate interface representations using accepted outcomes and resource use under matched task budgets
