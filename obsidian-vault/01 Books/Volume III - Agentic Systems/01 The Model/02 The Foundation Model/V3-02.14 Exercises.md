# V3-02.14 Exercises

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02 The Foundation Model|V3-02 The Foundation Model]]

^sec-vol3-foundation-model-exercises

All quantities below are hypothetical problem givens, chosen to be round, and describe no particular model, accelerator, or service. Where a problem uses the per-token work floors of [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.09 The Cost of a Model Call#^eq-vol3-fm-token-floors|equation 7]], take them as floors in the chapter’s sense, which exclude queueing, transfer, attention-dependent work, and serving overhead.

**1. Admitting a request with a long observation (Basic).** A repair call runs against an interface with a combined context window ${S_{\max}} = 32{,}768$ tokens, and the runtime reserves ${K_{\max}} = 4{,}096$ tokens of output headroom. System instructions and tool definitions serialize to 3,200 tokens and the retained conversation to 18,000. The newest tool observation, a test log, was estimated at 9,500 tokens by dividing its 38,000 characters by four.

1.  Compute ${S}$, the input ceiling, and whether the request is admitted. If not, find the largest observation that fits with the reservation unchanged.
2.  A teammate proposes halving ${K_{\max}}$ instead of shortening the log. Does the request then fit? Past proposals in this workload have run to 3,000 output tokens; state what the smaller reservation risks and which status the runtime would then record.
3.  The model’s tokenizer reports the log as 11,400 tokens, because indentation and escaped quotation marks split into many short tokens. Recompute both options, and state which measurement the runtime must take before any admission decision.

**2. Where a call’s time goes (Basic).** A dense model with ${P} = 40$ billion parameters stores 8-bit weights (${s_{\text{elem}}} = 1$ byte) on an accelerator with peak rate ${R_{\text{peak}}} = 1{,}000$ TFLOP/s and memory bandwidth ${\text{BW}} = 4$ TB/s.

1.  Compute ${t_{\text{prefill}}}$, ${t_{\text{decode}}}$, and their ratio.
2.  The first repair turn sends a 12,000-token prompt and generates a 300-token reply. Compute the prefill and decode times at these floors, the share of estimated work spent generating, and the share of tokens that are output.
3.  Two optimizations are proposed: trimming 3,000 tokens of retrieved documentation from the prompt, or a terser proposal format that halves the reply. Compute the work each saves and choose one. Then say how 4-bit weights (${s_{\text{elem}}} = 0.5$ byte) would change the floor ratio and whether they change that choice.

**3. How much diversity a setting buys (Basic).** At one decision point a model’s logits over four candidate tokens are ${\mathbf{z}}_t = [8, 7, 5, 2]$, and a later selection stage wants a first token that differs from the top-scoring one so that it has a genuine alternative to compare.

1.  At ${\tau_{\text{temp}}} = 1$, compute the four probabilities and the set retained by top-${p}$ sampling with ${p} = 0.90$, with its renormalized probabilities.
2.  Compute the probability that one draw differs from the top token under (i) top-${p}$ at unit temperature and (ii) untruncated sampling at ${\tau_{\text{temp}}} = 0.5$. How many independent draws does each setting need so that at least one differs from the top token with probability at least 0.9?
3.  An engineer concludes that the lower temperature is the “more accurate” setting because the top token receives more mass. Explain what the calculation does and does not show, and name what should choose the setting.

**4. Paying for an append-only history (Intermediate).** A repair trajectory runs ${H} = 40$ turns with ${S_{\text{base}}} = 10{,}000$ tokens and appends ${\Delta S_{\text{turn}}} = 2{,}000$ tokens per turn; each call generates 250 tokens. Hypothetical prices per million tokens are \$3 for uncached input, \$0.30 for cached input, and \$15 for output.

1.  Compute the total prompt tokens supplied, the fresh-prefill tokens under prompt-prefix reuse ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.09 The Cost of a Model Call#^sec-vol3-foundation-model-cost|section 2.8]]), and the total output tokens. Repeat the first two for ${H} = 80$ and report each growth factor.
2.  Compute the trajectory’s dollar cost with no reuse and with every reused prefix billed as cached input. What share of the dollars is input in each case?
3.  A developer adds the current timestamp to the first line of the system prompt so the model knows the time. Compute the new cost, explain the mechanism, and redesign the request so the model still receives the time.

**5. Ordering fallible checks (Intermediate).** Suppose 25 percent of generated connection-pool patches violate the required concurrency property. Checker A (compile and unit tests) passes defective patches with ${\epsilon_{\text{FA}}} = 0.5$ and valid ones with probability 0.9, at \$0.02 per run. Checker B (a concurrency stress test) has ${\epsilon_{\text{FA}}} = 0.2$ and passes valid patches with probability 0.8, at \$0.30 per run. The task contract tolerates at most 5 percent defective patches among those accepted.

1.  Compute $\Pr(\text{Defective} \mid \text{PASS})$ for A alone and for B alone. Does either meet the contract?
2.  Assume the two checkers’ verdicts are conditionally independent given a patch’s validity. Compute the residual for requiring both, the fraction of candidates accepted, and the expected checking cost per candidate when A runs first and B runs only on A’s passes, and when B runs first.
3.  Measurement shows that among defective patches that pass A, B passes 40 percent rather than 20 percent, because both miss races that the unit tests never schedule. Assume that the checkers’ verdicts remain conditionally independent for valid patches. Recompute the residual, state whether the pipeline still meets the contract, and propose one change to the checking design that attacks the correlation rather than adding another run of either checker.

**6. Reject early, or never emit (Intermediate).** A tool-calling service handles 10,000 proposals a day with prompts of 8,000 tokens and successful replies of 400 tokens, at ${t_{\text{prefill}}} = 80$ µs and ${t_{\text{decode}}} = 10$ ms per token. Of these proposals, 6 percent violate the argument schema; the violation first appears at decode step 40 on average, and such a response otherwise runs 600 tokens before stopping. Every failed attempt is followed by one retry, which is assumed to succeed. Successful retries and completed grammar-constrained responses each contain 400 tokens. Measure added latency relative to one successful unmasked call; ignore cancellation signaling, validation, queueing, and transfer delays, and allow the retry to start immediately after local rejection. Three designs are proposed: validate after completion; validate the stream and cancel at the first illegal token ([[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.06 The Invocation Contract#^sec-vol3-foundation-model-contract|section 2.5]]); or grammar-constrained decoding, which removes schema violations but adds 0.3 ms of mask work to every generated token.

1.  For the two rejection-and-retry designs, compute the latency a failed first attempt adds before its retry can start and the expected added latency per proposal. For grammar-constrained decoding, compute the added latency from mask work instead.
2.  Compute the daily decode time the service spends on failed attempts under post-hoc validation and under streaming validation with an honored cancel. How does the second figure change if the service ignores cancellation, and which of the runtime’s guarantees survive?
3.  Find the per-token mask overhead at which grammar-constrained decoding ties streaming validation on expected latency. Then argue which design to ship, naming one property none of the three establishes.

**7. The same method, a different binding term (Intermediate; second lighthouse).** The research agent answers one question with 8 parallel workers. Each worker makes ${H} = 12$ calls, starts from ${S_{\text{base}}} = 6{,}000$ tokens, and on every turn appends a 5,000-token retrieved page plus its own 100-token output, so ${\Delta S_{\text{turn}}} = 5{,}100$. Use the floors and prices of problems 2 and 4, and ignore prefix reuse throughout.

1.  Compute the prompt tokens supplied per worker and across the question, the output tokens across the question, and input’s share of the uncached dollars.
2.  For a worker’s final call, compute the prefill and decode times at the floors. Which term of [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.09 The Cost of a Model Call#^eq-vol3-call-latency|equation 6]] binds, and how does that compare with the repair agent’s first turn in this chapter?
3.  One proposal copies the repair agent’s lever and halves every output to 50 tokens. Another keeps each retrieved page in full only for the call that reads it and replaces it afterward with a 400-token note. Compute the dollars each saves per question and choose one. What constraint of this lighthouse does neither calculation address?

**8. Choosing a representation when the deadline moves (Advanced).** A repair call starts from 9,000 context tokens, with the floors of problem 2 and the prices of problem 4. A whole-file response adds 300 instruction tokens and generates 1,200 output tokens; 98 percent apply to the expected version, and 60 percent of those pass the repair checks. A localized edit adds 100 instruction tokens and generates 120; 85 percent identify an applicable target, and 55 percent of those pass. Every attempt, whatever its outcome, also incurs a \$0.05 check charge.

1.  Under an invocation deadline of 10 s, which representations can produce an eligible candidate?
2.  The deadline relaxes to 20 s. Compute $\mathbb{E}[{C_{\text{attempt}}}]$, ${p_{\text{acc}}}$, and ${C_{\text{eff}}}$ (**[[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.07 Reliability and Cost Over a Horizon#^eq-vol3-cost-per-accepted-task|equation 1.2]]**) for each design, and the estimated model time per accepted repair. Which design wins on each measure?
3.  Find the applicability rate at which the localized edit ties the whole-file design on ${C_{\text{eff}}}$. Then critique the benchmark: which of the two measures should decide for an agent whose trajectory has a wall-clock budget, what could raise the localized design’s applicability without lengthening its output, and what single measurement should be added before choosing?

**9. A truncated command at the irreversible end (Advanced; second lighthouse).** The remediation agent proposes 5,000 shell commands a month under an output allowance of 512 tokens, generated at ${t_{\text{decode}}} = 10$ ms per token. Of these calls, 2 percent end `TRUNCATED`. Of the truncated fragments, 40 percent still parse as a complete command, as when `--replicas=12` stops after `--replicas=1`. Executing a parseable fragment causes a wrong production change with probability 0.5, and each wrong change costs \$20,000 to detect and reverse.

1.  Compute the expected wrong changes and loss per month for a runtime that dispatches anything that parses, and for one that applies the quarantining rule of [[01 Books/Volume III - Agentic Systems/01 The Model/02 The Foundation Model/V3-02.06 The Invocation Contract#^sec-vol3-foundation-model-contract|section 2.5]].
2.  For a truncated call, a blind retry at the same allowance truncates again with probability 0.9; a retry at a doubled allowance truncates with probability 0.1. Treating retries as independent and charging each attempt its full allowance as an upper bound, compute the expected attempts and decode time until a completed candidate under each policy.
3.  A colleague proposes a “repair parser” that closes truncated fragments so they can proceed without a retry. Critique the proposal using this lighthouse’s binding constraint, and redesign the runtime’s handling of `TRUNCATED` for this agent, stating what evidence a completed command still needs before it may execute.

**What’s Next: From one candidate to deliberate computation**

The contract ends at one prompt and one candidate, and a completed candidate can still rest on the wrong diagnosis. When the repair agent’s first patch extends a timeout that may not have caused the stall, the runtime can spend more before committing: a longer derivation, more sampled candidates, or a targeted test that observes the running pool. Each option buys a different kind of evidence, and only the test adds a fact the model did not already have. **[[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03 Test-Time Compute#^sec-vol3-test-time-compute|Test-Time Compute]]** examines how to divide a limited budget among these options, how to select from a candidate pool without being fooled by a plausible failure, and when to stop.
