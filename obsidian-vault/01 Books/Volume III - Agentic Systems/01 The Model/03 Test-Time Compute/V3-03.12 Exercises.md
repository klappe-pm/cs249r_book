# V3-03.12 Exercises

Unless a problem states otherwise, use the hypothetical givens in [[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.12 Exercises#^tbl-vol3-test-time-compute-exercise-givens|table 8]]. They are problem inputs chosen for round arithmetic, not measurements of any model or service. Omit prefill, queueing, and transport time, and apply no prefix-cache discount unless a problem introduces one.

| **Quantity**                                 | **Symbol**            | **Given**                 |
|:---------------------------------------------|:----------------------|:--------------------------|
| Generation time per output token, per stream | ${t_{\text{decode}}}$ | 20 ms                     |
| Generator input price                        |                       | \$3 per million tokens    |
| Generator output price                       |                       | \$15 per million tokens   |
| Learned-scorer input price                   |                       | \$0.50 per million tokens |

Table 8: **Givens for the exercises**: Hypothetical rates shared by the problems below. Concurrent streams keep the per-token rate up to the concurrency a problem states.

^tbl-vol3-test-time-compute-exercise-givens

**1. Three allocations, one repository (Basic).** A repair request carries an $8{,}000$-token prompt and a ceiling of $6{,}000$ generated tokens. Depth spends the whole ceiling on one candidate. Breadth generates six $1{,}000$-token candidates, but the service admits only three concurrent streams. Feedback runs ${H} = 3$ rounds of $1{,}000$-token candidates; each round ends with a 6 s check that returns a 500-token report, and later requests append every earlier candidate and report.

1.  Using [[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.03 Three Axes of Test-Time Compute#^eq-vol3-allocation-critical-path|equation 1]], compute each allocation’s critical path, input tokens, output tokens, and model-token bill.
2.  The repository context grows to $64{,}000$ tokens. Recompute the three bills and the breadth premium $({N}-1){S}$ in tokens and dollars.
3.  The task owner now requires a result within 60 s. Which allocation meets the deadline, and at what bill? A prefix cache would charge re-read prompt tokens at 10 percent of list price. What does breadth then cost, and what omitted term in this accounting should an engineer measure before committing to it?

**2. Sizing a pool against a target (Basic).** For a fixed repair task, independent candidates pass the acceptance check with probability ${p} = 0.20$, and the selector returns a passing member whenever one exists.

1.  Find the smallest pool ${N}$ whose pass@${N}$ reaches 90 percent, and the availability gained by its last candidate.
2.  Compare candidates spent per accepted repair for the parallel pool and for sequential retry that stops at the first pass and gives up after ${N}$ attempts. What does the parallel pool buy for its premium?
3.  The workload is actually mixed: half the tasks pass at $0.40$ per candidate and half never pass, so the average rate is still $0.20$. What pool success does the pool size ${N}$ from part (a) deliver, and what is the largest pool success any ${N}$ can deliver? What should the runtime do with the second half of the workload instead?
4.  In a benchmark, 4 of 20 samples for one task pass. Compute the subset estimate of pass@5 and compare it with the plug-in value $1-(1-{c}/{n})^5$.

**3. How strict must the check be? (Basic).** A candidate pool has valid-candidate rate ${p_{\text{valid}}} = 0.10$. The current check has ${\epsilon_{\text{FR}}} = 0.05$ and ${\epsilon_{\text{FA}}} = 0.01$ and costs \$0.10 per run.

1.  Compute the probability of a pass ${q}$ and the precision ${\Pi_{V}}$ from [[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.05 Verifying Candidates#^eq-vol3-verifier-precision|equation 3]].
2.  Precision must reach 95 percent. Find the largest ${\epsilon_{\text{FA}}}$ that meets the target at this ${p_{\text{valid}}}$, and alternatively the smallest ${p_{\text{valid}}}$ that meets it with the current check.
3.  The policy pre-generates 32 candidates and checks them in a fixed order until the first pass, abstaining if none passes. Compute the probability of any selection, the probability that the batch contains at least one false pass, and the probability of selecting a defective candidate. Explain why the second and third differ.
4.  A stricter check has ${\epsilon_{\text{FA}}} = 0.005$ and ${\epsilon_{\text{FR}}} = 0.08$ and costs \$0.40 per run. A defective selection costs \$2,000 in incident loss. Compare the two checks on expected incident loss plus expected checking cost per attempt, and decide which to deploy.

**4. What step scoring costs (Intermediate).** A learned process scorer reads a $3{,}000$-token task input and the growing prefix of a candidate built in ${J} = 20$ steps of 150 tokens each. The runtime scores 64 candidate trajectories per task at the scorer price in [[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.12 Exercises#^tbl-vol3-test-time-compute-exercise-givens|table 8]].

1.  Using [[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.05 Verifying Candidates#^eq-vol3-prm-rescoring|equation 2]], compute scorer input per trajectory and per task when every prefix is rescored from scratch, and when the interface supports incremental prefix reuse.
2.  For this ${S}$ and ${\Delta} {S_{\text{step}}}$, beyond how many steps does the quadratic term exceed the ${J} {S}$ term?
3.  Without prefix reuse, a team proposes scoring only every fourth step. Compute its scorer input and bill per task. A defective step is then caught on average 1.5 steps later, and every pruned trajectory generates those extra steps at the output price. Bound the added generation cost per task, and recommend a scoring stride with and without prefix reuse.

**5. Keeping a tree finite (Intermediate).** Each retained node proposes ${b} = 4$ children of 200 generated tokens, a step check rejects each child independently with probability ${p_{\text{prune}}} = 0.60$, and the search runs ${d_{\max}} = 5$ steps deep under a ceiling of $20{,}000$ generated tokens.

1.  Compute ${b_{\text{eff}}}$ from [[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.07 Bounded Search#^eq-vol3-effective-branching|equation 6]] and the expected generated nodes and tokens with and without pruning. Which expected counts fall below the ceiling, and why does an expected count below it not guarantee that every run fits?
2.  What rejection rate would make the tree die out on its own, and why is a rejection rate that high rarely available?
3.  The step check also rejects valid steps with probability ${\epsilon_{\text{FR}}}$. A correct solution needs five consecutive valid steps to survive. Compute its survival probability at ${\epsilon_{\text{FR}}} = 0.10$, and the largest ${\epsilon_{\text{FR}}}$ that keeps survival at or above 80 percent. What does this imply for tuning the check’s threshold?

**6. A waiting customer sets the policy (Intermediate).** The support agent answers a policy question while the customer waits. Each request carries a $6{,}000$-token prompt of policy excerpts and conversation, each candidate reply is 150 output tokens, and a grounding check against the cited policy takes 1.5 s. A first reply passes with probability $0.70$; conditional on a failed first reply, a revision that reads the check’s report passes with probability $0.50$. Concurrent candidates are checked concurrently, and the reply must arrive within 8 s.

1.  Compute the duration of one generate-and-check round. How many feedback rounds fit the deadline, and what pass probability does feedback therefore deliver?
2.  For concurrent breadth of ${N} = 1$ to $4$, compute pass probability, model-token bill per request, and bill per passing reply. Find the smallest ${N}$ that reaches 95 percent.
3.  The service can hold 600 concurrent decode streams for all sessions. How many simultaneous sessions does the choice in (b) support, compared with a single candidate? Which resource binds this policy?
4.  Contrast with the repair scenario (notebook [3.7](https://mlsysbook.ai/vol3/03_test_time_compute/03_test_time_compute.html#nbk-03-strategy-comparison)), where a second feedback round fit the deadline. Name the constraint that changed the answer, and state one design change that would make feedback viable for the support agent.

**7. Scoping a revision (Intermediate).** A repair candidate records generated artifacts. Each is listed here with its output tokens and direct prerequisites: diagnosis $\text{Dx}$ (300; source excerpt, failure observation), pool patch ${P}_1$ (600; source excerpt, $\text{Dx}$), metrics patch ${P}_2$ (200; $\text{Dx}$), check selection $\text{Chk}$ (150; ${P}_1$, test inventory), API notes $\text{API}$ (250; API declaration), release note $\text{Rel}$ (200; ${P}_1$, ${P}_2$, $\text{API}$), and migration script $\text{Mig}$ (400; $\text{API}$). The labels are local names for this problem only.

1.  A waiter-and-return test contradicts $\text{Dx}$. List $\text{Desc}(\text{Dx})$, and compute the output tokens of scoped regeneration (the diagnosis and its descendants) against full regeneration.
2.  Instead, the API declaration changes while the diagnosis stands. Which artifacts need review, and what share of the output does scoped regeneration avoid?
3.  The pool patch in fact calls the pool’s public constructor, so ${P}_1$ depends on the API declaration, but that edge was never recorded. After the declaration changes, which stale artifacts survive the traversal, and what could the runtime then wrongly reuse? Propose how the runtime should record edges so that this failure cannot occur silently, and state what that costs.

**8. A judge under selection pressure (Advanced).** The research agent drafts ${N}$ candidate summaries of what it has read, and a learned judge scores each as ${\hat{U}}_i = {U}_i + {\epsilon}_i$. True quality is ${U}_i \sim {\mathcal{N}}({\mu}, {\sigma_{U}}^2)$ with ${\sigma_{U}} = 1.0$, scoring error is ${\epsilon}_i \sim {\mathcal{N}}(0, {\sigma}^2)$ with ${\sigma} = 0.5$, all independent. The exact expected maximum of ${N}$ standard normal draws is 1.03, 1.77, and 2.34 for ${N}$ = 4, 16, and 64. Each candidate costs \$0.12.

1.  Using the exact values in place of [[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.05 Verifying Candidates#^eq-vol3-argmax-noise|equation 4]], bound the winner’s expected scoring error at each ${N}$.
2.  Show that when selection is on ${\hat{U}}$, the winner’s expected quality gain over ${\mu}$ is $({\sigma_{U}}^2/{s})\,{m_{N}}$ and its expected error is $({\sigma}^2/{s})\,{m_{N}}$, where ${s} = \sqrt{{\sigma_{U}}^2 + {\sigma}^2}$ and ${m_{N}}$ is the expected standard-normal maximum. Evaluate both at the three pool sizes, and compare quality gained per dollar in moving from 4 to 16 and from 16 to 64 candidates.
3.  A fraction ${p_{\text{exp}}} = 0.002$ of summaries cite a retrieved page whose planted text the judge rewards but which does not support the claim. Compute the probability that a pool of 4, 16, and 64 contains at least one such summary, and explain why selection then tends to return it.
4.  Redesign the selection policy. Choose a pool size and a check the planted page cannot influence, and state what evidence the returned summary must carry. How does the binding constraint here differ from the repair agent’s?

**9. Stopping before an irreversible change (Advanced).** The remediation agent generates candidate configuration changes in rounds, each costing \$0.20 in generation and a staging check. Calibrated on held-out incidents, the estimated probability of a staging-accepted candidate after ${m}$ rounds is ${\hat{p}}_{{m}}$ = 0.40, 0.58, 0.68, 0.74, 0.77, 0.79 for ${m}$ = 1 to 6, with ${\hat{p}}_0 = 0$, and the hard ceiling is six rounds.

1.  For each prospective round, derive the conditional acceptance gain given no earlier pass and the increment in expected stopped-policy cost. Compute the marginal ratio of [[01 Books/Volume III - Agentic Systems/01 The Model/03 Test-Time Compute/V3-03.07 Bounded Search#^eq-vol3-marginal-stopping|equation 7]]. With ${\epsilon_{\text{stop}}} = 0.25$ per dollar, how many rounds can the policy admit after earlier failures, and what are its acceptance probability and expected generation-and-check expenditure if it stops at the first accepted candidate?
2.  An accepted automated change saves \$30 of on-call time compared with escalation. Derive ${\epsilon_{\text{stop}}}$ from that value, and state how many rounds the policy now admits and which rule ends the search.
3.  A colleague proposes that when the ceiling is reached without an accepted candidate, the agent applies its highest-scoring candidate. That candidate is defective with probability 0.5, a defective change costs \$40,000, and escalating to a human costs \$150. Compute each fallback’s expected loss conditional on reaching the ceiling without an accepted candidate, then its contribution per initiated task under the policy in (a). Treat deliberation expenditure as common to both alternatives. Identify the stopping-precedence rule the proposal violates.
4.  Write the redesigned policy as the ordered checks the runtime applies before admitting another round, including what it returns in each case. Why does a staging-accepted candidate still not authorize the production change?

**What’s Next: From deliberation to working state**

Deliberation leaves candidate versions, failed hypotheses, observations, and dependency records. The next model call cannot treat all of them as equally current or useful, even when every one of them still fits in its window. It needs a working context that retains the evidence supporting the selected candidate, distinguishes superseded material, and carries unresolved questions forward. **[[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04 Context Engineering#^sec-vol3-context-engineering|Context Engineering]]** develops this logical state-selection problem. Only after deciding what belongs in the working context does the physical question arise of how to store and reuse its model state, developed in **[[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05 KV Cache Management#^sec-vol3-kv-cache|KV Cache Management]]**.
