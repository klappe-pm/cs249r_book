*Agentic Machine Learning Systems Stack*

*Agent stack focus for this chapter.*

*Why can individually tested components still leave an agent’s task unfinished or its effects unaccounted for?*

An autonomous agent combines several systems disciplines (foundation models, memory hierarchies, isolated execution sandboxes, transactional event logs, and independent verifiers) in one closed-loop control architecture. Each component can pass its own tests, yet the system can still fail if the contracts between components are missing or unclear. The core challenge of agentic systems engineering is designing the deterministic harness that bounds and verifies a stochastic proposer, a problem that larger models and more elaborate prompts do not remove. Over a long trajectory, with state carried between steps and authority delegated to the agent, reliable autonomy depends on a runtime that settles at every boundary what was proposed, what was done, and what evidence shows the task is complete.

**Learning Objectives**

- Trace an incident-remediation trajectory, identifying the owner and record of each consequential transition
- Translate a task contract into bounds and acceptance requirements proportionate to its horizon, state, and authority
- Diagnose state and evidence mismatches at subsystem boundaries using the authority and lifetime of each record
- Resolve an uncertain external action without confusing a lost response with permission to repeat its effect
- Select a system intervention using attributed failures, outcome evidence, and its full deployment cost
- Construct a safety case that connects scoped claims to arguments, evidence, assumptions, and residual uncertainty
- Distinguish assistance with specifications from authority to adopt them and accept the resulting task
