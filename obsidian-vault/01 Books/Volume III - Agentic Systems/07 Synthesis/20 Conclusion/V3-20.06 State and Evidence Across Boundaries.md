# V3-20.06 State and Evidence Across Boundaries

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/07 Synthesis/20 Conclusion/V3-20 Conclusion|V3-20 Conclusion]]

^sec-vol3-conclusion-memory

Before the mitigation, the context manifest selects diagnostic evidence describing the old configuration. Once the endpoint confirms that the rollback applied the new configuration, any prompt that still presents the old configuration as active state gives the model an incorrect basis for its next decision. The earlier observation remains true, but its role has changed; it no longer describes the live system and serves instead as historical evidence of the trajectory.

### Evidence Refresh and Cached Computation

^sec-vol3-memory-coherence-invalidation

That role change is easy to miss when derived stores and serving caches sit between the database and the next prompt. A cached summary or vector index that still reports the old configuration after the rollback commits misleads the next turn even though the KV cache for the old prompt tokens remains mathematically valid. To keep those guarantees separate, the incident’s records occupy distinct roles in an evidence chain. The configuration service is the *source record*, the runtime operation log is the *event log* of decisions, approvals, and settlement status, model-written incident summaries are *agent-written memory*, and diagnostic vector indices are *derived retrieval indexes*. The context manifest is none of these; it is the working-context view assembled for the next model call. No derived role can override the source, and the operation log attests only to the events it durably wrote, not to an external effect it has not verified (**[[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/11 Durable Execution/V3-11.03 The Trajectory Log#^sec-vol3-persistence-event-sourcing|The Trajectory Log]]**).

↩︎ Source records, event logs, agent-written memory, and derived indexes as roles in an evidence chain are established in **[[01 Books/Volume III - Agentic Systems/02 Agent Memory/06 Long-Term Memory/V3-06.03 Persistent Records#^sec-vol3-long-term-memory-record-roles|Record roles]]**.

When the source confirms the new configuration, context assembly updates the active configuration entry, keeps the old record only where it justifies the remediation step, and invalidates derived artifacts that depend on the superseded version, such as diagnostic summaries and precomputed runbook excerpts. If the retrieval index lags, the runtime issues an authorized direct read, and if no read is possible the manifest records the omission rather than presenting stale data as current.

↩︎ Withdrawing a staged observation’s authority over current state when its source changes is established in **[[01 Books/Volume III - Agentic Systems/02 Agent Memory/04 Context Engineering/V3-04.08 Context Invalidation#^sec-vol3-context-engineering-context-rot|Context Invalidation]]**.

The serving system judges validity by a different rule. KV cache tensors computed for tokens describing the old configuration remain valid representations of those tokens whatever the service now holds, so substituting evidence for the new configuration ends prefix reuse at the first changed token and leaves the unchanged prefix reusable. Prefix coherence (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-prefix-coherence|5]]) governs computational reuse and source authority (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-source-authority|6]]) governs semantic freshness, and a cache hit establishes only the first. Freshness checks at prompt time also cannot freeze the service while the model deliberates, which is why the endpoint’s expected-version check at application remains the final guard.

↩︎ Reuse of KV state only over an exact token prefix computed under the same weights and execution parameters is established in **[[01 Books/Volume III - Agentic Systems/02 Agent Memory/05 KV Cache Management/V3-05.06 Prefix Caching Across Turns#^sec-vol3-kv-cache-prefix-compatibility|Prefix compatibility]]**.

Provenance follows the same separation. The runtime records which endpoint supplied each observation under the read grant, its timestamp and version, any filtering applied, and the model request that consumed it, and these host-verified events stay distinct from the model’s hypotheses about the cause of the alert. Text read from a trusted store, including an instruction injected into a log stream, gains no authority by being stored there. Permissions are evaluated against capability grants, and observed data remains passive payload.

### Boundaries Between Subsystems and Their Owners

^sec-vol3-conclusion-seams

In the source-to-context example, storage and serving each operate within their local specifications while the agent as a whole acts on stale evidence. That failure pattern recurs at every subsystem boundary the incident crosses. [[01 Books/Volume III - Agentic Systems/07 Synthesis/20 Conclusion/V3-20.06 State and Evidence Across Boundaries#^tbl-vol3-seams|Table 4]] names five such boundaries, the last two of which arise only if the deployment adds learning or delegation.

| Boundary                                 | Incident-specific failure                                                                                       | Principles that meet here                                                                                                                                                                                                                                                                                         | Owner and required record                                                                                                                                                 |
|:-----------------------------------------|:----------------------------------------------------------------------------------------------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| World and its representations            | `config_v7` is presented as current after `config_v8` is confirmed                                              | Source authority (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-source-authority\|6]]) against prefix reuse (principle [[01 Books/Volume III - Agentic Systems/02 Agent Memory/V3 Agent Memory Principles#^pri-vol3-prefix-coherence\|5]])                             | Context and retrieval owners preserve source/version bindings in `context_manifest_42`; the action endpoint enforces the expected version when applying a change          |
| Proposal to effect                       | A lost reply is treated as failure, leading to an unsafe repeat of `op_42`                                      | Intent before effect (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-intent-before-effect\|11]]), then settlement before retry (principle [[01 Books/Volume III - Agentic Systems/03 Tool Use/V3 Tool Use Principles#^pri-vol3-exactly-once-settlement\|8]]) | The settlement process and `operations_owner_42` retain the admitted intent, operation identity, and unresolved status until the endpoint supplies outcome evidence       |
| Recovery and authority                   | A recorded recovery plan is treated as permission to apply a corrective change to a now-different service       | Intent before effect (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-intent-before-effect\|11]]) against the typed action contract (principle [[01 Books/Volume III - Agentic Systems/03 Tool Use/V3 Tool Use Principles#^pri-vol3-strict-action-abi\|7]])   | `operations_owner_42` retains the descriptor and residual duty; any corrective action needs current authorization and applicable preconditions                            |
| Recorded incident to learning, if chosen | Acceptance of the incident makes every step a training target, or the release grader becomes a selection reward | Release evidence (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-release-evidence\|12]]) against the verification asymmetry (principle [[01 Books/Volume III - Agentic Systems/01 The Model/V3 Model Principles#^pri-vol3-verification-asymmetry\|3]])        | Curation and evaluation owners separately admit any training record derived from the incident, keep its permitted use and evidence limits, and protect release evaluation |
| Across workers, if delegated             | Diagnostic workers duplicate a consumable allowance or their agreement is treated as independent confirmation   | Coordination tax (principle [[01 Books/Volume III - Agentic Systems/06 Agents at Scale/V3 Agents at Scale Principles#^pri-vol3-coordination-tax\|14]]) against trajectory-level encapsulation (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-trajectory-encapsulation\|10]]) | Delegating runtime records scoped assignments and reservations; the integration owner checks returned evidence and retains unresolved child obligations                   |

Table 4: **Incident boundaries, principles, and owners**: Each boundary needs both an owner and a record that preserves the distinction the next subsystem relies on, and at each one two principles meet or pull against each other. Local success alone does not establish the end-to-end task result.

^tbl-vol3-seams

Delegation makes the final row concrete without changing the acceptance contract. A worker may receive a subset of the read grant, a reusable capability, but a consumable allowance cannot be copied the same way; concurrent workers reserve against one shared budget rather than each receiving an independently spendable quota (principle [[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/V3 Agent Runtime Principles#^pri-vol3-trajectory-encapsulation|10]]). Agreement among diagnostic workers also cannot substitute for verification, because workers that read the same noisy inputs or each other’s intermediate results fail together. Whether delegation pays at all is weighed against the coordination tax (principle [[01 Books/Volume III - Agentic Systems/06 Agents at Scale/V3 Agents at Scale Principles#^pri-vol3-coordination-tax|14]]) in [[01 Books/Volume III - Agentic Systems/07 Synthesis/20 Conclusion/V3-20.08 Choosing a Remedy from the Evidence#^sec-vol3-conclusion-adaptation|section 20.7]].

With these records in place, an auditor can reconstruct what the runtime observed, what it proposed, what authority it held, and what state the external world committed. Turning that evidence into an admissible next action, whether settling an ambiguous request or dispatching a compensating repair, falls to the execution and recovery boundary.
