# V3-09.14 Exercises

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09 Agent Security|V3-09 Agent Security]]

^sec-vol3-security-exercises

The problems use the chapter’s notation and mechanisms. All numeric givens are hypothetical problem inputs, not measurements of any system; workload read volumes and approval parameters are those of the chapter’s lighthouse profiles.

**Problem 1 (Basic): A read budget behind a screen.** A repair task reads external documents in which a fraction ${q}$ = 0.5 percent independently carry a payload. The team wants at most 10 percent of tasks to meet a payload before any release or evidence check fires.

1.  With [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.03 The Adversarial Threat Model#^eq-vol3-injection-exposure|equation 1]], compute $\Pr(\text{exp})$ for a task that reads 40 documents.
2.  Find the largest ${n_{\text{read}}}$ that meets the target.
3.  A screening classifier misses 10 percent of payloads. Find the new largest ${n_{\text{read}}}$, and state what the screen changes about the runtime’s release check and what it leaves unchanged.

**Problem 2 (Basic): Labels on a derived query.** A repair planner’s context holds three records. A public issue has ${\iota} = \{\texttt{issue\_12}\}$ and no recipient restriction. A private configuration has ${\iota} = \{\texttt{config}\}$ and ${\kappa} = \{\text{runner}, \text{reviewer}\}$. A protected-runner log has ${\iota} = \{\text{runner}\}$ and ${\kappa} = \{\text{runner}, \text{reviewer}, \text{dashboard}\}$. The planner emits a message ${x}$.

1.  Compute ${\iota}({x})$ and ${\kappa}({x})$ with [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.07 Information-Flow Policy#^eq-vol3-flow-join|equation 2]].
2.  Apply [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.07 Information-Flow Policy#^eq-vol3-flow-dispatch|equation 3]] to three proposals. One posts ${x}$ to the public issue tracker. Another submits ${x}$ to the internal review service, whose task policy accepts any source. A final proposal records ${x}$ as a test pass, whose ${\text{Inf}}({o})$ is $\{\text{runner}\}$. For each, name the condition that fails or state that both hold.
3.  Redesign the acceptance path so that a test pass can be recorded without weakening the evidence check.

**Problem 3 (Basic): How many clean episodes a release needs.** A release rule requires that the 95 percent upper bound on the attack-success rate be at most 0.5 percent.

1.  Using the zero-success bound of [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.10 Adversarial Robustness and Red-Teaming#^sec-vol3-security-evaluation|section 9.9]], find the smallest number of attacked episodes with zero observed successes that meets the rule, and compare it with the rule-of-three estimate.
2.  The team reports zero disclosures in 200 attacked episodes. Compute the upper bound this supports.
3.  The same report excludes 3 episodes whose endpoint outcome was unresolved at the horizon. Critique the exclusion and compute the conservative outcome fraction once they are restored. Decide whether the restored report supports the release rule, and explain why unresolved outcomes cannot be treated as clean trials in the zero-success calculation.

**Problem 4 (Intermediate): Pricing a release check.** Two policies run the same repair distribution with 200 attacked and 200 benign episodes each. Policy A checks the search operation and destination only; Policy C adds typed fixture handles and a release check. [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.14 Exercises#^tbl-vol3-security-ex-policy-outcomes|Table 6]] records the outcomes.

| Outcome count                          | Policy A | Policy C |
|:---------------------------------------|---------:|---------:|
| Attacked episodes, observed disclosure |       30 |        6 |
| Attacked episodes, unresolved outcome  |        4 |       16 |
| Accepted benign repairs                |      180 |      171 |
| Benign repairs lost to a false block   |        8 |       17 |

Table 6: **Outcomes for two repair policies**: Counts from the same attacked and benign repair episodes under each policy; problem inputs, not measurements.

^tbl-vol3-security-ex-policy-outcomes

1.  Compute each policy’s observed attack-success rate and its upper disclosure fraction counting unresolved outcomes as disclosures. Find the relative reduction using the observed rates and in the stipulated scenario where unresolved outcomes in both arms are disclosures. Then find the least favorable comparative reduction using A’s confirmed lower rate and C’s upper rate.
2.  At \$2 per attempt for both policies, compute ${C_{\text{eff}}}$ per accepted benign repair for each with **[[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.07 Reliability and Cost Over a Horizon#^eq-vol3-cost-per-accepted-task|equation 1.2]]**, and the added monthly cost of C at 10,000 accepted repairs per month.
3.  Assume 100 production tasks per month meet this attack exactly as tested. Find the cost per disclosure above which C pays for itself using the observed rates and in the stipulated both-arms disclosure scenario of part (a). Repeat using the least favorable difference between A’s confirmed lower rate and C’s upper rate.
4.  Name two assumptions in part (c) that the chapter warns a benchmark rate cannot supply, and name the cheapest change to C that would lower its break-even cost without touching the release check.

**Problem 5 (Intermediate): Same payload rate, different binding constraint.** Transfer the repair analysis to the research agent, which reads 100 untrusted items per task, and the support agent, which reads 6. Both face ${q}$ = 1 percent, and an exposed task yields a successful injection with probability 10 percent. A successful research injection discloses data worth \$20; a successful support injection issues a redirected refund worth \$400.

1.  Compute the per-task exposure and the expected loss per task for each agent.
2.  For the support agent, compare two defenses: a screening classifier with miss rate 5 percent, and an effect-scope check that takes the refund amount and account from the case record, which caps a successful injection’s loss at \$20. Compute the expected loss per task under each.
3.  An adaptive attacker raises the classifier’s miss rate to 50 percent. Recompute both options and choose one. Explain why the binding constraint for the support agent is consequence rather than exposure, while for the research agent it is the release of what it reads.

**Problem 6 (Intermediate): Drawing the sharing domain for a support fleet.** Each support session holds 8,192 tokens of context, of which the first 6,144 are a public policy and instruction prefix identical for every customer; the rest is the customer’s private conversation. A replica prefills 10,000 tokens per second. Treat each session as one prefill of its full context, each session as a different customer’s only session, a resident prefix as always hit when its sharing domain permits reuse, and private conversations as never repeated.

1.  Compute prefill tokens per session and replica-hours of prefill per 1,000,000 sessions for three designs. The first design uses a tenant-wide sharing domain for all cached state. The second uses a per-customer domain for all cached state. The last is a split in which the public prefix follows a shared policy while the private suffix is confined to a per-customer domain.
2.  Explain what a customer can learn under the first design by timing candidate prefixes, and why the split design removes that channel at no prefill cost relative to the first.
3.  Name one condition under which the split design still leaks, and the serving-side control that closes it.

**Problem 7 (Advanced): Paying for conservative labels.** Under the conservative invocation rule, a planner that has read the private fixture taints every later query, so every subsequent search fails the release check. Without the rule, a repair attempt is accepted with probability 90 percent. In 60 percent of tasks the planner reads the fixture before it needs a search, and a task whose searches are all blocked then fails with probability 50 percent. An attempt costs \$1.50.

1.  Compute ${p_{\text{acc}}}$ under the conservative rule and the resulting rise in ${C_{\text{eff}}}$.
2.  A redesign routes search construction through a trusted query adapter that reads only public manifest fields and receives no planner output. It adds \$0.01 per search and a task makes 3 searches on average. Assuming it restores the original acceptance probability, compute its ${C_{\text{eff}}}$ and compare the three designs.
3.  A colleague proposes instead that the planner choose which of two public package names the adapter should search. Compute the query’s ${\iota}$ and ${\kappa}$ when that choice depends on the fixture, decide whether it passes [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.07 Information-Flow Policy#^eq-vol3-flow-dispatch|equation 3]], and state what the adapter must not receive for part (b)’s assumption to hold.

**Problem 8 (Advanced): Standing approval for the remediation agent.** The remediation agent requests 2 approvals per hour, each costing 10 minutes of an approver paid \$120 per hour. Each change follows a diagnosis that reads 10 untrusted alerts and log lines at ${q}$ = 1 percent. An exposed diagnosis redirects the change’s parameters with probability 10 percent, and a redirected change costs \$12,000. A reviewer inspecting the exact represented action catches 90 percent of redirected changes. To save approver time, the team proposes a standing approval: one review per hour authorizes every configuration change to the same service during that hour. The standing review sees no individual change’s parameters, so it catches no redirected change.

1.  Compute the approver cost per hour under per-action approval and under the standing approval.
2.  Compute the expected redirected-change loss per hour under each, and the total hourly cost.
3.  Find the injection success probability below which the standing approval would be cheaper, and explain why that break-even is not a safe basis for the decision.
4.  Propose a redesign that lowers approver cost while keeping the approval bound to the exact represented action, and state which approval fields it must still show.

**What’s Next: From security boundaries to trajectory supervision**

Every check in this chapter fires at one dispatch, on one proposal and the labels it carries. None of them decides whether the trajectory should propose again. Suppose the test of candidate `r18` is still running when an operator asks to pause and the repair nears its budget. The pending job, the workspace lease, any held approval, and the labels on retained information then need a single owner that keeps the task’s grants, budgets, and outstanding work current as execution continues or someone intervenes. **[[01 Books/Volume III - Agentic Systems/04 The Agent Runtime/10 The Agent Harness/V3-10 The Agent Harness#^sec-vol3-agent-harness|The Agent Harness]]** develops that whole-trajectory supervision, which decides when to call the model, dispatch permitted work, wait, request approval, or stop. Making that supervision survive a crash, and repairing effects already completed, are separate responsibilities developed afterward.
