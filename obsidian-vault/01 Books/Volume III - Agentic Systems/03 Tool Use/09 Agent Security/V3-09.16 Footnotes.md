# V3-09.16 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09 Agent Security|V3-09 Agent Security]]

^footnotes

<sup>1</sup> **Prompt Injection**: Simon Willison named the attack in September 2022, immediately following public examples posted by Riley Goodside, by analogy to SQL injection ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-willison2022prompt|Willison 2022]]). SQL injection admits a structural fix: parameterized queries carry executable code and data to the database engine through separate communication channels. A foundation model’s input context has no such second channel, which is why this chapter places the defense on the proposed operation rather than on the text.

^fn1

<sup>2</sup> **Adversarial Suffix**: The concept descends from adversarial examples in computer vision, where Szegedy and colleagues showed that small, optimized perturbations imperceptible to humans can alter a network’s classification ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-szegedy2013intriguing|Szegedy et al. 2013]]). GCG adapts that optimization to discrete token sequences, generating readable or pseudo-random text suffixes that bypass model alignment. Input filters tuned to known perturbations invite new evasions, whereas runtime checks on the resulting action remain invariant to how the prompt was phrased.

^fn2

<sup>3</sup> **Bell–LaPadula Model**: The model Bell and LaPadula developed at MITRE beginning in 1973 formalized confidentiality for multilevel systems with two rules: forbidding a subject to read above its clearance (simple security) or to write below it (the $\star$-property) ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-bell1973secure|Bell and LaPadula 1973]]). An agent breaks the $\star$-property whenever a model that ingests private context and then composes an outbound search query writes confidential data down to an untrusted public recipient.

^fn3

<sup>4</sup> **Biba Integrity Model**: Biba formulated integrity as the dual of confidentiality, forbidding a subject to read data of lower integrity or to write data of higher integrity ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-biba1977integrity|Biba 1977]]). A README-derived claim accepted into the task’s acceptance record as test evidence represents an unauthorized write from low integrity to high integrity, which is precisely what the runtime’s evidence check must refuse.

^fn4

<sup>5</sup> **Lattice Model of Information Flow**: Denning showed in 1976 that security classes form a lattice, so the class of a value computed from several inputs is the least upper bound, or join, of their classes ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-denning1976lattice|Denning 1976]]). [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.07 Information-Flow Policy#^eq-vol3-flow-join|Equation 2]] is that join for two properties at once, with provenance sets growing by union and permitted-recipient sets shrinking by intersection. Because the join is associative, a runtime can propagate labels one step at a time through a long trajectory and reach the same label as a single global computation.

^fn5

<sup>6</sup> **Dynamic Taint Analysis**: Newsome and Song’s TaintCheck (2005) marked data arriving from the network as tainted, propagated the mark through execution by rewriting binaries at run time, and detected overwrite attacks when tainted data reached a sensitive use ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-newsome2005dynamic|Newsome and Song 2005]]). Instruction-level tracking works because each machine operation has a known dependency rule. A model invocation has none the runtime can read, which is why this chapter propagates labels at the granularity of whole invocations.

^fn6

<sup>7</sup> **Noninterference**: Goguen and Meseguer defined one group of users as noninterfering with another when nothing the first group does has any effect on what the second group can observe ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-goguen1982security|Goguen and Meseguer 1982]]). The property belongs to the whole system rather than to any single check, which is why the conservative invocation rule claims only an over-approximation of dependence.

^fn7

<sup>8</sup> **Decentralized Declassification**: Myers and Liskov’s decentralized label model attaches a policy for each owner of a value and lets principals declassify their own data safely, so declassification is an authority a principal holds rather than a property of the value ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-myers1998complete|Myers and Liskov 1998]]). The agent analogue is that release authority belongs to the data owner and the task policy, never to the model that produced the output.

^fn8

<sup>9</sup> **Delegation vs. Impersonation**: RFC 8693 distinguishes impersonation, in which the acting party becomes indistinguishable from the subject, from delegation, in which an `act` claim records the acting party alongside the subject ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-jones2020tokenexchange|Jones et al. 2020]]). Delegation preserves the distinction this section needs, because an audit record can then name both the requester and the automation service that acted for it.

^fn9

<sup>10</sup> **Confinement Problem**: Lampson observed in 1973 that a confined program can leak information through channels never intended to carry it, including its effect on shared system resources ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-lampson1973note|Lampson 1973]]). A prefix cache shared across callers is such a resource. A 2025 audit of commercial model APIs used response timing alone to detect prompt caches shared across users at seven providers ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-gu2025auditing|Gu et al. 2025]]).

^fn10

<sup>11</sup> **Rule of Three**: With no successes in ${n}$ independent trials, the 95 percent upper bound $\Pr(\text{success})$ solves $(1-\Pr(\text{success}))^{n} = 0.05$, so $\Pr(\text{success}) = 1 - 0.05^{1/{n}} \approx \ln(20)/{n} \approx 3/{n}$. Hanley and Lippman-Hand drew attention to the rule for clinical studies that report zero adverse events ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-hanley1983nothing|Hanley and Lippman-Hand 1983]]). Inverted, it tells a security team how many clean attacked episodes a release target demands, about three divided by the tolerable attack-success rate.

^fn11
