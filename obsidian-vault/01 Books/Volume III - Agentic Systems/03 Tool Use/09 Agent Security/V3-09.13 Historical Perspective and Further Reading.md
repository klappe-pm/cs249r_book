# V3-09.13 Historical Perspective and Further Reading

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09 Agent Security|V3-09 Agent Security]]

^sec-vol3-security-history

The problem of a program misusing ambient authority on behalf of an untrusted request predates language models by half a century. In a foundational 1972 planning study for the U.S. Air Force, Anderson introduced the concept of the reference monitor, a tamper-proof, universally invoked validation mechanism through which every resource access must pass ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-anderson1972computer|Anderson 1972]]). Three years later, Saltzer and Schroeder articulated the enduring design principles of protected computer systems, establishing complete mediation, least privilege, and fail-safe defaults as prerequisites for dependable software ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-saltzer1975|Saltzer and Schroeder 1975]]). Lampson observed in 1973 that confining an untrusted program is harder than restricting its immediate entry points, because sensitive information can easily escape through covert channels never designed for communication ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-lampson1973note|Lampson 1973]]). Hardy’s 1988 confused deputy, already met at the tool boundary, named the failure that prompt injection now industrializes ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-hardy1988confused|Hardy 1988]]).

Traditional access control inspects permissions at the perimeter, but it cannot track where data travels after it is read. Information-flow security emerged to close this gap. Bell and LaPadula formalized multilevel confidentiality to prevent sensitive data from leaking into lower-security sinks ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-bell1973secure|Bell and LaPadula 1973]]), while Biba formulated the mathematical dual for integrity to prevent untrusted inputs from corrupting trusted system state ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-biba1977integrity|Biba 1977]]). Denning synthesized these models by organizing security classes into an algebraic lattice, establishing that the label of any derived value is the join of its constituent inputs ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-denning1976lattice|Denning 1976]]), the operational rule expressed in [[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.07 Information-Flow Policy#^eq-vol3-flow-join|equation 2]]. Goguen and Meseguer gave these flow constraints a semantic foundation with noninterference, formalizing the requirement that low-privilege observers must not be able to distinguish whether high-privilege computations occurred ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-goguen1982security|Goguen and Meseguer 1982]]). Later work made these guarantees practical in software. Myers and Liskov introduced decentralized label models so that individual principals could safely declassify their own data without a centralized arbiter ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-myers1998complete|Myers and Liskov 1998]]). Newsome and Song demonstrated that dynamic taint tracking could trace untrusted data through commodity binaries at machine-instruction boundaries ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-newsome2005dynamic|Newsome and Song 2005]]).

Language models reopened these classical security challenges at an entirely new system boundary: the prompt, where executable instructions and passive data share a single channel. Willison identified and named prompt injection in 2022 ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-willison2022prompt|Willison 2022]]). Greshake and colleagues expanded the threat model by demonstrating indirect prompt injection, showing how retrieved context such as web pages, email messages, or database records can carry adversarial instructions directly into an agent’s reasoning loop ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-greshake2023not|Greshake et al. 2023]]). Zou and colleagues then showed that these adversarial prompts do not rely on clever manual phrasing; gradient-based search algorithms can generate transferable token sequences automatically ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-zou2023|Zou et al. 2023]]). Early defenses attempted to secure the system within the model weights, for example by training models to distinguish between developer instructions and untrusted context ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-wallace2024instruction|Wallace et al. 2024]]). Heuristic filtering inside the neural network proved fragile against adaptive attackers, however. Modern system architectures instead enforce isolation outside the model weights. The shift runs from dual-model pipelines that separate untrusted parsing from privileged planning ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-willison2023dual|Willison 2023]]) to runtimes that attach provenance and permitted-use metadata to values and check that metadata before every tool execution ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-debenedetti2025camel|Debenedetti et al. 2025]]). The architectural progression mirrors that of classical systems: heuristic content filtering inevitably yields to the strict, external mediation of information flows.

- **Saltzer and Schroeder, “The Protection of Information in Computer Systems”** ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-saltzer1975|Saltzer and Schroeder 1975]]). The foundational treatise on secure systems architecture. Its design principles, particularly complete mediation, least privilege, and fail-safe defaults, remain the essential working vocabulary for any enforcement layer, including an agent runtime.
- **Hardy, “The Confused Deputy”** ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-hardy1988confused|Hardy 1988]]). In just three pages, Hardy demonstrates why identity-based access controls fail when a privileged program exercises borrowed authority on behalf of an untrusted client. This dynamic is the central failure mode of an injected agent.
- **Denning, “A Lattice Model of Secure Information Flow”** ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-denning1976lattice|Denning 1976]]). This paper presents the concise mathematical argument for why security labels combine through a lattice join operation. It is essential reading before designing label propagation or dynamic taint tracking in an agent engine.
- **Greshake et al., “Not What You’ve Signed Up For”** ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-greshake2023not|Greshake et al. 2023]]). The paper that transformed prompt injection into a concrete systems threat model, establishing how untrusted content ingested through retrieval or tool execution can commandeer an agent.
- **Debenedetti et al., “AgentDojo”** ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-debenedetti2024agentdojo|Debenedetti et al. 2024]]). A benchmark and execution environment that evaluates security mechanisms by measuring task utility alongside attack mitigation success, embodying the evaluation discipline developed in this chapter.
- **Debenedetti et al., “Defeating Prompt Injections by Design”** ([[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09.15 Source References#^ref-debenedetti2025camel|Debenedetti et al. 2025]]). A comprehensive systems design that applies capability architectures and information-flow tracking to an agent runtime, best read with close attention to the utility and flexibility that strict isolation requires sacrificing.
