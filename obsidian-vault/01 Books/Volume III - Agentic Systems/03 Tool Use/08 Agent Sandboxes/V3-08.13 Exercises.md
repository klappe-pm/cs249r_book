# V3-08.13 Exercises

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08 Agent Sandboxes|V3-08 Agent Sandboxes]]

^sec-vol3-sandboxes-exercises

All givens below are hypothetical problem inputs, not measurements of any product. Decimal units apply throughout these problems (1 GB is $10^9$ bytes and 1 KB is $10^3$ bytes), while configured guest memory in the worked notebooks is a binary capacity quoted in conventional megabytes, so a problem’s answer need not reproduce a notebook value digit for digit.

**Problem 1 (Basic): Splitting a repair grant across test shards.** A repair task holds ${\Gamma_{\text{repair}}} = ({\mathcal{R}_{\Gamma}}=\{\text{read}, \text{write}, \text{execute}\},\ \mathcal{O}_{\Gamma}=\texttt{repo/},\ {\phi_{\Gamma}},\ {t_{\text{exp}}}={T}_0 + 900\,\text{s})$, where ${\phi_{\Gamma}}$ binds use to this task and carries an aggregate budget of 600 CPU-seconds. The controller proposes three children for parallel test shards: ${\Gamma_{a}} = (\{\text{read}, \text{execute}\},\ \texttt{repo/tests/},\ 250\ \text{CPU-s},\ {T}_0 + 600\,\text{s})$, ${\Gamma_{b}} = (\{\text{read}, \text{execute}\},\ \texttt{repo/},\ 200\ \text{CPU-s},\ {T}_0 + 1200\,\text{s})$, and ${\Gamma_{c}} = (\{\text{read}, \text{write}\},\ \texttt{repo/src/},\ 200\ \text{CPU-s},\ {T}_0 + 600\,\text{s})$. (a) Apply the component-wise attenuation check to each child and decide which may be issued. (b) The parent keeps 150 CPU-seconds for its own work. Decide whether the valid children fit the aggregate budget, and whether they would still fit if ${\Gamma_{b}}$ were corrected to expire at ${T}_0 + 900\,\text{s}$. (c) At ${T}_0 + 700\,\text{s}$ a shard holding ${\Gamma_{a}}$ requests execute on `repo/tests/run.sh`. Evaluate [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.05 Capabilities and Credentials#^eq-vol3-capability-verdict|equation 1]] term by term and state the verdict.

**Problem 2 (Basic): Resident memory of a repair pool.** A platform admits repair trajectories at ${\lambda_{\text{arr}}} = 0.25\ \text{s}^{-1}$, each holding its lease for ${T_{\text{hold}}} = 1600\,\text{s}$. The shared template occupies 0.5 GB, each active lease writes 96 MB of private pages, three standby instances hold 16 MB each, and a full private guest image would be 0.5 GB. The pool host has 64 GB for sandbox residency. (a) Compute ${N_{\text{active}}}$ and ${M_{\text{pool}}}$ by [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.09 Sandbox Pools and Reset#^eq-vol3-pool-memory|equation 6]], and compare with private images. (b) Trajectories double in length. Recompute ${M_{\text{pool}}}$ and decide whether the host still fits. (c) If it does not, find the largest admission rate the host supports at the longer horizon and state the admission policy that enforces it.

**Problem 3 (Basic): Paying the system-call tax on a build.** An untrusted dependency build performs 30 s of useful computation and issues $2 \times 10^{6}$ system calls, of which $5 \times 10^{4}$ touch a virtual device. Take these per-call costs as givens. A shared-kernel container pays ${T_{\text{trap}}} = 0.1\,{\text{µ}}\text{s}$ and ${T_{\text{filter}}} = 0.05\,{\text{µ}}\text{s}$ on every call. A user-space kernel pays $0.1\,{\text{µ}}\text{s}$ trap, $1.5\,{\text{µ}}\text{s}$ emulation, and $2.0\,{\text{µ}}\text{s}$ switch on every call. A microVM pays a $0.1\,{\text{µ}}\text{s}$ native trap on ordinary calls and $5.1\,{\text{µ}}\text{s}$ in total on each device call. (a) Using [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.06 Choosing an Isolation Envelope#^eq-vol3-syscall-tax|equation 3]], compute each envelope’s added time and its overhead relative to the useful work. (b) Find the system-call count at which the user-space kernel’s overhead reaches 10 percent. (c) The build holds no credentials but runs code nobody reviewed. Choose the envelope and justify the choice by both cost and trusted components.

**Problem 4 (Intermediate): Guard checks for the remediation agent.** The remediation agent attaches a model-written guard to each proposed configuration change, such as `p99_ms < 400 and error_rate < 0.01`. The supervisor, which holds the agent’s production-change credentials, evaluates the guard on 500 service samples per second, with a 10 ms deadline per sample and a budget of 0.5 CPU cores for guard checks. Three options are available. The first is an in-process evaluator for a purpose-built expression language whose only operands are the supplied metric values and numeric literals. The language offers arithmetic, comparisons, `and`, and `or`, with no attribute access, subscripts, calls, or loops, and at most 200 syntax nodes at no more than 0.2 µs each. The others are a fresh bytecode sandbox per sample (0.5 ms setup) and a fresh microVM per sample (20 ms setup). (a) Compute each option’s worst-case time per sample and the CPU cores it consumes, and decide which options meet the deadline and the budget. (b) The agent asks for a `matches(line, pattern)` operator over log lines of up to 200 characters. A backtracking matcher can take $2^{n}$ steps of 10 ns on an adversarial ${n}$-character input. A linear-time automaton matcher, with patterns capped at 100 states, takes at most one 10 ns step per state per character. Compute the backtracking time on a 40-character line and the longest input that stays within the evaluator’s 40 µs bound, then the linear matcher’s worst case and the resulting CPU cores. Decide which matcher, if either, may run inside the supervisor, and explain why the supervisor cannot simply stop a runaway match. (c) The agent next proposes replacing guards with a model-written Python script that parses the last minute of logs through a native parsing library, running once per minute with 2 s of useful work. Test the script against each condition that made the guard safe to evaluate in-process, choose its envelope and whether to start one per run under a 10 percent setup cap, and state which authority that envelope may hold.

**Problem 5 (Intermediate): Per-document envelopes for the research agent.** The research agent parses 400 retrieved pages while answering one question, each parse needing 2 ms of useful work and no filesystem or network access. The task requires mutable parser and module state from each independently hostile page to be inaccessible to the next; sharing a trusted read-only baseline is permitted. The options are a fresh bytecode sandbox per page (0.5 ms setup), a fresh microVM per page (20 ms setup), or one microVM retained for the whole question (20 ms setup once). (a) Compute the elapsed setup plus work for each option and each option’s setup share of a fresh call. (b) For a cap of ${\phi} = 10$ percent, compute the minimum per-call work for each fresh-per-call option. (c) The retained microVM is fastest. Apply the stated freshness requirement to decide whether the retained microVM is eligible, and decide which option to deploy even though it misses the 10 percent cap.

**Problem 6 (Intermediate): Sizing the reserve under load, not at idle.** A repair pool receives offered Poisson requests at ${\lambda_{\text{arr}}} = 0.5\ \text{s}^{-1}$ under the no-loss, constant-lead-time replenishment policy of [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.09 Sandbox Pools and Reset#^sec-vol3-sandboxes-pooling-queueing|section 8.8.3]], with a request-level miss target ${\epsilon} = 10^{-3}$. Snapshot restore takes 40 ms on an idle host but 200 ms at the restore concurrency a burst produces. (a) For each restore time, compute ${\lambda_{\text{arr}}} {T_{\text{init}}}$ and the smallest reserve whose Poisson tail at or above the reserve meets the target. (b) Find the largest ${T_{\text{init}}}$ each of the reserves one and two tolerates. (c) Evaluate the normal approximation of [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.09 Sandbox Pools and Reset#^eq-vol3-pool-reserve|equation 5]] at the loaded mean, explain why its answer should not be trusted here, and decide the reserve to provision.

**Problem 7 (Intermediate): Draining a burst of repair tasks.** A continuous-integration trigger releases forty repair tasks at once into a pool holding eight standby instances. With up to four concurrent restore workers each restore takes 25 ms; with eight workers restores contend and each takes 40 ms. Queued tasks take precedence over rebuilding the reserve, and each standby holds 16 MB of private memory. (a) Compute the last admission’s wait and the time at which the reserve of eight is rebuilt with four workers. (b) The platform requires every task in such a burst to start within 100 ms. Decide whether doubling the workers meets the requirement. (c) Find the smallest reserve that meets it with four workers, its standing memory cost, and the time at which that larger reserve is rebuilt.

**Problem 8 (Intermediate): When copy-on-write stops paying.** An evaluation host starts sixty-four workspaces from a 6 GB pinned base; each task writes 150 MB of edits and build outputs, and the shared drive sustains 5 GB/s. (a) Compute provisioning payload and drive-time lower bounds for full private copies and for a copy-on-write view. (b) The test suite then modifies a 3 GB database fixture in place once per task, and the storage copies whole files on first write. Recompute the copy-on-write payload and its advantage over full copies. (c) Redesign the fixture’s storage so that the advantage returns, given that the tests touch 2,000 blocks of 64 KB. Compute the resulting payload, drive time, and advantage, and name one alternative that avoids copying altogether.

**Problem 9 (Advanced): Admission latency for the support agent.** The support agent runs each customer session in its own sandbox. At peak it receives offered Poisson sessions at ${\lambda_{\text{arr}}} = 40\ \text{s}^{-1}$ under the same no-loss, constant-lead-time replenishment policy, so eventual admitted throughput equals that rate. Each admitted lease lasts ${T_{\text{hold}}} = 45\,\text{s}$, and a customer waiting for a sandbox counts against a 1 s first-response budget. Two provisioning paths exist: snapshot restore at 50 ms, or cold boot at 1.5 s. Use ${\epsilon} = 10^{-3}$, a 0.5 GB template, 24 MB of private pages per active session, and 16 MB per standby. (a) Compute ${N_{\text{active}}}$ and, for each path, ${\lambda_{\text{arr}}} {T_{\text{init}}}$, the reserve from [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.09 Sandbox Pools and Reset#^eq-vol3-pool-reserve|equation 5]], and the smallest reserve from the exact Poisson tail at or above the reserve. (b) Compute ${M_{\text{pool}}}$ for each path and the relative margin ${z_{1-\epsilon}}\sqrt{{\lambda_{\text{arr}}} {T_{\text{init}}}}/({\lambda_{\text{arr}}} {T_{\text{init}}})$. (c) Compare with Problem 2. Identify which term binds the repair pool and which binds the support pool, and recommend a provisioning path and reserve conditional on the declared policy. State why the miss target alone does not prove the 1 s end-to-end response budget, and identify the remaining response-work and waiting-time evidence needed.

**Problem 10 (Advanced): Critique a rate-limited resolver.** A design review proposes letting repair guests resolve any name under the package mirror’s domain subtree, limited to 20 queries per second, and claims the limit “bounds exfiltration.” Each query name can carry 120 base32 characters of attacker-chosen labels (5 bits each), and a trajectory lasts 1200 s. A legitimate dependency install needs about 400 lookups. (a) Compute the channel’s payload per query, its rate at the limit, the time to leak a 40 KB file, and the total a trajectory could leak. (b) Compute the query budget per trajectory that would hold leakage below 1 KB, and compare it with the install’s legitimate lookups. (c) State what the rate limit actually bounds, then redesign name resolution so the guest’s lookups stop being a channel while installs still work, and say which residual channel the redesign leaves.

**Problem 11 (Advanced): Suspend the sandbox while the model deliberates.** Extend Problem 2 at the doubled horizon (${T_{\text{hold}}} = 3200\,\text{s}$). Each trajectory runs forty turns, and 70 percent of every lease is spent waiting for model calls. A proposal suspends the guest to the shared 5 GB/s drive at the start of each model call and resumes it after, writing and then reading its 96 MB of private pages every turn; suspended guests hold no host memory. (a) Compute the admission rate the 64 GB host supports with suspension, the admission rate at which the drive saturates, and the resulting gain over Problem 2(c). (b) Compute the lower bound on added resume latency per turn and per trajectory, and choose an operating admission rate that leaves the drive 20 percent headroom for provisioning traffic. (c) The binding constraint has moved. Name it, and list the reset-contract and authority conditions a suspended guest must satisfy (which work may be running, what happens to its broker sessions, and where its image may go) before the proposal can ship.

**What’s Next: From contained code to a defended agent**

The `submit_report` request that passed every boundary in this chapter is not an isolated gap. The same README text can persuade the model to place a private test fixture in the query of a permitted package search. The query reaches an approved registry, the broker keeps its credential, and the code never leaves its envelope, yet the registry receives information the task was never authorized to share. The README can also claim that the test suite passed, and no envelope stops the agent from recording that claim as evidence. **[[01 Books/Volume III - Agentic Systems/03 Tool Use/09 Agent Security/V3-09 Agent Security#^sec-vol3-security|Agent Security]]** opens with these attacks through permitted operations and builds the runtime checks that decide which data may cross an approved boundary and which sources may justify a consequential decision.
