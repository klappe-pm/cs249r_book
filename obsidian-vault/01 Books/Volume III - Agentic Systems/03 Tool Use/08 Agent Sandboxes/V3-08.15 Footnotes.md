# V3-08.15 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08 Agent Sandboxes|V3-08 Agent Sandboxes]]

^footnotes

<sup>1</sup> **Subclass Walk**: The expression `().__class__.__base__.__subclasses__()` goes from an empty tuple to `object` and returns the classes derived directly from it, from which every loaded class can be reached by recursion, including classes that wrap files and processes. It uses no builtin name and no import, so a filter that deletes `open` and `__import__` leaves the process’s reach unchanged.

^fn1

<sup>2</sup> **Access Matrix**: Lampson ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-lampson1974protection|1974]]) described protection as a matrix of subjects by objects whose entries list the permitted operations. An access control list stores one column with its object; a capability list stores one row with its subject. The choice decides whether a request is checked against who is asking or against what the requester was handed, and only the second can express “this task, this file, this operation” without a new identity per task.

^fn2

<sup>3</sup> **Check-Then-Use Races**: Early user-level sandboxes confined untrusted helper programs by intercepting each system call and checking its arguments ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-goldberg1996secure|Goldberg et al. 1996]]). Garfinkel ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-garfinkel2003traps|2003]]) catalogued why that design is fragile: a path argument lives in memory the confined process controls, so another thread can change it after the check and before the kernel reads it, and a filter that imperfectly replicates kernel semantics misses indirect routes to the same resource. Checking the resolved object inside the kernel at the moment of use closes that window, which is what an in-kernel access-control module such as Landlock does.

^fn3

<sup>4</sup> **Sensitive Instructions**: Popek and Goldberg ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-popek1974formal|1974]]) stated the classical condition for an efficient virtual machine monitor: every instruction that reads or changes machine control state must trap when run unprivileged, so that the monitor sees it. The x86 architecture had such instructions that did not trap, and hardware extensions added a separate guest mode in which those operations exit to the hypervisor ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-uhlig2005intel|Uhlig et al. 2005]]). That exit is the enforcement point: guest code cannot change host control state without passing through code the host trusts.

^fn4

<sup>5</sup> **Two-Dimensional Page Walk**: On a TLB miss the hardware must translate each guest page-table pointer through the hypervisor’s tables as well, so a four-level walk in each dimension can need up to twenty-four memory references instead of four ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-bhargava2008accelerating|Bhargava et al. 2008]]). Page-walk caches reduce that cost, but a memory-intensive test suite inside a microVM pays more per TLB miss than the same suite in a container. The second mapping that isolates the guest is also a per-miss tax on its memory accesses.

^fn5

<sup>6</sup> **Software Fault Isolation**: Wahbe et al. ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-wahbe1993efficient|1993]]) showed that an untrusted module can be confined to its own region of a shared address space by rewriting its code so that every store and indirect jump is forced into that region, with no hardware protection-domain switch. Bounds-checked linear memory in WebAssembly applies the same confinement to a portable format ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-haas2017bringing|Haas et al. 2017]]). The consequence is the cost row of [[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.06 Choosing an Isolation Envelope#^tbl-vol3-isolation-transitions|table 4]]: a call into the host is a function call rather than a trap, which is why this envelope suits short per-call tools.

^fn6

<sup>7</sup> **Capability Mode**: Capsicum brought the same discipline to UNIX processes ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-watson2010capsicum|Watson et al. 2010]]). A process in capability mode loses access to global namespaces such as absolute paths and can open files only relative to directory descriptors it already holds, so the descriptors its parent passed in are the whole of its filesystem reach. Preopened handles in a bytecode sandbox and a supervisor’s grant installed before `execve` are both ways of handing over the capability before untrusted code starts.

^fn7

<sup>8</sup> **The Confinement Problem**: Lampson ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-lampson1973note|1973]]) posed the problem of running a borrowed program so that it cannot leak its caller’s data, and observed that a program can signal through channels never intended for communication, such as its use of shared resources. Name lookups are such a channel for a guest whose web requests are blocked. Confinement has to account for every externally observable effect of the code, and a rate limit narrows a channel’s bandwidth without closing it.

^fn8

<sup>9</sup> **Content-Dependent Memory Sharing**: Sharing a selected read-only baseline differs from dynamically merging private pages because their contents happen to match, the content-based page sharing introduced for hypervisor memory management ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-waldspurger2002memory|Waldspurger 2002]]). With cross-tenant merging, the copy-on-write delay on a write can reveal that a matching page exists in another guest, a timing channel that was shown to detect which applications and files a neighboring virtual machine had loaded ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-suzaki2011memory|Suzaki et al. 2011]]). A pool’s memory budget must therefore state which pages may be shared; baseline sharing is not a general guarantee against timing channels.

^fn9

<sup>10</sup> **Lazy Snapshot Restore**: A study of serverless functions restored from microVM snapshots attributed their high startup latency to page faults that bring guest memory in from disk one page at a time ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-ustiugov2021benchmarking|Ustiugov et al. 2021]]). Recording the stable working set of pages a function touches after restore and prefetching it in one pass substantially reduced that latency. For an agent pool, the analogous working set is the interpreter, toolchain, and dependency pages the first tool call touches, and its size, not the snapshot’s, sets the first command’s latency.

^fn10

<sup>11</sup> **Square-Root Staffing**: The reserve rule has the form of the square-root staffing rule for many-server queues, which provisions the mean load plus a margin proportional to its square root. Halfin and Whitt ([[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.14 Source References#^ref-halfin1981heavy|1981]]) showed that holding the margin’s coefficient fixed keeps the probability of waiting at a stable value strictly between zero and one as the offered load grows. The relative margin shrinks as $1/\sqrt{{\lambda_{\text{arr}}} {T_{\text{init}}}}$. That resemblance motivates a sizing screen; the many-server waiting theorem does not establish a miss guarantee for this replenishment policy.

^fn11
