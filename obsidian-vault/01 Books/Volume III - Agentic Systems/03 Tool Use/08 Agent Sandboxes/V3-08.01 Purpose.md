*Why must the limit on what an agent’s code can reach be enforced below the model rather than requested of it?*

When an agent runs a shell command or a test script, what that code can touch is set by the environment it runs in, not by the tool description or the prompt that produced it. A command that passes every schema check can still read a credentials file, open a connection to an unapproved host, fork until the machine stalls, or rewrite the tests that will judge it. Model alignment and system-prompt instructions lower the chance of such a proposal but bound nothing, and a restriction enforced inside the supervisor’s own interpreter leaves reachable objects and inherited authority in place. The limit must instead be enforced beneath the executing process, where the operating system or a hypervisor mediates files, processes, network egress, and resource quotas regardless of what the code attempts. That confinement has a price. Every isolation envelope adds startup latency and memory, a workspace must persist across the turns of one task without leaking into the next, and a platform serving many tasks needs a reserve of warm environments that return to service only after a verified reset. An environment handed to the next tenant with a stray background process or a lingering credential turns one task’s compromise into another’s. Sandboxing turns a task’s authority into limits the host enforces on what code can read, change, send, and consume, and on how long it may do so, so that a destructive proposal can damage only what the task was granted.

**Learning Objectives**

- Explain why containment must be enforced beneath the executing process, not inside the supervisor’s interpreter
- Apply the capability admission check, attenuation rule, and credential brokering to bound what agent-run code can reach under a task grant
- Select an execution envelope and its per-call or per-trajectory lifetime from reachable objects, system-call cost, and setup cost
- Calculate copy-on-write provisioning and first-modification cost for task-local workspaces
- Diagnose disclosure channels that remain open under an egress policy, including name resolution
- Specify a reset contract over execution, storage, network, and device state before an instance is reused
- Select a sandbox pool’s standby reserve and provisioning path by calculating whether memory residency or restore latency binds
