# V3-07.12 Fallacies and Pitfalls

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07 Tool Calling|V3-07 Tool Calling]]

^sec-vol3-tool-calling-fallacies

The tool boundary fails when evidence about one stage is treated as a guarantee about another. These misconceptions recur across structured, terminal, and visual interfaces.

**Fallacy**: *A schema-valid call is safe to execute.*

Structural validity checks the shape of a request; the session’s grant, the current domain preconditions, and resource limits are separate checks ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.04 Tool Interface Schemas#^sec-vol3-tool-calling-schemas|section 7.3]]). In the GitHub MCP leak (war story [7.1](https://mlsysbook.ai/vol3/07_tool_calling/07_tool_calling.html#ws-07-github-mcp-2025)), every call the agent made was schema-valid and within its credential’s reach. The call that exceeded the task’s grants was the first private-repository read, and no check compared it with the task.

**Pitfall**: *Treating a timeout as permission to retry.*

A timeout records missing knowledge, not a failure. Under the blind-retry model of notebook [7.1](https://mlsysbook.ai/vol3/07_tool_calling/07_tool_calling.html#nbk-07-settlement-budget), a per-call duplicate probability of 1.9208 percent becomes about 3,842 duplicate effects a day across 200,000 mutating calls. Retry only on safe operation semantics, an endpoint that honors the operation ID, or reconciliation evidence ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.06 Retrying Uncertain Actions#^sec-vol3-tool-calling-idempotency|section 7.5]]); otherwise record the effect as unresolved.

**Fallacy**: *A zero exit status establishes task completion.*

Exit status is the invoked program’s convention. A runner that discovers zero tests, a script without `pipefail`, and a client that prints its error and exits normally all return zero ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.08 Terminal Output Normalization#^sec-vol3-tool-calling-observation-parsing|section 7.7]]). The `r18` reproducer pass supports one exercised connection-pool case; acceptance follows the task’s evidence standard (principle [[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.06 Invariant Closure#^pri-invariant-closure|1]]).

**Pitfall**: *Shrinking an observation without recording what was dropped.*

Truncation itself is unavoidable, since the illustrative log in notebook [7.2](https://mlsysbook.ai/vol3/07_tool_calling/07_tool_calling.html#nbk-07-observation-budget) is 62.5× the entire context window. The mistake is losing the record of omission. A head-only policy applied to [[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.07 Observation Stream Truncation#^lst-vol3-head-truncation|listing 4]] keeps the banner and passing tests and drops the one panic that explains the failure. The head, notice, and tail of [[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.07 Observation Stream Truncation#^eq-vol3-observation-byte-budget|equation 2]] keep it within the same byte budget, and an inspection handle recovers the middle on request.

**Fallacy**: *Staging every registered tool is harmless because each descriptor is short.*

Descriptors add up, and they recur on every call. In notebook [7.4](https://mlsysbook.ai/vol3/07_tool_calling/07_tool_calling.html#nbk-07-memory-footprint-and-prefill-latency), a 50-tool catalog occupies 15,000 tokens of each request, while the 6 tools a step needs, with selection overhead, use 2,200. Over a trajectory that difference is paid once per turn, in capacity taken from task evidence ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.10 Designing the Active Toolkit#^sec-vol3-tool-calling-toolkit-design|section 7.9]]).

**Pitfall**: *Letting the model poll a long-running job.*

Each “still running” answer is a full model call. In notebook [7.3](https://mlsysbook.ai/vol3/07_tool_calling/07_tool_calling.html#nbk-07-token-cost-and-inference-overhead), a 300 s job checked every 5 s costs 59 extra model calls and \$0.8764 in tokens that change no decision. Runtime polling or a completion notification detects the change without inference and wakes the model only when the result can alter the next action ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.09 Asynchronous Tool Dispatch#^sec-vol3-tool-calling-async-resumption|section 7.8.3]]).
