# V3-07.14 Historical Perspective and Further Reading

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07 Tool Calling|V3-07 Tool Calling]]

^sec-vol3-tool-calling-history

The tool execution boundary is the modern incarnation of a problem operating systems encountered half a century ago, when an untrusted program requested an operation the system could not let it perform directly. Three ideas from that era apply directly at the tool boundary: Anderson’s reference monitor from a 1972 study for the U.S. Air Force ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-anderson1972computer|Anderson 1972]]), Saltzer and Schroeder’s principle of complete mediation ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-saltzer1975|Saltzer and Schroeder 1975]]), and Hardy’s confused deputy ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-hardy1988confused|Hardy 1988]]). The confused deputy is a privileged service that acts for a client without checking the client’s authority. In agent runtimes, that last vulnerability manifests whenever a model holding private credentials executes operations triggered by untrusted user prompts or retrieved external content. The wider protection lineage these ideas belong to, from Dennis and Van Horn’s capabilities ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-dennis1966|Dennis and Van Horn 1966]]) to Lampson’s access matrix ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-lampson1974protection|Lampson 1974]]), is traced in **[[01 Books/Volume III - Agentic Systems/03 Tool Use/08 Agent Sandboxes/V3-08.12 Historical Perspective and Further Reading#^sec-vol3-sandboxes-history|Historical Perspective and Further Reading]]**, where it grounds containment beneath the model.

A second historical lineage governs operations that cross network boundaries. Birrell and Nelson designed the Remote Procedure Call (RPC) to make remote invocations feel as natural as local function calls, but they documented the tension of distributed execution. During network partitions or server crashes, a caller cannot know whether a request succeeded, failed, or stalled midway through execution ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-birrell1984rpc|Birrell and Nelson 1984]]). In the same year, Saltzer, Reed, and Clark articulated the end-to-end argument, demonstrating that reliability and correctness cannot be guaranteed solely by intermediate communication layers and must ultimately be validated by the endpoints themselves ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-saltzer1984endtoend|Saltzer et al. 1984]]). Distributed systems researchers developed several robust patterns to handle this inherent ambiguity. Kung and Robinson introduced optimistic concurrency control, allowing transactions to proceed without heavy upfront locking and validating serializability before commit ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-kung1981optimistic|Kung and Robinson 1981]]). For distributed operations that cannot be rolled back atomically, Garcia-Molina and Salem formulated sagas, coordinating sequences of local transactions coupled with compensating actions to undo partially completed work ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-garciamolina1987sagas|Garcia-Molina and Salem 1987]]). Gray and Cheriton introduced leases, using time-bounded grants to manage shared resources without requiring indefinite locks ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-gray1989leases|Gray and Cheriton 1989]]). Finally, Helland made the practical case that reliable distributed systems must push retry safety into the receiver by enforcing endpoint idempotence ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-helland2012idempotence|Helland 2012]]), a requirement that directly informs how tool runtimes deduplicate requests and handle agent retries.

Language models converged on tool execution from the opposite direction, evolving from passive sequence predictors into interactive system callers. Early modular architectures routed model queries to external calculators, symbolic solvers, and database interfaces ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-karpas2022mrkl|Karpas et al. 2022]]). Yao et al. ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-yao2023react|2023]]) established the ReAct pattern, demonstrating that interleaving explicit reasoning traces with concrete actions and environment feedback improves multi-step problem solving. Schick et al. ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-schick2023toolformer|2023]]) showed with Toolformer that models could learn in a self-supervised manner to propose external API calls spontaneously, complete with appropriate arguments, during standard text generation. As the scope of external tools expanded, retrieval-augmented tool selection reduced hallucinated function signatures by fetching accurate documentation on demand ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-patil2023gorilla|Patil et al. 2023]]), while large-scale instruction tuning exposed models to thousands of diverse, real-world REST APIs ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-qin2024toolllm|Qin et al. 2024]]). Interacting with external environments also has roots in web agents that manipulate user interfaces through simulated keyboard and mouse events ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-shi2017world|Shi et al. 2017]]). However, designing interfaces specifically tailored to language models proved even more effective. Yang et al. ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-yang2024sweagent|2024]]) demonstrated with SWE-agent that structuring the agent-computer interface around model-friendly commands, such as concise file viewers with line numbers and restricted editing primitives, substantially lifted task success on complex software engineering benchmarks. To manage the proliferation of heterogeneous tools, open specifications like the Model Context Protocol (MCP) standardized the boundary between host runtimes and external tool servers ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-mcp2025specification|Model Context Protocol 2025]]). As tool calling gained ubiquity, however, it exposed a distinct vulnerability. An agent interprets untrusted external text within the same context window that guides its decisions, allowing adversarial inputs to steer the model into executing unintended tool invocations ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-greshake2023not|Greshake et al. 2023]]). Because the language model is an untrusted caller that can be influenced by malicious prompts, the enclosing systems runtime must enforce complete mediation and least privilege on every operation, and permit retries of uncertain effects only when their repetition is safe.

For further reading:

- Saltzer and Schroeder, “The Protection of Information in Computer Systems” ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-saltzer1975|Saltzer and Schroeder 1975]]). The canonical catalog of security principles for computer systems. Read through the lens of agent execution, principles like complete mediation, least privilege, and economy of mechanism serve as a direct checklist for designing secure tool boundaries.
- Birrell and Nelson, “Implementing Remote Procedure Calls” ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-birrell1984rpc|Birrell and Nelson 1984]]). The foundational paper on RPC and the clearest exposition of distributed failure semantics. It establishes why a caller can never be completely certain whether an unacknowledged remote call executed, providing the theoretical basis for retry budgets and timeout policies.
- Hardy, “The Confused Deputy” ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-hardy1988confused|Hardy 1988]]). A concise, three-page paper that identifies how an entity with broad ambient authority becomes an unwitting tool for attackers. It represents required reading for understanding why language agents must never carry ambient credentials across security domains.
- Helland, “Idempotence Is Not a Medical Condition” ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-helland2012idempotence|Helland 2012]]). A practical guide to designing distributed systems that survive retries by pushing deduplication and idempotence keys into receiver interfaces, directly applicable to tool runtime dispatch.
- Ousterhout, *A Philosophy of Software Design* ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-ousterhout2018philosophy|Ousterhout 2018]]). A compact treatment of interface design and deep modules. The book’s criteria for module depth and interface complexity provide concrete guidance for sizing tool APIs so models can invoke them effectively without leaking implementation details.
- Yang et al., “SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering” ([[01 Books/Volume III - Agentic Systems/03 Tool Use/07 Tool Calling/V3-07.16 Source References#^ref-yang2024sweagent|Yang et al. 2024]]). An empirical demonstration that the design of model-oriented tool interfaces, alongside the underlying language model, determines agent performance.
