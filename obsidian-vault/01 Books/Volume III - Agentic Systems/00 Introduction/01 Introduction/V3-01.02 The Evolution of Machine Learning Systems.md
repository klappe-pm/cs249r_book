# V3-01.02 The Evolution of Machine Learning Systems

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01 Introduction|V3-01 Introduction]]

^sec-vol3-intro-evolution

A prediction service returns a score, a conversational assistant proposes a patch, and an agentic system applies and checks that patch under delegated authority. These three deployment arrangements trace the progression from predictive pipelines through conversational foundation models to autonomous workloads. They overlap historically: predictive models can participate in feedback loops, and a foundation model can serve any of the three arrangements. The engineering distinction is who controls the actions and checks the outcome, as three representative arrangements illustrate:

1.  **Predictive Machine Learning Systems**: A predictive model maps a supplied input to a structured output (${y} = {f}({x})$), as in image classification, recommendation ranking, or fraud scoring. Application code supplies the input and consumes the returned score, so the serving call needs no conversational memory or tool loop, even when the application feeds its scores into a broader process. Systems engineering concentrates on serving throughput, memory layout, and batch latency.
2.  **Generative Foundation Models**: Large autoregressive transformers trained on internet-scale corpora generate open-ended text, code, and multimodal tokens. In standard conversational deployment, however, the interaction remains **open-loop** and **human-mediated**. A developer working with a conversational assistant acts as the runtime controller, issuing a prompt, inspecting the response, copying code into an editor, running commands in a terminal, and pasting compiler errors and stack traces back into the prompt window. The model generates candidate tokens; the human provides the execution environment, carries working memory across turns, diagnoses failures, and verifies correctness.
3.  **Agentic Machine Learning Systems**: Agentic systems replace the human in the inner control loop with a software runtime. Instead of requesting advice, a user delegates an end-to-end objective: clone a software repository, reproduce a reported defect, synthesize a candidate fix, run the full test suite in an isolated sandbox, iterate until regressions clear, and return a verified patch. The foundation model shifts from an advisory partner to an action-proposing component inside an active feedback loop.

Replacing the human operator in the interaction loop with a software runtime defines an agentic system and shifts what engineering optimizes ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.02 The Evolution of Machine Learning Systems#^tbl-vol3-three-eras|table 1]]).

| **Era**                          | **Interaction pattern**                          | **Who closes the loop**                                             | **What engineering optimizes**                                           |
|:---------------------------------|:-------------------------------------------------|:--------------------------------------------------------------------|:-------------------------------------------------------------------------|
| **Predictive systems**           | One fixed input mapped to one structured output  | Application code consumes the score in this arrangement             | Serving throughput, batch latency, and memory layout                     |
| **Generative foundation models** | Open-loop prompt and response                    | A human, who runs the tools and carries errors back to the prompt   | Tokens per second, tail latency, and accelerator utilization             |
| **Agentic systems**              | Closed loop of proposal, action, and observation | The runtime, which dispatches granted actions and checks the result | Task completion rate, cost per accepted task, and reliability over turns |

Table 1: **Three Eras of Machine Learning Systems**: The representative arrangements differ in who closes the interaction loop. The predictive serving call returns a score without an autonomous tool loop, the conversational arrangement relies on a person to act on the response, and the agentic arrangement delegates that loop to a runtime. This changes the metric the system is engineered against.

^tbl-vol3-three-eras

**Definition 1.1: Agentic system**

***Agentic system*** is an autonomous software system in which a runtime places a foundation model in a closed control loop with context, state, tools, and an environment, dispatching the model’s authorized proposals and returning their environmental observations to subsequent calls until the task is accepted, halted, or escalated.

1.  **Significance**: The unit of systems optimization shifts from the isolated model call to the complete task trajectory. Unchecked errors compound exponentially across sequential turns ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.07 Reliability and Cost Over a Horizon#^sec-vol3-intro-horizon-arithmetic|section 1.6]]), and every attempt, accepted or aborted, is charged to the task’s cost per accepted result.
2.  **Distinction**: In conversational interfaces, a human executes tools, verifies output, and bridges state between turns. In an agentic system, software executes these operations under delegated authority, meaning the model’s output is strictly a proposal that holds no standing authority of its own.
3.  **Common pitfall**: Treating agency as a capability inherent to the model’s weights. A more capable model produces more accurate candidate actions, but permission enforcement, sandbox isolation, durable state persistence, and completion verification belong entirely to the surrounding software runtime.

Production traffic shows how rapidly that third arrangement has overtaken the volume of isolated prompts. Across a multi-provider inference gateway serving more than 200,000 production teams ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-vercel2026aigateway|Vercel 2026]]), the share of requests ending in a tool call nearly doubled over six months, rising from 11.4 percent to 22.2 percent. Because each tool-using turn carries accumulated history and environment output, those 22.2 percent of requests already consumed 58.9 percent of all production tokens (up from 31.6 percent), or 5.0× as many tokens per request as calls without tools. [[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.02 The Evolution of Machine Learning Systems#^fig-vol3-agentic-token-growth|Figure 1]] tracks the aggregate token volume, total inference spend, and average price per token over the following five months on the same gateway.

Figure 1: **Cheaper Tokens Fuel an Agentic Volume Surge**: Monthly production token volume, total inference spend, and average price per token across a multi-provider inference gateway, each indexed to 100 in April 2026. All three series share a common baseline so their divergence is directly comparable: while the per-token price index falls below half of its starting level by September, token volume climbs nearly eightfold and pulls total inference spend to more than three times its April level. ^fig-vol3-agentic-token-growth

As the average price per token fell by 57 percent (to an index of 43.3), teams did not pocket the savings on a fixed request volume; they deployed multi-turn loops that consumed 7.9× as many tokens (reaching 790.8) and raised total expenditure 3.4× (to 342.7). Lower per-token prices made multi-step delegation affordable, and multi-step delegation in turn broke the assumptions of isolated-request serving. An isolated-request service accounts for each call separately, retains no task state after the response, and treats an HTTP 200 status as success. None of those conventions holds when a delegated task spans dozens of dependent steps, accumulates context and serving state between calls (the attention key-value cache retained for the growing prefix, so that the next turn need not recompute it, can occupy gigabytes of accelerator memory), and triggers side effects that permanently alter external systems. Turning a model’s candidate output into a completed task therefore requires examining everything that must happen between a useful proposal and an accepted outcome.
