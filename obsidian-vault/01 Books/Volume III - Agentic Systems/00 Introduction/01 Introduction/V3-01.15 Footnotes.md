# V3-01.15 Footnotes

[[Home|Home]] · [[01 Books/Volume III - Agentic Systems/Volume 3 Overview|Volume Overview]] · [[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01 Introduction|V3-01 Introduction]]

^footnotes

<sup>1</sup> **Repository Repair as a Benchmark Task**: SWE-bench established repository repair as a standard benchmark for agentic systems: each instance pairs a real GitHub issue with the unit and integration tests from the patch that fixed it ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-jimenez2024swebench|Jimenez et al. 2024]]). A candidate patch is evaluated by whether those tests pass after application. The model is never permitted to inspect the evaluation tests directly, ensuring that acceptance rests on independent, untampered evidence rather than self-reported success.

^fn1

<sup>2</sup> **Foundation Model**: Bommasani and colleagues introduced the term in 2021 to describe models trained on large, diverse datasets at scale that can be adapted to an expansive range of downstream tasks ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-bommasani2021opportunities|Bommasani et al. 2021]]). Because a foundation model is general-purpose, its weights encode neither the security permissions nor the specific acceptance criteria of a given production task; those boundaries must be defined and enforced by the surrounding runtime.

^fn2

<sup>3</sup> **The Stored-Program Organization**: Von Neumann’s 1945 draft report on the EDVAC partitioned a computer into central arithmetic, central control, memory, and input/output organs ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-vonneumann1945edvac|Neumann 1945]]). In von Neumann’s architecture, central control holds the absolute authority to fetch and execute instructions. In an agentic system, that authority is deliberately inverted: authority resides strictly within the surrounding runtime, while the learned model only proposes actions. Trust is decided outside the processor.

^fn3

<sup>4</sup> **Compensating Transactions**: Garcia-Molina and Salem introduced sagas for long-lived distributed transactions where holding locks across the entire workflow is impractical: a saga consists of a sequence of local transactions, each paired with a compensating transaction that semantically undoes earlier steps if the overall workflow aborts ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-garciamolina1987sagas|Garcia-Molina and Salem 1987]]). Compensation is an active forward recovery action rather than an atomic rollback; concurrent processes can observe intermediate states, and the compensating action itself may fail. An ${A}_2$ capability grant therefore requires an executable compensation handler before dispatching the initial mutating effect.

^fn4

<sup>5</sup> **Least Privilege and Complete Mediation**: Saltzer and Schroeder’s protection principles state that every program should run with the smallest set of privileges needed to complete its task (least privilege), and that every access to every object should be checked for authority (complete mediation) ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-saltzer1975|Saltzer and Schroeder 1975]]). Checking capability grants on every tool call applies both principles to a non-deterministic model whose proposals cannot be trusted on their own. Restricting the task’s initial capability grant remains the most dependable way to limit damage when runtime verification checks fail to catch an unsafe request.

^fn5

<sup>6</sup> **Signaled and Unsignaled Failures**: The standard dependability taxonomy classifies failures by detectability as well as by kind: a signaled failure raises a warning when the service goes wrong, and an unsignaled one does not ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-avizienis2004basic|Avizienis et al. 2004]]). A fail-plausible fault is an unsignaled content failure (the delivered result is wrong and nothing announces it), so a runtime that watches only for crashes, timeouts, and error codes will record it as a success.

^fn6

<sup>7</sup> **Fail-Stop and Byzantine Faults**: Schlichting and Schneider defined a fail-stop processor as one that halts on failure without first making an erroneous state transition, so that other processors can detect the halt ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-schlichting1983failstop|Schlichting and Schneider 1983]]). Lamport, Shostak, and Pease showed that reaching agreement when some components may send arbitrary, conflicting messages requires more than two-thirds of the components to be correct, the origin of the $3{f}+1$ replica bound for tolerating ${f}$ such faults ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-lamport1982byzantine|Lamport et al. 1982]]).

^fn7

<sup>8</sup> **The Confused Deputy**: Hardy described a compiler that held a license to write files in its own directory; a user passed it the name of the billing file as an output path, and the compiler, acting with its own authority rather than the user’s, overwrote the billing records ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-hardy1988confused|Hardy 1988]]). Authority that comes from where a program runs rather than from the request it serves can be steered by whoever supplies the names, which is exactly the position of a model whose tool calls run with host credentials while it reads untrusted text.

^fn8

<sup>9</sup> **Wiener’s Warning on Delegated Purpose**: In 1960 Wiener argued that when a mechanical agency acts too fast and irrevocably for anyone to intervene before the action completes, “we had better be quite sure that the purpose put into the machine is the purpose which we really desire” ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-wiener1960|Wiener 1960]]). The warning binds hardest where authority is irreversible, which is why the contract that follows is written and adopted before the loop runs rather than repaired after an effect lands.

^fn9

<sup>10</sup> **Design by Contract**: Meyer framed a software component’s interface as a contract of preconditions the caller must establish, postconditions the supplier guarantees, and invariants both preserve, each written as a checkable assertion ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-meyer1992applying|Meyer 1992]]). The task contract borrows the structure but not the trust: in classical design by contract the supplier’s own code checks its postconditions, whereas here the supplier is the model, so the completion criteria must be checked by the runtime and tools rather than asserted by the component that produced the result.

^fn10

<sup>11</sup> **Reliable Systems from Unreliable Components**: Von Neumann posed the problem in 1956 for logic networks whose every element errs with some fixed probability, so that errors accumulate through the depth of the computation ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-vonneumann1956probabilistic|Neumann 1956]]). His remedy interleaved redundant computation with “restoring organs” that re-establish a correct signal at intervals, keeping the error bounded however deep the network grows. Checks paired with restoration play the same structural role for the errors they detect, limiting their accumulation to the distance between successful restorations.

^fn11

<sup>12</sup> **Cybernetics**: Wiener’s 1948 book named the study of control through feedback, in which a system measures the result of its own action and uses the difference from its goal to choose the next one ([[01 Books/Volume III - Agentic Systems/00 Introduction/01 Introduction/V3-01.14 Source References#^ref-wiener1948cybernetics|Wiener 1948]]). The loop corrects errors only if the measurement comes from the environment; a runtime that feeds back the model’s own account of what it did has closed a loop around a claim rather than around the result.

^fn12
