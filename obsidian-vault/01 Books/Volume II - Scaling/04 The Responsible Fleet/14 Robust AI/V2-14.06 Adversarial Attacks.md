# V2-14.06 Adversarial Attacks

[[Home|Home]] · [[01 Books/Volume II - Scaling/Volume 2 Overview|Volume Overview]] · [[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14 Robust AI|V2-14 Robust AI]]

^sec-robust-ai-inputlevel-attacks-model-robustness-d6ea

For a classifier that labels skin-lesion images, an attacker who modifies an image of a benign lesion can induce a malignant prediction while preserving its apparent clinical content. Whether that manipulation succeeds depends on the classifier, the allowed modifications, and the evaluation conditions. The high-dimensional decision boundaries learned by deep neural networks possess counterintuitive blind spots, and adversarial attacks expose them by testing what an adversary can force when controlling gradients, queries, physical sensors, or training data.

**Definition 14.3: Adversarial attack**

***Adversarial attack*** is a deliberate manipulation of a model’s input, interaction, or environment designed to violate a specified behavioral objective. The manipulation may be norm-bounded and visually subtle, but it can also be semantic, physical, query-based, or conspicuous.

1.  **Significance**: Adversarial evaluation asks whether an attacker can choose inputs or transformations that drive the model outside its intended behavioral envelope. High-dimensional, norm-bounded image perturbations are one important case, but patches, rotations, printed objects, malicious text, and repeated black-box queries expose different system boundaries.
2.  **Distinction**: Unlike random corruption sampled independently of the target, an adversarial manipulation is selected to cause failure. It need not use gradients: attackers may use surrogate models, decision-only queries, search, semantic edits, or control over the physical sensing environment.
3.  **Common pitfall**: A frequent misconception is that adversarial vulnerability is a “bug” to be patched. In reality, it is a structural vulnerability of many standard neural networks trained by empirical risk minimization; robust defense typically requires fundamental changes to the objective function (for example, adversarial training).

When an attacker can inspect a model’s gradients directly, a change no person can see is enough to fool an image classifier. A perturbation that follows the sign of the loss gradient (${\epsilon_{\text{adv}}} = 0.007$), using the fast gradient sign method defined in [[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.06 Adversarial Attacks#^sec-robust-ai-attack-categories-mechanisms-fed5|section 14.5.1]], flips GoogLeNet’s prediction ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.06 Adversarial Attacks#^fig-adversarial-googlenet|figure 7]]) from panda (57.7 percent confidence) to gibbon (99.3 percent confidence). The classifier is left paradoxically more confident in the erroneous label than in the ground truth.

![[90 Assets/Volume II/14 Robust AI/Adversarial Googlenet c40a96eeee.png]]

Figure 7: **Imperceptible Misclassification in GoogLeNet**: Adding a perturbation of ${\epsilon_{\text{adv}}} = 0.007$ in the sign direction of the loss gradient changes GoogLeNet’s prediction from panda (57.7 percent confidence) to gibbon (99.3 percent confidence), although the two images look identical to a person. The attack does not merely flip the label; it leaves the model more confident in the wrong answer than it was in the right one. Source: ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-goodfellow2015explaining|Goodfellow et al. 2015]]).

^fig-adversarial-googlenet

A visually small change need not produce a small change in a classifier’s score.[[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.15 Footnotes#^fn7|⁷]] Adversarial perturbations exploit how input changes accumulate in the model’s decision function. Even a linear function can be sensitive to many small, aligned changes across input dimensions, so nonlinearity alone does not explain the vulnerability. For a linear score, changing every input coordinate by the full per-coordinate budget in the direction of its weight’s sign moves the score by that budget times the sum of the absolute weights. For weights of typical size, that total grows in proportion to the number of input dimensions, even though no single coordinate moves visibly. The relevant constraint is whether the allowed perturbation can move the input across the learned decision boundary, and how an attacker finds that direction depends on the access the deployed system exposes.

### Attacks by Attacker Access

^sec-robust-ai-attack-categories-mechanisms-fed5

An attacker who can read a model’s weights and gradients can flip a prediction in a single backward pass, whereas an attacker facing a rate-limited API must spend thousands of queries or train a local surrogate model to find a boundary-crossing input. The useful axis is therefore not the attack name by itself, but the attacker’s access. Each mechanism reveals a different cost that the defense must raise: gradient access, optimization time, surrogate-model construction, or physical control over the sensor environment.

The most direct case is white-box gradient access. Neural networks compute gradients to learn how parameter changes reduce loss; an attacker with access to gradients can run that logic against the input instead. In the GoogLeNet panda example of [[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.06 Adversarial Attacks#^fig-adversarial-googlenet|figure 7]], the gradient with respect to the input image gives a local, first-order estimate of how pixel changes affect the loss. The **fast gradient sign method (FGSM)** turns that idea into a single-step attack by choosing each feature’s perturbation sign to maximize that first-order increase within a coordinate-wise budget.[[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.15 Footnotes#^fn8|⁸]]

FGSM computes the adversarial example in one step:

$$
{x_{\text{adv}}}= {x}+ {\epsilon_{\text{adv}}} \cdot \text{sign}\big(\nabla_{x}{\mathcal{L}}({\theta}, {x}, {y})\big)
$$

In this formulation, ${x}$ denotes the original input, ${x_{\text{adv}}}$ is the generated adversarial example, and ${\mathcal{L}}({\theta}, {x}, {y})$ represents the prediction loss evaluated at model parameters ${\theta}$ and true label ${y}$. The gradient term $\nabla_{x}{\mathcal{L}}$ describes local loss sensitivity, $\text{sign}(\cdot)$ extracts each component’s sign to maximize the linearized loss within the coordinate-wise budget, and the scalar ${\epsilon_{\text{adv}}}$ bounds the maximum allowable perturbation magnitude under the $\ell_\infty$ norm. This single step need not maximize the nonlinear loss or cause misclassification. Image implementations also clip the perturbed input to its valid pixel range. The subscript distinguishes this adversarial radius from other uses of ${\epsilon}$ in the book, such as the differential-privacy budget.

Geometrically, moving along the sign vector of $\nabla_{x}{\mathcal{L}}({\theta}, {x}, {y})$ carries input ${x}$ to a corner of the bounding cube defined by the $\ell_\infty$ budget ${\epsilon_{\text{adv}}}$, producing ${x_{\text{adv}}}$. In the illustration of [[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.06 Adversarial Attacks#^fig-gradient-attack|figure 8]], that corner lies across the decision boundary in the adjacent class region. A different boundary or gradient need not produce a successful attack within the same budget.

![[90 Assets/Volume II/14 Robust AI/Gradient Attack a27bd92b8a.svg]]

Figure 8: **Gradient-Based Attack Geometry**: Around a correctly classified input ${x}$, the dashed square marks every perturbation allowed by the $\ell_\infty$ budget ${\epsilon_{\text{adv}}}$. FGSM moves each coordinate by the full budget in the sign direction of the loss gradient $\nabla_{x} {\mathcal{L}}({\theta}, {x}, {y})$, which lands ${x_{\text{adv}}}$ on a corner of that square, the allowed point that maximizes the first-order increase in loss. A step no larger than ${\epsilon_{\text{adv}}}$ in any coordinate therefore carries the input across the decision boundary. The class labels are illustrative.

^fig-gradient-attack

FGSM is cheap because it takes one step. The **projected gradient descent (PGD) attack** ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-madry2018towards|Madry et al. 2018]]) spends more compute for a stronger attack: it repeatedly applies gradient updates and projects each step back into the allowed norm ball around the original input. That iterative refinement makes PGD a standard white-box robustness benchmark. The **Jacobian-based saliency map attack (JSMA)** ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-papernot2016jsma|N. Papernot et al. 2016]]) uses the Jacobian to identify the most influential input features and perturb a smaller set of dimensions toward a target class. These methods are most effective in white-box settings,[[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.15 Footnotes#^fn9|⁹]] where the attacker knows the model architecture and gradients.

When the attacker cares less about speed and more about stealth, the attack becomes an optimization problem. The Carlini and Wagner (C&W) attack[[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.15 Footnotes#^fn10|¹⁰]] ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-carlini2017|Carlini and Wagner 2017]]) searches for a small perturbation that causes misclassification under a chosen distance measure. Minimizing that distance encourages similarity, but does not certify human perceptual equivalence or a globally minimal perturbation. Instead of merely following the sign of a gradient, C&W optimizes a custom objective that trades perturbation size against confidence in the wrong answer.

The attack can search under different norm constraints, such as $\ell_2$ or $\ell_\infty$. Its perturbations can be visually subtle, although a perturbation a person cannot see may still be one a detector flags. The **elastic net attack to DNNs (EAD)** adds elastic net regularization, combining $\ell_1$ and $\ell_2$ penalties to generate sparse, localized perturbations. **DeepFool** ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-moosavi-dezfooli2016|Moosavi-Dezfooli et al. 2015]]) takes a geometric route to the same goal: it linearizes the classifier around the input, steps to the nearest boundary of that linear approximation, and repeats until the label flips, giving a fast estimate of the smallest perturbation that suffices. These optimization-based methods are more computationally intensive than gradient-sign attacks, but they give the attacker finer control over the adversarial example’s geometry.

Black-box attackers lose direct gradient access but keep two routes. Transfer attacks rely on transferability, the tendency of an adversarial example to fool models other than the one it was crafted on. The attacker crafts examples offline on a surrogate model and submits them to the target, typically through its public API, without seeing its weights or gradients. Query-based attacks probe the target itself. A decision-based, or boundary, attack needs only the returned label. It starts from an input the model already misclassifies and walks along the decision boundary toward the original input, querying at each step to stay on the wrong side. Its cost is the number of queries, which is why query budgets and rate limits belong to the defense.

↩︎ The adversary knowledge spectrum, from white-box gradient access to black-box attackers who work through a surrogate or a public interface, is established in **[[01 Books/Volume II - Scaling/04 The Responsible Fleet/13 Security & Privacy/V2-13.05 Systematic Threat Analysis and Risk Assessment#^sec-security-privacy-threat-vector-classification-3042|Threat vector classification]]**.

Transfer works because models trained for the same task on similar data tend to learn similar decision boundaries, so a perturbation that pushes an input across one model’s boundary often pushes it across another’s. Transfer success depends on model similarity, training-data overlap, and regularization, and attackers can improve it with input diversity, such as random resizing or cropping, and with momentum during optimization. Closing that route costs the defender training work. Ensemble adversarial training trains against perturbations generated on several models to improve transfer robustness, but the extra attack generation and model diversity make it a deliberate training-budget decision rather than a free mitigation ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-tramer2017ensemble|Tramèr et al. 2017]]).

### Physical-World Attacks

^sec-robust-ai-physical-world-attacks

White-box and black-box digital attacks modify pixel tensors directly in memory, whereas an attacker in the field cannot edit the camera buffer and must place the perturbation on physical objects such as road signs, clothing, or 3D-printed surfaces. **Adversarial patches** are printed patterns placed in the scene so that cameras and detectors misread it even after the pattern passes through sensors, distance, lighting, viewing angle, and ordinary deployment variation. The modification need not be visually imperceptible, because graffiti-style markings and sticker patches that pass for ordinary vandalism can still induce misclassification through the camera pipeline ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-eykholt2018robust|Eykholt et al. 2017]]). The robustness question therefore becomes operational rather than purely mathematical, because a defense that works on a saved image may fail once the attack passes through a camera lens, compression, motion blur, and changing illumination. These threats matter most for AI systems deployed in physical spaces, such as autonomous vehicles, drones, and surveillance systems, where a model error becomes a safety, security, and accountability problem in the world.

**Example 14.1: The stop sign attack**

**Scenario**: The road-sign sticker attack places black and white stickers on a stop sign so that a vision model reads it as a speed limit sign ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.06 Adversarial Attacks#^fig-adversarial-stickers|figure 9]]) ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-eykholt2018|Eykholt et al. 2018]]). The robustness question is what its two reported success rates say about how an evaluation must be run.

**Diagnosis**: The attack succeeded on every tested laboratory image but on 84.8 percent of frames in the moving-vehicle field test. Each number is evidence only for its own capture conditions, and the gap between them does not isolate any one factor, such as distance, viewing angle, lighting, or motion.

**Systems lesson**: A physical attack must be evaluated through the full sensor loop, not on saved benchmark images. The evaluation should optimize the attack averaged over random draws from the expected range of transformations, a method called expectation over transformation, and then test it with real captures. Any claimed mitigation, such as checking consistency across frames (spatio-temporal validation) or across sensors (sensor fusion), must be tested against attacks on the complete perception stack.

The attacker’s access determines the evaluation a defense must survive. Gradient access, optimization, surrogate transfer, and physical sensor manipulation each call for their own evaluation ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.06 Adversarial Attacks#^tbl-attack-types-07c41ec8|table 6]]), so a result under one attack mechanism does not become a claim about all of them.

| **Category**     | **Method**      | **Mechanism**                                                           |
|:-----------------|:----------------|:------------------------------------------------------------------------|
| **Gradient**     | FGSM            | Perturbs inputs along the loss gradient                                 |
|                  | PGD             | Iterative multi-step FGSM refinement                                    |
|                  | JSMA            | Targets the most influential features                                   |
| **Optimization** | C&W             | Minimizes perturbation size subject to misclassification                |
|                  | DeepFool        | Estimates a small boundary-crossing perturbation by local linearization |
|                  | EAD             | Elastic net regularization for sparse perturbations                     |
| **Transfer**     | Transferability | Adversarial examples transfer across models (black-box)                 |
| **Physical**     | Patches         | Printed patches fool detectors in the real world                        |
|                  | 3D Objects      | Sculpted objects deceive sensors in deployment                          |

Table 6: **Adversarial Attack Categories**: Attack mechanisms determine defense selection: gradient and optimization attacks require robustness against explicit decision-boundary crossing, transfer attacks test black-box exposure, and physical attacks require evaluation through the deployed sensor loop.

^tbl-attack-types-07c41ec8

Medical-imaging attacks can cause misdiagnosis ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-tsai2023|Tsai et al. 2023]]), while fraud and trading models face analogous manipulation risks. The common vulnerability is reliance on features that remain predictive on clean data but fail under crafted perturbations ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-goodfellow2015explaining|Goodfellow et al. 2015]]; [[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-madry2018towards|Madry et al. 2018]]). Defense shifts the resource cost: adversarial training adds training work ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-bai2021|Bai et al. 2021]]), while runtime detection such as feature squeezing adds inference evaluations ([[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.14 Source References#^ref-xu2018|Xu et al. 2018]]). The choice among these spending points motivates the defenses in [[01 Books/Volume II - Scaling/04 The Responsible Fleet/14 Robust AI/V2-14.07 Adversarial Defenses#^sec-robust-ai-input-attack-detection-defense-19d3|section 14.6]].

**Self-Check: Question**

1.  Why can a small gradient-directed perturbation change a high-dimensional classifier’s score more than independently sampled, zero-mean noise of comparable coordinate scale?

    1.  Random noise changes model parameters directly, whereas gradient perturbations only affect input metadata.
    2.  Gradient-directed perturbations require visible, large-scale pixel alterations that physically overwhelm convolutional filters.
    3.  The perturbation aligns coordinate changes with local loss sensitivity, while independent zero-mean changes can cancel in the first-order sum.
    4.  Random noise affects only training data, whereas adversarial noise can only exist during inference.

2.  An attacker lacking access to a commercial vision API’s internal weights or gradients trains a local ResNet surrogate, crafts PGD adversarial images against that surrogate, and successfully fools the target API on 50 percent of queries. Which property of adversarial examples enables this black-box attack?

    1.  Differential privacy, which guarantees perturbation bounds across diverse neural architectures.
    2.  Transferability, where adversarial examples crafted to exploit decision boundaries of one model frequently deceive different models trained on similar tasks.
    3.  Quantization noise, which forces all deployed models into identical weight matrices.
    4.  Batch normalization collapse, which disables activation functions across distributed API servers.

3.  Which scenario represents a physical-world adversarial attack rather than a digital evasion attack or an environmental covariate shift?

    1.  An attacker submits a JSON payload containing an $\ell_\infty$-perturbed pixel array directly to a cloud inference API endpoint.
    2.  A sudden heavy snowfall changes ambient lighting and road surface reflections, reducing camera detection accuracy by 15 percent.
    3.  An engineer accidentally inverts the normalization constants in a client-side image preprocessing script.
    4.  An attacker places small, calibrated black-and-white stickers on a roadside stop sign that cause a vehicle camera to classify it as a speed limit sign across varying distances, angles, and lighting.
