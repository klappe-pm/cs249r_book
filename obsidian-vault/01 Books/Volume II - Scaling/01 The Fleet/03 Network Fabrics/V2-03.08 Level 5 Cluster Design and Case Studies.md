# V2-03.08 Level 5 Cluster Design and Case Studies

[[Home|Home]] · [[01 Books/Volume II - Scaling/Volume 2 Overview|Volume Overview]] · [[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03 Network Fabrics|V2-03 Network Fabrics]]

^sec-network-fabrics-cluster

Cluster design reduces to concrete engineering decisions: which cables to buy, how to wire the racks, which protocol to deploy, and how to validate that the resulting fabric delivers the bandwidth the training job expects. At this final level of the stack, wires, transport, topology, and congestion control combine into a coherent system, an end-to-end gradient bus that makes thousands of distributed GPUs feel like a single machine. Two representative large-scale architectures, one built on InfiniBand and one on Ethernet, illuminate the trade-offs that define ML infrastructure ([[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.15 Source References#^ref-nvidia2023dgxSuperpodH100|NVIDIA 2023]]; [[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.15 Source References#^ref-meta2024genaiInfrastructure|Meta Engineering 2024]]; [[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.15 Source References#^ref-gangidi2024rdma|Gangidi et al. 2024]]).

### The GPU-To-GPU “Gradient Bus”

^sec-network-fabrics-gradient-bus

In a well-designed cluster, the network fabric acts as a scheduler-aware extension of the system bus, not a passive pipe. The ~9× per-direction cliff between NVLink and one external port, stated at the start of this chapter, is the gap the cluster must hide. Communication-computation overlap, which the Fleet Law credits as ${T_{\text{overlap}}}$, is the first mechanism for hiding it, through the same layer-staggered AllReduce launch that spreads incast bursts in [[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.07 Level 4 Fabric Behavior, Congestion, and Routing#^sec-network-fabrics-incast|section 3.6.5]]. Overlap cannot hide the last mile of the exchange, because the gradients computed at the end of backpropagation have little computation left behind which to hide their transfer (**[[01 Books/Volume II - Scaling/02 Distributed ML/05 Collective Communication/V2-05.11 Communication-Computation Overlap#^sec-communication-overlap|Communication-Computation Overlap]]**).

Placement is the second mechanism, because it decides which communication crosses each boundary. The placement that the bandwidth hierarchy of **[[01 Books/Volume II - Scaling/01 The Fleet/02 Compute Infrastructure/V2-02.06 The Node#^sec-compute-bandwidth-hierarchy|Bandwidth hierarchy]]** sets, tensor parallelism inside the NVLink domain with pipeline stages and data-parallel replicas spanning nodes, becomes a wiring rule at cluster scale, because each fabric tier must be provisioned for the traffic placed on it. The links between nodes must meet the pipeline’s activation-transfer budget, which physical adjacency alone does not guarantee. The full fabric carries the data-parallel exchanges, which gradient accumulation makes less frequent and overlap partly hides. Production designs therefore differ mainly in how they provision that outermost tier, as the two that follow show.

### NVIDIA DGX SuperPOD Architecture

^sec-network-fabrics-dgx-superpod

The NVIDIA DGX SuperPOD, a concrete implementation of the gradient bus, provisions the outermost tier by obtaining losslessness from the link layer and aligning the wiring with the data-parallel ranks, so that the fabric’s tail behavior depends on hardware mechanisms rather than on congestion tuning. It connects DGX H100 nodes using an NDR InfiniBand network ([[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.15 Source References#^ref-nvidia2023dgxSuperpodH100|NVIDIA 2023]]). Each node acts as a dense compute island, with eight H100 GPUs connected via NVSwitch, which gives each GPU 900 GB/s of bidirectional internal bandwidth. Externally, each GPU pairs with a ConnectX-7 NIC delivering 400 Gb/s of injection bandwidth. Across a standard scalable unit of 32 nodes (256 GPUs), this yields an aggregate injection bandwidth of 12.8 TB/s (256 $\times$ 50 GB/s), the rate the scalable unit can offer the fabric when every GPU transmits at once.

This architecture connects all five levels of the network model into a single chain. At the wire (Level 1), it standardizes on 400 Gb/s NDR links, choosing copper or optics by the reach between each node and its leaf and between leaf and spine. Because those links run InfiniBand’s native link-layer credit-based flow control (Level 2), they provide a lossless medium without the pause-cascade fragility of Ethernet PFC. Above the transport, the topology (Level 3) arranges the switches as a rail-optimized fat-tree, aligning GPU rails across each scalable unit so that same-rail traffic stays close while cross-rail traffic traverses the spine layer (replacing the simpler per-rack ToR allocation of [[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.06 Level 3 Switch and Topology#^sec-network-fabrics-tor|section 3.5.1]], which illustrated switch radix). When cross-rank traffic climbs to the spine, hardware-based adaptive routing (Level 4) selects among spine paths to preserve bisection behavior. Finally, at the cluster level (Level 5), additional switching joins multiple SuperPOD scalable units into larger fleets ([[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.15 Source References#^ref-nvidia2023dgxSuperpodH100|NVIDIA 2023]]): for the 175B-parameter model, four SuperPOD scalable units wire together so that 1,024 GPUs function as one synchronous training system.

### Meta Grand Teton Platform

^sec-network-fabrics-grand-teton

Meta’s Grand Teton clusters take the opposite approach, accepting Ethernet’s congestion-tuning burden in exchange for multi-vendor supply and shared operations. Meta disclosed two Grand Teton-based 24,576-H100 clusters: one using RoCE over an Arista/OCP Ethernet fabric and one using NVIDIA Quantum-2 InfiniBand, both with 400 Gb/s endpoints. Meta used both for Llama 3 training and reported ongoing Llama 3 training on the RoCE cluster ([[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.15 Source References#^ref-meta2024genaiInfrastructure|Meta Engineering 2024]]). Ethernet lets Meta source switches from multiple vendors and reuse the optical infrastructure and management tooling of its front-end serving fleet, avoiding the operational silo of a dedicated InfiniBand island.

Meta’s RoCE study shows how Level 4 choices affect the complete fabric. It describes PFC watchdogs for long-duration pause events, iterative routing designs beyond plain ECMP, future-oriented flowlet switching experiments, and a 400G deployment in which DCQCN tuning proved difficult enough that Meta proceeded without DCQCN while relying on PFC plus higher-layer collective controls ([[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.15 Source References#^ref-gangidi2024rdma|Gangidi et al. 2024]]). That choice moved injection control from the NIC into the collective library rather than removing it, and the study cautions that the approach may not apply to all scenarios. The lesson is to validate the combination of endpoint behavior, routing, and flow control under the intended collective traffic. Large-transfer throughput alone does not establish small-message latency or recovery tails, and those results cannot be inferred from the Ethernet or InfiniBand label. Small-message latency matters in training through frequent small exchanges, which expose startup cost even when a full step lasts seconds, and in serving to a degree set by model partitioning, request shape, and service-level objectives (SLOs).

These case studies close the five-level stack by showing how the physical wire, transport protocol, topology, and congestion controls become one production fabric. The remaining operational problem is not how to build a single fast cluster, but how to share that expensive substrate across teams and workloads without sacrificing the predictable performance that training demands.

    1.  Data Parallelism within the node over NVLink, Pipeline Parallelism across the leaf switches, and Tensor Parallelism across the core spine switches
    2.  Tensor Parallelism within the node over high-bandwidth NVLink, Pipeline Parallelism across immediate inter-node links, and Data Parallelism across the cluster fabric with backward-pass overlap
    3.  Tensor Parallelism across the multi-hop core network, Data Parallelism within the CPU socket, and Pipeline Parallelism over PCIe storage buses
    4.  All three parallelism dimensions mapped uniformly across all network tiers using round-robin flow allocation

2.  Why can communication-computation overlap not hide the last mile of the gradient exchange in distributed training, and what does that leave on the critical path?

    3.  Commodity Ethernet enables multi-vendor switch and optics sourcing, supply chain resilience, and unified management tooling with web serving infrastructure, despite requiring careful PFC and routing tuning
    4.  InfiniBand switches cannot support link rates exceeding $100\text{ Gb/s}$
