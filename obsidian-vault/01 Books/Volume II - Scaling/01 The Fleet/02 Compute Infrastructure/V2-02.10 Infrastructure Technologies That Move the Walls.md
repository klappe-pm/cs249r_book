# V2-02.10 Infrastructure Technologies That Move the Walls

[[Home|Home]] · [[01 Books/Volume II - Scaling/Volume 2 Overview|Volume Overview]] · [[01 Books/Volume II - Scaling/01 The Fleet/02 Compute Infrastructure/V2-02 Compute Infrastructure|V2-02 Compute Infrastructure]]

^sec-compute-emerging

A new data center will host several generations of accelerators over its facility life, which operators typically depreciate across 15–20 years ([[01 Books/Volume II - Scaling/01 The Fleet/02 Compute Infrastructure/V2-02.14 Source References#^ref-barroso2019|Barroso et al. 2019]]), so future-facing technologies matter only when they change a durable planning constraint. The useful test is not whether a technology is novel, but which wall it moves, what new wall appears after the move, and which fleet-design decision changes as a result. Compute Express Link (CXL) moves the memory-capacity boundary, wafer-scale integration the chip-to-chip communication boundary, and optical circuit switching the fabric topology and power boundary, while advanced packaging moves the die boundary inside the accelerator package. None of them repeals the physics of data movement; each relocates the place where infrastructure teams must spend power, cooling, cost, and software complexity.

### Compute Express Link (CXL)

^sec-compute-cxl

Holding 1,400 GB of Adam optimizer state or terabyte-scale embedding tables inside accelerator HBM consumes the most expensive memory tier in the cluster for data touched only once per parameter update or sparse lookup. **CXL** addresses this capacity bottleneck by building protocols for I/O, caching, and coherent memory access on top of the PCIe physical layer. Supported device types and platform configurations determine which of those capabilities are available. Memory expanders and pooled memory can make host capacity less rigid, but accelerator access also requires a supported data path and software placement. Fleet planning must establish those capabilities before treating a pool as available training memory.

For ML training, the natural target is cold or phase-local state rather than the active matrix-multiply working set. The 1,400 GB Adam optimizer state of our 175B model is touched during parameter updates rather than streamed through every Tensor Core operation. A shared CXL pool could therefore reduce per-node memory pressure by holding optimizer shards, embedding-table spillover, or local data-cache buffers outside the accelerator HBM tier. The training framework still has to schedule this state carefully, but the placement problem becomes less binary than “fits in this node” or “spills to storage.”

The new wall is bandwidth. A representative CXL memory path over PCIe Gen5 x16 provides 64 GB/s, while H100 HBM provides 3.35 TB/s. That 52× gap means weights and activations for the forward and backward passes still belong in HBM. CXL is a capacity tier, not an HBM replacement. For fleet design, planners should ask whether server platforms, rack layouts, and orchestration software can absorb CXL memory pooling, not whether CXL removes the need for high-bandwidth accelerator memory.

### Wafer-Scale Planning Constraint

^sec-compute-wafer-scale-integration

At the opposite extreme from CXL sits the wafer-scale engine introduced in [[01 Books/Volume II - Scaling/01 The Fleet/02 Compute Infrastructure/V2-02.03 The Accelerator#^sec-compute-wafer-scale|section 2.2.1]]. Its on-wafer fabric removes package- and board-level transfers for mapped operations, but it does not make communication free. Infrastructure planning instead shifts toward capacity, placement, and injection bandwidth.

Our 175B running model needs 350 GB for FP16 weights alone, far beyond the 44 GB of on-wafer SRAM. Cerebras addresses this through weight streaming: external MemoryX units feed weights to the wafer over a 1.2 TB/s path while the wafer executes each layer, decoupling model capacity from the on-wafer memory. Weight streaming was designed for training. Activations stay on the wafer while weights stream in layer by layer and gradients stream back to MemoryX, which performs the optimizer update. The approach works when each layer’s computation is large enough to hide the streaming time. The wafer trades the communication wall for a streaming-bandwidth wall.

The lesson for infrastructure planners is not that wafer-scale systems replace GPU fleets. It is that memory proximity and memory capacity trade against each other. WSE-style designs buy extraordinary local bandwidth by putting the working set near the arithmetic, while CXL buys flexible capacity by moving memory farther away. HBM sits between those extremes: off-chip but on-package, smaller than host memory but fast enough for the active computation. The right architecture is the one whose memory tier matches the workload’s reuse pattern.

### Reconfigurable Topologies and Optical Circuit Switching

^sec-compute-reconfigurable-topologies-ocs

Beyond the package, optical circuit switching (OCS) moves the fabric topology and power boundary. Micro-electro-mechanical systems (MEMS) mirror arrays steer light between fiber ports without converting it to electrical form. A pod’s physical topology can therefore be rewired for each job and around failed hardware, as in Google’s TPU v4 pods. Millisecond-scale reconfiguration, however, limits OCS to job-level allocation rather than per-message routing. **[[01 Books/Volume II - Scaling/01 The Fleet/03 Network Fabrics/V2-03.06 Level 3 Switch and Topology#^sec-network-fabrics-ocs|Optical circuit switching and reconfigurable topology]]** develops the mechanism, the TPU v4 deployment, and its fault-isolation limits.

The common theme is relocation rather than elimination. CXL pushes capacity outward into a fabric where PCIe bandwidth becomes the limiting discipline, whereas wafer-scale integration pulls communication inward onto silicon where on-wafer capacity and yield take over. In the same way, advanced packaging, with 2.5D interposers such as TSMC’s CoWoS and 3D stacking such as SoIC, compresses die-to-die distance past the reticle limit. It leaves the rack to absorb the resulting power density, which must be checked against the package and cooling budgets. Optical circuit switching, in turn, removes the optical-electrical-optical conversion inside the switch only to make reconfiguration latency the new boundary. Infrastructure planning therefore still begins by identifying where the next byte moves, how quickly it must arrive, and what physical system must be built so that movement does not dominate the workload.

1.  A representative CXL memory path over PCIe Gen5 x16 delivers roughly $64\text{ GB/s}$ of bandwidth, approximately $50\times$ lower than an H100’s $3.35\text{ TB/s}$ HBM3 bandwidth. Which infrastructure bottleneck is CXL memory pooling designed to relieve, and which bottleneck does it explicitly not solve?

    1.  It relieves peak Tensor Core throughput shortages, but does not solve the memory capacity limit.
    2.  It relieves rack cooling limits by eliminating electrical resistance, but does not solve chip-to-chip latency.
    3.  It relieves the memory capacity ceiling by holding phase-local optimizer state in shared pooled memory, but explicitly does not replace HBM for bandwidth-critical forward and backward pass weight streaming.
    4.  It relieves wafer-scale weight injection bottlenecks, but does not solve semiconductor yield.

2.  A systems team proposes moving a 1.8-trillion parameter LLM training workload to a Wafer-Scale Engine (such as Cerebras WSE-3) to eliminate chip-to-chip network communication delays. Explain why this move changes rather than eliminates communication constraints and identify the resulting capacity and bandwidth budgets.

3.  Advanced packaging technologies (such as 2.5D silicon interposers and 3D chiplet stacking) enable dense die-to-die interconnects on a single package. According to systems engineering principles, how does advanced packaging alter the landscape of infrastructure bottlenecks?

    1.  It allows accelerators to run uncooled at ambient room temperature by eliminating electrical resistance across die boundaries.
    2.  It permanently eliminates both the memory wall and the power wall by integrating optical waveguides directly onto the silicon substrate.
    3.  It eliminates the need for distributed training frameworks because all model parameters can fit permanently in on-die SRAM caches.
    4.  It shortens die-to-die paths while requiring package power density, current transients, and heat removal to be checked against the intended configuration.
