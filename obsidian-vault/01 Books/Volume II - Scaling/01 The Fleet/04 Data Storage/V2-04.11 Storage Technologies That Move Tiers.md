# V2-04.11 Storage Technologies That Move Tiers

[[Home|Home]] · [[01 Books/Volume II - Scaling/Volume 2 Overview|Volume Overview]] · [[01 Books/Volume II - Scaling/01 The Fleet/04 Data Storage/V2-04 Data Storage|V2-04 Data Storage]]

^sec-storage-emerging

Today’s six-tier hierarchy leaves a 1,000× latency cliff between host DRAM (~100 ns) and local NVMe (~100 μs), forces the host CPU to spend cycles decoding and staging payload bytes, and pauses training while synchronous checkpoints reach flash. Compute Express Link (CXL), the coherent capacity tier of **[[01 Books/Volume II - Scaling/01 The Fleet/02 Compute Infrastructure/V2-02.10 Infrastructure Technologies That Move the Walls#^sec-compute-cxl|Compute express link (CXL)]]**, targets the DRAM-to-NVMe gap first. Seen from storage, CXL-attached memory is a “Tier 1.5,” slower than host DRAM but byte-addressable, with access latencies of roughly 200 to 500 ns against the roughly 100 μs of an NVMe read. It offers a capacity pool for the structures that the Tier 1 discussion showed competing for host DRAM. For the running example, CXL-attached memory could expand the effective host memory tier from 512 GB to over 4 TB per node. That pool could hold deeper prefetch queues, embedding-table spillover, or a local shard cache as large as the 3 TB compressed source corpus without paying NVMe access latency on every read, though it still falls short of the full 6 TB tokenized training copy on one node.

A different bottleneck appears when CPU-side decoding, not storage bandwidth, throttles the pipeline. The computational storage drive relieves that bottleneck by embedding processing elements, either field-programmable gate arrays (FPGAs) or simple CPU cores, directly on the SSD controller, enabling decompression, filtering, or format conversion to happen at the storage device rather than consuming host CPU cycles. For ML pipelines where CPU-side decoding is the bottleneck, computational storage could eliminate the CPU from the data path entirely, complementing GDS by offloading work that direct DMA cannot address.

Checkpoint writes impose the pause ${T_{\text{write}}}$ while a consistent snapshot reaches the first storage tier, and shrinking it makes frequent saves less costly. Persistent memory, despite market shifts such as Intel’s 2022 wind-down of its Optane memory business ([[01 Books/Volume II - Scaling/01 The Fleet/04 Data Storage/V2-04.15 Source References#^ref-intel2022optane|Intel Corporation 2022]]), remains the architectural idea that attacks that term directly. Byte-addressable non-volatile memory could lower the destination-device latency, but the checkpoint pause still includes snapshot creation, byte transfer, and coordination. A lower device-access latency reduces ${T_{\text{write}}}$ only to the extent that this device lies on the pause’s critical path.

These technologies are not yet broadly deployed at the scale of the largest ML clusters, but they illustrate the direction of the storage hierarchy’s evolution. The fundamental principle remains unchanged, with faster, more expensive storage closer to the accelerator and slower, cheaper storage at the periphery. What changes is the *granularity* of the tiers and the *size of the gaps* between them.
