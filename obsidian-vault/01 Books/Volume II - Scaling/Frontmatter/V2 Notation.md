# V2 Notation

[[Home|Home]] · [[01 Books/Volume II - Scaling/Volume 2 Overview|Volume Overview]]

^notation

To a machine learning researcher, ${B}$ denotes batch size, while to a network engineer, ${B}$ denotes bandwidth. In distributed systems, ${N}$ represents the count of worker accelerators, whereas in statistics, ${N}$ denotes sample count. In high-performance computing, ${P}$ is commonly used for processor count, but in deep learning, ${P}$ is reserved for model parameter count. Similarly, in this book’s communication models, ${\alpha}$ denotes per-message network latency and ${\beta}$ denotes link bandwidth, whereas in statistical learning, ${\alpha}$ represents a power-law scaling exponent and ${\beta}$ represents optimizer momentum.

These collisions arise because machine learning at scale combines three fields that developed their mathematical conventions independently: machine learning, distributed systems, and high-performance data center networking. Training and serving modern foundation models requires orchestrating workloads across thousands of accelerators connected by high-speed networks, which places symbols from all three fields into the same equation.

This book establishes a unified mathematical notation for distributed machine learning systems. The conventions defined below eliminate ambiguity across scaling laws, collective communication algorithms, parallel execution schedules, and cluster reliability models.

## The Governing Equations of Distributed Performance

^sec-notation-governing-laws

A distributed training step or serving request spends time both inside each accelerator and across the network that connects them, so performance modeling follows a two-tier hierarchy: the single-device execution foundation and its fleet-wide composition. The subsections that follow state each governing equation and define the symbols that appear in its terms.

### The Single-Device Foundation (The Iron Law of ML Systems)

^sec-notation-conventions-iron-law-ml-systems-ce9d

Every distributed training step or inference pass builds on local execution on individual accelerators. For serialized execution phases on a single accelerator, the **iron law of ML systems** decomposes execution time into memory access, arithmetic computation, and latency overhead:

$$
{T} = \underbrace{\frac{{D_{\text{vol}}}}{{\text{BW}}}}_{\text{Memory Time}} + \underbrace{\frac{{O}}{{R_{\text{peak}}} \cdot {\eta_{\text{hw}}}}}_{\text{Compute Time}} + \underbrace{{L_{\text{lat}}}}_{\text{Latency Overhead}}
$$

Each symbol was chosen deliberately to preserve machine learning conventions while maintaining architectural precision. The table below records the definition, physical unit, and collision-avoidance rationale for each term:

| **Symbol**                              | **Definition**                | **Unit**      | **Notes**                                                                                                                                                                                                    |
|:----------------------------------------|:------------------------------|:--------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **${T}$**                               | **Execution Time**            | seconds       | Total serialized execution time in the iron-law performance decomposition.                                                                                                                                   |
| **${\text{BW}}$**                       | **Bandwidth**                 | bytes/s       | **Avoids collision with ${B}$ (Batch Size)**. Systems literature often uses ${B}$ for bandwidth, while ML literature often uses ${B}$ for batch size. The notation preserves the ML convention.              |
| **${D_{\text{vol}}}$**                  | **Data Volume**               | bytes         | **Avoids collision with ${D}$ (Dataset Size)**. In scaling laws, ${D}$ means training tokens. Here we need bytes moved through memory. The subscript disambiguates.                                          |
| **${\eta_{\text{hw}}}$**                | **Efficiency**                | —             | Hardware utilization $(0 \le {\eta_{\text{hw}}} \le 1)$. Avoids collision with learning rate $({\eta})$.                                                                                                     |
| **${L_{\text{lat}}}$**                  | **Latency**                   | seconds       | **Avoids collision with ${L}$ (Loss)**. Fixed overhead time (kernel launch, network RTT). The subscript distinguishes from the loss function.                                                                |
| **${O}$**                               | **Operations**                | FLOPs         | Total floating-point operations. Clean in equations (vs. “$\text{Ops}$”).                                                                                                                                    |
| **${R_{\text{peak}}}$**                 | **Peak Rate**                 | FLOP/s        | **Avoids collision with ${P}$ (Parameters)**. Roofline presentations often use ${P}$ for performance, while ML literature commonly uses ${P}$ for parameter count. The notation preserves the ML convention. |
| **${\Theta}$**                          | **Asymptotic Tight Bound**    | Operator      | Asymptotic tight bound: grows at the same rate as its argument, up to constant factors.                                                                                                                      |
| **${D_{\text{vol}}^{(\text{batch})}}$** | **Batch Data Volume**         | bytes         | Bytes of input data one batch carries to the accelerator.                                                                                                                                                    |
| **${f}$**                               | **Clock Frequency**           | hertz         | Rate at which a processor’s clock ticks, setting how many switching cycles occur per second.                                                                                                                 |
| **${\Delta}$**                          | **Finite Change**             | Operator      | Finite change in the quantity it prefixes, between two states, configurations or points in time.                                                                                                             |
| **${\text{µ}}$**                        | **Micro Unit Prefix**         | Operator      | SI unit prefix micro, one millionth, written before a unit such as seconds.                                                                                                                                  |
| **${b}$**                               | **Numeric Bit Width**         | Integer       | Number of bits used to represent one numeric value, such as an arithmetic operand or a quantized weight or activation.                                                                                       |
| **${T_{\text{pipelined}}}$**            | **Pipelined Execution Time**  | seconds       | Execution time of a workload whose data movement and computation overlap, set by the slower of the two plus fixed latency.                                                                                   |
| **${T_{\text{sequential}}}$**           | **Sequential Execution Time** | seconds       | Execution time when data movement, computation and fixed overhead run one after another with no overlap, the sum of the iron-law terms.                                                                      |

| **${T_{\text{step}}}$**                 | **Training Step Time**        | seconds       | Wall-clock time of one training step, bounded below by the slower of compute and input I/O.                                                                                                                  |
| **${k}$**                               | **Unit Alias Multiplier**     | Dimensionless | Number of base units in one unit alias, the conversion multiplier of a unit-conventions table row.                                                                                                           |

#### Why These Choices Matter

^sec-notation-conventions-choices-matter-0c16

Without careful notation, statements about distributed systems become ambiguous. Consider a typical unsubscripted claim:

> *“Reducing ${D}$ improves performance.”*

In distributed machine learning, this could mean reducing the dataset size (fewer training samples), shrinking the data-parallel degree ${N_{\text{DP}}}$, or reducing the data volume ${D_{\text{vol}}}$ moved across the memory bus through quantization. With our notation, we distinguish them precisely:

> *“Reducing ${D_{\text{vol}}}$ through FP8 quantization cuts memory traffic across the interconnect while ${D}$ (training tokens) and ${N_{\text{DP}}}$ remain unchanged.”*

#### Subscripted Variants

^sec-notation-conventions-subscripted-variants

The root symbol names the fundamental physical quantity, while an upright subscript specifies the precise domain or measurement point. Three recurring families illustrate this convention across this book:

- ${\text{BW}_{\text{memory}}}$, ${\text{BW}_{\text{network}}}$, ${\text{BW}_{\text{interconnect}}}$: bandwidth across distinct tiers of the distributed memory and fabric hierarchy.
- ${D_{\text{vol}}}$, ${R_{\text{peak}}}$, ${L_{\text{lat}}}$, ${\eta_{\text{hw}}}$: single-node iron-law terms, held clear of shared ML symbols.
- ${E_{\text{move}}}$, ${E_{\text{compute}}}$, ${E_{\text{total}}}$: energy budget components across distributed compute nodes.

The subscript therefore carries part of the claim. Memory and network bandwidth differ by orders of magnitude, so a figure is reproducible only when the subscript says where it was measured.

### The Fleet Law (Distributed Step Time)

^sec-notation-distributed

When scaling a model across a fleet of ${N}= {N_{\text{GPU}}}$ accelerators, single-device compute time is distributed across workers, while communication and synchronization overheads are introduced. Under partitioned execution of fixed work, the governing equation is the **Fleet Law** (the distributed step-time model, **[[01 Books/Volume II - Scaling/00 Introduction/01 Introduction/V2-01.06 The C³ Taxonomy and Foundations of Scale#^eq-fleet-law|equation 1.3]]**):

$$
{T_{\text{step}}}({N}) = \frac{{T_{\text{compute}}}}{{N}} + {T_{\text{comm}}}({N}) + {T_{\text{sync}}}({N}) - {T_{\text{overlap}}}
$$

| **Symbol**                                    | **Definition**                        | **Unit**      | **Notes**                                                                                                                                                                                                    |
|:----------------------------------------------|:--------------------------------------|:--------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **${N}, {N_{\text{GPU}}}$**                   | **Number of Devices**                 | Integer       | Accelerator count in a distributed job, the core’s ${N_{\text{GPU}}}$ (${N}= {N_{\text{GPU}}}$); also the rank count of a collective. *(Not parameters, use ${P}$.)*                                         |
| **${G_{\text{node}}}$, ${N_{\text{nodes}}}$** | **Accelerators per Node, Node Count** | Integer       | Hierarchical collectives split the fleet as ${N}= {G_{\text{node}}} {N_{\text{nodes}}}$. *(Bare ${G}$ is the LogGP gap per byte.)*                                                                           |
| **${T_{\text{step}}}({N})$**                  | **Distributed Step Time**             | seconds       | Wall-clock time for one training step at scale ${N}$.                                                                                                                                                        |
| **${T_{\text{compute}}}$**                    | **Single-Device Compute Time**        | seconds       | The core’s compute term for one training step (forward + backward pass) on one device.                                                                                                                       |
| **${T_{\text{comm}}}({N})$**                  | **Communication Time**                | seconds       | Time for collective operations (AllReduce, AllGather); depends on payload, topology, and ${N}$.                                                                                                              |
| **${T_{\text{overlap}}}$**                    | **Overlapped Time**                   | seconds       | Communication hidden behind computation. Reduces effective overhead.                                                                                                                                         |
| **${T_{\text{sync}}}({N})$**                  | **Synchronization Time**              | seconds       | Total nonoverlapped synchronization or coordination cost per step at scale ${N}$.                                                                                                                            |
| **${\rho}$**                                  | **Communication-Computation Ratio**   | Dimensionless | ${\rho}= {T_{\text{comm}}}({N})/({T_{\text{compute}}}/{N})$. Values near or above 1 indicate communication-bound scaling.                                                                                    |
| **${\text{CI}}$**                             | **Communication Intensity**           | bytes/FLOP    | Network bytes moved per local FLOP, ${\text{CI}} = {M}/{O}$; the fleet analogue of arithmetic intensity ${I}$.                                                                                               |
| **${C_2}$**                                   | **Communication Axis**                | Set           | Communication axis of the C$^3$ taxonomy, data movement across the network fabric, viewed as the set of techniques it covers so that axis intersections name zones of the taxonomy.                          |
| **${C_1}$**                                   | **Compute Axis**                      | Set           | Compute axis of the C$^3$ taxonomy, local arithmetic and memory within a node, viewed as the set of techniques it covers so that axis intersections name zones of the taxonomy.                              |
| **${C_3}$**                                   | **Coordination Axis**                 | Set           | Coordination axis of the C$^3$ taxonomy, synchronization, failure recovery and scheduling across the fleet, viewed as the set of techniques it covers so that axis intersections name zones of the taxonomy. |
| **${C}$**                                     | **Operational Dimension**             | Record        | One of the three operational dimensions of the C$^3$ taxonomy, indexed 1 to 3 as compute, communication and coordination.                                                                                    |

### Scaling Laws of Foundation Models

^sec-notation-scaling-laws

Scaling laws anchor the book’s account of why machine learning moved onto fleets. The single-resource power law and the dense-transformer compute rule are:

$$
{\mathcal{L}}({X}) = {A_{\mathcal{L}}} {X}^{-{\alpha_{\text{scale}}}} + {C_{\mathcal{L}}}, \qquad {O_{\text{train}}} \approx 6{P} {D}
$$

| **Symbol**                    | **Definition**           | **Unit**      | **Notes**                                                                                                                                                 |
|:------------------------------|:-------------------------|:--------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------|
| **${X}$**                     | **Scaled Resource**      | varies        | Training compute, parameter count ${P}$, or training tokens ${D}$, depending on the fitted law.                                                           |
| **${\alpha_{\text{scale}}}$** | **Scaling Exponent**     | Dimensionless | Fitted power-law exponent; valid only within the regime in which it was measured. *(Not network latency ${\alpha}$.)*                                     |
| **${A_{\mathcal{L}}}$**       | **Scale Coefficient**    | loss units    | Task-dependent fitted constant.                                                                                                                           |
| **${C_{\mathcal{L}}}$**       | **Irreducible Loss**     | loss units    | Loss floor that added resources do not remove within the fitted regime.                                                                                   |
| **${O_{\text{train}}}$**      | **Training Compute**     | FLOPs         | About $6{P} {D}$ for a dense transformer: $2{P}$ per token forward and $4{P}$ backward.                                                                   |
| **${B_{\text{base}}}$**       | **Base Batch Size**      | Integer       | Reference batch size at which the base learning rate was tuned.                                                                                           |
| **${\eta_{\text{base}}}$**    | **Base Learning Rate**   | Dimensionless | Learning rate tuned at the reference batch size before linear scaling.                                                                                    |
| **${N_{\text{epochs}}}$**     | **Epoch Count**          | Integer       | Number of full passes a training run makes over its dataset.                                                                                              |
| **${B_{\text{new}}}$**        | **Scaled Batch Size**    | Integer       | Batch size a training recipe is scaled to under the linear scaling rule.                                                                                  |
| **${\eta_{\text{new}}}$**     | **Scaled Learning Rate** | Dimensionless | Learning rate used at a new batch size under the linear scaling rule.                                                                                     |
| **${\mathcal{L}}$**           | **Scaling Law Loss**     | Function      | Loss a trained model reaches as a function of the resource scaled, such as parameters, training tokens or compute, in an empirical power-law scaling law. |

### The Distributed Energy Corollary

^sec-notation-conventions-energy-corollary-a1da

At data center scale, energy and power delivery are primary system constraints. For ${N}$ devices that each move the same ${D_{\text{vol}}}$ bytes and execute the same ${O}$ FLOPs over a workload interval, effective per-byte data-movement costs and per-operation compute costs give the following fleet energy model. Here the work and traffic terms are per-device quantities, so multiplying by ${N}$ sums the device contributions:

$$
{E_{\text{total}}} \approx {N}\times \left( {D_{\text{vol}}} \times {E_{\text{move}}} + {O} \times {E_{\text{compute}}} \right)
$$

## Network Communication Models and Collectives

^sec-notation-comm-models

Collective communications (AllReduce, AllGather, ReduceScatter, AllToAll) move payloads across the network fabric, following ring or tree schedules over topologies such as the fat tree. The models below price those transfers by separating fixed per-message latency from bandwidth-proportional transmission time.

### The Communication Model

^sec-notation-alpha-beta

In the standard first-order model, network communication time decomposes into fixed message startup latency and bandwidth-dependent transfer. For a single point-to-point message, transfer time is the sum of those two terms:

$$
{T}({n}) = {\alpha}+ \frac{{n}}{{\beta}}
$$

The model keeps its literature’s letters as aliases of core concepts: ${\alpha}$ is the per-message ${L_{\text{lat}}}$ and ${\beta}$ is a link’s ${\text{BW}}$, written in ${\alpha}$-${\beta}$ form. Inside ${\alpha}$-${\beta}$ formulas, write ${\alpha}$ and ${\beta}$; elsewhere, write ${L_{\text{lat}}}$ and a subscripted ${\text{BW}}$.

| **Symbol**                                   | **Definition**                   | **Unit**      | **Notes**                                                                                                                                                                                                                                                                   |
|:---------------------------------------------|:---------------------------------|:--------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **${T}({n})$**                               | **Point-to-Point Transfer Time** | seconds       | Wall-clock time to transmit one message of size ${n}$ across one link.                                                                                                                                                                                                      |
| **${n}$**                                    | **Point-to-Point Message Size**  | bytes         | Size of one message in ${T}({n})$.                                                                                                                                                                                                                                          |
| **${\alpha}$**                               | **Per-Message Latency**          | seconds       | The core’s ${L_{\text{lat}}}$ for one message, in ${\alpha}$-${\beta}$ form: the fixed startup cost. *(Not significance level or Rényi order, which carry subscripts.)*                                                                                                     |
| **${\beta}$**                                | **Link Bandwidth**               | bytes/s       | The core’s ${\text{BW}}$ for one link (${\text{BW}_{\text{link}}}$), in ${\alpha}$-${\beta}$ form: effective throughput per link.                                                                                                                                           |
| **${n^*}$**                                  | **Crossover Point**              | bytes         | ${n^*}= {\alpha}\cdot {\beta}$. Below ${n^*}$: latency-bound. Above: bandwidth-bound.                                                                                                                                                                                       |
| **${M}$**                                    | **Collective Payload Size**      | bytes         | Per-rank gradient, model-state, activation, or compressed payload that a collective moves. Not a memory footprint (those are ${M_{\text{total}}}$, ${M_{\text{weights}}}$, and so on) and not the core’s GEMM dimension ${M}$, which appears only in GEMM shape statements. |
| **${M_{\text{coll}}}$**                      | **Collective Tensor Size**       | bytes         | Full tensor acted on by Broadcast, Reduce, or AllReduce, reconstructed by AllGather, or partitioned by ReduceScatter. An equally sharded AllGather starts with ${M_{\text{coll}}}/{N}$ bytes per rank; AllToAll uses the per-rank payload ${M}$.                            |
| **${T_{\text{ring}}}$, ${T_{\text{tree}}}$** | **Collective Completion Time**   | seconds       | AllReduce time under the ring or tree algorithm in ${\alpha}$-${\beta}$ form, for example ${T_{\text{ring}}} = 2({N}-1){\alpha}+ 2\frac{{N}-1}{{N}}\frac{{M}}{{\beta}}$. ${T_{\text{allreduce}}}$ names an AllReduce whose algorithm the text leaves open.                  |
| **${M_{\text{crossover}}}$**                 | **Ring-Tree Crossover Payload**  | bytes         | Payload at which ${T_{\text{ring}}} = {T_{\text{tree}}}$; approximately ${N}{\alpha}{\beta}/\log_2 {N}$ for large ${N}$.                                                                                                                                                    |
| **${T_{\text{allreduce}}}$**                 | **AllReduce Completion Time**    | seconds       | Time to complete one AllReduce collective over a group of devices, whatever algorithm implements it.                                                                                                                                                                        |
| **${T_{\text{alltoall}}}$**                  | **AllToAll Completion Time**     | seconds       | Time to complete one AllToAll collective, in which every device exchanges a distinct share of its payload with every other device.                                                                                                                                          |
| **${\text{BW}_{\text{bisect}}}$**            | **Bisection Bandwidth**          | bytes/s       | Total bandwidth across the narrowest cut that divides a network’s nodes into two equal halves.                                                                                                                                                                              |
| **${i}$**                                    | **Local Rank Index**             | Integer       | Position of an accelerator within its node, its local rank, which in a rail-optimized fabric also names the rail it attaches to.                                                                                                                                            |
| **${\text{BW}_{\text{network}}}$**           | **Network Bandwidth**            | bytes/s       | Sustained rate at which a network path delivers bytes between machines.                                                                                                                                                                                                     |
| **${M}$**                                    | **Network Traffic Volume**       | bytes         | Bytes one worker moves across the network over a stated interval, such as one training step.                                                                                                                                                                                |
| **${m}$**                                    | **Rank Count Binary Exponent**   | Dimensionless | Integer exponent for which the rank count equals two raised to it, the condition algorithms such as butterfly AllReduce require.                                                                                                                                            |
| **${i}$**                                    | **Rank Index**                   | Integer       | Position of one rank, a device or worker, within a collective communication group, counted from zero.                                                                                                                                                                       |
| **${\text{BW}_{\text{link}}}$**              | **Single Link Bandwidth**        | bytes/s       | Bandwidth of one network link in one direction, written in the core bandwidth notation outside alpha-beta formulas.                                                                                                                                                         |
| **${k}$**                                    | **Switch Radix**                 | Integer       | Number of ports on one network switch, its radix.                                                                                                                                                                                                                           |
| **${N}$**                                    | **Topology Endpoint Count**      | Integer       | Number of endpoints, accelerators or hosts, that one network topology connects, the size variable of its scaling relations.                                                                                                                                                 |

### The LogGP Extension

^sec-notation-loggp

LogGP refines the ${\alpha}$-${\beta}$ model by separating network transit latency, processor initiation overhead, and long-message injection gaps. The book uses descriptive subscripts for the highest-collision terms; the bare letters ${g}$ and ${G}$ keep their LogGP meanings inside this model only.

| **Symbol**                   | **Definition**                 | **Unit**     | **Notes**                                                                                                                                                                                                                                     |
|:-----------------------------|:-------------------------------|:-------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **${T_{\text{long}}}({n})$** | **LogGP Long-Message Time**    | seconds      | Transfer time for an ${n}$-byte long message. Reuses ${n}$ from the ${\alpha}$-${\beta}$ model.                                                                                                                                               |
| **${L_{\text{LogGP}}}$**     | **LogP/LogGP Network Latency** | seconds      | Network transit time of one message, the part of the core’s ${L_{\text{lat}}}$ that excludes processor overhead, so ${\alpha}\approx {o_{\text{send}}} + {L_{\text{LogGP}}} + {o_{\text{recv}}}$. The subscript avoids bare ${L}$ collisions. |
| **${o_{\text{send}}}$**      | **Sender Overhead**            | seconds      | Processor/NIC overhead to initiate a message.                                                                                                                                                                                                 |
| **${o_{\text{recv}}}$**      | **Receiver Overhead**          | seconds      | Processor/NIC overhead to complete a message. Symmetric LogP writes ${o}= {o_{\text{send}}} = {o_{\text{recv}}}$, so one message costs $2{o}$.                                                                                                |
| **${g}$**                    | **Message Injection Gap**      | seconds      | Minimum interval between consecutive message injections. *(Gradients are bold, ${\mathbf{g}}$.)*                                                                                                                                              |
| **${G}$**                    | **Long-Message Gap per Byte**  | seconds/byte | Per-byte long-message gap; distinct from ${\beta}$ link bandwidth. *(Accelerators per node are ${G_{\text{node}}}$.)*                                                                                                                         |
| **${o}$**                    | **Symmetric Message Overhead** | seconds      | Processor time spent initiating or completing one message in the symmetric LogP model, where sender and receiver overheads are equal, during which the processor cannot compute.                                                              |

| **${T_{\text{compressed}}}$** | **Compressed Communication Time**   | seconds  | Total time after encode, transfer of ${M}/{r_{\text{comp}}}$, and decode.                               |
| **${T_{\text{encode}}}$**     | **Codec Encode Time**               | seconds  | Local compression overhead before transfer.                                                             |
| **${T_{\text{decode}}}$**     | **Codec Decode Time**               | seconds  | Local decompression overhead after transfer.                                                            |
| **${b_{\text{block}}}$**      | **Quantization Block Size**         | Integer  | Number of tensor elements in one block of block-wise quantization, all sharing one scale.               |
| **${s}$**                     | **Quantization Scale**              | Varies   | Real-valued step between adjacent integer levels of a uniform quantizer.                                |
| **${K_{\text{top}}}$**        | **Retained Gradient Element Count** | Integer  | Number of largest-magnitude gradient elements top-k sparsification keeps and transmits.                 |

## Parallelism Dimensions and Scaling Efficiency

^sec-notation-parallelism-scaling

Scaling large foundation models requires combining multiple parallelism strategies across device dimensions. The notation below tracks how devices are partitioned across those dimensions and how efficiently the combined schedule converts added hardware into speedup.

### Parallelism Dimensions

^sec-notation-parallelism

A single parallelism strategy rarely scales across an entire cluster without hitting memory or bandwidth limits. To stay within both bounds, 3D parallelism partitions the training workload across three orthogonal dimensions:

### Scaling Efficiency

^sec-notation-scaling

Adding accelerators to a job increases communication and synchronization overhead alongside raw compute capacity. Scaling efficiency measures the resulting realized speedup relative to ideal linear scaling:

$$
{\eta_{\text{scaling}}} = \frac{{T_1}}{{N}\times {T_N}}
$$

| **Symbol**                    | **Definition**         | **Unit**      | **Notes**                                                                                                                                              |
|:------------------------------|:-----------------------|:--------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------|
| **${\eta_{\text{scaling}}}$** | **Scaling Efficiency** | Dimensionless | Ratio of measured speedup to ideal linear speedup. $1.0$ is the ideal linear baseline, not a hard upper bound.                                         |
| **${T_1}$**                   | **Single-Device Time** | seconds       | Baseline wall-clock time for the same productive work on one device.                                                                                   |
| **${T_N}$**                   | **N-Device Time**      | seconds       | Wall-clock time for the same productive work on ${N}$ devices; excludes operational downtime counted by ${\eta_{\text{runtime}}}$.                     |
| **${r}$**                     | **Serial Fraction**    | Dimensionless | Share of a fixed workload’s single-device execution time that does not shrink when the work is spread across devices, the serial term of Amdahl’s law. |

## Cluster Reliability, Fault Tolerance, and Checkpointing

^sec-notation-reliability-sec

At cluster scale, hardware component failures are standard operating conditions rather than rare anomalies. The symbols in this section quantify failure rates, checkpoint intervals, recovery overheads, and their net effect on fleet goodput.

### Fault Tolerance and Reliability

^sec-notation-reliability

When a job requires many components to remain healthy simultaneously, individual failure hazards compound across the fleet. Assuming independent components with exponential failure distributions, system reliability across ${N}$ components is:

$$
{R_{\text{system}}}({t}) = e^{-{N}{\lambda} {t}}
$$

The aggregate exponent uses the system-level rate ${N}{\lambda}$, where ${\lambda}$ is the per-component failure rate under the independent, identical-component assumption. The exponent ${N}{\lambda} {t}$ is dimensionless, so the elapsed time ${t}$ must use the same time unit as ${\lambda}$ (hours, when ${\lambda}$ comes from the FIT-derived rates below).

Checkpointing too frequently wastes wall time writing state to storage, whereas checkpointing too rarely loses long stretches of training work when a node fails. The optimal checkpoint interval balances that I/O overhead against recomputation rework:

$$
{T^\ast_{\text{ckpt}}} = \sqrt{2 \cdot {T_{\text{write}}} \cdot {\text{MTBF}_{\text{system}}}}
$$

The formula uses the *system-wide* mean time between failures (the failure interval for the whole job), not a *component* lifetime; substituting the per-component value would overestimate ${T^\ast_{\text{ckpt}}}$ by $\sqrt{{N}}$. For dimensional consistency, ${T_{\text{write}}}$ and ${\text{MTBF}_{\text{system}}}$ must be in the same time unit. Industry-standard ${\text{MTBF}}$ is reported in hours; to combine it with seconds-scale write times, multiply the hour value by 3600. The result ${T^\ast_{\text{ckpt}}}$ then carries the time unit chosen for the inputs.

## Units, Precision, and Disambiguation

^sec-notation-units-disambiguation

A link rate quoted in gigabits per second looks eight times larger than the same rate in gigabytes per second, and an 80 GB memory label can mean either $80 \times 10^9$ or $80 \times 2^{30}$ bytes depending on whether decimal or binary prefixes apply. The unit, precision, and disambiguation conventions below keep numerical comparisons consistent across every chapter.

### Units and Precision

^sec-notation-conventions-units-precision-fdaf

- Physical units: This book uses SI (metric) units throughout, including meters, kilograms, seconds, watts, and °C, consistent with standard engineering and scientific practice. Where source data was originally reported in imperial units, the book converts to SI and notes the original values parenthetically. A space always separates the number from the unit (for example, 100 ms, 2 TB/s).
- Data and memory: This book uses **decimal SI prefixes only**: KB = $10^3$ bytes, MB = $10^6$, GB = $10^9$, TB = $10^{12}$. Binary-prefixed units do not appear in prose; model sizes, activation footprints, throughputs, and transfer volumes are reported in decimal units (for example, 2 TB/s, 102 MB). Hardware memory capacities retain the vendor’s nameplate figure and label. A modeled capacity of $80 \times 2^{30}$ bytes follows the registered device assumption, not a guarantee implied by an 80 GB label. Where a worked example subtracts a computed footprint from a device capacity, the registered capacity in bytes and the footprint are both converted to decimal; **[[05 Reference/Volume II - Scaling/V2 System Assumptions#^sec-appdx-fleet-system-assumptions|System Assumptions]]** states this exception in full.
- Compute: The notation distinguishes operation counts from rates. Total work uses FLOPs (for example, GFLOPs, TFLOPs), while throughput uses FLOP/s with decimal prefixes (for example, GFLOP/s, TFLOP/s).
  - 1 TFLOP = $10^{12}$ FLOPs
  - 1 TFLOP/s = $10^{12}$ FLOPs per second
  - Arithmetic intensity conventionally uses FLOP/byte as a unit ratio (floating-point operations per byte moved).
- Network throughput: Reported in bytes/s (GB/s, TB/s) or bits/s (Gbps) depending on convention. InfiniBand and Ethernet specifications use Gbps; application-level throughput uses GB/s. The text states the convention on first use.
- Power: Power carries a subscript (${P_{\text{avg}}}$, ${P_{\text{device}}}$, ${P_{\text{cluster}}}$, ${P_{\text{IT}}}$); bare ${P}$ remains parameter count.
- Latency percentiles: Written p50, p95, and p99 in upright type, inside math as well as in prose.
- Currency: Dollar amounts use the dollar sign (`$`); unless otherwise noted, dollar-denominated costs are U.S. dollars (USD).
- Precision:
  - **FP64**: Double precision (8 bytes)
  - **FP32**: Single precision (4 bytes)
  - **TF32**: TensorFloat-32 (19-bit Tensor Core compute mode; inputs and storage remain FP32)
  - **FP16**: Half precision (2 bytes, standard range)
  - **BF16**: Brain float (2 bytes, wide dynamic range)
  - **FP8**: Quarter precision (1 byte, E4M3 or E5M2 format)
  - **FP4**: 4-bit floating-point format
  - **INT8**: 8-bit integer (1 byte)
  - **INT4**: 4-bit integer; lower integer precisions follow the same uppercase `INTn` pattern (for example, INT3, INT2)

### Quick Reference: Resolving Collisions

^sec-notation-conventions-quick-reference-resolving-collisions-a9cf

Several single-letter symbols carry conflicting default meanings in machine learning and systems papers. The table below resolves the four primary single-device collisions:

| **Symbol**   | **ML meaning**    | **Systems meaning** | **Book convention**                                         |
|:-------------|:------------------|:--------------------|:------------------------------------------------------------|
| **${B}$**    | **Batch Size**    | Bandwidth           | **Batch Size**. Use ${\text{BW}}$ for bandwidth.            |
| **${D}$**    | **Dataset Size**  | Data Volume         | **Dataset Size**. Use ${D_{\text{vol}}}$ for bytes moved.   |

As a general principle, ML conventions take precedence for single letters, while systems concepts get subscripts or multi-letter symbols. This reflects the primary audience (ML practitioners learning systems) and preserves compatibility with the ML literature.

| **${N}$**           | (none)                                             | Number of Devices                            | **Device Count** in distributed context (accelerators, not host nodes); ${N}= {N_{\text{GPU}}}$.                                                                                                                                          |
| **${M}$**           | GEMM dimension; memory root (${M_{\text{total}}}$) | Collective Payload                           | **Payload** when bare, outside GEMM shape statements. Memory footprints always carry a subscript.                                                                                                                                         |
| ${\lambda}$         | Regularization weight                              | Failure Rate                                 | **Subscript every other use**. Bare ${\lambda}$ is the per-component failure rate; arrival rate is ${\lambda_{\text{arr}}}$.                                                                                                              |
| ${d}$, ${t}$, ${p}$ | Hidden dimension; time; distribution ${p}(\cdot)$  | Data-, tensor-, and pipeline-parallel degree | **Core meanings**. Parallelism degrees are ${N_{\text{DP}}}$, ${N_{\text{TP}}}$, and ${N_{\text{PP}}}$.                                                                                                                                   |
| ${\tau}$            | Temperature or threshold                           | Checkpoint Interval or Delay                 | **Subscript every distributed use**. Checkpoint intervals are ${T_{\text{ckpt}}}$ and ${T^\ast_{\text{ckpt}}}$; gradient staleness is ${\tau_{\text{stale}}}$.                                                                            |
| ${\alpha}$          | Significance Level                                 | Network Latency                              | **Subscript every other use**. Bare ${\alpha}$ is ${\alpha}$-${\beta}$ per-message latency; ${\alpha_{\text{scale}}}$ is the scaling exponent, ${\alpha_{\text{sig}}}$ the significance level, and ${\alpha_{\text{R}}}$ the Rényi order. |
| ${\rho}$            | Correlation                                        | Utilization or Ratio                         | **Subscript every other use**. Bare ${\rho}$ is the communication-computation ratio; ${\rho_{\text{serv}}}$ is serving or queue utilization.                                                                                              |
| ${\epsilon}$        | Small Constant                                     | Privacy Budget                               | **Subscript every other use**. Bare ${\epsilon}$ is the privacy budget; ${\epsilon_{\text{adv}}}$ is the adversarial radius, and stabilizing constants carry their own subscripts.                                                        |
| ${g}$, ${G}$        | Gradient ${\mathbf{g}}$                            | LogGP gaps; GPUs per node                    | **LogGP only** when bare. Gradients are bold ${\mathbf{g}}$; accelerators per node are ${G_{\text{node}}}$.                                                                                                                               |
| ${K}$               | Top-${K}$, key matrix ${\mathbf{K}}$               | Attack Steps                                 | **Local when bare**. PGD attack steps are ${K_{\text{PGD}}}$; other counts are defined at use or subscripted (${K_{\text{top}}}$).                                                                                                        |
